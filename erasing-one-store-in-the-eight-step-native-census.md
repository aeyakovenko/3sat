# Erasing a store on fresh paths and exhausting the one-comparison cases

In the 16-bit selector SAT catalog the remaining eight-step paths have one comparison. A correct accepting path on any of the 64 complementary targets must read all four original words before their first overwrite. With two arithmetic operations and one store, or three arithmetic operations and no store, there are exactly four loads, so every load on each covered target is fresh. [Earlier leaf capacities and last-fresh-word bounds](one-comparison-after-the-last-fresh-word.md) · [Marked decision-tree recurrence in Lean](EightStepMarkedCapacity.lean)

## The store-erasure implication

Consider a fixed path with one store at address $t$. Delete the write and evaluate the same operations. Restrict the resulting test to the files on which none of its later loads has address $t$. Every file passing this restricted test passes the original path: before the first possible later hit, both runs fetch equal words, have equal registers and choose equal next addresses. Every accepted target in the original path passes the restricted test. Its later reads use virgin original cells, so none could have observed the preceding store. The same equality argument starting with the stored run shows the erased trajectory has the same reads on each target. Thus the restricted erased predicate retains the target support and is sound if the original path is sound. The stored value need not be enumerated. Lean checks the equality of the final states and address lists starting from either trajectory, with state-dependent read addresses. [Adaptive erasure and retention in Lean](FreshReadStoreErasure.lean)

If every load is literal, let $J\subseteq\{0,1,2,3\}$ be the addresses of the later loads. On inputs with all words at least four, a store using a raw input as its address misses all four cells. A literal store cannot hit a later necessary read on an accepted target. The remaining case has $t$ equal to either arithmetic result; the necessary condition is just $t\notin J$. Grant all four original words to both operations in their dependency order, then choose a native final comparison. For each accepting comparison, every passing negative on this high-word suite would need its $t$ to belong to $J$. A value outside $0,1,2,3$ refutes the candidate immediately. The smallest possible $J$ consists of all other store addresses observed on passing negatives, and larger $J$ can only reduce target support. The census considered all 20,412 negative files with words $4,\ldots,15$, 1,050 first arithmetic tables and 1,329,620 second-stage fast tables. None supports 37 targets. If the second ALU is absent both from the comparison and from the store address, the restricted one-ALU, two-guard high-suite census already bounds the same guarded predicate; this includes the empty $J$. [Direct-load store exclusion](two_arithmetic_results_with_a_literal_read_store.cpp) · [One-ALU high-suite cases](marked-leaves-and-high-word-lookups.md)

If both arithmetic results give fresh addresses, the endpoint argument for a chronologically last fresh read applies. All previously computed ALU values are low addresses and all previously loaded target words are distinct physical inputs, although their values can coincide. Equality and signed prefix tests against such endpoints cover at most 28 targets, and the other branch outcomes have the stated smaller bounds. This argument uses the actual last chronological read; a later store changes no subsequently observed data.

The remaining store case has three literal reads and one read through an ALU result $r$. First delete the write, then reorder the resulting read-only computation by moving direct reads to the beginning and the computed read immediately after its defining ALU. Write $D$ for the three direct physical addresses. The omitted cell $j$ is fixed, and $r=j$ on every covered target. The original store address $t$ is now one of the original program's register values or a literal. Grant any available register value for it. The store-erasure subdomain has $t\notin J$ for some $J\subseteq D$. If the computed read came after the store in the original path, additionally require $t\ne r$. Both choices are tested; the pre-store address itself cannot be a value first produced by the later computed load. Every negative passing the final comparison and the optional $t\ne r$ must have $t\in J$. The minimum-set procedure above determines the strongest possible target support compatible with these negatives.

When the second ALU supplies the computed address, both ALUs occur before the chronologically last original load. The one computed read and the three literal reads have fixed, distinct physical identities across all covered targets. Changing only that last word leaves its earlier prefix and its other comparison operand fixed. The signed initial-interval case covers at most 24 targets and a literal or other raw word cannot give an equality endpoint for 37. Therefore the only remaining comparison in this subcase is equality of the sole non-address arithmetic result with some loaded word. That word could be a direct read later than the computed read. The census includes all three literal loads as well as the computed load as choices.

A surviving store-erasure predicate would require a separate check of whether a single actual write can realize it. Exhaustion of that enlarged family is sufficient for the lower bound.

## The read-only cases

With three ALUs and four fresh loads, keep arithmetic dependency order and move the direct loads and computed-address loads as in the two-ALU census. The last ALU either supplies a computed read or produces a word to compare.

- When the last ALU gives a fresh address, the comparison must observe the returned word. Three computed reads are already excluded by the endpoint argument. For one or two computed reads, the signed and unsigned order bounds leave only equality with an earlier ALU result that is not itself a fresh address. On the targets that earlier value must equal the last remaining original word. The census first imposes this necessary equality and the pointwise distinct-address conditions. Every surviving candidate is checked against all negative physical files. There are 16 layouts, with four possible single omitted columns or six omitted pairs and two possible choices of the earlier pointer ALU.
- When the last ALU has no following read, it must appear in the final comparison. Otherwise the two-ALU unlimited-read bound applies. If the second ALU supplies a fresh word, that word must appear either in the final ALU or directly in the comparison, since it is a necessary original read. If the second ALU has no subsequent load, deleting an unused second result again gives a two-ALU case. For each covered target, change its last fresh word to 15: every complementary mate is nonzero, so this is a negative file. The common prefix and chosen address are unchanged. Recompute the one or two remaining ALUs on the changed read and require rejection. Full negative-file verification follows for the remaining candidates. This family has 14 layouts, eight for one computed address and six for two.
- If all four addresses use literals, the direct-address lower bound already applies. The preceding counts require at least one data-dependent read.

## Reproduction and verification

The three remaining search families have 38 layouts and 29,966 first arithmetic tables across layouts. These tables and all raw syntactic second-operation choices form 202,695,726 pairs before the eligibility tests. The worker enumerates all third operations and guards required for each pair. It reuses second-result tables on the fast files only when the preceding representative had no candidate on those files. Any possible witness continues to be checked for actual operations. A third-stage failure caused by the synthetic fresh-word mutation cannot by itself license disposal of another implementation whose fast values agree. [Residual native census](remaining_native_one_guard_census.cpp)

Compile the direct-store test using `c++ -O3 -std=c++20 two_arithmetic_results_with_a_literal_read_store.cpp -o /tmp/sat-literal-store && /tmp/sat-literal-store`. Compile the larger worker with `c++ -O3 -std=c++20 remaining_native_one_guard_census.cpp -o /tmp/sat-one-guard`. A single-partition execution is `OPENBLAS_NUM_THREADS=1 python remaining_native_leaf_campaign.py --binary /tmp/sat-one-guard --state /path/to/state --seconds 3600`. For four workers use disjoint state directories and pass `--parts 4 --part 0` through `--part 3`. Resume with the same binary and settings; `--verify` checks the saved interval cover and independently evaluates any reported path or relaxed store candidate on all 65,536 files. There is a separate distinction between this finite clock question and an asymptotic RAM lower bound for ordinary SAT.
