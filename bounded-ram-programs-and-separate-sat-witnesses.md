# One hard input per RAM program

Let $P$ be a correct, fixed deterministic RAM SAT solver and $n(x)$ the encoded bit length of a formula $x$. Ruling out linear worst-case time asks for
$$
 \forall P\quad\forall C\ge1\quad\forall B\quad
 \exists x:\quad n(x)\ge B,\quad T_P(x)> Cn(x).
$$
Only one witness is needed for a specified program, multiplier and length threshold. Different triples may have different witnesses. At any single formula there is a program that gives the right verdict immediately on the promise of that one formula. Moreover, the two constant-answer programs can never both be wrong on the same formula. This is why an exhaustion should seek a suite that defeats every candidate somewhere, with the candidate fixed across all tests. On well-formed inputs a wrong verdict also eliminates a candidate as a general solver. [Quantifier check in Lean](BoundedRamWitnesses.lean)

## Turning the cutoff into a finite test

Keep static code size $s$, time multiplier $C$, input length $n$, and instruction count $T$ separate. Fix the word-size rule and the instruction set. Charge the bits of all immediate constants and labels in the binary program description, or specify an effective coding of packages that includes any machine-dependent constants. There are then finitely many candidates of description length at most $s$ for each $C$. If every candidate misses some input within its deadline, take the union of one witness per candidate. The lengths in this finite suite have a maximum $H$. Conversely, if such a suite exists for every $s$ and $C$, no single uniform solver obeys that clock on every input. An eventual bound on a total solver can be turned into an all-input bound $C(n+1)$ by increasing $C$ on the finitely many short inputs. This handles the asymptotic quantifier.

Equivalently enumerate packages $(P,C)$ by a natural-number code $p$. A finite suite for codes through $p$ and one validated failure for code $p+1$ give a suite for codes through $p+1$ by taking their union. The unproved step is producing that new failure for *every* next code. The list may need new formulas unrelated to the old witnesses. Measuring the fastest program separately at each length also loses uniformity. In a conventional RAM with separate finite control, for any one fixed length $n$ a large fixed program can store a binary decision tree for that length, scan the input words using hardwired comparisons, and use an exhaustive decider at other lengths. This costs $O(n)$ steps on its selected length with an absolute constant; the description can grow exponentially with $n$. Thus the envelope obtained by minimizing independently at each length cannot certify an asymptotically superlinear lower bound in this model.

## Testing a native deficit under one more variable

For a tiny exact experiment, give $k$ variables one public clause $(x_1\lor\cdots\lor x_k)$. The $n=2k$ selector bits specify which of their positive and negative unit clauses are also present. In the sign-plane layout the first $k$ bits form the positive mask $P$ and the next $k$ the negative mask $M$. The verdict is SAT exactly when $P\mathbin{\&}M=0$ and $M\ne 2^k-1$. The small-input convention counts just the selector payload. An ordinary explicit SAT encoding also has variable names, literals and records.

For $k=1,2,3$ the word width $w=\lceil\log_2 n\rceil$ is $1,2,3$, respectively. The two words are initially in RAM cells 0 and 1. All other cells and registers start at zero. The input length may be known to the program. The same instruction conventions apply at each size. Registers can be reused arbitrarily, memory addresses can depend on data, and arithmetic, comparisons, shifts, loads and stores each cost a step. Conditional branches have two direct finite-control targets and terminal verdicts are free constant labels. No verdict can inspect memory for free. The synthesis note specifies the full set of operations and compares other tiny input conventions. [Native instruction census](exact-clocks-for-two-word-sat-inputs.md) · [Split-word exhaustive search](split_word_sat_adaptive_audit.py)

At two, four and six data bits the exact optimal worst-case step counts in this model are **2, 5, 5**, respectively. The four-bit step deficit quantifies over every program and workspace available on this native two-bit-word machine. The search even permits a different continuation at every node of an unrolled execution tree. At six bits five instructions give a decision on all 64 formulas. Load the negative mask and reject if it is all ones, load the positive mask, AND the masks and test for zero. Every instruction, including both loads and both tests, is counted. Thus the natural operation of introducing one additional variable preserves the algebraic SAT rule but loses the exact time deficit. No inference about an unrestricted solver on ordinary encoded SAT follows from a four-bit payload.

A less restrictive choice of output conventions, word size, addressing mode or instruction fusion can change exact thresholds. The $O(n)$ target quantifies over *every* constant multiplier. A preserved one-step excess over $n$ would still permit a linear bound. An induction on $s$ has to handle new static programs (including loops); an induction on $n$ must be valid for the *same* program and provide arbitrarily large time-to-length ratios. These requirements explain why even a fully checked finite seed with $T>n$ does not start the asymptotic induction on its own.

On the four-bit catalog the lower bound also holds for **static** size four with no time cutoff. Six specific inputs suffice to defeat every four-slot program, with different failing inputs allowed for different programs. Every suite of at most five inputs is consistent with some four-slot program. The separate cyclic-program search exhausts every size-four loop that can reach both decisions. It includes writes to the original input. Thus the induction from three to four static slots succeeds even when the programmer is free to replace all the instructions. The displayed five-slot sign-plane program then passes the entire catalog. Adding more witnesses from that four-bit family cannot defeat it with a five-step or larger deadline. ## A size induction that does survive on an explicit SAT family

Here is a native-time inequality that handles all programs through size $s+1$ without inspecting how a new program changes its instructions. It quantifies over the ordinary register RAM with separate finite control, single-result register operations, and one separate instruction per word load, store or branch. An address is a word in a register or a literal of the instruction. There is no free postincrement, implicit base-plus-index arithmetic, code-as-data read or initialized array of addresses. Each stored instruction has at most two literal numeric operands. The clock counts the work of constructing addresses as well as reading input words.

Start with twelve fixed proper 3-clauses forcing three variables $x_1,x_2,x_3$ true. Use the four sign choices on distinct shared dummy names $x_4,x_5$ to express each unit clause. Append many copies of $C=(x_1\lor x_2\lor x_3)$ in the explicit 16-bit record format of the clock experiment. The base is satisfiable. Changing one record to $D=(\neg x_1\lor\neg x_2\lor\neg x_3)$ makes it unsatisfiable. Take $w=16\lceil\log_2(n+2)/16\rceil$, so every word in the tail contains whole records. Choose $k$ full words wholly in the repeated tail. The suite consists of the base and one edited formula per chosen word. The choice of edited record within the word is public.

If a deterministic program answers the suite correctly, its execution on the base must read the original value of each of these $k$ words before it overwrites that word. Otherwise the corresponding edited input follows its execution by induction, giving the same verdict. All raw words in the tail have the same value. Counting the header, the twelve fixed records, a possible final padded word, zeros and fixed initial size registers, at most $d=20$ distinct initially obtainable numeric values are needed besides program immediates (take the usual single length register, with zeroed workspace). A size-$s$ program supplies at most $2s$ more constants. A load or store only copies a word already obtainable from initial data or produced earlier. Therefore the $k$ distinct numeric addresses force at least $k-2s-d$ separate operations producing new numeric values, in addition to the $k$ loads. In particular
$$
        T\ge k+\max(0,k-2s-d)\ge 3k/2\qquad(k\ge4s+2d).
$$
Labels of code branches are not numeric data addresses. The argument permits arbitrary indirect data reads and writes, loops, and programs that have incorrect behavior elsewhere. Such a program either fails this suite somewhere or pays the stated time on its single common base input.

When $s$ increases to $s+1$, reserve four more full tail words. Those cover the two additional numeric immediates the new instruction might supply, giving the same factor $3/2$ by the displayed inequality. At a change of word width simply append further valid records until enough full words are present in the enlarged packing. This is possible because the number of words grows without bound. The property proved at the new size depends on the code-size bound alone. In particular it also covers replacements of *all* old instructions. Taking all full repeated words makes $k$ of order $n/w$. The induction thus preserves a native-step lower bound of order $n/\log n$ in the project's input units. This family has a uniform matching-order upper bound: validate the fixed prefix, compare all tail lanes in parallel against the two legal codes, and track the occurrence of $D$, with generic fallback on other inputs. The original SAT lower bound would require a charge exceeding $Cn$ for arbitrarily large $C$. ## What this eliminates on ordinary explicit SAT, for every linear multiplier

Fix the separate-operation RAM above with ordinary logarithmic-word arithmetic, separate finite control and two terminal verdicts. No program with at most **four static instruction slots** decides general explicit SAT in worst-case $O(n)$ time, even if its machine has unrestricted memory. The elimination is by instruction type and uses the established small-workspace SAT lower bound for one case. It makes no restriction on the workspace allowed to programs in the other cases.

* A correct program must read input memory. An acyclic program of bounded static size reads only boundedly many words, contradicting the single-edit family.
* A cyclic program that can reach both verdicts needs at least two binary branch slots. With one branch, each of its two continuations either returns to that same branch, ends at a fixed verdict, or diverges. To produce both verdicts, both continuations must lead to opposite terminals, which leaves no useful loop. Acyclic prefixes implement only a bounded number of inspections.
* A program with no instruction producing new numeric values cannot decide the edit suite for sufficiently many words, regardless of runtime. The preceding address argument applies also to an ordinary periodic clause-record encoding. An $O(\log n)$-bit header occupies $O(1)$ words. A repeated record of bit period $p$ supplies at most $p$ distinct interior words. Even if every variable-name field is widened to $O(\log n)$ bits, this gives only $O(\log n)$ raw values, whereas disjoint equal-length sign edits in the repeated tail require access to $\Omega(n/\log n)$ original words. This argument uses direct literal or register-indirect data addresses. A machine with free arithmetic inside a memory operation would need different accounting.
* With no indirect STORE, a fixed program uses only its finitely many registers and directly named writable cells. Even if it overwrites input there, a simulation keeps the few modified cells in a table and treats the original input as read-only. This costs $O(\log n)$ workspace bits and at most polylogarithmic time overhead per original step, including simulation of the fixed word operations. If the solver ran in $O(n)$ time, this would contradict the known SAT time-space lower bound for subpolynomial workspace on the random-access machine. A fixed exponent strictly between 1 and the published lower-bound exponent absorbs the overhead. [Williams, *Alternation-Trading Proofs, Linear Programming, and Lower Bounds*](https://arxiv.org/abs/1001.0746) · [Encoding and instruction conventions](packed-band-transfer.md)

A surviving program therefore needs five different occupied slots: two branches, a LOAD, an indirect STORE, and an operation capable of creating new numeric values. This is a lower bound on *static code* for a hypothetical linear SAT algorithm in this instruction convention. It applies to arbitrary linear multipliers and ordinary SAT input lengths; it does not give a growing bound on static program size.

There is also a restriction at **five** slots. Any surviving control-flow graph uses exactly those five slots. After keeping reachable instructions and the two verdict vertices, its underlying connected multigraph has at most seven edges on seven vertices. To have a useful loop it must be unicyclic. Each slot outside the cycle executes at most once along any halting path. If the LOAD or value-producing operation is outside it, the address argument rules out the program. If the STORE is outside it, at most one word is ever overwritten and the small-space simulation applies. Thus all three data operations must lie on the cycle. This covers every change to a four-slot program except for that residual class of five-slot programs. For the separate-operation ISA on ordinary ASCII DIMACS with the specified word-width rounding, a subsequent classification eliminates the full five-slot residual even at an $O(n^{11/10})$ deadline. The layout-specific proof uses parity, absolute word values and the raw alphabet. [Five-slot DIMACS proof](five-instruction-loops-on-dimacs-sat.md) The full SAT objective requires the same witness quantifier for programs of every finite size.

For an input layout in which a clause on fixed small names has a fixed bit period, one can narrow the five-slot case by the actual opcode. On the repeated-clause base above there are at most a fixed $h$ initially obtainable numeric words, including all immediates and the length, independent of $n$. Their values may vary with $n$. Any additional word explicitly supplied at initialization must be counted in $h$.

* If the sole value-producing site is bitwise Boolean, every obtainable word is constant on classes of bit positions that have the same initial $h$-bit column. There are at most $2^h$ position classes, hence at most $2^{2^h}$ obtainable words, uniformly in $w$. Single word comparisons returning a Boolean likewise add at most two values.
* If it is a one-direction logical shift, an arithmetic right shift, or a rotation, all obtainable values are shifts or rotations of single initial words. For shifts in the same direction, composition adds the effective counts, saturating the resulting value when appropriate. Rotation composes modulo $w$. The count is at most $h(w+1)$ plus a constant, even with data-dependent counts.
* If it multiplies by a fixed literal modulo $2^w$, an even multiplier sends every initial word to zero in at most $w$ applications. An odd multiplier preserves the exponent of two dividing every nonzero word. Consecutive tail addresses have unboundedly many different such exponents as $n$ increases, while the initial words have at most $h$. For the squaring instruction the orbit of every word has length $O(w)$. Even words reach zero under successive squaring and odd words reach one by the exponent of the finite group of odd residues modulo $2^w$.

In each case loads and stores merely copy obtainable values. The program eventually lacks some required address on the base, independently of its runtime. Ordinary addition, for example, can enumerate all addresses by adding one, so the bounded-set argument stops there. The program's remaining challenge is to decide SAT while using the same few instructions to transform data and manage memory.
