# How many SAT runs must read every data word when every file has a short certificate?

For $L=3^h$ there are $2^L$ well-formed proper ternary DIMACS files on $L$ independently editable aligned data words. Each word contains one editable bit. The full files have $N=\Theta(L\log(L+2))$ bits. Fix any correct deterministic word-RAM solver with unrestricted writable memory. There are at least
$$
                         2^{(L-1)/2}
$$
**disjoint opposite-verdict pairs** one physical bit apart such that the two genuine executions agree through the address of the load discovering the last editable word. Both executions read every editable word. This counts the first exposure of *original* input data. Overwriting an original unobserved word only prevents its exposure. For machines permitting unaligned word loads space the editable bits more than a word apart.

The count is **exact**. One uniform solver correct on all well-formed DIMACS formulas attains it at every height, for the affirmative and negative files simultaneously. On the family its total time is $O(L)$ word operations. After its only pass over the fixed input words and a common preprocessing phase, it takes $O(1)$ worst-case instructions between successive editable-word reads, and $O(1)$ after the final editable-word read. On every file the fewest data bits certifying its verdict within the face is exactly $2^h=L^{\log_3 2}$. Checking the common public structure separately, the corresponding certificates remain sound against arbitrary well-formed contents of the unread data words.

A second construction below gives $2^{L-o(L)}$ disjoint pairs while every file has an $O(\sqrt{L\log\log(L+2)})$ data-word certificate. The matching algorithm for that construction uses only a constant number of registers after public validation.

The first example uses recursive majority of three, whose deterministic worst-case query complexity and randomized versions have an extensive literature. The lower bound on complete-read pairs is an application of the journal's integer-coefficient lemma. The additions here are its exact attainment on actual executions of a globally correct SAT solver, the protection of skipped words on off-family inputs, and bounded time between all data loads. Priority for the combination is unestablished. [Recursive majority and its query complexity](https://arxiv.org/abs/1309.7565) · [Integer-coefficient lemma for real executions](one-bit-sat-pairs-at-the-last-input-load.md)

## The exact count

Let $f_0(x)=x$ and form $f_{h+1}$ as the majority of three independent copies of $f_h$. Write $J(f)$ for the coefficient of the product of all the variables in its real multilinear polynomial. A majority of three bits is $ab+ac+bc-2abc$. Since the child inputs are disjoint, $J(f_{h+1})=-2J(f_h)^3$. Therefore $|J(f_h)|=2^{(3^h-1)/2}$.

On a fixed RAM transcript all original data values outside the read set are free. Those files form a subcube. A halted subcube with a free coordinate contributes zero to $J(f)=\sum_x(-1)^{L-|x|}f(x)$. Truncate other runs just before the last fresh data load. In a trace class reaching this stage precisely one bit remains free. Both files issue the same load at that point. Equal verdicts cancel in the sum and opposite verdicts contribute $+1$ or $-1$. This proves the stated bound. Data-dependent addresses, branches, arbitrary private state, and work on the other input words are all included in the argument. A native load may also see fixed bits, and implementations may split instructions with boundedly many word accesses into their ordered accesses.

A decision tree queries the first and second children, and the third precisely when the first two disagree. Apply the same rule recursively. To read all $3^h$ leaves, the computation must read all leaves in all three subtrees, the first two outputs must be opposite, and the third must supply the final answer. If $M_h$ is the full-read count on each verdict, $M_0=1$ and $M_{h+1}=2M_h^3$. On a full-read pair, changing the final bit changes the outcome of its entire chain of pending third children. All earlier data addresses agree. Hence this algorithm attains the lower bound on both full-read files per verdict and opposite pairs. The verifier below realizes the same read sets on a legal SAT input.

For an individual certificate forcing a majority to $b$, two of its three children must themselves be forced to $b$. Otherwise the disjoint partial assignments admit completions making two children $1-b$. Conversely any two agreeing children certify their parent. Starting at a single leaf gives the claimed optimal certificate size on every input. Every individually pivotal bit belongs to every certificate, so at either endpoint of each hard pair at least $L-2^h$ of the words actually read are individually insensitive on that very file. Before the last data load the accumulated data still contain no verdict certificate, since the opposite endpoint remains possible. This gives a simultaneous charge for relevant and locally insensitive data on a single real run.

## Guarding the actual input words

Use names 1, 2, 3 for fixed values false, false, true respectively. Enforce these values by seven proper clauses on that triple. Give every vertex of the complete ternary tree its own new activation variable, and force the root active using a unit padded with names 1 and 2. At each internal node $z$ with children $a,b,c$, use the three proper clauses
$$
       (\neg z\lor a\lor b),\quad (\neg z\lor a\lor c),\quad (\neg z\lor b\lor c).
$$
An active node thereby needs two active children. For leaf $s_i$ insert one row $(\neg s_i\lor x_1\lor u_i)$, where $u_i$ is the positive literal named 2 or 3. The clause permits $s_i$ to be active exactly when the data bit is one. Induction gives the recursive majority at the root. There can be several satisfying assignments.

Put the header, fixed pins, and internal clauses in a public prefix. Each leaf row occupies a fixed number of aligned words. The negative activation literal and name 1, with delimiters, are in a fixed prefix of the row. The entire data word consists of spaces followed by the ASCII digit 2 or 3, changing only the digit's least significant bit. The fixed suffix begins with newline, the clause terminator 0, and newline. Fill the rest with spaces. The DIMACS specification permits a clause to span lines. Include enough public spacing to isolate each data word even from an unaligned read of another editable bit. Both the native algorithm and the counts below can use the journal's aligned word convention. [DIMACS suggested format, §2](https://www21.in.tum.de/~lammich/2015_SS_Seminar_SAT/resources/dimacs-cnf.pdf)

The global solver checks the header, all public words, and every fixed terminator while skipping the data words completely. The checked header gives exactly the number of public terminators. The delimiters around each fixed terminator are immutable. In any well-formed completion there can be no additional terminator in any data word, since none of the fixed terminators can be removed or absorbed by a comment on an earlier line. Thus each unread clause always contains its designated negative activation literal, even if new literals have appeared inside the data word. On each visited data word compare the entire word against the two canonical possibilities. If a public check or an attempted data-word check fails, invoke a general SAT solver.

Suppose the query procedure returns true. Its visited positive bits force the root true even when all other leaves are unavailable. Activate a proof subtree supported only on these known positive leaves, setting every other activation false. Every unread row is then satisfied by its fixed negative literal, whatever its other literals may be. If the procedure returns false, the visited negative leaves suffice to force the root false even when all other leaves are allowed active. The checked negative leaf rows forbid those activations in any actual model. Thus rejection is sound as well. The solver needs no further input reads in either case.

This argument uses correctness on all **well-formed** formulas, as in the static instruction census. If the language also requires rejecting every malformed byte string, each affirmative run on this layout must read every data word, since changing an unchecked digit to an illegal token would otherwise preserve the run. This stronger convention alters exact attainment on the positive files. The lower bound itself always applies.

## Time between genuine data loads

The layout can derive $L$ from the checked variable count or the input length and can choose a public padded length of $\Theta(L\log(L+2))$ bits to determine the host word width before aligning its records. All linked decimal vertex names fit $O(1)$ words. List the tree nodes in heap order. Building a table of the packed decimal spellings of all names costs $O(L)$ word operations, for example by a decimal odometer with $O(L)$ total digit changes. Storing each successive packed spelling and its length costs $O(1)$ words. The fixed clause bytes can then be emitted or compared using $O(1)$ word operations per row, using aligned loads that never access an omitted word. On inputs failing size sanity checks use the general fallback. A writable-input implementation can keep its work above the whole input. The whole setup is independent of all editable bits. [Packed decimal operations](dense-sorted-cores-for-ram-exhaustion.md)

During short-circuit evaluation an ancestor has only four statuses. It is evaluating its first child, its second after a zero, its second after a one, or its third after a disagreement. A returning value $b$ propagates *unchanged* over an agreeing second child and over every third child. At the first frame requiring another child, change the first status to “second after $b$”, or the second to “third”. Reset all frames below this one to first-child status. When no such frame exists the computation halts with $b$.

The $h$ statuses fit in $O(1)$ logarithmic words. Split them into at most four chunks of at most $\lceil h/4\rceil$ base-four digits. Make a table on each possible chunk giving, for each return bit, either propagation or the updated chunk after a stop, and also the chunk's physical path offset. To compute the offset, read the status digits from root to leaf as ternary path digits $0,1,1,2$. Standard positional weights join these chunk offsets into the index of the next leaf in constant time. Precompute these tables using $O((h+1)4^{\lceil h/4\rceil})=O(L)$ operations. Each return now touches at most four chunks, subsequent steered addresses are ordinary word addresses, and each data step costs $O(1)$ even in the worst case. Thus neither the recursive depth nor the population of late, opposite-answer pairs gives an unbounded work charge after a data discovery. The globally correct program already includes its $O(L)$ preprocessing and public-file checks.


## Near-maximal pair counts with near-square-root certificates

A second family strengthens both quantities at once. Put $s=2r+1$, $K=4^h$, and $L=sK$. On each of $K$ disjoint blocks take majority of $s$ independent input bits. Join these block results by a complete tree of height $h$ whose operation is $g(a,b,c,d)=(a\land b)\lor(c\land d)$. The following three claims hold on the same proper DIMACS files.

* Every file has minimum data-certificate size exactly $(r+1)2^h$ on its own verdict.
* Each full-read input has a unique possible partner, obtained by flipping its last data bit. The minimum over solvers of the number of these opposite-verdict pairs is exactly $\binom{2r}{r}^{K}$, for globally correct deterministic solvers on well-formed formulas.
* One uniform global solver attains the pair count in $O(L)$ word operations when $r\le h+O(1)$ or $r$ is fixed. After public validation it needs only a constant number of registers, spends worst-case constant work per data word, and reads no auxiliary table. This includes the work after the final data load.

For either verdict of $g$ a minimum certificate needs two children. For true force one entire pair true. For false force a zero in each pair. Any partial assignment forcing the root value must include such a certificate on the child outputs it forces, since the children have disjoint inputs. Each bottom majority requires $r+1$ bits agreeing with its verdict. This proves the first claim on every file.

For a bottom majority, the highest integer coefficient is $(-1)^r\binom{2r}{r}$ by summing $(-1)^{s-j}\binom sj$ for $j\ge r+1$ and cancelling adjacent binomial terms. The highest coefficient of $g$ is $-1$. Composition on disjoint supports gives the pair lower bound. Sequentially querying a bottom block until some sign wins has exactly $\binom{2r}{r}$ full-read assignments of each verdict. Its first $2r$ bits must split evenly. Short-circuit $g$ from left to right. It visits all four children exactly when their answers are $(1,0,1,d)$. The fourth answer determines the root verdict. Thus the number of full-read assignments of each sign is multiplied across all four children, and the last bit flips the answer on every full-read path. This attains the bound.

When $r=h\to\infty$, the number of disjoint hard pairs is $2^{L-O(L\log(h+2)/(h+1))}=2^{L-o(L)}$, since $4^r/(2r+1)\le\binom{2r}{r}\le4^r$. Their files each have an $O(\sqrt{L\log L})$-word certificate. Taking $r=\lceil\log_2(h+2)\rceil$ instead gives the same $2^{L-o(L)}$ conclusion with $O(\sqrt{L\log\log(L+2)})$-word certificates. More generally, for each $\epsilon>0$ choose a sufficiently large fixed $r$. There are then at least $2^{(1-\epsilon)L}$ disjoint hard pairs while every file of either verdict has an $O_\epsilon(\sqrt L)$ certificate. In a decision problem of ordinary bit-query depth $L$, $\max(C_0,C_1)\ge\sqrt L$ follows from the classical $D\le C_0C_1$ inequality. To see the inequality, query the unknown bits of a compatible positive certificate, repeating while both signs remain possible. Each round fixes a new coordinate of every surviving negative certificate because it conflicts with the positive certificate. At most $C_0$ rounds at $C_1$ queries per round suffice.

Use the same isolated guarded rows. At a $g$ node its activation implies $(a\lor c)\land(a\lor d)\land(b\lor c)\land(b\lor d)$. Padding each disjunction with the negative parent literal gives four proper clauses. At a bottom node require that activation imply a majority of its $s$ child activation variables. A Boolean counting circuit of $O(s)$ gates computes this bit. Repeatedly add three bits of one binary weight, replacing them by a sum bit and a carry bit. Each such operation lowers the number of bits by one, with $O(1)$ two-input Boolean gates. Once each weight has at most two bits, add the resulting two binary numbers and compare with $r+1$ using $O(\log(s+2))$ more gates. Fixed-fanin gate equivalences translate to $O(s)$ proper clauses using the already pinned false variables for padding and eliminating any repeated literals or tautologies. Guard the resulting output by implication from the bottom activation. Gate variables always have a consistent extension for any choice of child activations. Thus true proofs can inactivate all unused leaves, and false certificates remain sound when every unused leaf is permitted. The family still has $\Theta(L)$ clauses and $O(L)$ dense names. Generating a gate schedule once per width, with bucket lists of pending bits, costs $O(s)$ word operations. Use it for each bottom block. The packed construction and verification of the public words take $O(L)$ work. One may fix $r$ as a uniform function of $h$ or derive the two parameters from an explicitly checked shape and length before checking the template.

The upper tree can be evaluated with two bits per level and no stack memory or lookup table. The current base-four block index $x$ records which child is being evaluated at each level, with the root most significant. Reaching a bottom majority starts two ordinary counters for the number of bits read and the number of ones. Once it returns a bit $b$, the upper frames at which it propagates all return the very same $b$. For $b=0$, child positions 0 and 1 advance to child 2, while 2 and 3 return zero. For $b=1$, positions 0 and 2 advance by one, while 1 and 3 return one.

Compute $P=\sum_{j<h}4^j$ once, and set $u=P\mathbin{\&}\neg(x\mathbin{\gg}1)$ for $b=0$ or $u=P\mathbin{\&}\neg x$ for $b=1$. If $u=0$ halt with $b$. Otherwise $t=u\mathbin{\&}(-u)$ marks the deepest frame requiring another child. For zero the next block index is $(x\mathbin{\&}\neg(4t-1))\mathbin{|}(2t)$, and for one it is $(x\mathbin{\&}\neg(t-1))\mathbin{|}t$. The masks reset all deeper frames for the next descent. Every index fits a logarithmic word. A bit's slot is indexed by $sx+j$, where $j$ is its position within the block. This calculation accounts for all instructions between consecutive data probes, even when the pending value finishes many subtrees. ## Verification

The audit derives the CNF decisions independently by DPLL, compares the entire chunk-based read order with recursion through height eight, and checks off-face changes to skipped words. It obtains 1, 2 and 16 opposite pairs at heights zero, one and two. On the largest exhausted height all 512 files have an optimal four-bit certificate. Lean checks the Boolean semantics of the activation clauses for every ternary tree and proves that flipping the final leaf of any fully read short-circuit majority tree flips its verdict. It also verifies the four-child gate clauses and its unique four-read pattern. The executable checks include full certificate censuses at six hybrid parameter pairs and 64 threshold-circuit CNFs checked by DPLL. The native costs, exact population and off-face reasoning are manuscript arguments. These computations certify no unrestricted superlinear time lower bound.
