# Enumerating complete Boolean CSP solutions in time linear in the number of constraints

Fix \(k\ge2\). A complete Boolean \(k\)-CSP on \(v\) variables gives a nontrivial constraint on each \(k\)-element set. Each constraint excludes at least one of its \(2^k\) possible assignments. A signed \(k\)-clause on every \(k\)-set is a special case.

**Theorem.** A deterministic word RAM enumerates every satisfying assignment of a complete Boolean \(k\)-CSP in \(O_k(1+v^k)\) native word operations given its constraint table. This includes the time to write each satisfying assignment explicitly on the \(v\) named variables. On a proper, comment-free, packed ASCII DIMACS file of \(N\) bits the corresponding decision and enumeration algorithms take \(O_k(1+N/\log(N+2))\) native steps. Ordinary bytewise parsing, also allowing whole comment lines, gives \(O_k(N+1)\) steps. Constants depend on the fixed arity. The RAM has logarithmic-width words, addition, shifts, Boolean operations, and ordinary direct and indirect addressing. Its auxiliary memory has polynomial size.

Anand, Lee and Sharma bounded the number of satisfying assignments via VC dimension. Anand, Lee, Mazzali and Sharma used that bound to enumerate the surviving prefixes in polynomial time. The new step here is to check all extensions at a stage with shared computations on dyadic rectangles and to combine several successive variables into one native word. Checking every newly relevant triple separately for each surviving assignment instead gives the direct \(O(v^5)\) implementation for \(k=3\). The cited papers give the solution count and prefix algorithm. The November 2026 follow-up studies approximation and credits the preceding work for polynomial-time decision. A targeted search did not establish priority for the running time proved here. ## The projection bound needed by the algorithm

Number the variables \(0,\ldots,v-1\), put \(d=k-1\), and pad their domain to \(p\) positions, where \(p\) is the next power of two. At stage \(i\) let \(S_i\) be all satisfying assignments of the induced instance on the first \(i\) variables. Represent them as \(p\)-bit rows whose positions at and beyond \(i\) are zero.

For **every** set \(U\) of positions, the number of different restrictions to \(U\) is at most
\[
     \sum_{j=0}^{d}{|U|\choose j}.
\]
Indeed, no \(k\) assigned positions are shattered, because the constraint on them excludes a pattern, and no set containing an unassigned position is shattered. Apply the Sauer–Shelah lemma to the projections. Equivalently, one proves the elementary bound by splitting a binary row family at its last coordinate. Its size is the size of the union of the two projected slices plus the size of their intersection. The union has VC dimension at most \(d\), and the intersection at most \(d-1\), since a set shattered by the intersection can adjoin the last coordinate. Pascal's recurrence gives the display, with the empty-family and zero-coordinate cases dealt with directly. This argument also bounds the number \(|S_i|\) by \(O_k(v^d)\).

## One stage in \(O_k(v^{k-1}\log(v+2))\) time

Represent every row by a persistent binary tree of aligned dyadic coordinate intervals. At each *fixed location*, two intervals with the same bit string have the same identifier, with different strings having different identifiers there. An internal identifier supplies pointers to its two child patterns. Identifiers at different locations may coincide. Start with the all-zero tree. The batched updates below maintain the invariant without arbitrary dictionary lookups.

For a row \(x\in S_i\) compute two flags, indicating whether extending by zero or one violates a constraint whose largest variable is \(i\). Enumerate the ordered coordinate tuples in \([p]^d\) implicitly. At a tuple of unit positions \((j_1,\ldots,j_d)\), return two zero flags unless \(j_1<\cdots<j_d<i\). Otherwise read the constraint on \((j_1,\ldots,j_d,i)\); its two forbidden-extension flags depend only on \((x_{j_1},\ldots,x_{j_d})\) and its table. For an entire rectangle of positions return the bitwise OR of its children's two-bit flags. A zero flag at the root is equivalent to the corresponding extension satisfying all new constraints. This handles arbitrary nontrivial relations, including an empty allowed relation.

Subdivide all \(d\) axes at once, recursing into \(2^d\) equal-size children. A state at side length \(\ell\) is the ordered tuple of dyadic interval **locations** and the corresponding tuple of pattern identifiers. Use one state for each distinct key requested by any root, even when it occurs under many roots. At a specified location tuple, all identifier tuples are restrictions of rows in \(S_i\) to a union of at most \(d\ell\) positions. Overlapping intervals and repeated axes still determine all tuple entries from that union. The projection bound gives \(O_k(\ell^d)\) possible keys for these locations. There are \((p/\ell)^d\) possible location tuples, so **every level together uses only \(O_k(p^d)\) states**. Starting from the actual candidate roots ensures every generated key really comes from one common row. Treating the patterns on different axes as independently selectable would lose this bound.

Construct all levels from the top down. Produce the \(2^d\) children of every distinct state, radix-sort by the constant-length keys, assign a dense index to each distinct child and scatter the child links back to the parents. Deduplicate the initial requests for the same root in the same way if needed. Evaluate the resulting acyclic table bottom up, with each unit state inspecting one actual constraint and each larger state taking the OR of a constant number of flags. A radix of \(p\) (or two for tiny instances) includes the cost of initializing \(O(p)\) counters per digit pass. Every field is bounded by \(v^{O_k(1)}\), so each key has \(O_k(1)\) digits in this base. Stable counting sort takes \(O_k(p^d+p)\) deterministic word operations per level, inclusive of producing and regrouping child links. No assumption about the average performance of hashing is needed.

To obtain \(S_{i+1}\), retain each root admitting a zero extension without modification. For roots admitting a one extension, descend to the previously zero position \(i\) and keep all untouched siblings along the path. Set its leaf to one, then ascend in a batch. At a fixed level the changed interval has one location for every affected row. Group the child-identifier pairs of all modified intervals by the same radix sort, give one fresh identifier to each distinct pair, and retain both child links. The new strings have a one at position \(i\); at that location every string previously constructed had zero there. Therefore local canonicity needs no lookup against a growing historical table. All unaffected roots and their sibling pointers remain usable. This stage costs \(O_k(p^d\log(v+2))\) steps for the flags and the updates together. At most \(O_k(v^k\log(v+2))\) identifiers and work records occur over all stages, justifying the fixed number of radix digits and logarithmic word width. Induction gives exactly \(S_v\). Decoding each surviving root takes \(O(p)\) steps, totaling \(O_k(v^k)\).

## Grouping newly assigned variables to remove the logarithm

Use an aligned block size \(h\) equal to a power of two with \(h=\Theta(\log(v+2))\) and \(h\le\max(1,\lfloor\log_2(v+2)\rfloor)\). A bounded number of native words holds all \(2h\) flags or all \(h\) recent assignment bits. Include zero padding to the end of the last block. Call the variables before a block *old*. At each stage in a block split the newly introduced constraints into those whose other \(d\) variables are all old and those with at least one of those variables inside the block.

**All-old tuples.** At the block start run the full dyadic computation on the current old roots. Each unit tuple now returns the extension bans for **all** upcoming block positions, concatenated into one \(2h\)-bit word. Only strictly increasing old tuples return nonzero data. Computing that word can take \(O_k(h)\) table lookups at a leaf. There are \(O_k(p^d)\) distinct unit keys. Every internal state uses a constant number of word ORs and sorting records as before. The block-start computation thus costs \(O_k(p^d(h+\log p))\). Every descendant of an old prefix keeps its old root's packed flags throughout this block. The failed extensions they encode continue to fail independently of the earlier choices made inside the block.

**Tuples involving recent variables.** At each single stage traverse only rectangles for which at least one axis meets the current aligned \(h\)-position interval \(I\). Check this condition before emitting a child key. At each retained leaf enforce the same strict ordering and the current upper endpoint on every previous variable. For a side length \(\ell\ge h\), the block \(I\) has a unique containing dyadic interval of that length. There are at most \(d(p/\ell)^{d-1}\) relevant location tuples. The projection bound on their at most \(d\ell\) actual coordinates still gives \(O_k(\ell^d)\) different pattern tuples at each location. The total over these levels is at most
\[
          O_k\!\left(p^{d-1}\sum_{\ell\text{ dyadic},\ h\le\ell\le p}\ell\right)
          =O_k(p^d).
\]
For \(\ell<h\) the interval \(I\) covers \(h/\ell\) dyadic intervals. There are at most \(d(p/\ell)^{d-1}h/\ell\) location tuples and again \(O_k(\ell^d)\) realized patterns apiece. These levels cost \(O_k(p^{d-1}h\log(h+2))=O_k(p^d)\) states in total. Constant-degree child expansion, dense labels and a radix of order \(\sqrt p\) implement the entire computation in \(O_k(p^d)\) steps **per stage**. This smaller integer radix keeps the additive cost of clearing count arrays over all levels at \(O(\sqrt p\log(p+2))=O(p)\), including for \(d=1\). Field widths are still a constant number of digits.

**Canonical keys during the block.** A candidate consists of an old persistent root and one \(h\)-bit word for its assignments so far in \(I\), with all future positions zero. At a dyadic interval disjoint from \(I\) the canonical key is its old node. At an interval containing \(I\) the key is the old node and the whole recent word. Equal current patterns there imply equality of the old patterns by setting the coordinates of \(I\) back to zero, so the old identifiers agree. At an interval inside \(I\), take just the corresponding substring of the recent word; its old pattern was the known zero string. Locations are always included in the tuple key. Therefore the tuple of codes at a retained rectangle is determined by the actual current restriction to the union of its axes. No hidden prefix information multiplies the projection bound. When descending an axis, obtain its old child from the parent pointer and pass, mask or shift the recent word according to the child's location. This costs constantly many operations. A successful zero or one extension at an individual stage only copies a constant number of words, updates one bit, and carries the packed old flags. The active prefix family remains precisely \(S_i\) throughout.

At a block boundary install the entire formerly zero chunk into the old trees in one batch. Every possible substring of length \(h\) and lengths \(1,2,4,\dots,h\) already has a canonical node in a content table constructed once bottom up in \(O(2^h+h)=O(v+1)\) steps. Its two children are immediate table lookups on the low and high halves. For each retained row with a nonzero chunk, take its chunk ID from this table, retain the untouched sibling nodes on the old path, and update the path above the chunk in batches. At a fixed proper ancestor every changed pattern has a nonzero bit in \(I\), unlike any old pattern there. Radix-group the new child-ID pairs, allocating one fresh node per group; a zero chunk keeps its old root. A block end costs \(O_k(p^d\log(p+2))\). Old identifiers and transitions are stored in arrays containing polynomially many records, so all of these operations and radix passes have the stated native cost.

There are \(O(v/h+1)\) blocks and \(v\) individual stages. The block starts and ends together cost \(O_k(v^k)\), as do the mixed checks and the final enumeration. This proves the word-operation bound in the theorem. The [block implementation](complete_csp_macro_audit.py) computes the two types of flags independently, intersects their admitted extensions, installs complete chunks and checks the key bounds against the actually generated states at every level. On 4,243 complete instances it tested 4,513 block-size choices and 3,072,759 distinct keys, matching the complete sets of solutions.

## File representation and recognition

Place a constraint on sorted coordinates in an explicit \(v^k\)-entry array, with arbitrary values at unused nonsorted tuples. Flattening a constant-length tuple requires only fixed-arity products or, with power-of-two strides \(p\), additions and shifts. Canonical decimal literal names can be interned in one pass using a digit trie with constant branching; this handles names whose decimal values do not fit one word. Preserve the name-to-coordinate map if reporting assignments. Sort the \(k\) names in each proper clause and permute the signs or table into that order. Parse annotations, whitespace, terminators and the header in time linear in their encoded length.

Each of the \(v\) different variable names occurs exactly \({v-1\choose k-1}\) times in a complete clause file. At least a constant fraction of any \(v\) distinct canonical positive decimal names have \(\Omega(\log(v+2))\) digits. Consequently \(N=\Omega_k(v^k\log(v+2))\) for large \(v\). The monotonic growth of \(N/\log(N+2)\) for large \(N\) therefore gives \(v^k=O_k(1+N/\log(N+2))\), even for a heavily padded file. Assignments can be output as bit vectors in the fixed order with a common name dictionary written once. With an implicit lexicographically ordered array of fixed-size clause types, the input has \(\Theta_k(v^k)\) bits and the proved native bound is linear in its number of semantic constraints.

For comment-free well-formed input, the packed normalization algorithm outputs the sorted distinct clauses and dense variable names in scan order time. It applies to any fixed clause width. Its map back to word-sized offsets of original names suffices to report assignments. Count distinct supports and compare both the normalized and the proper original clause counts before allocating the lookup table. On a promised complete clause file every support occurs once. This gives the packed native theorem. The bytewise trie described above also handles whole comment lines. [Packed normalization of fixed-width DIMACS clauses](packed-normalization-of-dimacs-clauses.md)

A bytewise recognizer of this restricted subclass can run on arbitrary files within \(O_k(N)\) time. Check the distinct-name and clause counts against \({v\choose k}\) before allocating the dense array, with saturating counts or a constant number of limbs for fixed \(k\). A file passing this test has \(p^k=O_k(N+1)\). Require \(k\) distinct variables per clause, validate the supplied syntactic conventions, and detect any duplicate subset in the table. Exact count plus uniqueness gives completeness. Handle the constant range \(v<k\) separately. Unused variables in a file declaring a larger name universe have no effect on the decision; enumeration in the theorem is on the named variables of the complete instance. The promise is stricter than arbitrary \(k\)-CNF, and an unrestricted solver can recognize these files and discharge them within the stated time.

The [executable checker](complete_csp_dyadic_audit.py) uses stable radix sorting and persistent updates, and compares every returned assignment with direct exhaustive search. Its cases include all \(8^4\) signed complete 3-CNFs on four variables, every choice of three nontrivial binary relations on three variables, maximum-cardinality solution families, arbitrary relation masks, non-power-of-two sizes and permutations of selected incomplete inputs.

The [core Lean proof](DyadicCspProjection.lean) formalizes shattering as realizing every binary pattern on a coordinate selection and derives the full projection count by Pascal recursion. The solver, radix implementation and runtime analysis are proved in the manuscript. The checker also reads shuffled proper DIMACS bytes with 90-digit variable names and rejects malformed or duplicate clause supports.
