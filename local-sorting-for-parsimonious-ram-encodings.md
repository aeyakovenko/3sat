# Locally reading a parsimonious RAM computation in ordinary ASCII 3-SAT

Fix a deterministic word RAM program, a step cap $t$, at most $O(t)$ initialized input words and word width $O(\log(t+2))$. Use the journal's finite basis of word operations, including multiplication, ordinary division with a specified zero-divisor convention, and shifts. Write $h=\lceil\log_2(t+2)\rceil$. There is a proper ASCII DIMACS 3-CNF of $O(th^3)$ **bits** with exactly one assignment for a chosen true bounded outcome and none for a false outcome. Each packed word of the formula is available in $O(1)$ word operations after $O_\epsilon(t^\epsilon+\operatorname{poly}(h))$ setup for any fixed $0<\epsilon<1$, given constant-time access to the packed public words. A fixed constant number of limbs is allowed when simulating a different fixed word-width coefficient. The unpinned computation has a unique assignment, including all its auxiliary wires, with its output bits exposed.

The journal's earlier local bound with a Beneš router allows multiple switch settings for a fixed execution. Its parsimonious Batcher construction uses $O(th^2)$ word comparators. The argument below saves one logarithm there while retaining packed local access and parsimonious encoding. It combines established sorting constructions. Priority for this particular parameter accounting is unestablished. ## Precomputing only small sorting networks

Pad the number of memory events to a power of two $P=2^L=O(t)$. For a large box of $2^a$ records set $s=2^{\lfloor(a-1)/3\rfloor}$ and $r=2^a/s$. Here $r$ is even, $s\mid r$, and $r\ge2s^2$. Leighton's columnsort uses four column-sort phases, with reshaping, inverse reshaping and a half-column shift and unshift between or after them. Each phase sorts columns of $r$ records. The shifted phase has one extra column. In the usual column-major numbering the reshape sends $i$ to $(i\bmod s)r+\lfloor i/s\rfloor$, with inverse $j\mapsto s(j\bmod r)+\lfloor j/r\rfloor$. The shift sends $i$ to $i+r/2$, filling the opened ends with ordered minus and plus sentinels. Nested sentinels can enclose the current alphabet using a separate fixed tag per level. Tied real keys have a deterministic compare rule. [Leighton, *Tight Bounds on the Complexity of Parallel Sorting*](https://doi.org/10.1145/800057.808667) · [Chaudhry and Cormen, dimensions and permutations](https://digitalcommons.dartmouth.edu/cs_tr/210/)

Repeat this reduction a fixed $D$ times, stopping early on tiny boxes. The leaf width is $m\le 2^{O(1)}P^{(2/3)^D}$, the same in every live full-depth box for a given $P$. In each leaf use the same logspace-uniform $O(m\log m)$-size, $O(\log m)$-depth sorting network. A fixed polynomial in $m$ suffices to generate its wiring and tabulate it by layer and lane, with idle wires filled by copies. This uses just polynomial time uniformity, including the time to normalize the description. Choose $D$ once so this polynomial is $O(t^{\epsilon/2})$ for all large $t$. There is no preprocessing of a separate sorter for each occurrence. The original use of sorting networks inside columnsort is classical. [Ajtai, Komlós and Szemerédi](https://doi.org/10.1007/BF02579338) · [Holmgren and Rothblum, Lemma 4.5, on uniformity](https://eccc.weizmann.ac.il/report/2023/113/download/)

One can pad each phase of a box to $2s$ child slots, including fixed inactive slots. The sum of the child widths across all four phases is at most eight times the parent width. After $D$ levels the sum of leaf widths is $O_D(P)$. The leaf tables therefore specify $O_D(P\log P)$ comparator or idle slots in total. Boundary copies and permutation connections take $O_D(P)$ more word slots. Decode a slot using the fixed-depth path of phase and child indices, then the leaf layer and lane. Padded rectangular dimensions can be powers of two. Connecting input and output rows of each box by explicit separate copy gates ensures that resolving a predecessor crosses at most a fixed number of levels, even if a lane passes an entire phase without a compare. All boundary maps above are shifts, masks, or arithmetic on $O(h)$-bit coordinates. Unused slots in the Boolean layout are pinned to fixed values.

## From records to bytes

Guess chronological registers, read replies and event records, with all idle and disabled fields fixed. Enforce CPU transitions and the chosen clock outcome. Sort records by live tag, bank, address, chronological step and event order. Include the input initialization and fix all dummy fields. Compare adjacent sorted records and force each read to see the last value at its address, using zero for an uninitialized work word. All compare-exchanges use functional Boolean gates. The last-value bits are forced in sorted order. Ordinary induction on the native instructions then forces every guessed register and reply. Gate equivalences force the comparator wires and all other checked quantities. Conversely the actual bounded computation extends to this whole assignment. Idle the machine at halt; any designated bit or condition at the cap can now be pinned, including whether it has halted. Multiple halts or a timeout cause no ambiguity.

There are $O(th)$ word comparator slots with records of $O(h)$ bits, hence $O(th^2)$ Boolean gates. Fixed native word operations cost $O(h^2)$ gates per step, including multiplication by shifted partial products and division by restoring long division with a fixed guard. This fits the same bound. Use fixed within-row gate/bit tables, computed in $\operatorname{poly}(h)$ time. Use equivalence clauses for gates; simplify repeated variables and tautologies. Three reserve variables are all forced to zero by the seven proper clauses forbidding the other patterns. Pad any unit or binary clause with distinct zero reserve variables disjoint from its own gate variables. Use only declared variables fixed in this way or occurring in the actual deterministic computation. If rectangular slot indexing reserves unused variable names, pin the unused slots as well. All proper triples use three distinct variables.

Charge $O(h)$ ASCII bytes per fixed-stride record, including wire names. In a fixed-width field spaces can precede the sign and the ordinary decimal digits. Use a space for the positive sign and a minus for the negative sign, preserving the length. These are ordinary DIMACS files with no leading zeros required in a name. Packed decimal rendering can also be supported within the setup bound. Tabulate all integers below $10^u\le t^{\epsilon/4}$, where $u=\lfloor(\epsilon/4)\log_{10} t\rfloor$, storing their $u$ packed digits and significant digit lengths. Integer thresholds can use a slightly smaller fixed rational power-of-two bound instead of logarithm approximation. Every name of $O(h)$ bits is a constant number of such chunks. Divide and concatenate in a fixed number of operations; remove leading zero digits in the first nonzero chunk and insert the adjacent sign. Each rendered record occupies a fixed number of words, and a packed read straddles only a constant number of records. The header takes $O(h)$ bytes. This proves the stated access and size bounds and allows a fixed old name offset bounded by $t^{O(1)}$.

For a genuine execution the unique assignment can also be generated in $O(th^3)$ operations, including constructing the whole physical file if desired. Save the actual register and event fields and evaluate the sorter and its Boolean checks; a balanced dictionary suffices to record a native trace with logarithmic overhead when needed. The finite check exercises the columnsort boundary permutations and compares the composed sorter against numeric sorting.
