# Two native instructions for each independently changeable zero word

Fix an accepting or rejecting RAM execution on a file with $m$ designated physical words, each initially zero. For some nonzero word $B$, changing any nonempty subset of the designated words to $B$ reverses the required verdict. All other initial data, the input length and the code stay fixed. Use the separate-operation word RAM whose register-register word operations are the twenty of the native catalog (AND, OR, XOR, add, subtract, multiply, three full shifts, three modulo shifts, two rotations and the six value-returning comparisons) and whose branches test equality or signed or unsigned order with fixed successors. The execution takes **at least $2m$ instructions** if none of the designated addresses is zero and **at least $2m-1$** otherwise. The result applies to every globally correct program and to programs correct only on this promise, for a single width. It allows arbitrary fixed-label code, immediate word constants, indirect writes, and unlimited writable storage.

The promise is the OR of $m$ words. Loading each word and comparing it with zero decides it in $2m$ instructions, so this is an exact instruction count for a scan, in units of packed words. It uses no property of satisfiability, zero words do not occur in printable DIMACS, and it gives no information on the unrestricted SAT clock. The count is specific to the instruction set: with bitwise NOR as a native operation the $2m$ bound is false. Both constants are exact for suitable promises. At nonzero known addresses, load and compare each word to zero. At addresses $0,1,\ldots,m-1$ for $m\ge2$, use $B=1$. Load $z$ from address 1, load $x$ from address $z$, then branch on $x=0$. This checks the first two cells in three instructions. When $z=1$ the second load reads the value 1 from the same cell. When $z=0$ it reads the other cell. Check each remaining cell in two instructions. Terminal labels carry fixed verdicts without an extra paid instruction.

## The word operations

Write $u_0=0$ and $u_1=B$. Each binary value-producing opcode $f$ has this property for some pair $(a,b)\in\{0,1\}^2$ different from $(0,0)$:

$$
f(u_a,u_b)=f(0,0)\quad\text{or}\quad f(0,0)=0\text{ and } f(u_a,u_b)=B.
$$

Boolean AND, multiplication, shifts, and rotations can use $(0,1)$ because shifting or rotating zero gives zero. OR and modular addition give $B$ at $(0,1)$. XOR and subtraction give zero at $(1,1)$. Returning the result of an equality, signed/unsigned order, or its negation gives the same word on either diagonal. Every fixed-target comparison $g$ also satisfies $g(0,0)=g(B,B)$. These observations cover the journal's twenty register-register numerical operations at arbitrary native width. Operations on a literal are anchored to the literal in the graph below. The conclusion fails for other primitives. A single binary branch which tests whether the bitwise OR of its two inputs is zero lets three instructions check two cells. Among the sixteen bitwise truth tables the displayed property fails exactly for NOR: its value at $(0,0)$ is the all-ones word and every other corner gives the complement of $B$. If NOR is native and $B$ is the all-ones word, load three designated words $x,y,z$, form $r=\mathrm{NOR}(x,y)$ and branch on the unsigned test $z<r$. The test is true only when all three words are zero, so five instructions check three cells and $5m/3+O(1)$ instructions decide the promise. Notes whose instruction set admits every bitwise truth table are outside this theorem. [NOR as a native operation in the sparse-edit suites](tests-needed-for-the-exact-sparse-edit-clock.md)

## A perturbation through each acyclic component

Use symbolic replay along the actual trace. Mark the first load of each designated original cell and identify values on repeated reads, stores, and register copies at the run's concrete addresses. Pin the address on **every** indirect memory instruction. Pay for all comparison outcomes, binary operations, and indirect-address equalities other than those on the $m$ marked loads. The latter equalities are free pins on the word wires. Each equality on any other indirect read or write uses a literal incidence and is charged to that read or write. The resulting undirected bipartite incidence multigraph has value vertices, ternary arithmetic factors, and binary comparison factors. An acyclic component without a literal has exactly one fewer paid factor than it has sources. Every other source-containing component has at least as many factors as sources. Consequently $T\ge2m-F$, where $F$ is the number of acyclic, literal-free, source-containing components. [Operational replay and incidence count](charging-native-addresses-in-a-fixed-ram-trace.md)

Take such a tree with no free pin at zero. Cut it at a value wire. The branch on the producing side is a *supply*: it realizes the base wire value $x$ with no edits, and either realizes the same $x$ with a nonempty internal edit, or $x=0$ and it realizes $B$ with a nonempty edit. A branch on a consuming side is a *demand*: it accepts baseline $x$ with no edits; if $x=0$ then it can either accept zero with a nonempty internal edit or accept $B$ with any allowed internal edits. An empty demand imposes nothing. A free pin at any nonzero $x$ is a demand since the additional condition concerns only a zero boundary.

The following rules prove both properties by induction on the cut subtrees. The underlying graph is a tree, so the interiors combined in each rule use disjoint sets of sources. Every operation result has one producer. Repeated use of the same value in two inputs of one operation gives parallel edges and already puts that component outside the tree case.

* A raw source supplies its choice between zero and $B$. Several demands at one wire combine: if one can hide an edit at the baseline, leave the others at baseline. If the boundary is zero and none can hide an edit, they all accept $B$. A supply combines with any number of demands by the same alternatives.
* To supply an arithmetic result from two operand supplies, a hidden baseline edit on either operand leaves the result unchanged. Otherwise both operands have zero baseline and can change to $B$. The displayed opcode property produces either the original result with an edit or the required $0\to B$ change in it.
* To use an arithmetic factor as a demand on its first operand, only the case of baseline zero on that operand needs attention. A hidden baseline edit in the other operand or in the result-side demand immediately propagates. Otherwise the other operand is zero and can change to $B$. Use the displayed opcode property. If the result is fixed, its baseline is permitted. If the result changes from zero to $B$, the result-side demand accepts $B$. When the distinguished first operand stays zero, the other operand changed, so the demand hid a genuine internal edit. When the first operand changes to $B$, the demand accepts $B$. Interchanging the operand positions gives the reverse rule.
* In a comparison demand on an operand with baseline zero, the other operand can hide a baseline edit, or it also has baseline zero and can change to $B$. In the latter case changing both operands keeps the observed comparison by diagonal invariance. No assumption on the signedness of the base wire is needed.

Rooting the finite tree at any value and applying these rules gives a supply for the whole component. Either alternative of that supply gives a nonempty edit preserving every branch and every address observation. Operational replay then gives the base verdict, contradicting the promise. Thus every tree counted in $F$ contains a free pin at address zero. The free pins belong to the $m$ distinct marked original loads, at pairwise distinct addresses, so at most one such component exists. If the designated addresses omit zero there is none.

The Lean development checks the supply and demand composition rules, including the backward traversal of an arbitrary binary opcode with the stated property. The conversion of an arbitrary finite execution to a rooted incidence tree uses the argument above. In particular, the proof does not require detecting branch conditions in a syntactically restricted formula. A packed encoding in which a zero word denotes an absent unit clause and $B$ denotes a unit clause contradicting a public one turns the promise into a satisfiability promise. That is a restatement of OR and adds no hardness. With logarithmic native word width the bound is proportional to the number of words, a factor $\Theta(\log N)$ below the encoded bit length.
