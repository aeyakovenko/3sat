# SAT time from the model counts of successive clause prefixes

Read a proper ASCII 3-CNF in its supplied clause order. Keep the first occurrence of each unordered signed clause. Write $C_1,\ldots,C_q$ for the resulting subsequence and $H_i=C_1\land\cdots\land C_i$. Let $S_i$ count satisfying assignments of $H_i$ to the variables **occurring in $H_i$**, with $S_0=1$. Continue to count a previously encountered variable even if its last appearance in the file has passed. Exclude variables only declared in the header or first used later. Removing an already encountered clause, including a reordering of its three literals, changes neither the constraints nor the domain of these prefix counts.

For every fixed polynomial resource cap there is a globally correct logarithmic-word RAM solver which takes
$$
              O\!\left(N+\sum_{i=1}^{q} S_{i-1}\right)
$$
steps whenever the displayed work and storage fit the cap. Here $N$ is the full encoded length in bits. The program has access to all native addresses. The cap allows it to switch to an ordinary exhaustive decider if its intermediate tree would exceed the polynomially many cells addressable in its fixed word convention. One can take a larger fixed polynomial cap for each target clock. Thus for $k=1,2,3$ there is one correct solver running in $O(N^k)$ whenever
$$
              \max_{0\le i<q} S_i
                =O\!\left(N^{k-1}\log(N+2)\right).
$$
For example $O(\log N)$ viable assignments at every proper prefix suffice for deterministic linear elapsed time. The earlier sum can also give the bound when a few prefixes have many models. These are upper bounds for actual running time on the stated inputs. A uniquely satisfiable last formula by itself imposes no bound on its earlier counts.

## Keeping one tree for all viable assignments

Intern decimal variable spellings in a digit trie, assigning compact IDs in order of first appearance. Each character costs constant work. Numerical equality uses the normalized unsigned numeral and keeps the literal sign separately. To detect duplicates, sort the three signed compact IDs within each clause and store the triple in an initially empty table. Three fixed-width fields of $O(\log N)$ bits permit direct addressing with a sufficiently large fixed word coefficient. Alternatively one can insert the signed, normalized token spellings in a second trie in that canonical order. The total length inserted or searched is $O(N)$. This preserves the physical order of distinct clauses. Only the duplicate key sorts the three literals. Malformed inputs may first be rejected by the ordinary syntax pass, with header counts and ranges checked in $O(N)$; declared identifiers can be compared by canonical length and digits without storing a long identifier in one word.

Number the encountered variables in their order of introduction. A node at depth $j$ in a growing rooted tree stores the bit of the $j$th introduced variable. The root is the empty assignment. The current list consists of one node for each live model of the prefix, always at the common current depth. There is no need to delete a dead node from the tree. To process one new clause, inspect its old-variable values on each live node using at most three queries for ancestors at specified depths. Try all assignments to the at most three new variables. For each successful extension append its bits as a path of at most three fresh nodes and retain its endpoint in the new list. With no new variables, retain the old node itself on a successful test. Real descendants can have the same initial partial path labels if different extensions are built independently. Only their distinct complete endpoints enter the list. A new clause cannot revive an old prefix assignment already discarded. Each new model restricts to exactly one old model and supplies exactly one tested extension. Induction gives the claimed enumeration, including the first empty list on an unsatisfiable prefix. A nonempty final list proves satisfiability; walking one path also recovers a full assignment to the occurring variables.

Theorem 6 of Alstrup and Holm gives an incremental level-ancestor structure on a logarithmic-word RAM supporting adding a leaf and retrieving an ancestor at a given depth in constant time. A constant amortized implementation would suffice for the total elapsed bound. Use a dynamic size bound, or double the structure's capacity on demand and reinsert all existing nodes in parent-before-child order; linear rebuilding work over the doublings is charged to the actual node insertions. If an implementation needs size-dependent tables with linear setup, this initializes them at the used capacity rather than paying for the polynomial ceiling at startup. A machine with a sufficiently large fixed coefficient for its $O(\log N)$ words can simulate the $O(\log(\text{number of nodes}+2))$-bit operations under any fixed polynomial ceiling. The construction uses $O(1)$ updates and queries per tested extension and at most eight extensions per old node. A simpler finite implementation stores binary ancestors at powers-of-two distances, adding a logarithmic factor to tree operations. [Alstrup and Holm, *Improved Algorithms for Finding Level Ancestors in Dynamic Trees*](https://doi.org/10.1007/3-540-45022-X_8) · [Author's statement of the leaf-insertion bound](https://drops.dagstuhl.de/storage/15dagstuhl-seminar-reports/2000/DagSemRep.267/DagSemRep.267.pdf)

There are $q=O(1+N/\log(N+2))$ distinct clauses. Indeed, choose from the first physical occurrence of each such clause its ordered list of signed decimal names with single delimiters. These are distinct finite-alphabet strings with total length $O(N)$. At most half of $q$ such distinct strings can have length below $\log_{|\Sigma|}(q)/2$ for all sufficiently large $q$, giving $\Omega(q\log q)$ total length. If $q\le\sqrt N$ the desired bound is immediate; otherwise $\log q\ge(\log N)/2$. This counts even differently ordered physical spellings without charging a late line twice. The construction incurs $O(N)$ parsing and $O(\sum_i S_{i-1})$ tree work. For each $k$ one can use a fallback threshold of order $N^{k+1}$ on tree operations. Any fixed multiplicative constant in the favorable premise eventually fits that threshold.

## Consequence for extending uniquely satisfiable inputs

Suppose a sequence of appended batches starts from a fixed uniquely satisfiable base, each batch ends with a uniquely satisfiable formula, and at most $b$ new variables appear in any one batch. A prefix inside a batch has at most $2^b$ satisfying assignments on its occurring variables. Earlier variables are fixed by the preceding completed batch and cannot change their values. No bound on the number of old occurrences, on repeated clauses, or on the number of clauses used to restore uniqueness is needed. The solver need not be told the batch boundaries or a satisfying assignment. The fixed base's own prefix counts contribute a constant. In particular such a chain with $2^b=O(N^{k-1}\log(N+2))$ falls in the indicated $k$-clock on its ordinary SAT files. The condition on prefix model counts can hold even when many variables are simultaneously ambiguous. Enforce equality down a chain with fixed-false padding anchors: after each equality there are exactly two models, while every chain variable has both possible values.

On a sequence forcing the displayed program past every constant times $N^k$, the prefix-count sum must itself grow past every constant times $N^k$, and the peak count past every constant times $N^{k-1}\log(N+2)$, along that sequence. This is a necessary test for a proposed set of common hard inputs facing a portfolio containing this solver. Simply constructing a file with a large peak does not give a lower bound on another program, or even on this program if its exhaustive fallback takes a shortcut.

The audit checked 17,315 distinct-clause prefixes across 5,270 ordered families against independent truth tables. An additional chain kept all 1,000 equality-linked variables ambiguous with at most seven prefix models.
