# Offline checks of the weighted range transcript in linear encoded time

The original weighted dominance transcript admits a one-sided Monte Carlo verdict in $O(L)$ word time on **every** complete legal stream, where $L=\Theta(n\log n)$ is its ordinary DIMACS bit length. A truthful transcript always receives UNSAT. If at least one claim is false, a single trial returns SAT with probability at least $1/2$, with no loss for a lone error. A deterministic $O(L)$ checksum catches every file having a single false claim and every file whose nonzero errors all have the same sign. A second deterministic checksum counts all erroneous claims exactly when each one is a flip of the true answer's low bit, even with arbitrarily many errors of both signs. Each nonzero checksum remains a sound SAT certificate for an arbitrary legal transcript.

These checks read all the operands and proposed answers before processing them. This is compatible with Weinstein and Yu's lower bound on returning a correct integer answer before the next operation. The input here has no extra reverse answers or numerical certificates. [Physical construction and its exact model counts](weighted-range-transcript-encoding.md) · [Weinstein and Yu, §4](https://arxiv.org/pdf/1604.03030)

## Transpose the comparison

Write $F_j$ for the true sum at query $j$ and $A_j$ for the annotation. For any chosen subset $S$ of queries,
\[
     \sum_{j\in S} F_j=\sum_{t\text{ an insertion}} w_t C_S(t),
     \qquad
     C_S(t)=\#\{j\in S:j>t,\ a_j\ge x_t,\ b_j\ge y_t\}.
\]
The right side requires just $u=O(n/\log^2 n)$ **unweighted** three-dimensional dominance counts, each then multiplied by the original word weight. Construct the point array from the selected queries, in decreasing chronological order. Replace each spatial coordinate $z\in[n]$ by $n-z$. For an insertion, taking the prefix of this array strictly later than its time and testing both transformed coordinates against inclusive upper bounds gives $C_S(t)$. The operation order provides all time-prefix boundaries in linear time. Repeated coordinates and a possible empty subset require no perturbations.

Choose membership in $S$ by independent fair coins. Compute the displayed sum and compare it to $\sum_{j\in S}A_j$. Fix all the coins except one at a nonzero error. The two possible differences differ by that error, so at most one comparison can pass. Constantly many trials reduce the one-sided error geometrically. Integer sums of $O(n)$ values of size $O(n^2)$ occupy $O(\log n)$ bits or a constant number of native words. Even if multiplication of two such integers is charged $O(\log n)$ shifts and adds, the extra $O(u\log n)$ work fits the clock.

Taking all queries for $S$ gives the deterministic total-sum check. More generally two subset checks give a signed sum. Take $s_j=1$ for an odd claim and $s_j=-1$ for an even claim. If the only possibilities for $A_j$ are $F_j$ and $F_j\mathbin{\mathrm{xor}}1$, then $s_j(A_j-F_j)$ is exactly its error indicator. The sum over all $j$ equals the number of models of the original CNF. The same construction detects flips of any prescribed single bit per query by using the sign of that claimed bit. The contribution of an error at bit $k$ is then $2^k$.

A globally correct deterministic SAT program can first validate the public transcript template and packet inventory, reconstruct the logical stream by IDs, perform one or both checks, and accept immediately if a checksum differs. Template validation on the certified family costs $O(L)$ by generating and comparing the public clauses, checking each fixed-width packet against the allowable forms at its physical position, and testing record multiplicities and the public schedule with direct-address arrays. On a mismatch of template syntax or an inconclusive checksum it can use complete SAT search. Consequently every certified unique-model file in the family is accepted within $O(L)$ by one globally correct program. Under the promise of at most one error, or the low-bit noise promise with the signed check, the checksum gives an exact fast decision on both signs. Without a promise, a zero checksum alone cannot justify a deterministic UNSAT return. There is also a globally correct Las Vegas solver with expected $O(L)$ time on **every satisfiable file in this family**, however the annotation errors are distributed. After template validation, run independent checks while dovetailing an exact SAT fallback. Each nonzero signature certifies SAT, a satisfiable file needs at most two trials in expectation, and the fallback guarantees termination on every input. We do not obtain an expected $O(L)$ Las Vegas bound on the unpromised truthful side.

## The unweighted counting structure

For a chronological array of $s\le n$ points in $[0,2^h)^2$, where $h=\lceil\log_2(n+1)\rceil$, we build a deterministic index in $O(nh)$ word operations and words of space. Given a prefix length and two inclusive spatial bounds, it returns the count in $O(h^2)$ time. Thus the cost of one transcript check is $O(nh+uh^2)$, within $O(L)$ even for $u=O(n/\log n)$ if the unpacked stream is supplied. We use a logarithmic-word RAM with bit operations and lookup in a table constructed within the time bound.

Use an ordinary binary prefix trie on each coordinate. The cell $(v,z)$ consists of the points matching the $x$ prefix $v$ and $y$ prefix $z$, listed in original chronological-array order. Put $B=h$. A cell with at least $B$ points is heavy. Each heavy cell stores two packed bitvectors $X(v,z)$ and $Y(v,z)$ giving the respective **next** coordinate bits for every point, in that same order. At a full-depth coordinate its next bit is unused. Store prefix-popcount directories for these bitvectors. A light child of a heavy cell in the $y$ trie has a separate short list, described below. On the $x$ axis keep the actual list of time indices at each nonempty prefix, even if it is light.

Here are the two construction identities. For a child $v'=vd$ and a child $z'=ze$,
\[
\begin{aligned}
  Y(v',z)&=\operatorname{filter}_{X(v,z)=d}\ Y(v,z),\\
  X(v,z')&=\operatorname{filter}_{Y(v,z)=e}\ X(v,z).
\end{aligned}
\]
Both filters preserve the ordering. A filter of two length-$\ell$ bitvectors costs $O(1+\ell/h)$ operations. For example, use pieces of $\max(1,\lfloor h/8\rfloor)$ bits and tabulate every pair consisting of a piece of data and a piece of mask, obtaining the compacted piece and its length. There are $O(n^{1/4}+1)$ table entries, constructible in $O((n^{1/4}+1)h)$ time. Concatenate each output piece with shifts into a constant number of word positions. The same table scale supports popcount on a piece. Saving prefix counts at word boundaries gives constant-time rank queries within a vector. This accounts for the copying of packed bits, including short vectors.

Build the $x$-axis lists by ordinary stable binary partitions in $O(nh)$. At the empty $x$ prefix, the $y$ trie and the vectors on its heavy nodes are built directly from the point list in $O(nh)$ time. Given the $y$ trie already constructed for an $x$ prefix $v$, build the trie for each child $v'$ by a simultaneous top-down traversal of the old and new $y$ tries. Obtain $X(v',\varnothing)$ from the $v'$ axis list. At a heavy new cell $(v',z)$ its corresponding old cell $(v,z)$ must also be heavy. Filter the old vectors to obtain the new $Y(v',z)$. From this and the already available $X(v',z)$ obtain both child sizes and the two filtered $X$ vectors needed below. Stop at a light new child, recording its position. For a heavy new cell, save a link from its old cell in the $x$ direction. Also keep the ordinary $y$-child and $y$-parent links. These traversals locate both required vectors without a dictionary on pairs of prefixes.

At a fixed pair of coordinate depths, the cells partition the input. Their heavy nodes number at most $n/B$, and the total length of their bitvectors is at most $2n$. Each heavy node's vectors are filtered only constantly many times, and there are only constantly many light children per heavy node. Including rounding and links, the cost of all interior vectors and their directories is
\[
    O\big((h+1)^2(n/B+n/h)\big)=O(nh).
\]
Empty and light $x$-axis roots contribute at most $O(1+nh)$ as well. The construction handles $s=0$ directly.

To build short lists, scan the points once more in time order. For a fixed point and $x$ prefix on its path, consider the deepest heavy $y$ ancestor containing the point, if the $x$ root cell is heavy. Its $y$ depth cannot increase on extending $x$, since the new cell is a subset of its $x$ parent. At the root find the deepest ancestor by descending $y$. At each succeeding $x$ prefix, climb $y$-parent links until there is a heavy link to the requisite $x$ child, then follow it. If the root already has no such link there are no more heavy $x$ roots on this path. At each visited $x$ prefix, append the point ID to the first light $y$ child on its path, if there is one. All climbs together cost at most $h$ per point and there are at most $h$ moves down $x$. Every needed short list therefore receives its full points in sorted array order in total $O(nh)$ time and space. Lists at light $x$ roots are already available from the axis construction.

For a query decompose its $x$ prefix range $[0,a]$ into at most $h+1$ disjoint binary trie nodes. In each such node, binary search its ordered time indices to find how many belong to the selected time prefix. Descend along the **single** $y$ path to the other bound $b$. The node's $Y$ rank translates the current prefix length to each child. If the next bound bit is one, add the count from the entire zero child before descending into the one child. On the first light child scan only its first translated number of points, testing their full $y$ coordinates. A full-depth cell contributes its entire prefix count. This costs $O(h+B)$ per canonical $x$ node, hence $O(h^2)$ per query. It never follows the other child's short list.

Chazelle's compressed range trees are a classical precursor to the use of rank bitvectors here. Chan and Pătraşcu give $O(n\log^{4/3}n)$ total time for balanced offline unweighted three-dimensional dominance counting. Their static Theorem 3.3 also gives a faster $O((\log n/\log\log n)^2)$ individual query with $O(n\log^{4/3}n)$ preprocessing. Here there are few transposed queries, and construction time at a slower $O(\log^2 n)$ query bound is what matters. The two filtering identities above give the required construction directly. Priority for this preprocessing tradeoff or its transcript application is unestablished.
