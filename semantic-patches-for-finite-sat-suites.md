# Globally correct semantic patches for a finite SAT suite

Fix $h$, and consider $m\le n^h$ distinct proper ASCII DIMACS files of encoded length $n$ bits. If every file is satisfiable, there is a globally correct deterministic SAT solver taking $O_h(n)$ word steps on every file in the suite whose complete code uses
\[
                    O_h\big(mn/\log(n+2)+\log(n+2)\big)
\]
bits. This includes files with unique solutions and arbitrarily large decimal variable names. For a single positive file the bound improves to $O(v+\log(n+2))$ bits, where $v$ counts its occurring names. For negative files the analogous construction has a cost depending on an actual unsatisfiable subformula. The program uses a fixed logarithmic word-width coefficient, unit word multiplication, ordinary direct branches, and zero-initialized writable memory. Its finite binary description pays for instructions, targets and immediates. The constants in its clock are independent of the chosen suite once $h$ and the machine convention are fixed. [Previous finite-suite promise retrieval and globally sound literal comparisons](code-bits-needed-to-fit-a-finite-sat-suite.md)

## Code for mixed verdicts

For each positive file store a satisfying assignment on its $v$ variables in increasing numerical name order. For each negative file select any unsatisfiable core with $k$ occurring variables and $c$ distinct clauses. Numbers in a core refer to that file's normalized variable ranks. Set $U=8\binom{k}{3}$. A semantic certificate payload per file is bounded in bits by
\[
     b(F)=\begin{cases}
          v, & F\in\mathrm{SAT},\\
          v+O\big(c(1+\log_2(U/c))\big), & F\notin\mathrm{SAT}.
          \end{cases}
\]
The program size is $O_h(m\log(n+2)+\sum_F b(F))$. Identical payloads of the same type and dimensions may share one copy. The negative estimate also yields $O_h(mn/\log(n+2)+\log(n+2))$ if each negative file has a chosen core with $U=O(c)$, or with $c\log(n+2)=O(n/\log(n+2))$. A proper three-literal minimal unsatisfiable formula can have $\Omega(k^3)$ clauses, so a small number of core clauses cannot be assumed in general. [Choongbum Lee, *On the size of minimal unsatisfiable formulas*](https://arxiv.org/abs/0811.0427)

To encode a core, use a $v$-bit mask for the chosen ranks, renumber that support in increasing order, and enumerate signed triples of local ranks by an agreed order. Their indices form a sorted $c$-subset of $[0,U)$. Store $b=\lfloor\log_2(U/c)\rfloor$ low bits per index, and encode the nondecreasing high parts by unary gaps with one terminator per entry. The high-part stream has length at most $3c$, since $U/2^b\le 2c$. This proves the displayed size bound and gives sequential linear-bit-time decoding. Store dimensions and record boundaries in the directory. No proof search runs on the fast path. The core's unsatisfiability is a fact about the compiled finite program, which the program builder can verify by exhaustive search before use.

There are $O(n/\log(n+2))$ distinct names and also $O(n/\log(n+2))$ distinct clauses in any $n$-bit file. For $s$ different strings over a fixed finite alphabet their total printed length is $\Omega(s\log(s+1))$. Apply this to one occurrence of each name, and separately to the distinct clause records. The literals of a distinct clause have a textual representation, including separators, which occupies a disjoint substring at its chosen occurrence. Consequently each $b(F)$ is $O(n)$, every positive $b(F)$ is $O(n/\log(n+2))$, and dense negative cores have the same smaller bound.

The selector only has to suggest a payload. Guard the target input length, read the packed words of the input and evaluate their coefficient polynomial at one fixed element of a prime field. Taking $p>\max(2^w,2nm^2)$ within a constant factor of that lower bound leaves an evaluation point at which all $m$ suite files have distinct residues. Each pair rules out at most $n$ points. Store the selected prime, evaluation point and reciprocal for reduction, together with a balanced direct-branch tree on the $m$ stored fingerprints. A missing fingerprint goes to complete SAT search. Evaluation takes $O_h(n/w+1)$ native steps since all modular products and quotients use a fixed number of native limbs, as in the finite-suite construction. A tree lookup costs $O_h(\log(m+2))$ steps and $O_h(m\log(n+2))$ code bits in total. Collisions with files *outside* the suite are allowed. [Finite-suite fingerprint and charged arithmetic](code-bits-needed-to-fit-a-finite-sat-suite.md)

Pack the entire certificate stream into $w$-bit chunks. Fetch a chunk through a direct-branch tree ending in one immediate move per leaf. The number of directives and leaves is linear in the number of chunks, and each needs $O_h(\log(n+2))$ bits including its labels. A selected $b(F)$-bit payload costs $O_h((1+b(F)/w)\log(n+2))=O_h(n)$ steps to fetch, even if most other payloads are never visited. Only local variables and scratch actually written during this execution are initialized. The singleton case can dispense with fingerprints. For a length guard on machines that truncate immediate integers, first verify the native width is sufficient to hold $n$, using successive small-to-large thresholds $\lceil\log_2(n+1)\rceil$ and its iterated bit lengths in reverse order. Each constant fits once the preceding check passes. Only then compare length to the full literal $n$. These guard tests can sit together at entry with short targets and cost $O(\log(n+2))$ bits. Width can be found by shifts in $O(w)$ steps if the machine does not expose it.

Normalize and validate the actual clauses. Intern decimal names in a ten-way digit trie in $O(n)$, ignoring leading zeros where the grammar permits them. Scanning its nodes by increasing depth and lexicographic order within a depth enumerates the distinct positive integers in increasing order. Oversized header names can also be compared as digit strings. A promised assignment succeeds only if it satisfies every actual clause. A negative candidate succeeds only if its support embeds in the actual occurring ranks and **every decoded core clause occurs**. For example, counting-sort the signed triples of normalized ranks, sort or merge the core rows, and test inclusion. A constant number of stable passes, each on a rank or sign field, costs $O(n)$. One may index local unsigned triples in colexicographic order by $\binom{i}{1}+\binom{j}{2}+\binom{k'}{3}$ for zero-based $i<j<k'$, appending three sign bits. To avoid square or cube roots during core decoding, map the *actual* clauses on the selected support to their integer IDs, radix-sort these polynomial-range integers in constantly many word digits with $O(n)$-size counting arrays, and merge the two streams of IDs. On general inputs a malformed or failed suggestion invokes the fallback. A false positive cannot pass an assignment check, and any superformula of a trusted unsatisfiable core is itself unsatisfiable. All branches therefore preserve global correctness.

In particular for a fixed linear multiplier at least the construction constant, a defeating suite consisting only of such positive files must exceed the indicated code budget for the patch. This does not imply a matching program-size lower bound, or the same compressed cost for all negative files. The $2^m$ arbitrary-label counting argument measures what a promise lookup can represent and does not supply that lower bound for the SAT labelling.

## One program for repeated growing seeds

A separate uniform construction pays for each *distinct normalized connected component* only once. Let $\mathcal H$ be those component types after deleting duplicate clauses and locally renumbering variables by increasing numerical name. These are labeled types: isomorphic components with different local orders may be different keys. One fixed globally correct SAT program takes
\[
 O\!\left(n+\sum_{H\in\mathcal H} 2^{v_H}(1+v_H+c_H)\right)
\]
steps, with $v_H,c_H$ the numbers of variables and distinct clauses of $H$. The count is independent of literal ordering, clause interleaving, and duplicate rows.

After parsing, build the variable–clause incidence lists and find connected components by a depth-first or breadth-first search. Scan the globally ordered names once with a rank counter per component. Each resulting local name rank is at most the original positive name; printing it needs at most a constant times the original number of digits. Normalize each clause by its three local ranks and signs. Stable counting sorts on component ID, ranks and signs place the rows of each component together in canonical order in $O(n)$ time, allowing duplicate removal. Serialize each component's surviving rows as a uniquely framed local key with $O(1+\log(r+1))$ bits per local rank $r$. The sum of all key lengths is $O(n)$ by the original digit bound. Intern these strings in a binary trie in $O(n)$ total work. Decide each new terminal key by ordinary exhaustive assignment search in the displayed per-key time. Generating the next assignment and checking each distinct clause needs $O(1+v_H+c_H)$ word operations per assignment even when the assignment spans many words. The formula is satisfiable iff every component is satisfiable. All input bytes, construction work, and duplicate detection have been charged.

For disjoint copies from at most $h_0$ isomorphism types of seed components with at most $v$ variables each, there are at most $h_0 v!$ different local keys, since independent renaming induces only a permutation of the ranks. Each has at most $8\binom v3$ distinct clauses. Thus the clock is $O(n+h_0 v!2^v(1+v)^3)$, even with arbitrary fresh decimal names in each copy and arbitrary clause shuffling and repetition. In particular the same program runs in linear encoded time on every such family satisfying $h_0 v!2^v(1+v)^3=O(n)$. For bounded $h_0$ this includes $v\le (1-\varepsilon)\log_2 n/\log_2\log_2 n$ for every fixed $\varepsilon>0$ at sufficiently large $n$. A disjoint-sum induction that multiplies the cost of solving a hard seed by its number of copies fails this test. Mixing fresh interactions between copies, or introducing sufficiently many distinct component types, changes the calculation. [Related separator-based clause-batch algorithm](one-or-two-old-variables-in-clause-batches.md)

One can also pay the exponential SAT search once per *isomorphism type*. Build the trie of observed component keys first. On encountering an unresolved key, decide its formula, enumerate all permutations of its $v_H$ local ranks, renormalize and sort its signed clauses under that permutation, and propagate the verdict to any matching terminal already present in the trie. Store only the trie of actual inputs and the present permutation and key. A subsequent unresolved terminal must be in a different orbit. For representatives $H$ of the occurring isomorphism types this gives the alternative running time
\[
       O\!\left(n+\sum_H \big(2^{v_H}(1+v_H+c_H)
                   +v_H!\,(1+v_H+c_H)^{O(1)}\big)\right).
\]
The two searches need polynomial space in the component size and $O(n)$ storage for the original normalized keys. Dovetailing the two fixed programs yields the better bound for the given input within a constant factor on a RAM with a sufficient fixed width coefficient. No advice on the seed or its verdict is needed. When an induction introduces a new boundary through which different components constrain one another, this propagation rule no longer applies directly.

As a finite collision check, take the 256 subsets of the eight sign clauses on three fixed variables. For each positive source suggest its least model, and for the single negative source suggest all its clauses as the core. Trying every suggestion on every actual target gives 65,536 cases. Exactly 32,640 assignment checks and one core check return a verdict; all are correct. This counts suggestions that actually verify on the target, including suggestions meant for another file.
