# Two fixed query words for a coded SAT equality

Fix $m$ private word positions, $Q$ groups of $k$ database bits each, and $q=k+\log_2 Q$, with $Q$ a power of two. Write $A_j$ for group $j$. The one-group case uses $Q=1$ and $q=k$. Let $G$ be a public $q$-by-$m$ binary matrix. Supply any public straight-line XOR circuit with $s$ gates computing $x=Gz$ on $m$ bits; the circuit may be chosen separately at each length. Use the first $\log_2 Q$ bits of $x$ for the group index $j$ and the remaining $k$ bits for the comparison string $v$. The exact physical verdict is
$$
                       \operatorname{SAT}(A,z,t)
                      =[\, [A_j=v]=t\,].
$$
There are $m$ interchangeable private positions and $kQ$ distinct data packets. Across every position at one length the two possible seed words are **the same two numerical words**. The two tag words are likewise fixed and differ in one bit. Neither the code nor the grammar of a private word depends on the database. We require $m\ge kQ+q+1$ to accommodate the complete inventory.

With $Q=1$ and every column of $G$ nonzero, on the diagonal $Gz=A_0$ **all $m$ original private words are individually pivotal on both tagged files**, including every data word, the tag, and any fillers. One physical bit per word suffices. Thus on each of those two ordinary inputs every correct deterministic aligned-word RAM program must read all $m$ original private words before deciding. The program may use writable input and unrestricted workspace. The construction itself gives no superlinear bound in encoded input bits. ## A signed clause whose identifier spans a word boundary

Variables 1, 2 and 3 are forced false by the seven proper triples excluding the other seven assignments. Set $d=\max(1,\text{decimal digits of }m-1)$ and $u=10^d$. At private position $i$, $0\le i<m$, define the names $a_i=4u+i$ and $z_i=5u+i$. Two fixed clauses $(a_i,z_i,1)$ and $(-a_i,-z_i,1)$ make these complementary Boolean values. Other circuit and database names are allocated above both bands. All these identifiers are $O(m+s)$ when $kQ+q\le m$. Variables 4 and 5 are separately reserved for the two whole-query signs.

Each private word begins with **one complete proper clause**, followed by whitespace and a final ASCII digit. Each immediately following public word starts with the zero-padded $d$-digit decimal spelling of $i$, then the text ` 1 2 0` and a newline. The last digit of the private word and the first $d$ digits of that public word are contiguous in the actual file. A final `4` thus pins $a_i$, which forces $z_i=0$. A final `5` pins $z_i$, which forces $z_i=1$. The numeric identifier has no leading zero. The two possible last bytes differ in the least significant bit.

* A seed packet starts with the fixed proper clause $(-1,2,3)$, which is true under the anchors. Its last byte is `4` or `5`. An unused private position can be filled with exactly the zero-seed word.
* A data packet pins its own database variable by $(D,1,2)$ or $(-D,1,2)$. Its canonical last byte is `4`.
* A tag packet pins variable 4 or 5 by $(4,1,2)$ or $(5,1,2)$. Its canonical last byte is `4`. Switching the tag flips the first byte of its complete private clause and leaves its last byte fixed.

Changing the last byte in a data or tag packet changes the coordinate $z_i$ while preserving its data pin or query sign. The modified file remains a legally encoded proper 3-CNF. No sign byte, digit of the slot number, or piece of the public circuit enters the numerical spelling of a seed word.

The fixed public circuit computes $Gz$, compares its high $k$ output bits with each database group and selects one answer by the low group bits. It makes variable 4 equivalent to the negation of equality and variable 5 equivalent to equality. Standard gate equivalences use at most four proper clauses per XOR or multiplexer and three per conjunction after padding. Every canonical private inventory pins each of the $kQ$ database bits once, every $z_i$ once and exactly one alias. Evaluation supplies a model for the matching tag. For the opposite tag the fixed output contradicts the asserted alias. A nonuniform code circuit can be recorded explicitly in ignored public DIMACS comments, using $O(s+q)$ records. These also make uniform recognition possible without generating the code family from scratch.

The compiler organizes the header, public comments and fixed gate clauses into all-public words holding up to 24 complete short lines each. It then appends $m$ private/public word pairs as above. Let $M$ be the total word count and choose the least $\ell$ with $2^\ell\ge1024\ell M+2$. Then $N=1024\ell M$ bits and $w=1024\lceil\log_2(N+2)\rceil$. There is no partial word. All private words have exactly $w$ bits, starting at public, aligned addresses. There are $O(m+kQ+s)$ input words and $O((m+kQ+s)\log(m+kQ+s+2))$ encoded bits. In particular a linear-size XOR encoder gives $N=\Theta(m\log m)$. The adjacent public words use slot-specific suffix digits and one clause terminator. They may be inspected freely without revealing any of the private choices.

## What survives a common inspected set

Let the row code $\{a^TG:a\in\mathbb F_2^q\}$ have minimum distance $d_{\min}>0$ over nonzero messages. For a set $V$ of already inspected private positions, fix all their $z_i$ to zero. Reserve one still-uninspected position $t_*$ for the tag **before** choosing a basis. If $|V|+1<d_{\min}$, the columns outside $V\cup\{t_*\}$ span $\mathbb F_2^q$. Otherwise some nonzero $a$ would annihilate all survivors and $a^TG$ would have support inside $V\cup\{t_*\}$. Take the first $q$ independent survivor columns in increasing order. At those $q$ positions use the inverse basis to encode any desired $x$ in the two seed words. Put the canonical tag at $t_*$. At the other positions put the database pins, with every unused position a zero seed. This requires $|V|\le kQ$ if all previously inspected private slots have already received distinct database pins. The bound $m\ge kQ+q+1$ ensures the remaining data fit.

If the tag is the first position outside $V$ and the basis uses the stated rule, its location, basis order, inverse and slot-specific public clauses need no further advice given $V$ and the public code. A set $V$ of at most $\eta m$ inspected positions, $0<\eta\le1/2$, uses at most $\lceil m H_2(\eta)\rceil$ bits by ranking among all such subsets. A separately prescribed tag costs up to $\lceil\log_2 m\rceil$ additional bits. Data assignments still have to be represented or computed wherever the argument consumes them. An entropy budget for $V$ alone does not encode arbitrary database values. If a proof also transmits prefix machine states, a fixed program with $r_0$ addressed registers and $s_0$ control locations has $r_0w+\lceil\log_2(s_0+2)\rceil+O_P(1)$ bits of register, program-counter and finite flag information at its cut. Distinct fixed programs need their respective controllers. Nonuniform growing program counters and additional persistent state require their actual information budgets. This physical solver argument assumes aligned whole-word accesses, with instruction text distinct from the writable data.

Here is the writable-prefix point for several programs. If a program tries to erase a still-unobserved private position while all its own previously inspected private responses are distinct data packets, use **its own transcript** to rule out its first such write. Put the tag at the proposed write address; choose the basis after excluding that tag and the program's own inspected positions. All other missing data, seeds and fillers can now be identical in the two completions. A packet assigned to that address for some other program, but never observed by this one, can be relocated in this auxiliary pair. Both executions would erase the only difference before reading it and would give the same answer. The eventual common completion for a portfolio can separately retain all its assigned data packets and use the union $V$. Prefix writes to fixed public words need to be reflected in that machine's actual cut memory.

## Pivotal bits and the native fast path

On a fixed grouped file, toggling the last private byte in slot $i$ adds $G_{*,i}$ to $x$ and preserves both the database and the chosen tag. In the one-group case with $x=A_0$ and $G_{*,i}\ne0$, equality changes from true to false. This flips both tag verdicts at the same slot. All $m$ positions work on the same diagonal pair. A program reading neither the original word nor anything depending on it has the same run on the two versions; overwriting it first also erases the only difference. Thus even a machine specialized to a file length must read every original private word on each diagonal input. With several groups an edit may select a different matching group, so the all-slots conclusion here uses one group. A zero column of an otherwise suitable code can be replaced by the first standard basis vector: every old codeword was zero in that coordinate, so minimum distance does not decrease. The one modified output needs at most $m$ additional XOR gates.

A globally correct SAT program can recognize these files and decide them in $O(N)$ time. Read the public size and XOR records from the comment lines, rejecting the fast path on out-of-range counts, nonsensical wire references, an incorrect header or mismatched canonical public clauses. Comparing the full regenerated public portion also checks the fixed bytes of every adjacent suffix word. Read each private word, record its final bit, validate its entire remaining spelling, enforce one sign and one pin per database position, and evaluate the supplied XOR list, indexed group, and bit comparisons. One can allow either last digit in **every** kind of packet so that each pivotal mutation is also on this path. A duplicate or missing database pin, two tags, or mismatched marks must transfer to a complete SAT procedure.

In a native implementation each recorded wire and each assignment bit takes at most one word. Decimal input parsing takes one pass over its character count. Regenerating the prescribed bounded-size rows and words takes $O(\log N)$ steps per record by printing their $O(\log N)$ digits. Thus validation and evaluation have the claimed bit-length clock, including for an arbitrary supplied public circuit. Preliminary bounds on $m$, $kQ$, and the number of gates in terms of the physical file size avoid excessive allocations on malformed inputs. The test harness implements this exact recognizer and compares physical SAT verdicts to CaDiCaL. It includes ordinary files with $Q=1$ and one-bit changes in every private word on an equality diagonal.

The finite check parsed 2,352 base files in 1,176 complementary pairs. It verified 44 individual private-word bit flips on two one-group diagonals at both tags and included them in 260 independent CaDiCaL verdicts. It also computed the exact minimum erasure sizes 5, 4 and 8 for the three supplied small codes of dimensions and lengths $(3,11)$, $(3,8)$ and $(4,15)$. Run the helper with its optional `--solver` argument pointing to CaDiCaL to reproduce those solver checks.
