# One wrong initialization prediction in a complete SAT decision run

There is a fixed deterministic SAT program and a family of ordinary dense, proper ASCII 3-CNFs of encoded length $N$ with all the following properties. At each sufficiently large byte-aligned length the family has the circuit lower bound $\Omega(N(\log N)^\sigma)$ from the November 24 list theorem. The program is correct on arbitrary files, and throughout this family it uses $O(N/\log N)$ word steps. It reads input words once in increasing physical order. Its only writable memory accesses are one load and one store per source key, in fixed slots. **Every store writes the value one, no word is stored twice, and the entire list of genuine work-load replies differs from the all-zero list in at most one bit.** On every unsatisfiable member all replies come from initialization. On every satisfiable member exactly one load obtains a stored word. The program validates the entire ordered template on both verdicts. [Hard ASCII projection](checking-the-sat-circuit-bound.md) · [Canonical encoder](dense_ascii_chunk_circuit_audit.py)

Use a zero-initialized, word-addressed RAM with a fixed number of registers, its ordinary bitwise operations, shifts and integer addition. A word of $12\lceil\log_2(N+2)\rceil$ bits suffices. The implementation uses a polynomial address universe and touches only $O(N/\log N)$ writable words. The distinction matters because its indicator table uses addresses up to $O((N/\log N)^2)$. The result concerns the canonical order and formatting of this hard restriction. The earlier scan-time recognizer also handles reordered clauses but uses counting-sort and parsing tables. ## A fixed sequence of marks

Let $m=2^k$ and let $x_1,\ldots,x_m$ be the source's $2k$-bit keys. Formula satisfaction means that a key repeats. Give distinct keys distinct addresses $a(x)$ and reserve separate private addresses $d_i$, all initially zero. Keep in a register a bit $h$ recording whether a repetition has been found. At row $i$ perform the following two memory events.

1. Read $r$ from $a(x_i)$ if $h=0$, otherwise from $d_i$.
2. Set $h\gets h\lor r$. Store one at $a(x_i)$ if the new $h=0$, otherwise at $d_i$.

Before the first repetition every read sees zero and every store marks a new real key. At the first repetition the real cell returns one, and the store goes to the private address. Thereafter each private address is fresh for its own row. This proves every asserted event count. No real or private address is accessed more than three times, and at most one address is visited three times. The two address selections can use register masks, so a change in $h$ requires no extra instruction or slot. On every canonical file the CPU can follow the same opcode schedule up to its final verdict, with the same load and store times. Input and work addresses are separate banks. Validation failures on arbitrary inputs may use the general SAT fallback.

## Recognizing the hard ASCII files without a scratch table

Here are details needed for the native clock. In the existing projection, $b=\lceil k/4\rceil$. A row gives eight bank names, each consisting of its bank digit followed by $b$ ASCII digits chosen from `0` and `1`. Each name appears in two adjacent, prescribed padded clauses. For each bank $j=0,\ldots,7$, read the $b$ suffix bytes as a register $R_j$, with the first byte in its least significant position. Set $M_b=\sum_{s<b}2^{8s}$. Validate $(R_j\mathbin{\&}\neg M_b)=48M_b$, and extract $L_j=R_j\mathbin{\&}M_b$. Form

$$a(x)=\bigvee_{j=0}^7 (L_j\ll j).$$

The eight suffixes occupy disjoint bit positions in a single $8b$-bit address. It is an injective encoding regardless of the byte order within a suffix. Check the original projection's publicly padded positions are zero and that the two token copies are equal. This takes a bounded number of operations per row. Use $d_i=2^{8b}+i$ for $1\le i\le m$. The masks and the padding-bit tests are fixed for this length; they can be prepared in registers in $\operatorname{poly}(k)$ time. No lookup table, bit-extraction instruction or multiplication of variable words is needed.

The remaining ASCII fields can be validated in file order. The canonical header determines $k$ via its strictly increasing declared bound $V=(9\cdot10^b-1)+14+4m+8\cdot2^b$. Derive and check the header values and prescribed clause count with a polynomial-in-$\log N$ register-only setup, declining the fast path if $m>N$ or a bounded field overflows. The public part of the [canonical encoder](dense_ascii_chunk_circuit_audit.py) consists of eight bank walks, one selector walk and a final increasing list of reserved names. The selectors advance by one per row. In the bank walks adjacent identifiers of the running flag use consecutive auxiliary names, and the public bank suffix advances as a fixed-width binary numeral printed in ASCII. The selector-threshold walk uses three consecutive gate names per row, together with the previous two state names and the current selector. The reserved names advance by one up to $9\cdot10^b-1$. The remaining signs, padding names, group counts and punctuation are public. Thus finitely many counter streams generate all expected tokens, each running monotonically with bounded increments. Retain the previous and new strings when both are referenced. There are only constantly many restarts, including the eight bank boundaries.

Hold the full printable digits and length of each such counter in registers. For a decimal increment, turn trailing nines into zeros until the first smaller digit, then increment it. The number of changed digits in $u$ consecutive increments from an arbitrary $O(k)$-digit start is $O(u+k)$ by summing the carries through each digit position. Fixed-stride increments are a bounded number of single increments. The same calculation holds for the `0`/`1` digits of the public bank suffixes. An all-nine rollover prepends one digit. Arithmetic shifts put each digit at its known byte offset. Setup can obtain the first printable counter values by grade-school conversion; the total is polynomial in $k$. All public tokens fit in a bounded number of words. The number of body tokens is $O(m)$, because $9\cdot10^b=O(m)$.

Keep a constant-word sequential input buffer. Each public token or data suffix has known expected byte length before consuming it. Shifts and masks extract it from the buffer, loading the next physical word only when the buffer requires fresh input. This works also when the word boundary splits a byte. Compare the prescribed spaces and newlines. Fixed-length padding may be spaces immediately before the last newline, checked one buffer segment at a time. An ordered template instance remains valid under this padding. The fast path returns $h$ only after complete validation and on other inputs invokes an ordinary total solver using a separately initialized work bank. The cost on this family is $O(m+N/\log N+\operatorname{polylog}N)=O(N/\log N)$ because $N=\Theta(mk)$. The numerical word-width constant above accommodates both ASCII tokens and the sparse mark addresses. We have not established the same one-hit guarantee for a RAM with only $N$ addressable words.

## Authenticating an alleged all-initializer trace

Given the key list, present a chronological trace claim with load followed by store at $a(x_i)$ for each $i$. All proposed load replies are zero, all proposed stores write one, and every proposed producer is the initialization marker. These are the addresses the genuine program would calculate if the proposed replies were supplied. The address data wires are copies and rearrangements of the source bits with fixed padding. This stream can also be viewed directly as the proposed work log of the two-event mark computation. It has $O(mk)$ bits including time labels, if supplied.

The claimed work log is genuine exactly when the physical keys are distinct. Therefore any exact finite-field trivalent network testing its validity requires $\Omega(mk^{1+\sigma})$ volume at all sufficiently large $k$, with the exponent for that field. An exact Boolean circuit has the corresponding gate lower bound. This conclusion still holds if the verifier is promised that the proposed **reply array** differs from the real same-slot reply array in at most one **bit**, since every reduced input has that property. No bound is asserted on how many calculated addresses after the first error differ. The authenticating circuit may be arbitrary off the promised trace family. The projection pays $O(mk)$ bit wiring even if a value occurs in both proposed addresses. [Upstream list theorem and exact circuit conversion](checking-the-sat-circuit-bound.md)

One can require that both verdicts have exactly one delivered stored bit. Append two additional mark rows with one reserved key appearing in both, retaining $h$ at the end of the original list for the SAT verdict. If the source is distinct, the last sentinel read is the sole hit. Otherwise the sole hit was earlier. Consequently even deciding whether the one hit occurs in the final two slots still decides distinctness. The base-prediction gap with respect to the all-zero reply list is then identically one.

The direct-address dictionary is elementary. What matters here is that the hard authentication predicate has a scan-time, globally correct SAT realization even when successful forwarding carries one bit in total. In particular, replacing the memory-consistency predicate by its table of *actual* prior-writer identities on the no-hit runs deletes the very check that proves those initializations are legal.
