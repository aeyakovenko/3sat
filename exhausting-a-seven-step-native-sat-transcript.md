# Exhausting seven executed instructions on a four-word SAT catalog

The sixteen-bit sign-plane catalog has 65,536 legal inputs. The native optimum in the journal is between seven and nine executed instructions. This search asks whether a single sensitive satisfiable input prevents **every** program from stopping by step seven. The finite question permits arbitrary program size, an unlimited supply of named registers, all sixteen addressable memory words (including writable inputs), arbitrary four-bit immediates, and indirect loads and stores. Its answer applies to this catalog and this fixed word width. [Previous lower and upper bounds](seven-tests-for-six-native-steps.md) · [Machine and input encoding](exact-clocks-for-two-word-sat-inputs.md)

Write the four memory words as $p,q,m,n$. The SAT verdict equals one precisely when $p\mathbin{\&}m=q\mathbin{\&}n=0$ and $(m,n)\ne(15,15)$. The remaining twelve memory cells and all initial registers contain zero. For example, the words $4,4,8,8$ give a satisfiable input. Changing any one of its four words to 15 gives an unsatisfiable input. Each word is therefore indispensable on the base execution of any globally correct solver: if it halts or overwrites an original word before reading it, changing that word to its pivotal value leaves the execution and verdict unchanged.

## The finite implication and its converse for paths

Unroll one computation path of a deterministic program. Keep its actual loads, stores, arithmetic, and comparisons, in order. Register writes can use fresh names: every later use simply points to the most recent defining instruction. A fixed jump or move contributes no new values or observations, so it can be bypassed for this feasibility test. A newly available register may always have been simulated by retaining its defining value. Given an unsatisfiable comparison input, execute the *same* straight-line instructions, continuing even if a comparison differs from the outcome on the base. This straight-line comparator-output vector is the **transcript**. If its bits agree throughout, determinism forces the globally correct program down precisely the accepting base path, which is impossible. Once any bit differs, all later bits on the straight-line trace are irrelevant.

If some globally correct program accepts the base in at most $d$ steps, then there is a length-$d$ transcript that (i) reads all four original words before their first overwrite on the base and (ii) differs on every input of the opposite verdict. Indeed discard the instructions after the last comparison and pad with constant comparisons if necessary. Truncation preserves discrimination, and each pivotal word must already have been read before the last comparison, by the same indistinguishability argument. Conversely, a separating transcript gives a sound partial acceptor: follow it on an arbitrary file and report acceptance only if all its comparisons match the base. A globally correct program can use arbitrary computation on the other branches. Thus success for one base gives a certificate for that input. A separate search over trees or programs is needed to turn many different base certificates into a common worst-case clock.

Use action letters $L,S,A,B$ for load, store, ALU, and comparison. The final action is $B$. With $d=7$, at least four of the six preceding actions must be $L$, giving
$$
           1+6\cdot3+\binom{6}{4}3^2=154
$$
different shapes. For six steps there are 16 shapes, and for eight steps there are 1,156. Each shape considers every operand and every operation in the earlier machine. The ALU includes AND, OR, XOR, modular addition, subtraction and multiplication, logical and arithmetic shifts with both shift-count conventions, rotations, and comparisons writing a word (including complemented comparisons). The branch can test equality or signed or unsigned order; swapping arguments or interchanging outcomes supplies the complementary tests. Terminal verdicts are free.

When there are exactly four loads and all four base words are at least four, every load on the base must read a different original word. Before the first ALU or store, all registers hold either a high original word or zero, and the latter has the same effect as an immediate. No high word can address one of the four input cells. In that initial region every load can use a literal address, and consecutive such loads can be sorted by address with corresponding renaming of their later register references. The implementation uses this symmetry only for adjacent loads in the initial region and only under the stated hypotheses.

## What the certificates check

For a fixed shape and a finite list of negative files, build a Boolean formula with a single copy of the instruction choices. Simulate their four-bit values separately on the positive base and every negative. An indirect load first selects the original column or zero, then replaces that value for each matching past store in chronological order. The final value therefore uses the newest matching store. The base additionally enforces the first-read-before-overwrite condition. For every negative require disagreement on at least one comparison. The CNF contains only Tseitin definitions of elementary Boolean gates, instruction selection constraints, and these observations. The independent arithmetic interpreter and the generator are in [clocked_native_path.py](clocked_native_path.py).

* On SAT, decode the candidate path, check the entire returned Boolean model against every generated clause, then execute the candidate on all 65,536 four-word inputs in a separate integer interpreter. A previously unseen opposite file that agrees with the base refutes this candidate and is added to the search. Retain a separating path only if **every** opposite file has a different transcript.
* On UNSAT, an independent LRAT checker replays the positive unit-propagation hints until the empty clause is derived. A timeout, a failed replay, or a resource cap yields no elimination. Split an unresolved task on an unused Boolean bit of the program description and pursue both sides. The search checks that the refuted binary leaves partition the whole shape before reporting that shape as excluded. All branch variables arise in the instruction description before any input-specific encoding, so adding examples leaves their identities stable.
* Save every completed solver call, the append-only example list, the remaining split frontier, and a hash of each refuted formula and proof. Each leaf remembers its example-list prefix so the exact formula can be reconstructed. A job can be resumed after termination. A verified file for one shape still leaves every other shape outstanding.

The clocked driver uses one active solver or proof checker at a time. On a known six-step control at base 4488, it independently refuted all sixteen shapes. The arithmetic test compares all 20 opcodes on every ordered pair of four-bit words, and the catalog interpreter compares the 65,536 truth values to a separate scalar calculation. A truth-checked nine-step positive path tests the opposite direction on the whole catalog. For frozen sources one may run:

```sh
OPENBLAS_NUM_THREADS=1 python clocked_native_path_campaign.py --selftest
OPENBLAS_NUM_THREADS=1 python clocked_native_path_campaign.py --state /path/to/research-state --solver /path/to/cadical --seconds 43560 --timeout 12 --max-timeout 45 --proofs
OPENBLAS_NUM_THREADS=1 python clocked_native_path_campaign.py --state /path/to/research-state --solver /path/to/cadical --replay /path/to/research-state/jobs/4488-LLLLBBB.json
```

The raw result for a base and deadline is recorded in a conclusion file. An all-shapes refutation implies a genuine executed-instruction lower bound for the entire program model on the finite catalog. A separating base path can instead rule out a proposed single-input proof at that horizon. Neither outcome establishes growth of the optimal SAT clock with encoded input length.
