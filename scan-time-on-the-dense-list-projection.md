# Tight native time on the dense ASCII inputs that give the SAT circuit lower bound

The dense list projection has a sharp worst-case word-RAM clock of $\Theta(n/\log n)$ on each verdict separately. Here $n$ is the full DIMACS input length in bits and the width is $w=16\lceil\log_2(n+2)/16\rceil$. At each sufficiently large byte-aligned length use the canonical padding of the circuit reduction, hence $n=\Theta(2^k k)$ for list parameter $k$. For the upper bound there is **one globally correct deterministic SAT program**, independent of the length, which attains the clock on every projected file. It also attains this clock after arbitrary permutations of clauses, arbitrary reorderings of literals within clauses, and additional body whitespace. Numeric identifiers are kept fixed in this recognition argument. For the lower bound every correct program, regardless of its workspace, needs $\Omega(n/\log n)$ steps on some projected satisfiable input and on some projected unsatisfiable input at the same length. The two inputs may depend on the program. [Exact dense projection and circuit lower bound](checking-the-sat-circuit-bound.md) · [Canonical encoder](dense_ascii_chunk_circuit_audit.py)

Consequently all these inputs simultaneously admit a scan-time fast path in a genuine SAT decider, although every bounded-fan-in Boolean circuit computing their decision bit has size $\Omega(n(\log n)^\sigma)$ under the pinned list theorem. An argument applying only the required SAT answers on this restriction cannot force any of the three unrestricted RAM time exclusions. This limitation is unconditional for the native fast path. The circuit lower bound is the cited consequence of the external tensor theorem. [List theorem](https://github.com/openai/math/blob/3344da59991ed94f9ba711217b29c1d760badfa6/preprints/The-matrix-multiplication-exponent-is-nine-fourths-November-24-2026/build/obstruction.tex#L40-L79)

## Recognizing the actual input and deciding its satisfiability

Write $N=2^k$, $b=\lceil k/4\rceil$, $U=9\cdot 10^b-1$, and $J=2^b$. The canonical numerical variable bound equals
\[
 V=U+14+4N+8J.
\]
There are four fresh names above $U$ for the pads, guard and passive variable, then $N$ selectors. The eight banks allocate $J+1$ auxiliaries apiece. The row-selection constraint starts with two more names and allocates three per row. This accounts for every fresh name. The bound is strictly increasing with $k$. A fixed program reads the canonical one-line header and finds its possible $k$ by trying successive integers, stopping when the computed bound reaches or passes the declared one. This takes $\operatorname{polylog} n$ steps on the image. A malformed, excessively long or out-of-range header can go immediately to the general fallback. The body can have arbitrary whitespace separating its tokens.

The positive padding name is $p=U+1$. Selector $s_i$ has identifier $U+5+i$ for $0\le i<N$. Let $B_{j,c}$ be the positive identifier whose printed digits are $j$ and then the $b$ binary digits of $c$, with $1\le j\le8$ and $0\le c<J$. The input-dependent part has two clauses for each row and each bank, given by
\[
 (-s_i\lor B_{j,c}\lor p),\qquad (-s_i\lor B_{j,c}\lor -p).
\]
The first of these clauses identifies its row, bank and chunk without using any positions in the file. In the fixed part, bank constraints using a flag have bank auxiliaries, row-selection constraints contain no bank flag, and clauses covering the reserved identifiers contain the guard and passive name. Therefore no public clause has this first signature. Generate a table of all flags and their inverse tags in $O(N)$ operations. In particular the decimal interpretation $D(c)$ of the binary digits satisfies $D(0)=0$ and $D(2v+e)=10D(v)+e$, giving $B_{j,c}=j\,10^b+D(c)$. Here $8J=O(N)$ and even the full interval of $U$ possible reserved identifiers has size $O(N)$, since $(\log_2 10)/4<1$.

Recover the $8N$ chunks using the first signature. Require each row/bank slot to occur exactly once. In each proposed $2k$-bit row, also check that all padded high bits in its eight chunks are zero. Generate the complete expected multiset of clause triples using those chunks. All the fixed clauses can be emitted in $O(N)$ operations with their numerical identifiers. Iterate in bank order through their consecutive auxiliary names, emit the three constant-size clauses per bank transition, then iterate through the row circuit with its three consecutive gate names per row. Expand binary and unit clauses with the public pads and add the $U$ guard clauses. These are exactly the public loops in the encoder. Include both signs of the padding variable in every input-dependent clause. Internally order each triple by its signed numerical identifiers and perform three stable counting-sort passes on these triples on each side, with keys in $[-V,V]$. Compare the arrays including multiplicities. Accept the recognition test only if the arrays and header counts agree. The comparison detects a changed fixed clause, a missing copy, or an inconsistent second occurrence of a recovered chunk.

After a match, SAT is exactly the presence of a duplicate among the $N$ records. Two stable counting-sort passes with radix $N$ carry the two $k$-bit halves of each record. Equality of neighbors decides the query in $O(N)$ native steps. These operations need only a constant number of words per record. If any image check fails, run an ordinary complete SAT algorithm on the original input. Thus the fast path is sound on arbitrary well-formed inputs, including files having many individually plausible pin clauses. Original input words can remain untouched throughout the fast path.

## The physical cost of body parsing

A scalar loop per ASCII digit would spend $\Theta(n)$ steps on the original projection. The following deterministic lookup uses writable space and is built anew by the single fixed program. For sufficiently large $n$ let $a=\lfloor(\log_2 n)/16\rfloor$ bytes. Split the body into consecutive blocks of $a$ bytes plus a possible tail. Scanning a block uses at most two aligned word loads and constant shifts and masks since $8a\le w/2$. Use precomputed tables, for all byte strings of lengths up to $a$, partitioning each block into whitespace runs and fragments of signed decimal tokens. For a numeric fragment store its leading-minus flag, presence of digits, digit count, numerical magnitude, and the power of ten for its digit count. Flag invalid syntax. All fields fit in $O(1)$ words since even $10^a$ is polynomially bounded below $2^w$. Straightforward per-byte generation of all these tables, with descriptors at fixed-width offsets, costs $O(256^a\operatorname{polylog} n)=o(n/\log n)$ time and words. A table need contain only its run descriptors and length, so run iteration ends after the last real descriptor.

Join fragments crossing a block boundary by multiplying the old magnitude by the stored power of ten and adding the fragment. Carry the sign and whether any digits have appeared. For out-of-range magnitudes use saturation at $V+1$ with a constant number of arithmetic limbs so overflow cannot cause acceptance. A whitespace transition flushes a complete nonempty token. Each nonempty token accounts for a constant number of descriptors apart from those introduced by block boundaries, and each boundary adds only a constant number. Therefore reading $s$ tokens costs $O(n/\log n+s)$ native steps. The clocks here include table initialization, input copies if used, and all counting-sort bucket initializations. For small lengths a fixed fallback absorbs the setup. On arbitrary invalid or nonmatching data all attempts are finite and may fall back if a proposed array would exceed the available memory. On genuine files there are $O(N)$ tokens and $O(N)$ work words in addition to the lookup table. Every true row contributes a selector of $\Omega(k)$ encoded bits on a constant fraction of the rows, so $n=\Omega(Nk)$ even after reordering. It follows that $N=O(n/\log n)$, including with longer whitespace padding. The work plus input fits the standard width because it occupies $o(n)$ words for large $n$.

## Why both verdicts require this many steps on the canonical files

Put $W=w/8$ bytes. In each of the eight chunks mark bit positions zero and $W$, counted from the least significant source bit of that chunk. At calibrated lengths $w=k+O(\log k)$. Every bank, including the padded high bank, eventually contains at least $W+1$ real bits, since the last bank has $2k-7b\ge b-6$ real bits. Choose any $k$ real coordinates of the $2k$-bit record that include these sixteen. List all $N$ records supported on those $k$ coordinates in a fixed order, using each once. This all-distinct base is unsatisfiable. For each row and each of the sixteen marked coordinates, replace that one row by its neighbor obtained by flipping that bit. The neighbor is already elsewhere in the list, so every one of the $16N$ changed lists gives a satisfiable formula.

Each individual flip changes just two ASCII digits, one in each copy of its bank flag. All the $32N$ designated digit positions lie in **different native words** for large $k$. Within a single clause the two eligible digits are $W$ bytes apart. Between the flag fields of successive clauses come the decimal pad name and the decimal selector name, each with at least $b$ bytes, in addition to separators. This gap exceeds $W$. The argument also applies across row boundaries because all variable clauses occur before the fixed suffix. Appending the canonical whitespace padding preserves the positions.

On the base any $t<16N$ original-word probes therefore miss both changed words of at least one of the $16N$ alternatives. A store before an original word's first read cannot reveal the edited value. One can view a writable RAM as keeping its writes in its internal state, consulting the original image only for cells without a previous write. This accounts for its genuine executions using at most one original-word probe per native instruction. Determinism makes the entire execution prefix on the surviving affirmative alternative identical. A correct verdict on either file would then be wrong on the other. Both time out at a deadline of $16N-1$ steps. In fact the same argument with a deadline on the number of original probes shows that one affirmative input requires at least $16N$ such probes. Choose the alternative first touched last on the complete base run.

A globally correct SAT decider must probe all **$32N$ designated original words** on the same unsatisfiable base. Change only one of the two copies of a marked digit. This valid input lies outside the canonical image but is satisfiable. Set the shared pad variable to activate the changed clause and satisfy its unchanged mate automatically. At every other row/bank pair the active clause retains its original flag. Set exactly the changed row and its neighbor as selected and turn on the matching flags. The at-least-two and at-most-one circuit constraints hold, the fixed clauses covering reserved identifiers permit a true guard, and the strict padding of public binary and unit clauses works for either value of the pad. This extends to a full satisfying assignment. Thus a skipped designated original word on the base would also skip a single-word affirmative change. This strengthening uses correctness off the projection. In the first $16N$ argument even the affirmative witnesses stay on the projection. The [Lean proof](DenseProjectionBothClocks.lean) verifies the two-verdict common-prefix argument for arbitrary state, reads and internal transitions.
