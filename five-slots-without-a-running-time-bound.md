# Can five stored instructions decide ordinary SAT at any speed?

The existence question remains unsettled in this journal. No five-instruction program here decides arbitrary ordinary DIMACS SAT. The theorem at commit `a1c4285` excludes each clock $O(n^{3/2-\epsilon})$ for $\epsilon>0$ on this instruction set. The five-slot case analysis is a manuscript proof, with Lean files for selected counting and scan lemmas. Its time-space and communication steps use a clock assumption. [Five-slot case analysis](five-instruction-loops-on-dimacs-sat.md) · [Near-three-halves bound](equality-communication-for-five-slot-sat.md)

Five means five **stored** instructions. The program is fixed across lengths and may loop. A LOAD, numerical instruction, STORE and branch are separate instructions. The two fixed verdicts are terminals. A finite sign-selector experiment does have an actual five-instruction solver, with a different input convention and just sixteen possible inputs. [Finite program and exact minimum](static-program-size-on-two-sign-planes.md)

## What can now be excluded without choosing any clock

* **Unshifted compulsory scan.** Let $p$ run through a fixed-stride orbit, read $x=M[p]$, then write $M[x]\gets p$. Suppose the only changing registers are the cursor and loaded word, as in this five-slot allocation. Every update stays on an existing undirected memory edge. With $h$ different initial memory values, at most $h$ edges can disappear. Two consecutive complete passes without a disappearance yield the same machine state at their respective endpoints. Consequently a halting run makes $O(h+1)$ passes. On suitable proper DIMACS formulas this would give a deterministic equality protocol using $O(\log n)$ bits for $\Theta(n/\log^2 n)$ private bits. This excludes the allocation even with no deadline. The state repetition and communication argument are manuscript proofs. [Proof](unshifted-crossed-scan-without-a-clock.md) · [Lean on the actual memory update](UnshiftedFunctionalScan.lean) · [Finite exhaustive check](unshifted_crossed_scan_audit.py)
* **Read-only RAM with one numerical site.** With any fixed number of loads and branches and a single numerical instruction, no program decides SAT at arbitrary speed. The case that can enumerate all input addresses is a cursor incremented by a fixed odd integer. A LOAD into that cursor resets every register into a small set of values on the equality inputs. A repeated post-reset state or a repeated complete-lap state would run forever. This bounds the number of handoffs in the equality protocol. [Opcode and control proof](read-only-ram-with-one-arithmetic-site.md)
* **Read-only fixed scan with a second numerical site for one accumulator.** Across each party's part of a scan, the allowed single opcode induces a map on the incoming accumulator with an $O(w^2)$-bit description. For example, compositions of adds and subtractions remain affine, and shifting a data word by the accumulator has only $O(w)$ possible results after the first operation. Exchanging the maps lets each party test exits on every lap up to state repetition. Placing the equality pins in the order of first visit also covers an arbitrary input-independent unary cursor orbit once the prologue is fixed. The communication again falls short of equality. [Proof and operand conventions](one-accumulator-scan-without-a-clock.md)

## Why the general question survives

The compulsory write $M[x]\gets p+1$ can introduce a new undirected edge. On proper DIMACS files containing a single clause and only three distinct initial memory words, its uninterrupted scan has different memory states for $\Omega(2^w)$ consecutive full passes. The example shows that a bound on the number of passes in terms of $h$ alone fails. A branch may still exit early. [Explicit files and propagation proof](shifted-crossed-scan-on-padded-dimacs.md)

The read-only cases with two numerical sites also include programs which compute an address from earlier loaded data, beyond the public-cursor proof. If any fixed read-only program decided SAT, its constant number of registers could be simulated in $O(\log n)$ space. On a fixed input a total program of this kind has polynomially many possible configurations and cannot repeat one before halting. The same conclusion holds for finitely many fixed writable addresses by recording their contents. This gives a strong consequence for any proposed positive example, but assuming a separation between SAT and deterministic logspace would beg a stronger open question. These examples of outstanding allocations suffice to keep the five-slot question open here.
