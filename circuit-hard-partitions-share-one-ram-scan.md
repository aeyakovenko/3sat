# Circuit-hard partitions share one RAM scan

Let $M=2^w$. An input supplies $M$ record values $x_i$ of $2w$ bits, followed by $M$ positions $p_i$ of $w$ bits, then $M$ inclusive interval queries $[\ell_j,r_j]$ on these positions. The decision asks whether **some** query contains two different rows of equal value. Positions may repeat. A reversed interval is empty. One ordinary proper dense ASCII 3-SAT family of $\Theta(Mw)$ bits realizes this decision. A single globally correct SAT program takes $O(M)$ word instructions on every canonical member, even though exponentially many fixed continuations give semantically different decision functions, each requiring $\Omega(Mw^{1+\sigma})$ bit-network volume.

## Hard continuations at the same physical length

Fix any permutation for the positions. For each depth $d=0,\ldots,\lfloor w/2\rfloor$, use the $t=2^d$ consecutive intervals partitioning the positions into blocks of size $m=2^{w-d}$. Repeat the final query to fill all $M$ slots. Pin the high $2d$ bits of every value to zero. The decision on the remaining independent bits is exactly the complement of $D_{w-d}^{\otimes t}$, the predicate that every one of $t$ lists of $m$ unrestricted records is internally distinct. The upstream volume theorem allows connections across the lists and covers $t\le m$. Its lower bound is $\Omega(t m(w-d)^{1+\sigma})=\Omega(Mw^{1+\sigma})$ uniformly at all those depths. Complementing a Boolean circuit costs one gate. For exact networks over $\mathbb F_2$ one can add a scalar one by a common control choosing a constant-one branch or the original branch, pinning inactive internal variables to zero. This has linear overhead. [Theorem 2.2](https://github.com/openai/math/blob/3344da59991ed94f9ba711217b29c1d760badfa6/preprints/The-matrix-multiplication-exponent-is-nine-fourths-November-24-2026/build/obstruction.tex#L43-L59) · [Pinned replay and bit-circuit conversion](checking-the-sat-circuit-bound.md)

For even $w$ take $d=w/2$. Varying the position suffix realizes every partition of the $M$ row indices into $m=\sqrt M$ unlabeled blocks of size $m$. Distinct partitions give distinct functions even with only the low $2(w-d)=w$ bits free. Choose a pair together in one partition and apart in the other. Give only that pair the same value and give all other indices distinct values. There are enough values for this witness. The number of different functions is
$$
   \frac{M!}{(m!)^m m!}=2^{\Theta(Mw)}.
$$
Each individual function has the displayed volume lower bound. A physical run receives one particular suffix.

## Proper files and a globally correct fast path

Use three separate one-hot selector families for a left row, a right row, and a query. An OR tree and an at-most-one prefix test per family cost $O(M)$ gates. For every $i$, include $\neg A_i\lor\neg B_i$, so the two selected rows differ even when their positions coincide.

Split fields into chunks of $b=\lceil w/4\rceil$ bits, padding at the high end. Allocate eight one-hot flag banks for the common record value and four banks apiece for each of four position words, the left row position, right row position, lower endpoint, and upper endpoint. A selector implies the flags named by the corresponding input chunks. Both row selector families use the same eight record banks. Each bank permits at most one flag. Its selected field forces a flag, making the record values identical. For a position bank recover each binary digit by OR'ing the flags whose index has that digit. Across the constant number of banks this uses $O(b2^b)=O(M)$ gates. Four ordinary word comparisons enforce that both recovered row positions are in the chosen interval. A duplicate pair in an interval supplies the three selectors and extends to a model. Conversely any model gives those distinct rows and that interval.

Write each flag ID as its fixed two-digit bank tag followed by the chunk bits written as decimal digits 0 and 1. The reserved range is $O(10^b)=O(M)$. Number auxiliaries above it. Simplify repeated gate inputs where necessary. Expand each short clause with all signs of fresh padding names to obtain three distinct names per clause. Choose the declared bound $D=2^{w+c}$ for a sufficiently large fixed $c$ and reserve two new high names $g,z$. Fill the identifier range with clauses $(g\lor v\lor z)$ for $1\le v\le D$ other than $g,z$. Setting $g$ true satisfies them all. List the record implications first, then the row-position implications, then the endpoint implications; the remaining clauses are fixed at this width. Only chunk digits vary. Every physical output bit is fixed or a copy of one source bit. Both signs of a short-clause padding variable carry the same chunk name. The $O(M)$ rows and $O(w)$-digit names give the length upper bound, and the record fields themselves occupy $\Omega(Mw)$ bits. [Dense chunk projection and strict-clause padding](checking-the-sat-circuit-bound.md)

Use a standard zero-initialized RAM with a sufficiently large fixed logarithmic word-width coefficient. It can address the $M^2$ possible record keys directly while touching only $O(M)$ cells. Stable counting sort by position costs $O(M)$. In this order keep the last position seen for each key. At coordinate $r$, after processing *all* rows there, store $H[r]$, the largest previous equal-key position seen at any coordinate through $r$, or $-1$ if none exists. Then $[\ell,r]$ contains a duplicate exactly when $H[r]\ge\ell$. In one direction the previous and current positions of the witnessing repeated value both lie between $\ell$ and $r$. In the other, the later occurrence in any witnessing pair has a predecessor at least as late as its partner. This handles tied positions. Each interval costs $O(1)$ after the order is known, even when its endpoints arrive online. Fischer and Lari give a succinct encoding for range distinctness in a fixed order with constant query time. [Fischer and Lari, CPM 2026](https://doi.org/10.4230/LIPIcs.CPM.2026.9)

For a genuine SAT fast path, check the **entire canonical template** before returning the range verdict. The declared power of two gives $w$ at the target lengths. Decode the chunk fields and compare all repeated copies. Check the header counts, every fixed and variable clause, token delimiters and EOF. Public counters, prefix gadgets and bank clauses can be generated in $O(M)$ word steps. For the bit-decoding ORs even direct enumeration of their flag sets costs $O(b2^b)$. Each canonical word-sized decimal token can be generated in $O(1)$ operations after tabulating chunks of $\lceil w/8\rceil$ decimal digits, including shortened leading chunks. The setup costs $10^{\lceil w/8\rceil}\mathrm{poly}(w)=o(M)$. A table for the $2^b$ allowed packed ASCII chunk strings costs $2^b\mathrm{poly}(w)=o(M)$ to initialize. A complete canonical row crosses $O(1)$ RAM words. Use conservative length and address checks before allocations on unrecognized files and a complete SAT fallback on any mismatch. This gives one fixed correct solver. Its online interval answers describe evaluation of the decoded data; its final SAT verdict also authenticates the rest of the file. ## What information actually crosses the boundary

Before the arbitrary positions have arrived, all possible continuations distinguish every equality partition of the $M$ row names. To test whether rows $i,j$ match, put them at positions zero and one and ask only $[0,1]$, repeating it to fill the slots. If a deterministic preprocessor permanently loses access to the record prefix, its retained state must distinguish $\operatorname{Bell}(M)$ partitions. In particular it needs $(1-o(1))M\log_2 M$ bits. For the lower bound count just the partitions into blocks of size $s=2^{\lfloor\log_2 w\rfloor}$, using $M!/((s!)^{M/s}(M/s)!)$. The upper bound $M^M$ suffices for the leading term. Include all information observable after the cut in the state. Ordinary retained input permits rereads, and the explicit fast path fits even with enough memory to retain the prefix.

This rules out adding the separate circuit or possible-writer demands merely because a solver has to support all these continuations. Even charging one $M$-word scan independently at each of $\Theta(w)$ dyadic depths would only reach the physical bit length $\Theta(Mw)$. The dynamic lower bounds used elsewhere concern sequences of actual updates and queries subject to an online information constraint. Here one common summary serves every interval after the order arrives, and each physically supplied order costs just one further scan.
