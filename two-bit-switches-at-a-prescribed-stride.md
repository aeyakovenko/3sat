# Opposite SAT verdicts at Hamming distance two with an optimal checksum stride

For every sufficiently large integer $D$, there are two dense, sorted, duplicate-free proper DIMACS 3-CNFs of equal length **$D+O(\log D)$ bytes** that differ in two physical bits. The two differing bytes are exactly $D$ bytes apart. One file exchanges the ASCII digits `2` and `3` between those two positions, so all byte counts agree. The verdicts are opposite and every variable occurs at most four times. All names and header counts are written minimally. This gives sharp length bounds for a specified family of modular tests.

### Filling an arbitrary distance

Use the [signed-copy selector template](physical-selector-parity-cubes.md) with two data bits $t_0,t_1$ and one common index bit $j$. Four proper clauses require a fresh bit $o$ to equal $t_0$ for $j=0$ and $t_1$ for $j=1$. Force $o$ true with the four sign choices on two fresh variables. Thus the template realizes index lookup. In both files choose $j=1$, and set $(t_0,t_1)$ respectively to $(0,1)$ and $(1,0)$. Each switch uses one clause $(p_i,q_i,a_i)$ or $(p_i,q_i,b_i)$, with adjacent names ending in `2` and `3`. In the original canonical physical order the first two switch rows start at $p_0<p_1$ and $a_0,b_0<p_1$. The index switch has its own distinct position. The original core has a fixed number of variables and clauses independent of $D$.

For $t\ge0$, increase each old numerical identifier $x\ge p_1$ by $30t$. The renaming is strictly order-preserving, keeps both alternatives in the same physical row order and preserves the final switch digits. Use the freed consecutive names $p_1,\ldots,p_1+30t-1$ as $10t$ independent positive three-literal clauses in ascending triples. These variables have degree one and each such clause can be satisfied independently of its signs. They occur between the first and second data selector rows in the sorted serialization. All numerical names through the new maximum occur. Equal-width changes to the two switch digits stay at exactly the same positions in both files.

Write $g(t)$ for the distance between the selected bytes with all new signs positive. The new rows increase the distance by exactly $50t+\sum_{x=p_1}^{p_1+30t-1}d(x)$ over the distance in the renamed old rows alone, where $d(x)$ counts decimal digits. The variable and clause counts in the header translate both positions equally. The fixed old rows have nondecreasing token lengths under this renaming. Between the two switch digits the first row contributes its unchanged suffix, all intervening old rows contribute full records, and the second contributes its prefix through the last digit of the third literal. Hence $g$ is strictly increasing, $g(t)=\Theta(t\log(t+2))$ for large $t$ and $g(t+1)-g(t)=O(\log(t+2))$. For the last estimate, changing the shift by 30 increases the digit count of any old token by at most two, and the number of those tokens is fixed.

Changing precisely $s$ signs in the inserted rows yields distance $g(t)+s$ for every $0\le s\le30t$. This holds for either switch setting. For large $t$ the intervals reach the next minimum, so every sufficiently large prescribed distance $D$ occurs. Build the common signed added rows using the largest $t$ with $g(t)\le D$. Outside the interval there are only the fixed collection of renamed old tokens and the header, occupying $O(\log(D+2))$ bytes. The construction can emit the two actual files. Padding beyond either end is unnecessary for the prescribed-stride theorem.

### Ordinary modular checksums

Let $B\ge3$, $L=\operatorname{lcm}(1,\ldots,B)$, $L_o$ its odd part, and $E_B=\operatorname{ord}_{L_o}(256)$. Associate to a file its big-endian integer prefixed by a leading one bit. For every sufficiently large $B$ there is an opposite pair as above with stride **exactly $E_B$** whose integers have equal remainders modulo *every* $m\le B$. Its total length is $E_B+O(\log E_B)$ bytes.

Indeed, for exchanged digits `2` and `3` followed by $h$ common bytes after the second edit, the integer difference up to sign is $256^h(256^D-1)$. The equal-length leading tags cancel. Taking $D=E_B$ deals with the odd part of $L$. Append disjoint positive triples on fresh consecutive identifiers past the current maximum until at least $\lceil\log_2 B\rceil$ common bytes follow the second edit. The added rows come after the old body and any header-size movement shifts both edit positions together. The first adequate padding uses $O(\log B+\log(D+2))$ additional bytes, since the final added clause has $O(\log(D+\log B+2))$ digits. This handles the entire power of two in $L$.

To bound the chosen stride from below, if $3^e\le B<3^{e+1}$ then $E_B\ge3^{e-1}>B/9$. In fact $256=1+255$ has $v_3(256-1)=1$. For $x\equiv1\pmod3$, the factor $x^2+x+1$ has 3-adic valuation one. Raising $x$ to a power prime to three leaves the valuation of $x-1$ unchanged by the geometric sum. This proves $\operatorname{ord}_{3^e}(256)=3^{e-1}$. In particular the requested stride eventually passes the fixed construction threshold, and $\log B=O(\log E_B)$. Finite small $B$ can use a sufficiently large multiple of the order.

There is also a converse for *any byte strings*. Two different strings at bit Hamming distance two with identical byte histograms must exchange two different bytes, each changed in just one bit. The numerical byte difference is a signed power of two. Modulo $L_o$ the file difference is therefore a unit times $256^D-1$. Checksum agreement for all $m\le B$ forces $E_B\mid D$. Thus the smallest possible stride cannot be improved by picking different CNF gadgets or different byte values. The minimum common length among these opposite-verdict canonical witnesses lies between $E_B+1$ and $E_B+O(\log E_B)$ bytes.

### All rolling bases and digit maps

At each byte $x$ a rolling checksum can update $z\gets uz+\phi(x)\pmod m$, for any fixed base $u$, byte map $\phi$ and common initialization. Write
$$
 \Lambda_B=\operatorname{lcm}_{2\le m\le B}\exp((\mathbb Z/m\mathbb Z)^\times).
$$
Use the same construction with stride $D=\Lambda_B$ and at least $h=\lceil\log_2 B\rceil$ common trailing bytes. It gives length $\Lambda_B+O(\log\Lambda_B)$ and collides for **all** such recurrences with $m\le B$ simultaneously. The difference has factor $u^h(u^D-1)$ for every digit map. For each $p^e\mid m$, either $p\mid u$ and $e\le h$, or $u$ is a unit modulo $p^e$ whose order divides $D$. This includes bases zero and one. A common initialization cancels at equal lengths. Conversely for each unit $u$ modulo $m$ take a digit map whose values differ by one on the exchanged bytes. Agreement forces $u^D=1\bmod m$. Thus $\Lambda_B$ is the optimal stride for simultaneous agreement with every base and digit map, and is attained on canonical opposite SAT verdicts for sufficiently large $B$. It is at least $E_B$ since $L_o$ is the lcm of its odd prime-power factors, each at most $B$. Both strides are at most $\operatorname{lcm}(1,\ldots,B)$ by the order bound modulo each prime power and Lagrange's theorem. The two-bit restriction can require much larger lengths than a construction permitting many changed bits. [Many-switch rank bound](checksum-collisions-on-actual-sat.md)

The [reproducible audit](switch_index_checksum_audit.py) constructs, parses and solves the literal files, counts occurrences, compares their entire byte sequences and histograms, and checks the residues. Its ordinary $B=48$ pair has 89,692 bytes with the differing bytes at zero-based offsets 487 and 80,182. The common tagged integer residue modulo $\operatorname{lcm}(1,\ldots,48)$ is 207140920066985194544. Its all-base $B=32$ pair has 65,186 bytes and the differing bytes are at offsets 480 and 55,920. On both finite examples there are also enough common bytes *before* the first edit to obtain the same obstruction when the byte order is reversed. The optimal-stride and size conclusions are manuscript arguments. SAT is easy on these particular pairs once one knows either differing address and the orientation of its verdict.

To emit the 89,692-byte files, run the following in the repository with `pycosat` installed. Both files omit the final body newline. The audit prints their SHA-256 digests.

```sh
python3 switch_index_checksum_audit.py --write-pair /tmp/3sat-checksum-example
```

The generated files are `b48-yes.cnf` and `b48-no.cnf`.
