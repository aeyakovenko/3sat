# Reading the set of distinct DIMACS clauses in one packed scan

**Theorem.** From a well-formed, comment-free ASCII DIMACS file with exactly three literals per clause and \(n\) encoded bits, a fixed deterministic logarithmic-word RAM can output a sorted set of distinct clauses with dense word-sized variable indices in \(O(1+n/\log(n+2))\) native steps and workspace words. The output is equivalent to the input up to variable renaming and removal of duplicate clauses. A mapping from each dense index to an occurrence of its original digit string can be retained at the same cost. Decimal identifiers and intervening whitespace can be arbitrarily long. The input may contain \(\Theta(n)\) clauses. The algorithm counts their original multiplicities for the header while materializing only \(O(1+n/\log(n+2))\) representative occurrences. In this statement sorting clauses uses the dense internal indices, with no requirement to preserve the order of the decimal numbers.

Let \(B=1+\lceil n/\log_2(n+2)\rceil\). Use blocks of \(b=\max(1,\lfloor\log_2(n+2)/32\rfloor)\) bytes. There are \(O(B)\) blocks, each obtained by at most a constant number of native word loads, shifts and masks. The last block may have a public short length. Add a final whitespace sentinel for recognizing a last token ending at EOF. The header, which may contain a long variable bound, can be scanned first using the same digit and whitespace block summaries as the body. Its size is charged to the total input length.

## Retain spanning records and one copy per block type

After the header, recognize a record boundary just after the first whitespace byte ending every fourth token. The input has constant clause width, so this needs only the number of completed tokens modulo four and a bit distinguishing the inside of a token from whitespace. A record extends from the previous boundary through this one, which assigns leading whitespace to the following clause. Whitespace after the last complete clause can be discarded. The degree-three grammar itself can be checked by the usual finite digit/sign/separator states together with the header checks below. For each possible block, entry state, and actual length precompute its exit state, the count of boundaries, the offsets of the first and last ones, and information to enumerate the boundaries when specifically requested. Including every offset and every short last-block length costs \(O(2^{8b}\operatorname{polylog}n)=O(B)\) time and words. Small lengths can use a direct scan.

A clause crossing a boundary between blocks is recorded by its original start and end offsets. There are at most as many crossing records as block boundaries. A scan retaining the start offset of the pending record emits it when its end occurs in a later block, using that block's first boundary offset. The last boundary in the block supplies the new pending start. Counts of boundaries give the exact number of clauses, including duplicates. A block without a boundary only advances the finite state and carries the pending start forward.

For records wholly inside a block, enumerate them only at the first occurrence of its type. A type consists of the packed bytes, their length, the incoming state, and one bit telling whether a record already started strictly before the block. Given the type, these internal records have literally the same bytes at every occurrence. If a record began earlier, the initial partial record ending at the first boundary is omitted from this enumeration; the crossing rule emits it separately. Accordingly every actual clause has an exact representative. The total raw length of the internal representatives is at most \(O(b 2^{8b}\operatorname{polylog}n)=O(B)\) bytes, and the total raw length of crossing records is at most the original input length plus the sentinel. There are \(O(B)\) retained records altogether. This charges no separate step per occurrence of a repeated short clause contained inside a block.

## Intern all decimal identifiers exactly

Scan each retained record for its three signed identifiers and zero terminator, using a table that skips a run of digits or whitespace to the next block boundary in one step. Remove any leading zero digits and separate the sign. The total work is \(O(B)\) because the sum of record lengths is \(O(n)\) bits and the number of retained records is \(O(B)\). For the same reason the retained identifiers, each divided into fixed-size chunks of \(b\) normalized digits with the length recorded for its final chunk, yield \(O(B)\) chunks.

For each identifier of \(j\) chunks, pad it to the next power of two with a distinguished symbol. Form a complete binary tree with the chunks as leaves. Its size is \(O(j)\), and all trees together have \(O(B)\) nodes. Give equal chunk codes equal dense labels by a word radix sort or a count table of \(O(2^{8b}\operatorname{polylog} n)\) entries. At height \(h\ge1\), radix-sort the ordered pairs of child labels and number the distinct pairs consecutively. The counting-sort array ranges at this height are bounded by the number of nodes at height \(h-1\), plus a constant. Summing these bounds over the heights gives \(O(B)\) including initialization. Height and root label together form an exact identity for a normalized decimal name. Number the different root identities densely with one further radix sort. Original representatives can be referenced by their digit offsets. To verify a declared variable bound, compare normalized digit lengths and lexicographic chunks on length ties, charging the tie comparison to the length of that occurrence. The clause-count field can be compared with the counted number of boundaries, including when the header uses leading zeros.

Finally sort the three signed indices in each clause, radix-sort the \(O(B)\) triples, and keep one copy of each. Dense components lie in an \(O(B)\) range. The resulting ordinary RAM computation has the claimed word cost. It also works for any *fixed* arity in place of three, with that arity in the lexical state and the last sort. The construction uses small-input tabulation in the style of the Four Russians method. Priority for the combined parser and duplicate elimination has not been established. [Arlazarov, Dinitz, Kronrod and Faradžev, *On economical construction of the transitive closure of an oriented graph*](https://www.mathnet.ru/eng/dan35675)

This yields an additional transformation for the [dense list projection](signed-renamings-of-the-dense-list-projection.md). Its original proper triples are pairwise distinct after clause and literal reordering. Arbitrarily duplicating each original clause one or more times therefore gives the same sorted dense clause set after this scan, independent of whitespace, identifier lengths, consistent polarity flips and order. The scan-time solver for the projection extends throughout that larger family. The theorem also applies to files outside this family but there it returns an equivalent formula to solve.

The [finite audit](packed_dimacs_normalization_audit.py) verifies equality of original and retained clause sets, exact clause counts, and equality of digit strings against their tree labels. It checks 900 combinations of sparse names, whitespace and block sizes, and five highly repeated short-clause inputs. It uses Python maps for the checks; the deterministic native running time comes from the tabulation and radix bounds above.
