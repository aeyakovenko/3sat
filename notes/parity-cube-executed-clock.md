# The native RAM clock at every corner of a proper SAT parity cube

Take two fixed proper 3-CNFs with opposite verdicts and the [physical selector construction](physical-selector-parity-cubes.md) on $r$ independent bits. All corners are dense sorted proper 3-CNFs of maximum variable occurrence four. Their verdicts alternate with the parity of the $r$ selected bits. At standard word width, every RAM program correct on the cube executes at least $r+\lceil r/2\rceil$ instructions on **each of its $2^r$ corners**. With the sources fixed, $r=\Theta(N/\log N)$ where $N$ is the physical bit length. There is a single choice of $r'=r-o(r)$ coordinates whose subcube has exact optimal clock $3r'/2$ at every padded length of the construction. The program attaining the optimum on the promise can be specialized to its layout at each length.

## Exposure of original inputs on a real run

At one corner let $a_1,\ldots,a_r$ be the distinct physical word addresses of the changed bits. Every marked word is full: the filler rows give at least one full word of following bytes even at the last selector. Its high byte is nonzero ASCII of value at least ten. The file occupies $\lceil N/w\rceil=o(2^w)$ low word addresses, so neither value at a marked site can be any marked address at all sufficiently large lengths. Use the separate-operation ISA with at most two explicit operands including the address and payload of a STORE, one operand for the address of a LOAD, separate branches, and constant terminal verdicts.

Fix a terminating correct run at this corner. For each marked site there must be some LOAD of its original word whose output definition is later consumed as an explicit operand before redefinition. Indeed, run the program on the single-bit neighbor. Until the first use of a differing register, both executions choose the same instructions, the same addresses, and the same payloads on every STORE. The only memory difference can be the original cell, until a write erases it. Every differing register then holds a value directly loaded from the original site. If the first differing-register use never occurs, the terminal verdict is the same on opposite corners. A register-payload STORE that copies a raw word already qualifies as a use. Re-reading a later copy cannot avoid that earlier charge. These facts permit arbitrary loops, indirect reads and writes.

Choose one such LOAD per site on the actual run, and one operand use of its surviving definition. The selected LOADs are distinct. An operand position uses just one live definition. No selected LOAD consumes a selected definition, because its address is marked whereas the numerical value of every selected definition exceeds every marked address. Thus the $T-r$ other instructions of a run of length $T$ provide at most $2(T-r)$ positions for $r$ uses, giving $T\ge r+\lceil r/2\rceil$. The argument holds whenever the one-site neighbors all reverse the answer at the chosen center. Parity supplies that property simultaneously at every corner. The earlier [homogeneous-word argument](executed-operands-on-homogeneous-sat-words.md) uses related instruction accounting for a different verdict function.

## A sharper cost for a fixed program

Let $d$ be the number of distinct addresses named by **direct LOAD instructions** of this program at this width. Let $s$ be the number of marked addresses initially present as numerical data in any register or memory cell. On the canonical files $s\le4$ for large $N$: all full original words exceed the physical address range, leaving at most zero, the partially filled final word, the length and the width. A fixed compare or STORE address literal has no effect on $s$.

At least $r-d-s$ marked addresses have to be produced as new data before their first required indirect LOAD. The first production of a new numerical value among all registers and memory cells can occur only at an ALU, including a move-immediate, or at a STORE with an immediate payload. A LOAD or register-payload STORE only copies an existing datum. Branches and address literals supply no new numerical data as a side effect. Distinct missing addresses require distinct production events. These events are disjoint from the $r$ selected LOADs and all are nonbranch instructions. Hence if $U$ nonbranch instructions execute,
$$
                   2r\le U+d+s .
$$
In particular meeting the above lower clock requires at least $\lfloor r/2\rfloor-s$ different literal addresses at LOAD sites in the code. The number of arbitrary-size literals used only in comparisons or address arithmetic does not relax this requirement. With at most $C$ stored instructions a halting branch-free segment has length at most $C$, as a repeated PC would continue with fixed successors forever. Thus $U\le C(T-U+1)$ and $T\ge (1+1/C)(2r-d-s)-1$. This refines the initial address-stock count on these and the earlier [one-byte centers](one-byte-successors-for-dense-sat-exhaustion.md) by charging only literal LOAD addresses without a production event.

## Pairing the same coordinates through consecutive byte lengths

At one length classify sites by the ordered pair of raw words at settings 0 and 1. For two sites of the same type a comparison for equality between their two loaded words gives the XOR of their two bits after complementing the Boolean answer. Where a type has odd size, leave one singleton and compare it with its zero-setting literal. An unrolled program carries the running parity in which of two instruction locations it enters. For each possible current parity, two direct LOADs and one branch handle a pair; one direct LOAD and one branch handle a singleton. Branches go directly to the appropriate next block and the final branch to a terminal. This uses $O(r)$ stored instructions. With $k$ singletons it runs in exactly $(3r+k)/2$ instructions on every corner. Freezing those $k$ bits to zero leaves $r'=r-k$ bits with lower and upper clocks both equal to $3r'/2$.

In fact the same pairing works throughout the entire construction interval $[K\lceil S/8\rceil,(K+1)\lceil S/8\rceil]$ of byte lengths. Work at coefficient one. Let $W_*$ be its largest word width in bytes. There are at most two possible byte widths for large $S$, because the logarithm of the length varies by less than one bit in the interval and the width is rounded in blocks of sixteen bits. Their values are $O(\log S)$, so their least common multiple is $O(\log^2 S)$. Record each site's offset in the fixed unpadded body modulo this multiple. Also record the literal $2W_*-1$ body bytes centered at its edited byte in the zero corner. Discard the sites without such a window wholly inside the fixed body. There are at most $O(1)$ of them since sites are spaced at least one full word apart even for the largest width. The sorted padding appends fresh rows after the entire body; only the header shift moves existing sites.

Two sites with the same records have identical ordered raw-word pairs at *every* padded length. Their offsets within words agree after the common header shift, and the recorded windows contain the whole selected word at every possible phase and width. There are only 13 body byte values (ten digits, minus, space, newline). Hence the number of records is at most
$$
 O(\log^2 S)13^{2W_*-1}=S^{\log_2(13)/4+o(1)}.
$$
The exponent is approximately $0.92511<1$. Pair by this common record and freeze at most one site per class plus the discarded boundary sites. This proves the advertised exact $3r'/2$ clock on the same subcube at each length when $r=\Theta(S/\log S)$. On the full cubes the upper and lower differ by $O(S^{\log_2(13)/4+o(1)})$ instructions. Width coefficients larger than one still obey the exposure bound if the filler was chosen for them, but the common-record counting estimate need not be sublinear at those widths.

The actual selector text gives a smaller count. Immediately before an edited byte there are $W_*-1$ decimal digits of its name for large $S$, since that name is at least $L=\Theta(S/\log S)$ and its decimal digit length divided by $\log_2 S$ tends to $1/\log_2 10>1/8$. Immediately after the edited byte are the fixed bytes for a space, the zero terminator and a newline. The first literal of the next row has an optional minus followed by the digits of a name at least $p_i\ge L$ by the sorting order. A next row exists because each selector has later filler rows. Therefore every remaining byte in the right half of the window is a decimal digit except for that optional sign. The two halves together give $O(10^{2W_*})$ possible records up to the offset factor. The exponent improves to $\log_2(10)/4\simeq0.83048$.

**Every large byte length and each dimension up to a positive word density.** There is a constant $\gamma>0$ such that at every sufficiently large physical bit length $N$ divisible by eight, and for *every* $1\le m\le\gamma N/\log N$, one can choose a degree-four canonical $m$-cube with exact optimal clock $m+\lceil m/2\rceil$ on every corner. To see this fix the two sources of opposite verdict once. For initial arity $r$, $S_r=n+r\lceil\log_2(2+n+r)\rceil$ increases to infinity and $S_{r+1}/S_r\to1$, including when the ceiling changes. Hence successive byte intervals $[K\lceil S_r/8\rceil,(K+1)\lceil S_r/8\rceil]$ overlap for large $r$. In any interval containing $N/8$, the above common pairs supply $r-o(r)=\Theta(N/\log N)$ coordinates. List pairs consecutively, retain the first $m$ coordinates and freeze all others to zero. On the restricted cube there are $\lfloor m/2\rfloor$ complete pairs and at most one singleton. The resulting cubes are nested for different $m$, and corresponding logical sites work simultaneously at every padded length of this interval. The optimum is for a program allowed to specialize to this particular promise and physical length.

For the original unrestricted RAM time question both $3r'/2$ and the fixed-code lower bound are linear in the number of marked *words*. The promise admits these specialized parity programs. Even so, supplying a short program by hiding numerical addresses in unrelated literals cannot realize the nonuniform optimum.
