# Three table reads in a SAT file carry the formal matrix multiplication exponent

There is a subcube of well-formed, dense ASCII DIMACS files on which deciding SAT amounts to reading three specified table bits. Each satisfiable file has exactly one model. The formal multilinear extension of the verdict on the same subcube has arithmetic size exponent exactly $\omega_F$ over each fixed field $F$, measured in matrix side length $d$. The file length is $\Theta(d^2)$ bits. In particular the arithmetic exponent in encoded length is $\omega_F/2$, or $9/8$ using the November 24 preprint. Here exponent means the infimum for polynomial size bounds for the family. The Boolean circuit size on this subcube is $\Theta(d^2)$, and one globally correct SAT RAM takes $O(N)$ steps on every file in it. [Upstream fieldwise exponent theorem](https://github.com/openai/math/blob/3344da59991ed94f9ba711217b29c1d760badfa6/lean/OAI/LinearAlgebra/SpectralBooks/ExactExponent.lean)

## Decision on the actual bits

Let $d=2^s$, $s\ge1$. The independent input bits are three binary $d$-square tables $A,B,Z$ and three $s$-bit indices $i,k,j$. The verdict is the single bit

$$A_{ik}\ \land\ B_{kj}\ \land\ Z_{ji}.$$

Given a promised file, first read its $3s$ selector bits, then query the three named physical table positions. Three table probes are necessary in the worst case even when the selectors are supplied for free: on an all-one selected triple, changing any one selected bit reverses the verdict. This argument applies only to table probes. The ordinary bounded-fan-in Boolean circuit upper bound is three multiplexer trees and two AND gates. Each of the $3d^2$ data bits is relevant, giving a matching lower bound by binary fan-in.

## An independent physical bit for every parameter

Use three copies of the chunk construction from the binary matrix mismatch encoding. In each table the row is the full first selector and the column is the second selector. Split a row into chunks of $b$ consecutive bits, where $b$ is a power of two between $s/16$ and $s/8$ for large $s$. Write the column as the high chunk number and a low offset. Generate one-hot flags for the row, chunk number and low offset by deterministic equivalences. In a separate library per table, define a wire $S_m$ for every $b$-bit mask $m$. For each possible low offset $h$, the flag for $h$ forces $S_m=m[h]$, even when the data never select that mask. For every physical chunk in row $u$ and high column $g$ emit the proper clause

$$\neg[\mathrm{row}=u]\ \lor\ \neg[\mathrm{high}=g]\ \lor\ S_m.$$

Exactly one of these clauses per table requires its $S_m$ to be one. All flags and mask wires are fixed by the selectors. Fix each *input selector bit* using a pair of complementary variables with consecutive decimal names ending in 2 and 3. A single padded positive unit picks one member by its final identifier digit. All later uses refer to the unchanged variable for the selector bit. Thus the changing ASCII character for each selector appears once. Force three fresh false anchors by the seven clauses excluding all other settings, pad short clauses with distinct false anchors, and fix all unused declared identifiers. The three data clauses use flags on different selector banks. At small dimensions simplify constant flags and pad resulting short clauses. All declared bits then have unique values before enforcing the three selected entries. [One-bit selector pins](one-bit-pins-for-dynamic-disjointness.md)

Give each mask wire a name consisting of the library's fixed decimal prefix followed by exactly $b$ digits, all 0 or 1, equal to its mask. Preset library definitions are independent of the table bits. Each chunk's varying name appears once in the data region. Hence changing any one matrix bit flips exactly the low ASCII bit of exactly one digit. The selector pin bank and all gates have disjoint names outside the reserved library ranges. There are $3d^2/b$ data clauses, $O(b2^b)$ library definitions, $O(d)$ decoder nodes and $O(10^b+d+s)$ identifiers including fillers, up to the fixed number of banks. Each full record has $O(s)$ bytes. The bit length is $O(d^2)$ and the varying positions alone give the matching lower bound. Every vertex of this physical subcube is a valid 3-SAT instance. All remaining DIMACS bits are constants. Consequently restricting the canonical multilinear extension of any total Boolean SAT predicate agreeing on well-formed files gives exactly the canonical extension of this subcube's verdict. [Compact physical encoding and DIMACS size accounting](compact-bit-projection-of-matrix-mismatch.md)

A globally correct solver can check this entire layout before returning the three-read verdict, with a complete SAT algorithm on the other files. For example include a fixed-for-dimension DIMACS comment giving $s$ in unary; cap it using the input length before computing sizes. Generate the public layout, compare every fixed byte and each allowed variable digit, and collect the selector and table data. Prefix and ordinal names can be tabulated in time linear in their emitted digits, as in the compact construction. The running time on this family is $O(N)$. The lookup count of three uses the promise and omits layout validation.

## The normalized verdict

Give a physical input bit with mean $x$ weights $(1-x,x)$. The sum of the Boolean verdict times the product of these weights over the entire subcube is its unique multilinear extension. Use means $X_{ik},Y_{kj},D_{ji}$ for the data bits. Independent selector bits induce probabilities $p_i,q_k,h_j$ on their three respective indices (formal polynomial weights over a general field). Conditional on these indices, all irrelevant bits sum to one. The three relevant bits belong to distinct tables. The resulting formal polynomial is

$$V_d=\sum_{i,k,j}p_iq_kh_j X_{ik}Y_{kj}D_{ji}.$$

For the upper bound, generate the dyadic prefix products for the three index distributions with $O(d)$ arithmetic gates. Scale the entries of $X$ by $p_iq_k$ and those of $Y$ by $h_j$. Multiply the resulting two matrices and contract their entries against $D$. This costs one $d$-square multiplication and $O(d^2)$ other arithmetic gates.

For the reverse direction choose a scalar $\theta$ different from zero and one. Give every selector bit mean $\theta$. Each index then has nonzero mass, since it is a product of factors $\theta$ and $1-\theta$. Replace the means of the first two tables respectively by $X_{ik}/(p_iq_k)$ and $Y_{kj}/h_j$. All denominators are fixed nonzero constants. This specializes $V_d$ to the trilinear form $\sum_{i,k,j}X_{ik}Y_{kj}D_{ji}$. Reverse differentiation in the $D$ inputs returns all of $XY$ at constant-factor arithmetic cost. Over $\mathbb F_2$ carry out the specialization in $\mathbb F_4$. A circuit over the extension with formal inputs over the base field can be simulated by a pair of base-field coordinates at each gate, at constant-factor cost. The coefficient of the basis element one in the output gives the desired base-field polynomial. All other fields already have a possible $\theta$. [Baur and Strassen, *The complexity of partial derivatives*](https://doi.org/10.1016/0304-3975(83)90110-X)

Together the finite-size inequalities are $S_F(V_d)\le T_F(d)+O(d^2)$ and $T_F(d)=O(S_F(V_d)+d^2)$ for division-free arithmetic size and matrix-product size. Binary fan-in gives $S_F(V_d)=\Omega(d^2)$ because every table variable matters already on the Boolean cube. Padding matrix side lengths to a power of two preserves exponents. These arguments prove exponent equality independently of its numerical value. They need only a specialization of the original normalized verdict. No higher derivative of a vector of output bits is required.

Three is also the minimum table-probe budget for a direct trilinear specialization of this kind. Fix the selectors in any depth-two adaptive deterministic bit-query algorithm on the data. Its accepted leaves are subcubes with at most two tested data variables, so their multilinear indicators have data degree at most two. Averaging over the selectors with data-independent weights preserves this bound, as do affine substitutions for table means. The trilinear form has data degree three. This scope allows adaptivity and arbitrary selector-dependent choice of data addresses; nonlinear substitutions and data-dependent selector weights are separate possibilities.

There is a small arithmetic representative on all Boolean inputs: use ordinary multilinear interpolation inside each of the three table lookups, and multiply the results. The circuit has $O(d^2)$ gates. Each table variable already has individual degree one. Each of the $3s$ selector variables has individual degree at most two, since its index occurs in two lookups. Reducing those selector powers by $x^2=x$ gives exactly $V_d$. Thus even multilinearizing just these logarithmically many variables can incur the full matrix multiplication exponent. [Read-once program-size tradeoff for the same Boolean function](three-table-probes-and-read-once-program-size.md)

## An actual unsatisfiable file whose three-bit repairs are matrix multiplication

A second physical encoding dispenses with auxiliary input selectors. Only $3d^2$ table data bits vary. Its satisfiable files are **exactly** the $d^3$ triples of one-bits at $(A_{ik},B_{kj},Z_{ji})$, with all other table bits zero. Each has a unique model. The blank member of the subcube is a genuine unsatisfiable file. Its minimum distance to a satisfying member is three physical bit edits. The degree-three homogeneous part of the canonical verdict at that very vertex is

$$\sum_{i,k,j} X_{ik}Y_{kj}D_{ji}.$$

To construct the layout, pin the $3d^2$ data variables with the one-bit positive-unit construction. For each table use deterministic OR trees to compute each row and column nonemptiness flag. Require exactly one true row flag and one true column flag, using a linear-size scan of each flag vector tracking whether any or at least two have appeared. A binary table meeting both tests has exactly one set entry. Require equality of the column flags of $A$ and the row flags of $B$, of the column flags of $B$ and the row flags of $Z$, and of the column flags of $Z$ and the row flags of $A$. Tseitin equivalences for all gates and the final positive verdict pin give a unique completion when the checks pass. Use the same false anchors, filler pins and distinct-name padding. Here the simpler per-bit pin layout uses $\Theta(d^2\log(d+1))$ bits. Directly validating the layout and checking the three singleton coordinates takes $O(N)$ time for a globally correct SAT solver on these files, on both verdicts.

In the normalized contraction each accepting triple contributes its three means times $(1-x)$ for every other table position. Scaling all data means by a marker $u$ and extracting $[u^3]$ keeps precisely the displayed sum, in every characteristic, without division or an extension field. All coefficients of lower order vanish. Conversely, for each position $e$ the weight of its being the sole set entry of its table is $x_e\prod_{e'\ne e}(1-x_{e'})$. All these weights can be computed in $O(d^2)$ operations using prefix and suffix products, even when some factor is zero. The full normalized verdict is one trilinear matrix contraction on the three resulting arrays. Hence the full extension and its first nonzero homogeneous component both have exponent $\omega_F$ in $d$. The hole at radius two and all three-edit repairs are statements about ordinary files *inside the specified physical subcube*. Other edits to arbitrary DIMACS syntax are outside this repair experiment.

Enlarging the tables from $d$ to $d+1$ embeds every existing solution by adding zero rows and columns. The new triples are those using the new index at least once. Exactly $3d^2+3d+1$ new degree-three monomials appear, with coefficient one in every characteristic. This gives an explicit algebraic successor for a combinatorial exhaustion. The minimum repair distance stays three and the same solver still handles every file in linear time. It is therefore possible for the entire matrix multiplication polynomial, with the correct successor at every size, to survive an induction on genuine SAT edits while the actual RAM time on the induction family stays linear.

## Freeing the selectors gives actual triangle detection

In the compact first template, remove the three groups of selector pins and let the formula choose the binary indices. Keep one free variable per index bit and all deterministic decoder definitions. For fixed table entries, the number of models is now exactly the number of tripartite triangles in the supplied adjacency tables. All $3d^2$ table bits still have independent, single ASCII positions in a file of $N=\Theta(d^2)$ bits. Triangle detection on three dense Boolean tables thus reduces to SAT with linear encoded length and construction time. An unrestricted linear-time SAT algorithm would give deterministic triangle detection in $O(d^2)$ native steps on this representation.

The low-degree obstruction occurs on these same files. At zero data, the degree-three part of the normalized **existence verdict** is the matrix multiplication trilinear form. No graph with fewer than three edges contains a triangle. On three edges, each accepting support has exactly one triangle, so its cubic coefficient is one over every field. If instead we normalize the **number of models**, its full polynomial is exactly this trilinear form: sum separately over the three edges of each triangle. On denser data the number of triangles and their existence can differ in the ground field.

Nevertheless a single globally correct solver takes $O(N)$ time on every file in this subcube within $\lfloor d^{4/3}\rfloor$ data-bit flips of the genuine all-zero file. Validate the complete compact template and extract the $m$ present edges in $O(d^2)$ steps. Orient each edge from lower to higher in the total order (degree, vertex identifier). Every vertex has outdegree at most $\sqrt{2m}$: this follows directly from its own degree if small, and otherwise from the number of vertices of at least that degree. For each pair of outgoing neighbors test whether their connecting edge exists using the explicit table. Each triangle is counted once, at its smallest vertex. The work after extraction is $O(m+m^{3/2})$, within $O(d^2)$ at the stated radius. Use any complete procedure if layout validation fails. This sparsity bound for triangle listing is classical. [Chiba and Nishizeki](https://doi.org/10.1137/0214017)

There is also a linear-time Boolean function on the entire table cube that agrees with the SAT verdict throughout that ball. Use the same algorithm up to this edge budget and return zero on larger edge counts. Its normalized polynomial consequently has **all** the same coefficients through degree $\lfloor d^{4/3}\rfloor$: the coefficient at a set of positions is the alternating sum of the Boolean values on its subsets. Thus exhaustively recovering coefficients even through order $\Theta(N^{2/3})$ around this genuine file cannot by itself distinguish the unrestricted triangle-existence predicate from a function with a linear-time algorithm. This argument concerns the editable table coordinates. Arbitrary syntax edits and lower bounds for dense triangle detection on RAMs are separate questions.

### Exact exhaustion on the blank run and a matching packed-word clock

| Table side $d$ | Three-bit triangle repairs | Least number of data bits that hits every repair | Number of minimum coordinate sets |
| ---: | ---: | ---: | ---: |
| 1 | 1 | 1 | 3 |
| 2 | 8 | 4 | 9 |
| 3 | 27 | 9 | 21 |
| General $d\ge1$ | $d^3$ | $d^2$ | $3\cdot2^d-3$ |

On the genuine all-zero file, any deterministic solver must inspect a set of data positions meeting each of the $d^3$ possible triangle triples. For an untouched triple the three-edit satisfying input gives exactly the same instructions and replies through the blank rejection. With the fixed template given, the minimum size of a blank certificate in the bit-probe model is exactly $d^2$. Each position meets $d$ triples and one whole table meets all triples. Equivalently the triples $j=i+k\bmod d$ form a packing of $d^2$ pairwise edge-disjoint three-edit witnesses. The packing works for every integer $d$, including the one-by-one seed. For a non-power-of-two side the compact encoding can reserve the next power of two and freeze padded row and column data to zero.

In graph terms, the minimum is the number of edges deleted from the complete balanced tripartite graph to make it triangle-free. The edge extremum is a special case of the multipartite Turán theorem of Bollobás, Erdős and Straus. [Original 1974 paper](https://users.renyi.hu/~p_erdos/1974-05.pdf)

All minimum certificates can be enumerated algebraically. Write $a_{ik},b_{kj},c_{ji}$ for the zero-one indicators of the queried positions. At the minimum, counting incidences forces

$$a_{ik}+b_{kj}+c_{ji}=1\qquad\text{for every }i,k,j$$

over the integers. Suppose two rows of $a$ differ. Subtracting their two equations shows the difference is constant across columns. A nonzero difference of binary entries forces one entire row to be one and the other zero. The row of ones forces the entire bank $b$ to be zero. Then each row of $a$ and corresponding column of $c$ are complementary constants. If no two rows differ but two columns differ, the argument with the shared index $k$ applies. If $a$ is constant, either it fills the entire certificate or the equation gives complementary constants on each $j$ in the remaining banks. The resulting certificates choose one of the two incident banks separately for each value of one shared index. Conversely every such choice works. The three shared-index classes each give $2^d$ choices; their only overlaps are the three whole-bank certificates, each counted twice.

Thus the number $H_d$ of optimal coordinate sets is $3\cdot2^d-3$, with $H_1=3$ and $H_{d+1}=2H_d+3$. The minimum probe count grows by $2d+1$ at this successor. It counts positions across the entire blank run, so arbitrary control flow and workspace give the same lower bound in this query model. On a word RAM one native load can expose up to $w$ of the positions. Consequently an actual blank rejection needs $\Omega(d^2/w)$ steps. Some actual three-edit acceptance needs the same order for every correct solver: follow the blank run until its last previously unhit packing triple is first inspected, then use the file with that triangle. Before this inspection the two genuine runs are identical. Each word can first hit at most $w$ disjoint triples.

There is a matching native bound for the compact free-selector files. With $w=\Theta(\log N)$ a single globally correct solver takes $O(N/w)$ steps on every such file with $m=O((d^2/\log(d+1))^{2/3})$ set bits. To validate the template in packed words, generate the header and fixed library, decoder and filler records digit by digit. Their total length is $O((d+b2^b+10^b)\log d)=o(d^2/\log d)$. Precompute the packed decimal strings of the fixed identifiers within this same budget. Only the $3d^2/b$ data records dominate. Each record occupies $O(1)$ words and consists of the two expected public flags, punctuation, a library prefix and its $b$ consecutive mask digits. Using a fixed repeating byte mask, clear the low digit bits and compare the entire record to its expected fixed part. Check the end of file as well. A bounded number of shifts, masks and word reads suffices at an arbitrary packed offset; keep the current word address and lane as the records advance. Checking for an all-zero mask takes constant further work. Visit the $b$ individual digits only in the at most $m$ nonzero chunks. This gives all edges and validates every byte in $O(d^2/\log d+mb)$ native steps. Include a public dimension comment as above so the solver can generate the layout before trusting it. Run a complete decision procedure if validation fails.

Build adjacency in a fresh zero-initialized work bank and store the edge list and degrees, costing $O(d+m)$ additional steps with direct indexing. The subsequent orientation and wedge checks cost $O(m+m^{3/2})$. Both $mb$ and $m^{3/2}$ fit $O(d^2/\log d)$ in the claimed range. There is therefore a tight worst-case $\Theta(N/\log N)$ packed-word clock on this sparse neighborhood, on each verdict separately, for the best globally correct solver. Every correct solver faces the lower bound and one solver attains the upper bound on both signs. The optimum blank probe count and its successor survive at every dimension. Normalizing by encoded bits gives exactly the ordinary packed-input scale.
