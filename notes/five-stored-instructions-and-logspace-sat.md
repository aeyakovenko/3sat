# A five-instruction SAT decider would imply L = NP

**Theorem (manuscript).** Fix the [five-slot ISA](five-instruction-loops-on-dimacs-sat.md), including its standard width $w=16\lceil\log_2(n+2)/16\rceil$, writable packed input, zero background, fixed integer literals, separate LOAD/STORE/numerical/branch operations and two terminal verdicts. If one fixed program of at most five stored instructions decides all well-formed ordinary ASCII DIMACS 3-CNFs, at any speed, then $\mathsf L=\mathsf{NP}$. This was the intermediate implication. A subsequent [unconditional case split](five-instructions-cannot-decide-dimacs-sat.md) rules out the antecedent at the standard width. The bounded-alphabet logspace reduction below is independent of that stronger result.

The reduction below gives logspace simulations for some schedules and the listed clock-free exclusions dispose of the others. Which argument applies is a property of the fixed program. A failure on a special family excludes the program outright. A simulation need only work on the image of one NP-hard reduction. The verifier can choose the appropriate construction for the fixed program in an existence implication.

## A logspace-complete-input reduction with finitely many packed word values

Start with ordinary proper 3-SAT on polynomial-sized variable indices, NP-complete under deterministic logspace many-one reductions. For completeness a polynomial-time nondeterministic computation can be expanded into a polynomial-size local tableau: logspace counters enumerate time, position and the finitely many disallowed local patterns. Auxiliary variables for splitting long constant-width clauses receive indices from these counters. Remove tautologies and repeated literals; replace a two-literal clause $C$ by $(C\lor z)\land(C\lor\neg z)$ and a unit by the four extensions on two fresh variables. A constant contradiction gadget handles an empty clause. These operations give exactly three distinct variables per clause and require only logarithmic workspace. [Cook's original SAT reduction](https://doi.org/10.1145/800157.805047)

For an input of bit length $m$, first choose a sufficiently large, length-only polynomial target bit length $n$ divisible by eight, for example a large power-of-two polynomial bound, and compute the specified word width from $n$. A variable with $q=O(\log(m+2))$ index bits gets a decimal name beginning with 1, then $q$ blocks each consisting of $w/8-1$ zero digits followed by its next bit as a decimal digit. The bits have common fixed width across identifiers; this map is injective. Put the sign and leading 1 in a fixed aligned word; a positive sign position is a space. Use aligned terminator/whitespace blocks between complete literal tokens and clause records. The header can declare the name corresponding to the all-ones index, permitted by DIMACS even if unused. Its long name consists of repeated identical blocks. At any fixed alignment its interior contributes just one word value, and the decimal clause count and transitions contribute $O(1)$ more. The body uses a fixed number of packed word values, including both sign variants, regardless of how many names occur. Append whitespace to the chosen length. The standard initialization adds zero. Thus the whole original memory image $H$ has $|H|=O(1)$ on these outputs. The length polynomial leaves room for $O(\log^2 m)$ bits per literal. Counter-based emission or recomputation of one output word takes $O(\log m)$ space, including for the header. Using names with unused indices is part of this ordinary DIMACS grammar. [Aligned decimal construction](communication-bound-for-public-crossed-scans.md)

On such an image a simulation uses $O(\log m)$ work bits if at every point just $O(1)$ cells differ from the initial image, even when the set of cells varies with time. Store the addresses and contents of all exceptions, removing an entry when a write restores its original value. A bounded prologue is included in the exceptions or frozen into the initial image. The constant register tuple and each numerical instruction can be simulated in that same space. Recomputing the initial word may take many steps. Totality on the reduction image suffices; no deadline is assumed. Read-only programs and programs writing only a constant set of addresses are immediate cases.

## Checking the writable cases

A program returning both verdicts on unboundedly large sensitive families needs two branches if it uses a cycle. With at most one branch and two reachable terminals the connected underlying control multigraph has at most $V-1$ edges and has no cycle. With no LOAD it cannot observe the inputs. With no numerical site, loads and stores only copy existing data, metadata and literals. On the periodic sensitive base all these values form a bounded alphabet, so only boundedly many original addresses can be read. A genuine recurrent indirect STORE with both a LOAD and a numerical instruction therefore leaves exactly two branch sites and exactly one each of LOAD, STORE and numerical instruction. The seven reachable vertices including terminals have at most seven edges. A recurrent computation follows the unique cycle in fixed order until it permanently exits. Unreachable sites only reduce the possibilities. An off-cycle STORE contributes bounded exceptions. An off-cycle LOAD cannot see the required distinct originals. With the sole numerical site off cycle the possible register and memory values on the bounded-alphabet base gain at most one exceptional result, and again miss the originals. [Control-graph proof and sensitive bases](five-instruction-loops-on-dimacs-sat.md)

A fixed-on-input STORE destination, even if represented by an immutable register, uses one exception. A fixed-on-input LOAD on the cycle misses the sensitive originals. If the LOAD and numerical result have the same register destination, or the LOAD is self-addressed with a distinct numerical destination, the coincident-register and self-addressed cases miss originals or have a fixed STORE destination. [Coincident-register proof](adaptive-five-slot-prefixes-without-a-clock.md#coincident-register-destinations) · [Distinct destinations with a self-addressed LOAD](five-instruction-loops-on-dimacs-sat.md#an-address-bound-for-repeated-resets)

It remains to write $x\gets M[p]$ with the numerical site updating the distinct register $p$. Fixed-on-input operands include the public bit length, word width and words in immutable registers. Besides a sparse fixed destination the only possible STORE addresses are $x,p$. An indirect write through $x$ with payload $x$ or a fixed word $c$ only ever writes into $H\cup\{c\}$ with bounded prologue adjustments: every read returns an initial word, $c$, or a previously available word. This is sparse on the reduction image, for **every** cursor update. Here are the other rows.

| Cursor update | Remaining STORE schedules and reason |
| --- | --- |
| $p\gets f(x)$, ignoring the old cursor | Group operations between changes of $p$. A store through the unchanged $p$ before its LOAD destroys the original. After the LOAD, payload $x$ writes the word straight back; a fixed payload confines read replies to $H\cup\{c\}$ and hence regular addresses to $f(H\cup\{c\})$ on a sensitive base. A payload equal to the current address marks that address and falls under the [orbit-prefix exclusion](adaptive-five-slot-prefixes-without-a-clock.md). For a STORE through $x$ with payload $p$, its value is either the old or updated cursor. Writing the old cursor can change only addresses in $H$, by the [initial undirected-edge invariant](unshifted-crossed-scan-without-a-clock.md). Writing the updated cursor marks $M[x]$ with $f(x)$, the second [orbit-prefix case](adaptive-five-slot-prefixes-without-a-clock.md). |
| $p\gets f(p)$, ignoring the raw word | On the even sensitive base the [single-opcode analysis](five-instruction-loops-on-dimacs-sat.md#which-operation-can-generate-the-addresses) excludes all unboundedly covering orbits except translation by a fixed odd integer. In particular multiplication by an odd fixed value preserves valuation and an even translation preserves parity. For the odd translation, a STORE through $p$ before its LOAD again destroys the original. After its LOAD, a raw writeback preserves it, and a store of $p$ or $c$ leaves a public value on subsequent passes. For the latter cases simulate by keeping the public position and a bit recording completion of the first period; the initial partial turn is bounded. A STORE through $x$ carrying the old or advanced cursor is excluded, with no deadline, by the [reverse-edge scan](unshifted-crossed-scan-without-a-clock.md) or the [private-sign erasure construction](arbitrary-stride-private-sign-erasure.md), respectively. |
| The opcode uses both $p$ and $x$ | A fixed bitwise operation generates only words constant on the bit-position classes of the bounded initial palette and constants. Shifts in one direction or rotations reach only $O(w)$ transforms of each initial data word. Counting shifts by either operand does not create a new data source. Comparisons add at most two words. These families miss sensitive addresses. For addition, subtraction in either order and multiplication, all data remain even on the even base if the STORE copies a register or an even fixed quantity. For a literal odd payload, a STORE through $x$ is sparse as above. A STORE through $p$ before its LOAD destroys the next original. After its LOAD, multiplication keeps $p$ even, and all three additive updates with an odd marker at $p$ are excluded by the [odd-marker path and cycle argument](odd-self-marked-cursors-without-a-clock.md). |

The prologue order and the stage of the last LOAD/STORE on a halting turn are those of the fixed program. Each missed-original argument uses unboundedly many independently sensitive addresses, while bounded initial and final segments can read only a constant number. Each simulation row that retains virtual changes accounts for the initial partial turn. The other exclusions cited in the table explicitly handle their required initial state or bounded prologue.

All alternatives for this ISA therefore either fail on well-formed 3-CNFs or yield a logarithmic-space algorithm on the NP-hard reduction image. A correct program gives $\mathsf{NP}\subseteq\mathsf L$. The reverse inclusion follows because a halting deterministic logspace computation has polynomially many configurations. This establishes the implication. It relies on the manuscript case analysis and the linked erasure and marked-cursor proofs; there is no end-to-end Lean proof of this theorem. It yields no unconditional nonexistence result for the entire five-slot model and no running-time lower bound on the unrestricted RAM.
