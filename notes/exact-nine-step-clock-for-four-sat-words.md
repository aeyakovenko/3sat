# Nine native instructions are necessary and sufficient on four SAT words

**Theorem.** On the 16-bit sign-plane selector encoding below, the minimum worst-case running time over all correct programs for the specified four-bit RAM is **nine executed instructions**. For every correct program there is a satisfiable input among 64 specified inputs on which it executes at least nine instructions. Every individual input in the full 65,536-input domain has an eight-instruction recognition path in some correct program.

The encoded formula has eight variables, one fixed disjunction of them all, and positive and negative units selected by the input. The two positive-unit bitmaps occupy memory words $P,Q$, and the two negative-unit bitmaps occupy $M,N$, in that order. The formula is satisfiable exactly when $P\mathbin{\&}M=Q\mathbin{\&}N=0$ and $(M,N)\ne(15,15)$. The four-bit words are stored at addresses 0 through 3. The remaining twelve writable words and all registers start at zero. The RAM has unrestricted code size and register count, all sixteen immediates, literal or register-indirect reads and writes, the twenty specified binary word operations, and signed or unsigned binary comparison branches with fixed labels. Each executed instruction costs one, and reaching a fixed terminal verdict ends the run. [Exact machine and encoding](exact-clocks-for-two-word-sat-inputs.md) · [Native word operations](../audits/native_four_bit_planes.hpp)

For the upper bound, load $M$ and branch on $M=15$. If $M\ne15$, test $P\mathbin{\&}M=0$ and then $Q\mathbin{\&}N=0$, rejecting on either failure. If $M=15$, first reject when $N=15$, then reject when $P\ne0$, and finally test $Q\mathbin{\&}N=0$. Each longest run uses four loads and five other instructions. Independent evaluation against assignments to the eight formula variables gives 256 inputs taking four instructions, 40,960 taking five, 3,600 taking six and 20,720 taking nine. Separately, for any chosen file, load and compare each of its four words to its four literals. Return the known answer when all agree, and continue with a general solver on failure. This proves the pointwise eight-step upper bound. ## Lower bound

Let $S=\{(p,q,15-p,15-q):4\le p,q\le11\}$. These are 64 satisfiable inputs. Each word is individually pivotal. Changing that word to 15 conflicts with its nonzero mate. A correct accepting path must therefore load every original cell before its first overwrite. Assuming all 64 inputs finish in eight instructions, each accepting path meeting $S$ has at most four comparisons. Between two comparisons the instruction labels are fixed by the previous outcomes, so we can unfold the program into a binary tree and count the targets reaching a particular accepting leaf. Along a single fixed path its comparisons can be checked at the end with their original operands retained.

| Comparisons on the path | Upper bound on targets at that accepting leaf | Reason |
|---:|---:|---|
| 4 | 1 | Four fresh loads leave four raw comparisons. Every pair of targets has some consistent negative for every four such comparisons. [Pair census](../audits/four_raw_comparisons_on_complementary_pairs.py) |
| 3 | 8 | Four fresh loads leave at most one extra instruction. Enumerate the native ALU and its possible addressed load. The raw cases follow by mixing low and high complementary words. [Reduction and census](coupling-four-word-native-sat-paths.md) |
| 2 | 18 | Zero or one ALU reduces to high-word, lookup and store cases. Two ALUs leave four fresh loads without stores. Enumerate the direct case and 14 layouts with one or two computed addresses. [Direct-address census](nine-steps-for-direct-addressing-on-four-sat-words.md) · [Small arithmetic cases](marked-leaves-and-high-word-lookups.md) · [Two computed results](exhausting-two-alu-indirect-accepting-leaves.md) |
| 1 | 36 | Zero or one ALU has the preceding high-word bound. Two ALUs without a write permit a finite closure even with unlimited loads. Two ALUs with one write, or three ALUs and no write, have exactly four fresh loads. Analyze the last fresh read and enumerate the remaining predicates. [Read-only and terminal bounds](one-comparison-after-the-last-fresh-word.md) · [Store erasure and residual census](erasing-one-store-in-the-eight-step-native-census.md) |

For the one-comparison case with a store, delete it on the subdomain where the store's address misses all later reads. Both trajectories agree there, and every accepted target belongs to that subdomain. After a computation of the same words without the store, the unknown set of later literal addresses must contain the store addresses of all passing negative examples. Choose the smallest such set to maximize target support. An additional inequality with the computed address is included exactly when that read followed the store in the original run. This avoids an assumption that removing a store preserves the behavior of arbitrary negative inputs. [Adaptive erasure proof in Lean](../lean/FreshReadStoreErasure.lean)

For four fresh read-only loads, all dynamic addresses on $S$ must be produced by an arithmetic instruction, since the raw words lie between 4 and 11. Two different fresh reads cannot use the same arithmetic result. On the targets, the dynamic addresses must exhaust the omitted physical cells, in an order that may depend on the input. The two-comparison enumeration permits that dependence. For one comparison, a last raw word $x$ read without further arithmetic must pass a fiber test with its mate fixed. In signed ascending order the only possible endpoints in $S$ are $8,9,11$, and in each case the next word already conflicts. The unsigned and descending cases give at most one possible target value. Raw-word coincidences and smaller signed-order endpoints are enumerated separately. The remaining equality and terminal arithmetic cases are included in the residual enumeration.

Mark one rejecting input, for example $00\mathrm{FF}$. Even if only the targets are assumed to finish in eight steps, the union of their paths with the marked path is finite for a decider. A reachable accepting leaf at depth $d$ covers at most $w_d$ targets from the table. At depth four a subtree covers at most one target, and one containing the mark covers zero. An internal node can send the mark to just one child. Thus the ordinary and marked capacities obey $F_d=\max(w_d,2F_{d+1})$ and $E_d=F_{d+1}+E_{d+1}$. At depths three, two and one their pairs are $(8,1),(18,9),(36,27)$. A marked root covers at most $36+27=63$ targets. It must cover all 64, a contradiction. This argument couples paths executed by one program. [Marked-tree proof in Lean](../lean/EightStepMarkedCapacity.lean)

## Reproducing the computation

From a checkout containing this note, run the following with a C++20 compiler, Python 3 with NumPy, and Lean 4.19 available. The directory argument holds the compiled executables and resumable interval receipts.

```sh
LEAN=/path/to/lean sh replay-nine-step-native-clock.sh /tmp/nine-clock
```

For a short receipt audit from the same checkout, run `OPENBLAS_NUM_THREADS=1 python3 nine_step_native_referee_audit.py --bundle nine-step-native-receipts.json.gz`. This checks the recorded source fingerprints and both interval partitions, together with the independent scalar tests. Rebuilding the workers and replaying the kernels is what verifies the decisions reported inside those intervals. [Primary receipts and source fingerprints](../audits/nine-step-native-receipts.json.gz)

The two-comparison worker has 11,258 different first-operation tables across its 14 layouts. The primary run used 708 intervals, examined 6,376,321 second-stage tables, and checked 12,059 concrete comparison pairs beyond the quick negative examples. Its positive control has a sound eight-target path, independently replayed on all 65,536 files. The residual one-comparison worker covers 38 layouts and 29,966 first tables. Its 3,748 primary rectangles partition 202,695,726 first-table/second-operation pairs, consisting of 53,388,160 for the stored case, 71,627,266 for a terminal load and 77,680,300 for terminal arithmetic. Each pair includes all required further operations and comparisons. None passes the primary quick negative screen. An independent scalar checker reconstructs both first-table counts and every rectangle, compares all 5,120 native ALU entries and 1,280 ordered comparison entries against scalar semantics, and checks the upper algorithm by enumerating assignments. [Complete replay](../audits/replay-nine-step-native-clock.sh) · [Independent checks](../audits/nine_step_native_referee_audit.py) · [Two-comparison worker](../audits/two_alu_indirect_leaf_census.cpp) · [One-comparison worker](../audits/remaining_native_one_guard_census.cpp)

A second build used Clang 15.0.1 with `-O2` instead of GCC 11.4.0 with `-O3`. It changed the negative-example shuffle from 73533011 to 20680722 in the two large workers, the pointer interval width from 16 to 23 and the residual interval width from 8 to 12. The second run exhausted all 14 pointer layouts in 498 intervals, including 16,768 concrete comparison pairs beyond the fast tests. It also exhausted all 38 residual layouts in 2,518 rectangles, again with zero fast-screen survivors. The other native census executables were rebuilt with Clang and passed. To reproduce the changed parameters in a disposable copy of the checkout, run the following from the copy.

```sh
sed -i 's/gen(73533011)/gen(20680722)/' two_alu_indirect_leaf_census.cpp remaining_native_one_guard_census.cpp
sed -i -e 's/-O3/-O2/' -e 's/--shard-width 16/--shard-width 23/' -e 's/--width 8/--width 12/g' replay-nine-step-native-clock.sh
CXX=clang++ LEAN=/path/to/lean sh replay-nine-step-native-clock.sh /tmp/nine-clock-clang
```

Lean 4.19.0 checks the explicit upper program, the adaptive store lemma and the marked-tree recurrence. The classification of native paths is a manuscript proof, and the finite capacities depend on the C++ and Python censuses. This finite model and encoding do not give an asymptotic lower bound for unrestricted RAM SAT. The sign-plane input family itself admits a word scan at growing lengths.
