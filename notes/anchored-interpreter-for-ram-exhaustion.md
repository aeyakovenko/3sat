# A finite exhaustion at the exact SAT time exponent

Fix $a\in\{1,2,3\}$ and use the journal's word RAM with fixed nonnegative integer width coefficient $D\ge1$, little-endian packed input, zero exterior, writable input, and separate at-most-binary operations. Each guest has ordinary fixed immediate integers. There is **one fixed finite instruction template** $U(e)$ with one variable immediate, at the **single host coefficient 4**, for which the following are equivalent.

* Proper DIMACS 3-SAT has no deterministic $O(n^a)$ algorithm among all the guest coefficients and all finite programs with unrestricted writable addresses.
* For every positive integer $C$ there is a finite suite of labeled proper files such that every $U(e)$ errs or exceeds $C(n+1)^a$ steps on some file in the suite, where $n$ counts the file's encoded bits.

For any fixed $C$, one explicit unsatisfiable file of $L=O(\log(C+2)\log\log(C+4))$ bits reduces **all** immediate integers to at most $O(L^2)$ surviving program descriptions. If the exclusion holds, the entire suite needs this one file and at most one further witness per surviving description. There is no effective upper bound on the *lengths* of the remaining witnesses supplied by the argument. Increasing $C$ and searching for each new suite completes every stage if and only if the exact exclusion holds. This criterion does not prove termination.

The fixed template matters. The [unrestricted literal census](finite-sat-exhaustion-with-unbounded-literals.md) for arbitrary instruction structures can retain coherent noninteger binary streams as the horizons grow. At this interpreter a complete finite parameter becomes necessary on one small known input. A standard alternative is to enumerate longer and longer ordinary programs and test each at larger deadlines. The extra conclusion here is a simultaneous finite suite quantifying over *every* parameter of one sufficient native structure at each stage. The choice of compiler influences both the suite size and the clock multiplier.

## Packing every guest into a single fixed host

Encode one guest program and its positive integer $D$ by a finite self-delimiting word. Use two-bit symbols `01` and `10` for data bits and `11` for the terminator in low-to-high pair order. Reject `00`, absence of a terminator before exhausting the visible word, and malformed decoded programs. Ignore everything above the terminator, including in all subsequent initialization costs. Dense numbering of registers and instruction labels is part of the encoding. At any host input width large enough the full text of a fixed guest becomes available. A fixed interpreter decodes it, initializes a private guest register array and reads the instruction for the current guest program counter. All loops over that fixed text or register list have program-dependent constant cost per guest step. Scanning the whole text at every step would also suffice. Negative guest literals can be stored by their sign and absolute value. Invalid programs may use the fallback described below.

Write $H=16\lceil4\log_2(n+2)/16\rceil$ for the host width. Compute the guest width $w=16\lceil D\log_2(n+2)/16\rceil$ during setup. Compute the positive integer $(n+2)^D$ by integer limb arithmetic, take the ceiling of its base-two logarithm by bit length and a power-of-two test, and round that integer up to a multiple of 16. For fixed $D$ this takes at most $O_D(\operatorname{polylog}(n+2))$ time. Represent each guest word by $O_D(1)$ short host limbs. Addition with carry, schoolbook multiplication, bitwise operations, comparisons and cross-limb shifts take $O_D(1)$ native operations. For counts reduced modulo $w$, precompute a reciprocal for the fixed divisor $w$ at this input length. In a most-significant-limb scan the running remainder is below $w=O_D(H)$ and each limb may use at most $H/4$ bits. The partial dividend fits in a host word. Multiplying by $\lfloor 2^H/w\rfloor$, taking the high word, and making at most one corrected subtraction performs the reduction with constant host work per limb. The high product uses a bounded number of half-width products. Rotation and signed comparisons are implemented at the guest width. Setup need only meet the asymptotic bound for each fixed valid parameter. Resource checks can invoke fallback on the other lengths. [Earlier interpreter with twice the guest width](constant-instruction-interpreter-and-size-induction.md) · [Cook and Reckhow on RAM simulations](https://www.cs.toronto.edu/~sacook/homepage/rams.pdf)

Keep the original packed host input pristine. For a guest memory read returning the original value, compare its multiword address with the physical input range, return zero outside the file and otherwise assemble the guest's consecutive bits in $O_D(1)$ host loads and shifts. Multiplication and division by the two widths determine the offset, using the same reciprocal method. Because this branch has already range-checked its address, its starting bit lies below $n$. The last guest word is zero-padded. Record guest writes including zero in a sparse radix trie keyed by the full guest address. A missing entry takes the original-file path. A present leaf contains its overwrite flag and all its limbs.

For the trie digit use $b=\max(1,\lfloor\log_2(n+2)/4\rfloor)$ bits. Its $\lceil w/b\rceil$ levels are bounded by a constant depending on the guest. Each allocated row has $2^b$ initially zero child pointers and is obtained by incrementing a next-free-row index. No instruction clears an untouched row. A new guest store needs at most one fresh row per level and one leaf. Give the trie, leaf records and register arrays disjoint regions above the pristine input. After $T$ guest steps the highest host location used can be kept within $O_{P,D}((1+T)n^{1/4}+n+\operatorname{polylog}(n+2))$, using constant tags or consecutive allocators in fixed tagged subranges. For $T\le K(n+1)^a$ this is $o(2^H)$, even if $K$ exceeds every small machine constant. Check row and record limits *before* incrementing or computing a possibly overflowing address. A failure can go to fallback on the pristine input. Untouched zero rows and pointer/flag sentinels distinguish guest cells overwritten with zero. The simulation thus has fixed code size, full guest semantics on all sufficiently large timely runs, and $O_{P,D}(T+\operatorname{polylog}(n+2))$ host time. A host coefficient $a+1$ works by the same calculation. No doubling of an unbounded guest coefficient is necessary. [Sparse RAM address interpretation](native-unary-clock-band.md)

The fallback is a fixed correct exhaustive SAT algorithm. Parse the file, group occurrences by equality of their numeric names, and enumerate all Boolean assignments to the *occurring* variables in sequence, testing the clauses on each assignment. Allocate space polynomial in the input length within the fixed host capacity, for example using direct lists of occurrences and comparing names by rescans. On an unsatisfiable file with $v$ occurring variables the routine considers every one of the $2^v$ assignments, taking at least that many native steps. It performs no initial contradiction simplification. It may reuse all host workspace after discarding the interpreter arrays. Use disjoint scratch or explicitly initialize its working cells. This ensures total SAT correctness on all lengths when the guest is globally correct. Other guests may err or run forever.

## One explicit file fixes the visible text

For $v=3+3k$, take all eight proper sign clauses on variables 1,2,3. Add one positive clause per disjoint triple on the remaining names through $v$. Sort and emit without redundant whitespace. This file $A_v$ is dense, proper, duplicate-free and unsatisfiable, and has length $L_v=\Theta(v\log(v+2))$ in bits. Find the first $v$ in this progression with $2^v>C(L_v+1)^a$. It exists, has $v=O(\log(C+2))$, and is effectively computable without running any candidate. On $A_v$ every string with a truncated or invalid guest description takes the slow fallback and fails the deadline. The ordinary fallback uses its own exact Boolean labels here.

Every remaining description has a first terminator inside the host word of width $H(L_v)$. All more significant bits are ignored. At a smaller width the available prefix is determined by the bits already seen at the anchor. At larger widths the first terminator is still present in precisely the same place. Replacing an immediate by its nonnegative low bits through the terminator consequently preserves its entire execution at **every** length, including its initialization time. This also applies if one extends the parameter domain to coherent infinite bit sequences. Among $H(L_v)/2$ available pairs, the number of possible completed data strings is $\sum_{j=0}^{H(L_v)/2-1}2^j<2^{H(L_v)/2}=O((L_v+2)^2)$. Parsing the payload grammar or timing the remaining guests on the anchor can discard more candidates.

For fixed $C$, if each of these finitely many representatives has a failing input, their union with $A_v$ defeats all parameters. If some representative has none, it is itself a globally correct RAM solver in $O(n^a)$. Conversely any such solver at any finite guest width is simulated at its compiled parameter in $O(n^a)$. Increasing one multiplier absorbs the simulation constants and all finitely many exceptional small inputs, where either fallback or the correctly simulated solver halts. This proves the equivalence. To execute a stage, enumerate well-formed files, evaluate SAT by exhaustive assignment, and simulate each remaining candidate for its explicit deadline. Retire a representative when its first failure is seen. No general solution of the halting problem is required.

One can enumerate only normalized cores as witnesses if the target is phrased on those cores: a representative fast and correct on them composes with the [compiler to dense sorted cores](dense-sorted-cores-for-ram-exhaustion.md) to decide ordinary SAT with the same time exponent. In that version the sufficient class includes compiled guests correct on all files, and testing only the core language changes the converse via normalization.

For $C+1$ the set of complete descriptions can grow when the anchor crosses a width boundary. A previous timeout may also become timely under the larger multiplier. These are genuine obligations for the successor search. This construction gives no size or discovery-time bound for the new hard inputs. The small count of surviving descriptions reflects the delayed visibility of program text at small inputs. A compiled fast solver's multiplier can be far larger than the original solver's multiplier. It does not imply a comparable bound on arbitrary code text at a preassigned constant.
