# Checking compiler chunks without a directory of their shared variables

Consider a proper 3-CNF with polynomially many clause positions in a clock parameter $T$. Each clause position, its chunk, its signs and its three canonical name keys are accessible from the source in $\operatorname{polylog}T$ time. A local chunk coordinate describes each occurrence, including its name and global position. Chunks contain at most $B$ literal occurrences. The ordinary fixed-degree wire names of the regular RAM-to-SAT trace compiler are examples of keys from a polynomial-size universe. The oracle giving clause records is implemented by the specified local compiler. [Native bounded-run construction](native-linear-time-and-locally-uniform-circuit-depth.md)

Write $q$ for the number of distinct names occurring in more than one chunk. No list of those names is given to the verifier. Fix a baseline assignment $\beta$ evaluable in $\operatorname{polylog} T$ time per name from the source, optionally using $a$ additional guessed bits. Suppose some satisfying assignment differs from $\beta$ on at most $e$ of the shared names. Private names may disagree arbitrarily. There is a four-block alternating verifier whose largest root-to-leaf number of guessed/challenged bits is
$$
    O\left(a+B+e\bigl[1+\log_2(q/e)\bigr]+\log^2(T+2)\right).
$$
For $e=0$ omit the term involving $e$; for an empty shared set use $e=0$. With packed word choices its path time is this numerator divided by the word width, plus $\operatorname{polylog}T$ steps. Dimensions can be supplied as public upper bounds, or guessed and checked against a common witness cap. The verifier is sound on all negative instances for any such cap. It is complete on the stated positives if the cap accommodates the indicated representation. Taking no baseline (`false`) and allowing $e=q$ gives the ordinary $O(q+B+\log^2T)$-bit verifier for a bounded interface. A compiler with arbitrary long identifiers accessible only one raw bit at a time would need to supply a way of comparing and hashing them within the stated time.

## An entropy-size total correction with polylogarithmic lookup

A static function specifies bits only on given keys and may return any fixed value elsewhere. Entropy-compressed static functions and fast retrieval are established data structures. Here a simple implementation uses explicitly stored finite-field hash coefficients and allows polynomial preprocessing, once the labels are given. The choice of free random oracles never enters the terminal verifier. [Belazzougui and Venturini, *Compressed Static Functions with Applications*](https://doi.org/10.1137/1.9781611973105.17) · [Dietzfelbinger and Pagh, *Succinct Data Structures for Retrieval and Approximate Membership*](https://arxiv.org/abs/0803.3693)

Call the $e$ exceptional keys positive and the $q-e$ other shared keys negative. Field elements in $\mathbb F_{2^k}$ encode the keys canonically for $k=O(\log T)$ sufficiently large, also ensuring the table sizes below fit in $2^k$. For each filter choose $R$ a power of two between $4e$ and $8e$, and take the low $\log_2 R$ bits of $Az+C$ for uniform independent $A,C$ in the field. Hashes of distinct keys are pairwise independent. Store an $R$-bit array marking just the buckets of the positives. All positives survive. A fixed negative hits a marked bucket with probability at most $e/R\le1/4$. There is a choice cutting the number of surviving negatives by at least half. Record successive such filters until at most $e$ negatives remain. A query dropping out of any filter returns zero. There are $O(1+\log(q/e))$ filters for $e\ge1$. If $e=0$, use constant zero.

For the $s\le2e$ residual keys, take two disjoint tables with equal power-of-two size $R$ between $8s$ and $16s$. Use two independent polynomial hashes of degree $\ell-1$, projected to $\log_2R$ bits, where $\ell=\min(s,\lceil\log_2(s+1)\rceil+2)$. For up to $\ell$ distinct keys their endpoints on each side are independent uniform by polynomial interpolation. Make each key an edge joining its two endpoints. An even cycle of $u\le\ell$ distinct edges demands $u$ independent endpoint equalities for an ordered choice of those edges and side orientation. The union bound over short cycles is at most $2\sum_{u=2}^{\ell}(s/R)^u$, including a parallel-edge 2-cycle. A longer cycle would have a path of $\ell$ distinct edges, requiring $\ell-1$ independent endpoint equalities. Its probability is at most $2s(s/R)^{\ell-1}$ if $s>\ell$; if $s=\ell$, longer cycles are impossible. The sum is below one. Thus a forest exists. Set a root bit arbitrarily in each tree and propagate vertex bits to make the XOR at the endpoints of every edge equal its prescribed label. Two indexed bit reads now answer the residual query.

All filter bit arrays and forest vertex bits together cost $O(e[1+\log(q/e)])$ bits. All explicit hash coefficients, an irreducible field modulus and all table headers cost $O(\log^2 T)$ additional bits. Filtering and evaluating the two $O(\log T)$-degree polynomials use only $\operatorname{polylog}T$ bit operations and random reads of the packed proposed tables. A Las Vegas constructor given the shared keys and labels can reject bad hashes by counting survivors or testing for cycles; its expected time is polynomial since all probability bounds leave constant success. The field modulus can also be sampled and checked in expected polynomial time. For positive inputs the alternating verifier needs existence of the representation. A malformed candidate can be rejected by checking lengths and all addresses; even an unreduced candidate modulus still defines a deterministic bit lookup if interpreted by the same bounded arithmetic. [Finite-field representation details](succinct-evaluation-of-a-given-dimacs-model.md)

The storage order reflects the freedom of the signs. Prescribing exactly $e$ flips among a fixed set of $q$ keys requires at least $\log_2\binom qe$ bits across some choices. The upper estimate is particularly relevant when $1\le e\le q/2$. One globally guessed default flip can exchange the two label classes when the smaller exceptional side is preferred.

## Checking a claimed model without trusting private/global annotations

1. Guess the optional baseline parameters and the fixed-cap correction seed. Together they define one public total function $g$ on all canonical names.
2. Universally choose a chunk. A padding index beyond the last chunk passes.
3. Guess a local bit for every literal occurrence in that chunk.
4. Universally select one of three possible defects. Reject if a clause in this chunk is false under the local bits, if two local occurrences with the same name have different bits, or if a local occurrence disagreeing with $g$ has the same name as a selected occurrence in **another** chunk. Invalid or out-of-range defect nominations pass. Only constantly many occurrence bits and locally generated clause records are needed for a single challenge.

On accepting paths all copies of a private name within their chunk agree. If a name appears in different chunks, its values in each must equal $g$. Pick the value at its first occurrence; this assembles the local models into one satisfying assignment. On a positive input use a real global model, correcting $\beta$ just on its shared names. A spurious positive correction on a private key imposes no constraint even if the local model disagrees with $g$ there. The quantified order allows a different local certificate for each chosen chunk. The final pair challenge enforces every globally needed consistency condition against those actual local certificates. [Lean assembly theorem](../lean/SparseInterfaceGluing.lean)

This verifier therefore spends its global bits on an entropy-size correction rather than on a list of name identifiers. Its terminal local work is polylogarithmic even for many thousands of errors. If $B$ and the outer guess are both polynomially sublinear in $T$, it gives a genuine constant-alternation speedup for the corresponding published compiler outputs. When such a speedup is collapsed using a hypothetical near-linear SAT solver, all earlier *bits*, including the chosen local certificate, must still be paid for. The unrestricted RAM compiler provides no analogous sparsity guarantee. On the explicit XOR computation with a dense transposed code, every fixed small partition has linearly many crossing model variables and a source-local baseline with too little advice gets a constant fraction of those bits wrong. That computation instead admits a much smaller locally indexed decision compiler by eliminating the dense code algebraically. [Counterexample and replacement compiler](local-source-probes-for-the-model-of-a-compiled-ram.md) · [Cost of eliminating the alternations](alternating-native-speedup.md)

The executable tests 258 full or sparse label patterns with 2,994 constrained lookups and 119 thinning stages, including long integer keys. It evaluates 608 tiny chunk games against centralized exhaustive SAT, including inconsistent pairs of individually satisfiable chunks and 432 off-interface settings. Lean checks that local models obeying the cross-occurrence rule glue to a global one. The hash probability and time bounds above were derived in the manuscript.
