# Nearly one forced binary-wire cycle per independent bit of the SAT verdict

Consider a fixed-layout family of proper ASCII DIMACS 3-CNFs with $h$ independently editable physical bits. The relation on these bits accepts exactly when the file is satisfiable. There is a uniform sequence of such families with the following two properties.

* Every Boolean network of arity at most three representing this **decision relation**, allowing arbitrary internal wiring, arbitrary Boolean local tables and existential internal bits, needs at least $(1-o(1))h$ independent graph cycles. The $h$ independent bits occupy $(3/8-o(1))N$ of the $N$ physical bit positions.
* One globally correct deterministic SAT program decides every file in these families in $O(N/w)$ instructions for $w=\Theta(\log N)$-bit words. Every correct program takes $\Omega(N/w)$ instructions on **every** positive file. For each such file there are also $\Omega(h)$ distinct negative files at physical Hamming distance one that take $\Omega(N/w)$ instructions under the same program.

A network deciding unrestricted SAT as a Boolean relation of the raw file bits must obey the same cycle lower bound at these lengths: pin all the fixed input bits of the layout and retain the independent digit bits as its terminals. Adding unary pins cannot increase cycle rank. The matching time upper bound applies to this particular family.

This gives a matching time bound on actual SAT files whose physical decision relation resists arbitrary reductions in binary-wire cycle rank. It tests an induction that charges those cycles to a RAM instruction sequence. The construction represents $(1-o(1))t$ forced cycles per $t$-bit record on average across the entire network, even when gates are shared across records. One word-indexed table suffices for a record. [Earlier lower bound on the assignment relation of each satisfiable file](sat-with-many-necessary-cycles-on-every-positive-file.md)

## Cutting a product of distance codes

Let $C\subseteq\{0,1\}^t$ have minimum Hamming distance at least $d\ge2$. A network for the relation $C^k$ on $kt$ terminal bits has cycle rank
$$
      b\ \ge\ k\log_2|C|-k\left\lfloor\frac{t}{\lceil d/2\rceil}\right\rfloor .
$$
Here $b=|E|-|V|+c$ with $c$ connected components. Attach an explicit leaf at each terminal and cut $b$ edges outside a spanning forest. Color the terminal leaves by record. In the remaining forest partition each tree by cutting edges until every part contains at most $d-1$ leaves of *each* color. To do this, process the tree bottom up, retaining one component at each child. When two such components together exceed the cap in some color, detach a child containing at least $\lceil d/2\rceil$ leaves of that color. The other child alone fits every cap. At a marked root leaf treat its one terminal as a singleton side, or subdivide an edge before rooting. Ignore empty branches created by the first cuts. Each charge uses distinct leaves of a finalized component. The additional cuts number at most $k\lfloor t/\lceil d/2\rceil\rfloor$.

Fix all severed wires consistently. The allowed terminal patterns form a Cartesian product over the resulting pieces. If it contains two distinct terminal words, splice a piece on which they differ into the first. In some changed record the resulting word differs at between one and $d-1$ positions. This contradicts exact membership in $C^k$. Thus the number of fixed wire tuples must be at least $|C|^k$, giving the inequality. This proof concerns representation of a global relation. Cost on any one RAM execution requires its own argument. [Code-graph cut bounds of Kashyap](https://arxiv.org/abs/0805.2199) · [Lean tree cutting and gluing for distance three](../lean/GluedCodeCut.lean)

For a simple explicit choice, divide each record of width a multiple of seven into seven-bit blocks and require each to have Hamming syndrome zero. The code has sixteen words and distance three. Applying the bound with each seven-bit block a separate color gives $b\ge h/7$, regardless of the grouping into physical words. This mode already forces $\Theta(w)$ cycles per physical record on average.

To obtain the larger coefficient, take $d=\max(3,\lfloor\sqrt{t/\lceil\log_2(t+2)\rceil}\rfloor)$ and construct $C_t$ in numerical order, adding a word when it is at distance at least $d$ from all earlier retained words. Every word is within distance $d-1$ of a retained one. Consequently
$$
 \log_2|C_t|\ge t-\log_2\sum_{j<d}\binom{t}{j}
             \ge t-O(d\log(t+2)).
$$
The last estimate follows already from $\binom tj\le t^j$. The resulting cycle rank is at least $kt-O(k\sqrt{t\log(t+2)})$. Construction by checking all pairs takes $O(4^t\operatorname{poly}(t))$ operations. The covering argument is the classical greedy code bound. [Gilbert, *A comparison of signalling alphabets*](https://doi.org/10.1002/j.1538-7305.1952.tb01393.x)

## A single physical occurrence of each independent bit

For $k\ge1$ records choose width $t=\max(4,\lfloor\log_2(k+1)/16\rfloor)$ in the greedy mode. In the Hamming mode use $t=7\max(1,\lfloor\log_2(k+1)/112\rfloor)$. Let $u=\lceil t/3\rceil$. The flag variable $F_s$ has the **decimal DIMACS identifier** whose ASCII spelling is the character 1 followed by the zero-padded $u$-digit **octal** spelling of $s\in[0,2^t)$. Octal is used only to choose characters. A DIMACS parser interprets every identifier in decimal. Each digit character 0 through 7 has three independent low bits, except that the unused top bits of the first digit are fixed. Thus the file contains one independently changing bit for each data bit.

Use identifiers 1 and 2 for flags forced false. For each of them emit the four clauses $(-a,\pm3,\pm4)$ with all sign choices. For each possible $s$, emit $(F_s,1,2)$ if $s$ belongs to the code and $(-F_s,1,2)$ otherwise. Fill every unused identifier $v$ between 5 and the largest flag with $(-1,v,3)$, which holds when variable 1 is false. This makes all names dense. Finally, for each actual record value $s_i$ emit just
$$
                             (F_{s_i},1,2).
$$
All clauses have three distinct variables. The header and all bytes outside the suffix digits in these last $k$ clauses are fixed for the chosen mode and $k$. The pins force every flag independently of the records. Therefore the file is satisfiable exactly when every record belongs to the code. An ordinary comment gives the mode, $k$ and $t$ so a uniform program can check the layout. This is a specialization of the journal's use of decimal variable names for dense data. [Packed control bits in DIMACS](processing-packed-control-words-in-dimacs.md)

The flag count is $2^t$ and the largest decimal identifier is $O(10^u)$. The prefix, including all fillers, has $O(10^u(t+1)+\log(k+2))=o(k)$ bytes as $k$ grows. Each record takes $u+8$ bytes in the audit format. Hence $N=8k(t/3+O(1))+o(k)$ and $h=kt=(3/8-o(1))N$. In particular the cycle bound concerns linearly many independent bits of the **physical decision problem**, without repeating a data bit at several positions.

## Elapsed time on neighboring files

A uniform RAM can check the canonical header in time $O(\log(N+2))$ on these files. A bounded fast path rejects a proposed layout descriptor if its comment exceeds a fixed multiple of that length, its counts overflow or its $k$ exceeds $N$. On any failure of recognition the program invokes a general SAT algorithm on the original file. Regenerate and compare the prescribed fixed prefix in $O(10^u\operatorname{poly}(t)+4^t\operatorname{poly}(t))=o(k)$ operations. These costs include generating and checking decimal spellings. A direct dictionary on all $8u$-bit byte strings checks that a suffix is a correctly padded octal spelling in range and returns its validity and code bit. Building it costs $O(2^{8u}\operatorname{poly}(t))=o(k)$ operations. All three tables fit in the RAM's address space. The finite small widths affect only constants.

The suffix and its fixed neighbors in each record occupy a constant number of words. Packed loads and shifts recover an unaligned field, after which its lookup costs one instruction up to constant overhead. Check the separators and literal spellings at their fixed positions, check the exact final length, and take the conjunction of the code bits. Every canonical positive and negative file therefore costs $O(k)=O(N/w)$ time, including preprocessing. A negative code bit remains a valid layout and does not trigger the fallback.

For the lower bound fix any correct solver, any positive file, and a fixed $0<\varepsilon<1$. Changing any of its $h$ independent bits gives another canonical file of the same length and flips the verdict, by minimum distance. A bounded number of input reads per instruction can touch only $O(w)$ physical bit positions. In a sufficiently small constant times $\varepsilon h/w$ initial instructions at most $\varepsilon h$ of the independent positions have been touched. The run cannot already have halted: changing an untouched bit preserves all these observations. At least $(1-\varepsilon)h$ of the one-bit negative neighbors follow the same prefix. This gives the promised lower bounds on actual executions of both verdicts. Since the positive words have mutual distance at least three, a one-bit negative neighbor is adjacent to at most one of them.

## A common finite test against every program in a roster

Fix any printed list of $p$ deterministic RAM programs, including programs that return wrong answers or run forever. Give program $i$ a step budget $d_i$ and let $a_i w_i$ bound the number of physical input bits one instruction can inspect. Run each on the same canonical positive file up to its budget or its halt and take the union of its inspected input bits. If
$$
                          \sum_{i=1}^p a_i w_i d_i < h,
$$
some data bit is outside the union. Flipping it gives one common negative file. Each program has the same observations and control flow on the two files until it halts or its budget expires. Consequently each is late or wrong on at least one of the pair. Every *correct* program is late on **both**. If the sum on the left is at most $\varepsilon h$, at least $(1-\varepsilon)h$ different negative neighbors work. This constructs the tests by finite simulation, without identifying the correct programs. In particular it applies to the complete list of programs having at most $C$ bits of code in any fixed effective encoding. To include code of length $C+1$ at a specified absolute deadline, enlarge $k$ until the inequality covers the new list, using the word width at the new input length. Such a $k$ exists for fixed deadlines because $w_i=O(\log N)$. For deadlines proportional to $N$, the same inequality already fails for a roster of one.

The factor $p$ for the *common negative* has a matching upper bound on this family for each fixed $p$. Partition the $k$ record positions into $p$ intervals of size at most $\lceil k/p\rceil$. Program $i$ first verifies the entire small canonical prefix. It then checks its interval for a record with a forbidden flag. It can reject immediately upon recognizing a complete such clause and verifying its preceding clause boundary. In the first record the prefix supplies that boundary. Elsewhere require the preceding newline-delimited line to spell a complete noncomment record ending in a standalone zero, and the next line to spell the offending record from beginning to end. The zero terminates any prior clause, including one that spans earlier lines. With the verified prefix forcing both guards and the flag false this is a local contradiction, irrespective of the rest of the file. A failed check or the absence of a contradiction invokes the ordinary full solver. This uses the strict full-file DIMACS convention in which every body clause counts and malformed input is rejected. [DIMACS CNF format, §2.1](https://www.cs.ubc.ca/~babic/doc/dimacs_cnf.pdf)

Each program is globally correct. On a canonical negative having a single damaged data bit, the program owning the offending record rejects in $o(k)+O(1+k/p)$ steps. Interval boundaries can also be computed in logarithmic time for fixed $p$. Thus although a single positive file needs a full scan in every program, the fastest member of a suitable roster can divide the negative search among $p$ different priorities. This upper bound concerns the minimum time among the $p$ individual runs; a single machine running all of them still pays for those runs.

## Reading a code table supplied by the input

The recognizer can also receive an arbitrary table $T\subseteq\{0,1\}^t$ in the prefix. Use two variable names per key, $P_s$ and $Q_s$, with leading ASCII digits 2 and 3 respectively and the same octal suffix. Force them to be complements using $(P_s,Q_s,1)$ and $(-P_s,-Q_s,1)$. The next row pins one of these variables true through the false anchors. Switching between the two names changes exactly the low bit of their leading ASCII digit. Data rows use $P_{s_i}$. The resulting verdict is $\bigwedge_i [s_i\in T]$ for every table, even one with adjacent allowed words. The solver verifies the fixed row structure while reading each switch, fills the lookup array from those bits, and uses the same packed scan. Verifying all prefix rows and dense fillers still takes $o(k)$ time.

Fix any subset $T$ containing at least half the words of the greedy $C_t$, with $T\subseteq C_t$. Minimum distance persists, and the cycle inequality on the editable data loses at most $k$ bits from its logarithmic cardinality term. Fixing the table switches costs no cycles. Since $|T|\le 2^t=o(k)$, one can choose a positive file whose records use every word of $T$. On this same file, changing any of the $kt$ independent data bits flips the verdict. Changing any one of the $|T|$ prefix switches currently allowing a word also flips it. These are physically disjoint bits. An unused word's switch has no effect on the verdict of that file. The scan still suffices when the whole table must first be learned from this input.

The physical audit reads the actual DIMACS, checks every clause and the dense header, and decides it using generic DPLL. It exhausts all single-record files at widths seven and four, checks multiple records and verifies the asserted individual byte-and-bit flips. It additionally tests all 128 table switches and all 112 data bits on one positive file with a variable table, and an unrelated table on both verdicts. It can invoke an external DIMACS solver on the original bytes. The mathematical packing and asymptotic bounds are manuscript arguments. The unrestricted SAT time lower bound remains open. ## Directly addressing a supplied table with a growing roster

There is a layout with the same $h=(3/8-o(1))N$ editable data bits for which **any** canonical negative file is rejected by some roster member in $O(\log(k+2)+\lceil k/p\rceil)$ steps, uniformly for $1\le p\le k$. The supplied table $T$ can be arbitrary. Taking $T=C_t$ gives the greedy code's $(1-o(1))h$ cycle lower bound on these same layouts. The program reads only the entries referenced by its stripe. It can certify a negative without constructing or scanning the table.

Use the greedy-mode width $t$, let $u=\lceil t/3\rceil$, and keep the paired decimal names $P_s$ and $Q_s$ with leading characters 2 and 3 and a shared $u$-byte octal suffix. For suffix bytes $b_0,\ldots,b_{u-1}$ in file order assign the table slot
$$
                  a=\sum_{j=0}^{u-1}(b_j\mathbin{\&}7)2^{8j}.
$$
The $2^t$ valid keys have distinct addresses below $M=2^{8(u-1)+3}$. The use of the byte positions themselves lets one packed load, a shift for alignment, and a mask recover the address. The data format uses the byte order of this packed load. The displayed convention takes the earliest byte as the least significant.

Write the header and eight guard clauses from the earlier construction. Each of the $M$ table slots occupies the same power-of-two byte stride $B=O(u+1)$. Start a valid slot with the complete line `-1 3 4 0`. Follow it by the clause $(-P_s,-Q_s,1)$ and then $(P_s,1,2)$ for an allowed key or $(Q_s,1,2)$ for a forbidden key. Pad with spaces after the final zero and before its newline. A hole holds three copies of the first line with the same padding. Include the harmless fillers $(-1,v,3)$ for every $v$ from 5 through the maximum identifier, giving a dense proper file. Each of the $k$ data records starts with the same `-1 3 4 0` line, followed by $(P_s,1,2)$. The guards force 1 and 2 false. Every assignment satisfying the local rows for a forbidden key forces $Q_s$ true and $P_s$ false, contradicting a data clause using that key. Conversely if all records use allowed keys, assign the two flags complementary values according to the supplied table to satisfy the entire file. A switch between allowed and forbidden changes just the low ASCII bit of the name's leading digit.

The prefix takes $O(M(u+1)+10^u(u+1)+\log(k+2))=o(k)$ bytes since $t\le \log_2(k+1)/16$ for large $k$. The additional fixed-size line per data record changes its size to $u+O(1)$ bytes. The preceding length and cycle estimates therefore persist. Fixing all table switches to a chosen $T\subseteq C_t$ containing at least half the code also retains the $(1-o(1))h$ estimate.

Member $i$ checks the bounded descriptor, header and guards from the beginning of the file. The descriptor determines the table start, stride and fixed record width. Subtracting $k$ record widths from the file length locates the first data record. Length and address bounds, masks for the packed digit field, and the stripe endpoints $\lfloor ik/p\rfloor,\lfloor(i+1)k/p\rfloor$ can all be computed in $O(\log(k+2))$ on canonical files. The endpoint arithmetic uses a bounded number of logarithmic-word integers, with ordinary shift-and-add multiplication and binary long division available for this setup. Each subsequent record uses $O(1)$ operations. Check its octal-byte masks and unused high bits, address its slot by a shift, and compare the digit bytes and surrounding clause text in a bounded number of packed words. The expected flag names at the slot reuse the digit field from the actual data row. A negative certificate requires exact text for the forbidden slot and its data record, each preceded by a verified newline and starting with the complete noncomment fence ending in a standalone zero. These fences ensure that even a clause opened in an earlier line terminates before the tested clauses. This verification needs no assumption about other slots, data records or fillers. Under the strict full-file syntax above, a successful local check entails rejection on every input. If it obtains no such certificate, the member falls back to the globally correct solver.

On a canonical negative, any member whose stripe includes a forbidden key finds a certificate within the stated time. For each pair $(i,p)$ the program is fixed across input lengths. The same algorithm with these two integer parameters gives constants independent of the roster size. The audit checks every key at each of five record positions for a greedy table and an unrelated table, across all five roster sizes. It checks 32 whole-file verdicts with DPLL and verifies that six damaged local certificates cease to justify rejection. [Physical audit](../audits/hamming_verdict_projection_audit.py)
