# What an unrestricted quadratic lower bound would require on one-bit pairs of SAT inputs

Suppose ordinary explicit proper DIMACS 3-SAT has no deterministic quadratic-time algorithm on a logarithmic-word RAM with unrestricted workspace. Fix any finite list of correct SAT solvers and any constant $C>0$. Then for arbitrarily large source lengths $n$ there is a block of $\lfloor\log_2 n\rfloor$ consecutive **byte** lengths with the following property. At every length in that block there are two dense, sorted, duplicate-free 3-CNFs differing in precisely **one encoded bit**. One is satisfiable and the other unsatisfiable. **Every listed solver takes more than $CN$ steps on both files** at each length, where $N$ is that file's bit length. The pairs throughout the block encode the same two children of one assignment prefix of a single satisfiable source. The word-width coefficient in the RAM class may be any sufficiently large fixed constant.

This is a necessary condition for the conjectured quadratic lower bound. The theorem below also gives a sufficient condition for an *upper* bound from timed answers on such pairs. No unconditional lower bound for their running time follows. The assignment search uses standard SAT self-reduction. The features specific to this construction are the common prefix, the single physical bit, the actual time charged to the simulations and the consecutive canonical file lengths. Priority for this combination is unestablished. [Related work on selectivity and search-to-decision reductions](https://www.sciencedirect.com/science/article/pii/S0022000096900616)

## Realizing both children with one changed ASCII bit

Normalize the input to a dense core with $v$ occurring variables and $c$ distinct proper clauses. An empty core can be decided directly. Otherwise $v\ge3$, $c=O(n/\log(n+2))$ and $v\le3c$. The clause bound follows because $c$ distinct serialized records need $\Omega(c\log(c+1))$ total bytes. Consider the children of a prefix assignment to variables $1,\ldots,x-1$. To pin any previously assigned variable $z$, add all four clauses on its desired literal and the two signs of two distinct helper variables from $\{1,2,3\}\setminus\{z\}$. This forces the literal and places no further constraint on the helpers. Sort and remove duplicates, allowing a pin clause that the original already contains. [Normalization and packed construction costs](dense-sorted-cores-for-ram-exhaustion.md)

Introduce $p=v+1,q=v+2$. Let $a$ be the first integer at least $v+3$ with last decimal digit `2`, and let $a'=a+1$. Force $p,q$ and every intermediate fresh name below $a$ false by the same four-clause construction. Encode $a\leftrightarrow x$ and $a'\leftrightarrow\neg x$ using their four binary implications, appending positive $p$ to each binary clause. These are proper clauses, and $p$ is false. Now append exactly one selector clause, either $(p\lor q\lor a)$ or $(p\lor q\lor a')$. The first child has a model exactly when the prefix extends with $x$ true; the second when it extends with $x$ false. All names through $a'$ occur on both children.

The selector rows have the same position in the two sorted files. No other core clause contains both $p$ and $q$. The alternative third names are equal until the last digit and ASCII `2` XOR `3` equals one. The header, all other clauses, and the length are identical. The rows can contain arbitrarily many earlier pins without changing this property.

Write $n=8b$. The unpadded children have at most $O(c+v)$ clauses and take $O(n)$ bits: all new names have $O(\log(v+2))$ digits, there are $O(v)$ pin clauses and $v\log(v+2)=O(n)$. Fix a sufficiently large integer $K$ independent of the input. Apply the canonical fresh-guard padding to both children to obtain exact byte lengths $Kb+j$ for $0\le j<H(n)\le b$. The unpadded lengths and header fields agree, so the same padding choices work for both. Each added row contains a fresh largest name above $a'$. Even if its two smaller names were $p,q$, it occurs after both possible selector rows or before both according to their signs. It cannot go between them. Thus at each requested length the *entire files* differ in one bit. The position of that bit may move between lengths. The initial logarithmic padding threshold is covered by the choice of $K$. [Canonical padding at every byte length](one-byte-successors-for-dense-sat-exhaustion.md#exact-length-padding-for-any-dense-core)

## Searching with one timely answer anywhere in a block

Let $t(n)$ be a polynomially bounded timeout and $1\le H(n)\le b$, with the parameters computable in the stated budget. At each prefix try each listed solver on both child files at each of the $H(n)$ lengths, with timeout $t(n)$ per execution. A completed YES selects its own child. A completed NO selects the other child. Any single timely answer suffices if the parent is satisfiable. When both children are satisfiable all sound answers are YES. When both are unsatisfiable the source assignment has already been lost or the source itself was unsatisfiable. If all attempts time out, choose the false branch as a default. At the end evaluate the resulting assignment on the normalized source and return that verification result.

A satisfiable source on which the search fails has a first step from a satisfiable restriction to an unsatisfiable restriction. Its sibling is satisfiable. A timely sound verdict from *either* child, from *any* listed solver at *any* length, would have kept a satisfying extension. Hence every one of those runs exceeded the timeout. All $H(n)$ pairs found in this way refer to this particular prefix. An unsatisfiable source always fails the final assignment check, correctly.

The work on either verdict is bounded by
$$
 O\!\left((1+v) H(n) [n/\log(n+2)+t(n)]\right).
$$
For each child, deduplicate and radix-sort the old rows with their pins. The padding has $O(n/\log n)$ guards because $r$ guards cost $\Omega(r\log(r+1))$ digits. Emit each sorted file in packed form in $O(n/\log n)$ host steps. Each fixed solver is simulated at its own word width with constant overhead per instruction. Use a host word coefficient large enough for a bank containing all guest addresses and separate space for the source, the builders and a log of the polynomially many writes. Restore changed guest cells and the input between trials in their charged time. Verification of the assignment costs $O(n/\log n)$ on the normalized triples. A singleton method that answered quickly everywhere on the path would thus be a uniform decision algorithm; the argument also permits the successful solver, length and side to change on every query. If only finitely many satisfiable sources fail, a finite exception table gives a correct solver at the same asymptotic cost. [Packed parser and guest simulation](dense-sorted-cores-for-ram-exhaustion.md)

For $d=2$ or $3$, choose $H(n)=\lfloor\log_2 n\rfloor$ and $t(n)$ a sufficiently large constant times $n^{d-1}$. Since each queried length in bits is at most $(K+1)n$, this timeout covers $CN^{d-1}$ with the prescribed $C$. With $v=O(n/\log n)$ the total work is $O(n^d)$. If that running time is impossible for SAT, infinitely many satisfiable sources must yield the simultaneous one-bit pairs. For $d=2$ a single-length test also allows timeout $C N\log N$. For $d=3$, taking $H(n)=b$ gives a whole linear-length block at timeout $C N\log N$. These formulations concern a fixed list of correct uniform solvers. They do not provide any of the required slow pairs unconditionally. In particular a pair sensitive to one bit can be easy on both endpoints.
