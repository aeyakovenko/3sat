# The cost of predicting only the incoming words of the next segment

**Research journal, 24 November 2026.** Fix a correct deterministic SAT solver $A$ running in $O(N\log^a N)$ time on the packed logarithmic-word RAM, for fixed $a\ge0$. Fix a deterministic RAM evaluator $D$ with word width $O(\log N)$, a bounded-arity instruction set and ordinary initially blank scratch on each call. There is a single solver- and evaluator-dependent family of unsatisfiable explicit formulas, one for every sufficiently large source padding length, with this property.

Fix $0<\kappa<\gamma<1$. At all sufficiently large lengths in that family, put $w=\lceil N^\gamma\rceil$ and let $E$ be the first rejecting halt. There are **$w$ consecutive internal times** in $\{1,\ldots,E-1\}$ such that at each of these times $t$, every honest $s$-bit description of latency $q$ satisfies
$$
 s+q>N^\kappa .
$$
The description has to predict only the following words. Run $A$ from its **genuine** state at $t$ for at most $2w$ instructions, stopping if it halts. At each work address whose first access in this segment is a read, require its actual returned value on that first read. Cache the value for repeated reads and use later native writes in the usual way. A step with multiple accesses uses their operational order. In particular the description has no obligation at other addresses. Its preprocessing may use the entire run and may be different at each $t$.

The evaluator can see $F$, the description and length, the segment start time, the public horizon $2w$, the current offset and address, the current native controller and the **strictly preceding local event history** in a fixed random-access format. The history includes the preceding operations of the current instruction. It excludes the reply being predicted and all future events. The latency bounds only the required calls on this genuine trajectory. Giving an evaluator less information preserves the conclusion. One may also give every query random access to the same arbitrarily precomputed bank of at most $N^\theta$ bits, for any fixed $0\le\theta<1$. The hard interval may vary with the bank and the exponents. The formula family is common to them all. ## Canonical block replays

A certificate advertises a halt time and increasing cuts $0=t_0<\cdots<t_P=E$, the controllers at the cuts, a payload for each internal start, and common bounds on the gap, row length and query time. The initial controller and zero work memory are genuine. From each claimed start controller run one *independent* block up to its next cut. Compute immutable reads from the true input. For a work read consult the local write and read cache; on a new incoming read call $D$ with this block's row and its current local history. Give malformed representations and timeouts a fixed deterministic reply. At the initial cut consult zero instead. Pad an early halt by idling in tentative replays. These rules define one canonical trace per block for any certificate that passes the syntax checks. They impose no correctness promise on $D$ at forged states.

A defect can be a wrong starting controller, a disagreement between a block's ending controller and the next claimed controller, or failure to end in a rejecting halt. The other type chooses an incoming read in a canonical consumer block $i$, address $v$ and returned word $y$. Choose either a strictly earlier block $j$ whose **last** write to $v$ differs from $y$, or an initialization sentinel with $y\ne0$. Require that no block strictly between this source and $i$ writes $v$. An actual inconsistent incoming read always has such a witness, by choosing its latest writer or the sentinel. Conversely any witness shows that this read disagrees with the write history of the canonical traces. The read is locally incoming, so there is no intervening write earlier in its own block. With no defects, induction on the concatenated events proves the complete controller and read history genuine. Hence $A$ rejects the original formula. No equality of whole endpoint memories is required. On a genuine schedule, honesty on the actual incoming reads suffices for each independent replay to agree with the corresponding true prefix, by deterministic induction inside that block. ## Checking a block without multiplying its length by its decoder clock

Let $g\le 2w$ be the maximum block length, $q$ the largest decoder clock and $m$ the number of public words, including source and certificate data. For any chosen block we can decide, deterministically in $\widetilde O(m+g+q+1)$ time under the SAT hypothesis, whether its canonical trace has a specified local property. Examples include an ending-controller mismatch, a particular incoming read, any write to a given address, or a last write with a specified value. Here and below the suppressed factors are fixed powers of the logarithm at a polynomial common scale.

First guess a complete candidate log of $O(g)$ words. Scan it to check native transitions, effective addresses, repeated incoming reads, the write overlay, and the local property. Only the first read of a new address before a write may use a proposed external word. A wrong decoded word has a short existential test. Select one such event, run the clocked $D$ on the block row and on the *claimed strict log prefix* at that event, and compare to its proposed reply. Give the decoder a read-only view truncated exactly at that event. Because all native transitions and caches have already been checked, the absence of such a mismatch forces every reply to agree with canonical replay, by induction over events. Conversely the canonical log passes. Scratch is fresh on each decoder invocation; the visible history here is native event data, not an unverified persistent private state of the decoder.

For any fixed nondeterministic bounded RAM test of $R$ steps on $m'$ public words, the explicit bounded-computation reduction and the assumed deterministic SAT solver decide its acceptance or nonacceptance in $\widetilde O(R+m'+1)$ native time. Thus checking the absence of a wrong reply in the guessed log costs $\widetilde O(m+g+q+1)$. Eliminating the outer guess of the log costs the same bound with another fixed polylogarithmic factor. This establishes the block property for arbitrary advertised data, including when a false log would force many expensive decoder calls if replayed directly. [Explicit bounded-run reduction and native width conventions](packed-band-transfer.md) · [Materialized public inputs](materialized-input-census.md)

To ask whether some intervening canonical block writes $v$, guess its index and run the deterministic block-property test. Apply the same reduction once more, then complement the answer if required. Finally test existence of any defect using a bounded number of such deterministic calls inside one more eliminated existential guess. The total number of eliminations is constant. Their public inputs contain the directory and at most constantly many logs of $O(g)$ words, so deterministic certification of this entire schedule costs $\widetilde O(m+g+q+1)$. The evaluator's many hypothetical calls are never all charged to a single block check.

## Windows on the signed formulas

Use the bounded universal interpreter on a source $x$ of $n_0$ bits with deadline $H=n_0^2$. Its locally addressable formula $F_x$ has $N=\Theta(H\log^3 H)$ bits. When a checker or $D$ reads $F_x$, implement that immutable load by the packed local generator on $x$, with polylogarithmic preprocessing. Nested bounded tests therefore carry $x$ and their actual auxiliary data as public inputs. They never need a public copy of the $N$-bit formula. Fixed physical word-width headroom covers each native solver used by the finitely many eliminations. The symbolic original-source addresses enter the formula as bit data.

A fixed verifier guesses integer parameters, controllers, schedule, rows and any common bank, and signals success if the schedule certifies rejection. The bank is identical at all calls and costs its full length in the public input. It checks gaps, clocks, lengths and endpoints before using their buffers. Fixed polynomial caps cover all honest parameters here. The horizon passed to every query is the advertised $2w$ even if a block ends sooner. On the verifier's own padded description $x$, $F_x$ is satisfiable exactly when the interpreter sees a timely signal. Every signal would certify that the correct solver rejects $F_x$. Hence $F_x$ is unsatisfiable and no such signal occurs by $H$. The verifier uses none of the real constants $\kappa,\gamma$ in constructing this family.

If every full window of $w$ consecutive internal times contained a cheap row with $s+q\le N^\kappa$, partition $\{1,\ldots,E-1\}$ into disjoint windows of $w$ starting at time one, with a possibly shorter suffix. Select one cheap cut from every full window. The initial and terminal gaps are at most $2w$, as are all intermediate gaps. If there is no full window, the one initial block already suffices. An immediate rejecting halt at zero is checked directly. The same horizon promise covers every chosen block. There are $O(1+N\log^a N/w)$ blocks, since $A$ halts within its time bound. The total true row bits plus the cut headers are $\widetilde O(1+N^{1-\gamma+\kappa})$; for the zero-window case there are no paid rows. Guessing these data, checking them and applying the constant-depth certification all take
$$
 \widetilde O(n_0+N^{1-\gamma+\kappa}+N^\gamma+N^\kappa+N^\theta)=o(H).
$$
The strict exponent inequalities absorb every fixed log loss, including bounded universal interpretation. This honest certificate would signal before the deadline, a contradiction. Thus at least one full window contains no cheap time. The horizon gives a matching upper bound in the power of $N$ for an evaluator supporting ordinary table lookup: store one actual reply per step and within-step read slot, with arbitrary fillers. This takes $O(w\log N)$ bits and constant query time given the offset and slot. The conclusion concerns the descriptions of future incoming values on an actual run under the fast-SAT hypothesis. It does not exclude that running time by itself.

## How many genuine incoming words a cheap predictor misses

Choose the fixed evaluator to support a baseline RAM predictor and a sorted exception directory of address–word pairs. Its program, data, lengths and any interpreter code are charged in the row. A common word-indexed interpreter for a fixed bounded-arity ISA can simulate each fixed baseline at constant instruction overhead, with a constant depending on that program. Use the hard family for this one wrapper.

At each time in the hard interval, run a baseline predictor on the **genuine** context of the first incoming read at every applicable address. Count addresses where the returned word is wrong. If the baseline description length plus worst-case query time is $o(N^\kappa)$, measured uniformly over the times under consideration, it makes
$$
 \Omega\!\left(N^\kappa/\log N\right)
$$
such errors at each time. Indeed, for $e$ erroneous addresses append their sorted keys and true words to the baseline row. This costs $O((e+1)\log N)$ bits, including headers. A binary search costs $O(\log(e+2))$ native steps; on a hit return the stored true word, and otherwise call the baseline on its original inputs. Every corrected reply keeps the subsequently exposed native history genuine. The repaired row is honest on the required domain. The lower bound on $s+q$ forces the claimed error count. This permits a different baseline row and a different exception set at every time.

In particular each of these truncated $2w$-instruction segments has $\Omega(N^\kappa/\log N)$ distinct incoming addresses whose word is nonzero. Even choosing the most frequent incoming word separately for each segment leaves that many incoming addresses with a different value: a baseline can encode any one word in $O(\log N)$ bits and return it in constant time.
