# Superlinear total trace change along one path of SAT inputs

**Research journal, 2026-11-24.** The [single-edit argument](dynamic-cuts.md) allowed the hard edits to live on unrelated inputs. Here all edits lie on one increasing path in the Boolean cube. Every edited position in the encoded formula changes from zero to one exactly once. Total change in a SAT solver’s execution along this path can exceed the length of any one formula.

## A chain bound

Use an explicit CNF encoding with ordinary fixed-width binary variable indices in literal records, with signs stored separately. For infinitely many bit lengths M there is a distribution on chains of valid bipartite Horn 2-CNFs of that length with the following property. For any fixed polynomial-clock deterministic word RAM correct on these templates for every database and choice of operation records, let D be the sum of the Hamming distances of successive time-aligned execution traces along a sampled chain. Then

    E[D] = Ω(M log M / (log log M)³).

In particular a single chain attains at least this much. Only variable identifiers in unit clauses change. A trace row includes the control, a constant number of registers, and its optional memory access and post-access value. Use the single-access normalization and O(log M)-bit words of the [replay lemma](dynamic-cuts.md). At halt write the answer to a dedicated cell, clear the registers and enter a common inert state. Include this constant overhead in the clock. Thus two halted, padded runs have identical subsequent rows even when their answers differ. The dynamic structure recovers the bit from the latest write to the dedicated cell in O(log log(T+4)) probes, using the same timestamp sets as the replay. The bound also applies to a machine correct only on these templates, which makes the statement nonvacuous independently of the existence of a polynomial-time SAT solver.

For the dynamical ingredient we use Ko's November 2026 preprint. Its Theorem 1.1 gives one distribution on N fixed query sets S₁,…,S_N⊆[N] and n=N^{1/4} distinct insertions, each followed by a query asking whether the inserted set is disjoint from a requested Sⱼ. Every correct online data structure with Θ(log N)-bit cells incurs Ω(n(log N/log log N)²) expected probes, excluding preprocessing. Ko allows randomized structures and small error on each query of each fixed legal sequence. We will use an exact structure and allow randomness in preprocessing. [Ko, Theorem 1.1 and §2.2](https://arxiv.org/pdf/2611.11508)

**Share one database among many batches.** Take K=⌈N²/n⌉ independent batches *conditional on the same preprocessed sets*, resetting the inserted set between batches. Put Q=Kn, so Q=Θ(N²). The expected charged cost during the K batches is Ω(Q(log N/log log N)²). To justify this use of the distribution, fix a batch number j. Construct a one-batch data structure that, given the sets in preprocessing, samples j−1 earlier batches from their actual conditional distribution and simulates their operations and resets in preprocessing. It then runs the proposed structure on its genuine operations in batch j. Its memory at that point has exactly the joint distribution in the K-batch experiment. On a database of zero probability under the hard distribution, use the explicit fallback from the outset. Earlier preprocessing coins convey no information about the current batch beyond the preprocessed sets. On other legal inputs a straightforward explicit data structure can handle any excess operations or departure from the alternating schedule, retaining a list of the genuine insertions at O(1) probes each. That overhead is lower order. If desired, choose j uniformly in preprocessing, obtaining the same lower bound on the cost averaged over j in a single application. The bound holds before charging any additional work to reset between batches.

**Encode a record in one literal identifier.** For the fixed database use variables Cⱼ for queries and Bᵢ for elements. Put in a clause (¬Cⱼ ∨ Bᵢ) for each i∈Sⱼ. Reserve N² fixed two-literal records, filling each absent position with the same implication from a fresh left vertex to a fresh right vertex, neither referenced by the units, so the encoded length is independent of the database. Add Q negative insertion units and Q positive query units. Initially the two kinds name their own unconstrained dummy variables. Their meanings during a batch are as follows.

* For insertion i, change a fresh negative unit to ¬Bᵢ and leave it live until batch end.
* For query j, change a fresh positive unit to Cⱼ and consult SAT. If an inserted i belongs to Sⱼ, the binary clause and the units force opposite values for Bᵢ. Otherwise set only the live queried C true among database query vertices, and set true exactly the element vertices it requires. This satisfies every clause. The dummy and retired positive and negative units use disjoint, unconstrained variable namespaces.
* Retire the query unit after answering it. At batch end retire the insertion units. Each unit has a field of low bits initially zero, enough to name any value 1 through N, and an initially zero retirement bit above that field. Set the appropriate low bits to name its live vertex. Setting the retirement bit remaps it to a disjoint unused namespace without erasing its suffix. Reserve aligned blocks of ordinary positive variable identifiers and declare the full range in the fixed header. Every bit in a mutable record changes at most once and always upwards. Setting the low bits in any order still gives valid formulas, including if an intermediate identifier denotes some other live vertex. Queries read the decision only after the relevant edits finish.

There are O(N) variable names and Θ(N²+Q) clauses of bounded width. Hence M=Θ(Q log N). The layout uses one occurrence of a logarithmic-length binary *name* for each operation. Encoding its bits as logarithmically many separately pinned variables would lose an additional factor of log N. Width-three-only formats can pad units and binary clauses with independent fixed-false variables using the [earlier construction](sat-extension.md), provided each mutable name occurs only once.

**Charge the replay.** Given a static machine A, maintain its full trace across these inputs in the dynamic data structure. Apply one-bit edits separately, using the previous replay lemma to pay O((1+d)log log(T+4)) probes for an edit of aligned row distance d. A changed encoded bit alters at most one input word. All auxiliary data used by the replay, including the ordered timestamp sets for every address, fits in polynomially many cells because T and the simulated address range are polynomial in M. Choosing a sufficiently large constant in Θ(log N) permits these cell addresses. Between dynamic operations all persistent state lives in cells. Within an operation the cell-probe model allows free computation on its probe transcript, including deduplication and chronological scheduling of affected rows. Record counters and the layout edits cost O(Q+M) beyond replay. Reading answers from the dedicated cell costs O(Q log log(T+4)) altogether. There are at most M single-bit edits, including resets, and T≤M^{O(1)}. Consequently

    Ω(Q(log N/log log N)²) ≤ O((M+E[D]) log log(M+4)).

This gives the claimed bound since (log N/log log N)² grows faster than log N log log N. It does not charge any look into the true future operation sequence. The fixed-length formula starts with all future records naming dummy vertices.

## Attempt to turn the chain into a long single run

For trace position t let vₜ count how many edits on the chain change its row. Double counting gives D=Σₜ vₜ. It would suffice for excluding a linear SAT clock to prove that some linear-time SAT solver, if one exists, can be normalized so its mean row variation on these hard chains is o(log M/(log log M)³), at a linear clock. A stronger sufficient condition bounds the variation of every row by this quantity. The counting identity alone gives only vₜ≤M. It does not reach either original polynomial clock.

**Test the normalization on packed parity.** Take M bits, iterate over packed words, and keep a single running parity bit. A lookup table on chunks of half log₂ M bits permits branch-free constant work per word after O(√M) setup. Along the chain flipping the first half of the bits one at a time, the parity register flips after every subsequent word on each edit. The total time-aligned row change is Ω(M²/log M), even with O(M/log M) word time on a packed input. A single register can repeatedly change for many independent reasons. Even a proof that each *bit* of each recorded word changes at most once would allow O(log M) changes per word, exceeding the desired sufficient bound.

**Test the reduction on its SAT promise.** Read all units to mark the demanded query vertices and the forbidden element vertices. A scan of the binary clauses detects whether a demanded vertex implies any forbidden one. Absent such a conflict all other query vertices can be false. Every record has O(log M) bits with a fixed layout and can be decoded in O(1) word operations. With O(N) initialized marker cells this decides every intermediate template in O(N²+Q)=O(M/log M) word operations. In particular a machine with that clock still has expected mean variation Ω((log M)²/(log log M)³) over its aligned rows. Therefore the chain lower bound applies to a family already having a linear-time static solver. An implication from correctness on arbitrary formulas would have to do extra work, for example yielding a reusable normalization that removes repeated row changes even on these restricted inputs. The condition is already impossible for any correct machine on the templates at a linear clock. Thus deriving it from an unrestricted linear SAT algorithm would itself rule out that algorithm. Correctness on the promises alone gives no route to it.

The online lower bound is Ko’s. The chain construction and trace accounting above are deductions from it and change propagation. Priority of this particular implication has not been established.
