## Two arithmetic operations with arbitrarily many read-only loads

Write $L$ for the initial contents as a function of address. Use all 64 targets and all 22,064 negative inputs satisfying $L(P)=L(Q)=L(M)=L(N)=0$. This set includes 00FF, so it tests the exceptional negative with two disjoint pairs. Before the first ALU, every available register table is an input column or literal. A load through a column gives zero, and a literal load gives a column or zero.

For any computed word $r$, the value $L(r)$ is an original column on that file or zero. Hence $L^2(r)$ is zero or $P$. Since $L(P)=0$ and $L(0)=P$, one has $L^4(r)=L^2(r)$. Giving unlimited read-only access between instructions adds only the three word tables $L(r),L^2(r),L^3(r)$ for each new arithmetic result. A two-ALU path can thus be simulated by giving the first ALU all 16 literals and all four columns, the second ALU those words and the four new tables, and the comparison those earlier words and the four second-stage tables. No bound on the number of loads is needed for this simulation on these files.

Exhausting these larger register sets rules out a single sound guard on 37 targets. The first ALU produced 1,182 distinct full tables. The second-stage tests examined 2,266,817 partial tables, retaining each concrete operation when a fast candidate survived. Only six comparison candidates needed checking beyond the fast blocks and all failed on a negative. A comparison using only earlier tables belongs to the one-ALU case, whose cap is eight. This eliminates the five-load, two-ALU, one-comparison read-only case. Compile and run `c++ -O3 -std=c++20 two_arithmetic_results_with_unlimited_native_reads.cpp -o /tmp/sat-two-results && /tmp/sat-two-results`. ## What the final physical read allows

Suppose the final comparison uses a fresh, unprocessed physical word $x$ against a word $y$ known before that read. Fix all input cells except the one just read. On a target its original value has never been read or overwritten. Changing it does not change the previous execution, the address selected for this last read, or $y$. Along this one-dimensional fiber the branch must reject every $x$ that overlaps the unchanged mate $m$. At the target, $m=15-x$.

For an unsigned initial interval containing the target, direct inspection of $x=4,\ldots,11$ leaves only $x=7$ with $m=8$. Every nonempty unsigned final interval contains 15, which overlaps every target mate. In signed order the initial interval begins at 8, followed by $9,10,\ldots,15,0,\ldots,7$. The only feasible upper target values are $8,9,11$. In each case the very next word in signed order conflicts with the mate. Consequently an inclusive comparison must have $y=x$ and a strict one must have $y=x+1$. A signed final interval includes 7, which conflicts with every target mate except 8, so it permits only $x=7$. A disequality accepts all but one potential word and cannot reject all overlaps with a nonzero mate. Equality requires $y=x$.

Even if the last address can adapt to the input, the presence of any specified value $v\in\{4,\ldots,11\}$ in the four words covers at most 28 targets: either $p$ or $q$ must be $v$ or $15-v$. Thus unsigned order, signed final intervals, and any fixed literal serving as the necessary equality or signed-prefix endpoint are already below 37. If the last address is fixed rather than chosen from several missing cells, signed initial intervals cover at most $3\cdot8=24$ targets.

When **every ALU produces a fresh address**, the last read is followed by its comparison without further arithmetic. Its other operand is a literal, an earlier fresh word from a different physical cell, or an arithmetic result that must be below four on every accepted target. Such a low result cannot equal a high $x$ or the high $x+1$ needed by signed prefixes. A different raw word equal to $x$ occurs only across the two mate pairs, forcing $p=q$ or $p=15-q$, covering at most 16 targets. For the signed prefix restricted to $x\in\{8,9,11\}$, existence of another raw word equal to $x$ holds on 12 targets and existence of one equal to $x+1$ on 16. These counts follow by listing the eight possible $p$ and $q$. The same reasoning permits a store: fresh reads still return original data on the target, and absence of a prior read or overwrite of the final cell preserves its fiber. This treats all three-indirect three-ALU paths and all two-indirect two-ALU paths when the four loads are fresh.

With three ALUs and two indirect fresh loads, suppose the final ALU gives the last address. For signed-prefix support above 36 the one non-address ALU would have to supply the high endpoint $y$. The raw and literal endpoint bounds above apply regardless of how earlier addresses varied. On the target family alone, enumerate the first two operations: either the first selects one of the two omitted cells and the second computes $y$, or the first computes $y$ and the second selects the earlier indirect address. The remaining omitted cell is the last. Grant the last address for free and enforce only the necessary conditions $x\in\{8,9,11\}$ and $y=x$ or $y=x+1$. Across the six pairs of omitted addresses, the largest counts are 24 for inclusive order and 25 for strict order. In contrast equality $y=x$ without the signed-prefix restriction can cover all 64 positive files in this test. Its verification requires information from negative inputs.
