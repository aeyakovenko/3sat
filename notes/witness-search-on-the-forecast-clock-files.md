# Which SAT files would a passing forecast lift actually refute?

There are two different conclusions. On the original learned-clock construction, a passing lift would give a computable sequence of ordinary, satisfiable 3-CNFs on which successive selected clocks answer NO. Eventually there would be an actual SAT counterexample for **every** clock in any prescribed finite code budget. On a different construction that first tries a fixed witness-finding program, every bounded-width lift fails unconditionally. In fact, after this change even width $o((\log W)^{1/4})$ is too small. The construction can still enumerate every unmodified raw program. A comment-free bitonic encoder preserves each of the three SAT clocks without adding inert bytes. No passing lift has been found on the original construction. The distinction matters for trying to turn a finite exhaustion into a lower bound on unrestricted machines. ## Uniformity of the clocks and of reporting a witness

Fix $k=1,2,3$, an ordinary direct binary numbering of clocked RAM programs, and a fixed implementation of the earlier common guest. Its selected code $i(n)$ is the least index not yet refuted in $n$ tape transitions, where $n$ is the bit length of $W$. Use canonical padding $W=w_0 2^h$ with $n=h+O(1)$. Use direct binary constants for the clock multiplier, the word-size coefficient and the instruction fields. The numbering can use shortlex descriptions with invalid strings denoting a fixed dummy. Every fixed clock in the model has an index. There are at most $n$ completed refutation reports, hence $i(n)\le n+1$ for indices starting at one. Every numeric constant in the selected description is at most $\operatorname{poly}(h)$. A fixed program generating or executing queries on its behalf can therefore charge a polynomial in $h$ uniformly over the possible selections, even when no correct clock exists. This specification is important. Index magnitude would give no such bound for a multiplier supplied by an arbitrary unbounded computation.

Use the earlier outer SAT queries for bounded nondeterministic acceptance with a **directly checked** branch for folded partial certificates. Let $B=2^j$ be its instruction allowance. For $1\le B\le2^n$ use an explicit row per allowed instruction, with canonical idle rows. For a known accepting branch of length at most $B$, the file **and** a satisfying assignment to its literal occurrences can be produced on an ordinary logarithmic-word RAM in $(B+1)(h+2)^c$ steps at the aged stages below, where the fixed $c$ is independent of $j$ and the selected clock. Its encoded length $N$ is at least $B$ and at most $(B+1)(h+2)^c$, after increasing $c$.

To reconstruct the witness, initialize the genuine input and the supplied nondeterministic choices. Simulate the accepting prefix and fill the idle rows. Generate the constant number of memory events per step and their address/time sorting checks. Computing the deterministic sorting network and all ordinary gate values, including the binary arithmetic, costs $B\operatorname{poly}(h)$ operations since event words and $\log B$ have polynomially many bits in $h$. Choose the full-equivalence Tseitin emitter with explicit decimal variable names. With the gate values available, a second pass supplies the truth bit of every occurrence in file order. Divisions with auxiliary witnesses can be filled by actual quotient and remainder. A Beneš routing witness, if used, can be calculated from the known permutation; an ordinary deterministic bitonic sort suffices here. Simulating wider virtual words in limbs and sparse addresses by tries costs a polynomial in $h$ per step. At $B=2^{\lfloor\eta h\rfloor}$ below, $\log N=\Theta(h)$, so an ordinary machine can address all these arrays with a fixed logarithmic-word coefficient. The input computation of $i(n)$ is polynomial in $h$. The direct branch does not need correct answers to any inner SAT call. These are properties of the chosen transparent bounded-run encoder, not of arbitrary many-one reductions to SAT. ## A passing cycle supplies a moving ordinary counterexample

Take any fixed rational $0<\eta<1/k$ and set $B_h=2^{\lfloor\eta h\rfloor}$. If a specific fixed cycle is valid on its progression in the original common header, its expanded pin certificate and its accepting direct check can be computed in $\operatorname{poly}(h)$ time there. Hence the outer file at stage $B_h$ is an actual YES for all sufficiently large widths of the progression. Meanwhile $V(W)=0$ by soundness of the pin certificate itself.

An early return from any reporting branch would make the observed bit one. Barring such a return, the whole-history branch reaches this particular stage within the physical budget. All earlier explicit outer queries have length $O(B_h\operatorname{poly}(h))$ and their timeout-totalized answers cost $O(B_h^k\operatorname{poly}(h))$ in total, allowing polynomial overhead for restarts, setup, and the varying binary code. More precisely the common initial division-table setup is separately $o(W/n)$ and all remaining work through the stage is $2^{k\eta h}\operatorname{poly}(h)=o(W/n)$. A supposed YES on this outer file would make the branch return and latch in time. The selected actual clock thus answers **NO on this specific satisfiable DIMACS file**. The argument here uses its worst-case timeout on all files, independently of its correctness.

There is an effective procedure if a passing cycle is supplied. Run down its progression, generate the files with their satisfying assignments, and test the actual selected clock. The finitely many small exceptions need no supplied cutoff: retain only checked false negatives. Wait in the external computation until the dovetailed refuter reports the offending clock, then resume on the progression at a length after that report. Its selection has strictly increased, and all smaller indices have already been reported. Each skipped index likewise has a genuine counterexample among the reporter's records, possibly of the opposite polarity. This gives every finite code budget in order. It gives neither a time bound on the waits nor a common file refuting all programs. A finite cycle would supply the missing input to this procedure. The Lean lemma checks escape past all finite indices from eventual defeat on a cofinal set of lengths. [Lean quantifiers](../lean/MovingClockRefutations.lean)

## A fast front end for explicit positive witnesses

There is a fixed YES-sound standard RAM routine $D$ of worst-case time $O((N+2)^{3/2})$ on explicit SAT files of $N$ bits. At sufficiently large lengths it answers YES on any file for which a fixed word-RAM program, given that file, produces consistent satisfying occurrence values within $O(N^{9/8})$ steps in the witness language below. No promise on the other files is needed. Its second outcome is abstention.

One construction tries the first $\lfloor\log_2(N+2)\rfloor$ binary program descriptions in shortlex order. Give each at most $O((N+2)^{5/4})$ host steps. Use a fixed load/store word language with standard bit operations, bounded space within the host's logarithmic address limit, and uniform dispatch. Fixed generators here need only arrays of $N^{1+o(1)}$ words or $O(N^{9/8})$ words; a fixed large host word coefficient suffices. Fixed-code interpretation and polylogarithmic overhead fit the slack between the two exponents. Charge initialization and clearing used memory to the hard cutoff. Check the output against the actual formula by interning decimal names, verifying that repeated names agree, interpreting signs and testing each clause. These checks take $O(N)$ using a radix trie on the literal spelling, normalizing leading zeros if necessary. On a legal file no arithmetic on a very large declared variable upper bound is needed for checking a proposed assignment. All timeouts and failed checks abstain. The underlying algorithm is Levin's universal search. Chen, Flum and Müller distinguish such witness search from optimality of SAT decision algorithms on individual inputs. The credential here is the actual assignment on the particular outer file. [Levin, *Universal Sequential Search Problems*](https://www.mathnet.ru/eng/ppi914) · [Chen, Flum and Müller, *Hard instances of algorithms and proof systems*](https://www.fim.uni-passau.de/fileadmin/dokumente/fakultaeten/fim/lehrstuhl/muller/Hard_instances.pdf)

On the old header a single fixed generator recovers a witness from the aged file on any passing progression. Given $N$, try $h'$ up to $O(\log(N+2))$, skipping any $B_{h'}>N$. A program with the fixed header, $\eta$ (choose rational) and proposed cycle hardwired reconstructs each public $W'$, selection, and the accepting direct branch if the width belongs to the progression. Use a fixed polynomial cutoff on this known check. For each match to the input file output its occurrence witness, and independently validate it. At the true $h$ a match exists. Each eligible trial costs at most $(N+1)\operatorname{polylog}(N+2)$, including comparison; the number of trials is logarithmic. The generator may explicitly check its prospective witness before returning, to handle any collision of parameter encodings. Thus the moving-index false negatives above occur on files that this single front end accepts in time $O(N^{3/2})$. A full correct SAT solver can always use the front first and resort to exhaustive assignment search after an abstention. The ordinary files obtained from a possible passing cycle would establish successive **errors of selected clocks**; these particular files are easy positives for another actual solver.

## Why a small change of header prevents a bounded-width cycle

Normalize each timeout-totalized raw clock by trying $D$ before it. Return YES if $D$ succeeds, else use the raw answer. For $k=2,3$ the normalized class contains a globally correct $O(N^k)$ decision procedure if the original class does, with a changed multiplicative clock constant. A correct raw decider's YES and NO answers remain correct. Implement the new reporter and guest with this same normalization and direct binary parameters. Their header changes. A passing cycle on that header would supply the very witnesses found by $D$ at the aged stages, including when no raw code is globally correct. This conflicts with the required NO on the selected outer query. There are consequently **no** passing cycles of any fixed certificate width on that header. This conclusion does not transfer to the earlier unmodified header.

Here is a linear-time version on a specified standard DIMACS layout. Prefix a valid comment giving the bounded-run query parameters, and add a second comment before the problem line or an allowed whitespace region of $\Theta((B+1)(h+2)^{c+4})$ bytes, increasing $c$ to dominate the fixed encoder's construction and witness-generation work. The actual core contains at most $(B+1)(h+2)^c$ occurrences. This preserves SAT truth, and all stage lengths still have the form $(B+1)\operatorname{poly}(h)$. Ordinary unpadded DIMACS elsewhere remains an allowed input. A solver for the comment-free core can also be used after a linear-time strip of the two leading comment lines, with no increase in its input length.

Parse any received formula once in $O(N)$, storing dense variable indices, signs and clause boundaries for its $m$ literal occurrences. Try candidate generators with geometric shares of an $O(N)$ host budget, charging generation, memory reinitialization and actual checking to each share. For example give one trial to each of the first $O(\log(N+2))$ indices with at most $\lfloor N/2^{i+1}\rfloor$ host steps. Each fixed generator eventually gets a constant fraction of $N$. With the shared parse a trial validates an occurrence assignment in $O(m+1)$ using a touched-name list. Empty clauses can be rejected in the shared parse, so a positive file has at most $m$ nonempty clauses. A fixed generator reads the advertised parameters, simulates the known short accepting branch and fills just the core occurrence values. It need not read or reproduce the padding. On the specified files its total work plus validation is $o(N)$, so eventually it fits its share. False metadata never bypasses checking against the parsed file. This fixed front end is YES-sound, costs $O(N)$ worst case, and can precede even an $O(N)$ raw decider. On this padded common header the same contradiction excludes all bounded-width cycles for any of $k=1,2,3$. The generic bound $B\operatorname{poly}(h)$ alone does not give a linear-time result on an arbitrary unpadded layout.

## Keeping every raw program in the enumeration

There is an implementation of the original least-unrefuted construction for which every choice is normalized, although **every unmodified clock really occurs in the numbering**. In zero-based order list the normalized $D'_j$ at index $2j$ and its raw partner $D_j$ at $2j+1$, allowing duplicate descriptions. Whenever $D'_j$ errs on a legal file $X$, $D_j$ errs on the same file with the same answer. The front end cannot cause an error, since it returns only checked YES or abstains. The refuter tests raw codes fairly in their own right. On finding an error of a normalized code, report the raw partner before reporting the normalized one. This refuter is sound and complete. Even during a partially written report, a completed report on $2j$ implies a completed report on $2j+1$. Therefore no odd index can ever be least unrefuted.

For literal native implementations give the normalized program disjoint scratch and raw-memory banks, initialize the input in the raw width convention, and simulate its exact timeout and invalid-return semantics after abstention. A host word width above the raw and front widths, with additional tag and counter bits, makes direct virtual memory tagging possible. The wrapper itself has an explicit multiplier covering both phases at all lengths. With direct binary raw fields the wrapper overhead, clock multipliers and width coefficients can be bounded by a fixed polynomial in $j+1$. Thus even before any stabilization the selected clock has the uniform bounds used above. For the superlinear front this pairing already works with the original unpadded bounded-run files for $k=2,3$. It proves that **an assertion of a passing cycle for every allowable exhaustive numbering and complete refuter is false**. It does not decide whether a particular different numbering has one.

## Linear time on comment-free files with no inert padding

The earlier common-guest construction permits an ordinary bitonic bounded-run encoder. Fix the following explicit layout. At the aged stages $B=2^{\lfloor\eta h\rfloor}$ use $\Theta(B)$ memory events and a power-of-two bitonic sorter, with $\Theta(h)$ bits per event. Build the full compare and conditional-swap gates on the data lanes, with fresh output names even for lanes that happen to be constant on a particular trace. There are $\Theta(B\log^2 B)$ comparators. The fixed native instruction rows, including schoolbook bit arithmetic, need $O(Bh^2)$ additional gates. Thus the total gate count $g$ is $\Theta_\eta(Bh^3)$. Emit bounded-fan-in gate equivalences as proper 3-CNF using fixed false anchors for shortened clauses and a dense distinct decimal identifier per gate. Each fresh output appears in the file. Consequently the count of literal occurrences $m$ is $O(g)$ and the actual bit length is $N=\Theta(g\log g)=\Theta_\eta(Bh^4)$. The lower bound follows even just from spelling all the distinct output names. No comment, long whitespace record, tautological bulk or input side channel is needed.

For a known accepting branch the **occurrence truth bits** can be generated in $O_\eta(g)$ instructions once the short branch has been recovered. Use the usual three nested bitonic loops for layer, distance and item. All numeric gate IDs and array indices fit in $O(1)$ local words since $\log B=\Theta(h)$. At each comparator, retain the array of wire IDs and values of its input records, generate its $O(h)$ gates and assign the new record IDs and bits. Generate the arithmetic and transition gates in the same topological way. The named values of supplied nongate choices (including memory records) are obtained from the short true branch followed by the canonical idle continuation; produce the $O(h)$ bits per row explicitly. Use a counting pass if a gate-ID base must be known in advance. Visit the clauses in the emitter's order and output the bit value of each occurrence by numeric ID. **Decimal serialization is unnecessary for this output.** Full-equivalence gates, pinned input bits and the anchor clauses all have occurrence values available. In particular generating the actual file byte for byte is not a prerequisite for witness search.

The input length $N$ alone gives a bounded list of candidate $h'$: filter by $c_1 2^{\lfloor\eta h'\rfloor}(h'+1)^4\le N\le c_2 2^{\lfloor\eta h'\rfloor}(h'+1)^4$ using fixed effective positive constants and handling finitely many small lengths separately. This costs $\operatorname{polylog}(N+2)$, for instance by trying $h'=O_\eta(\log(N+2))$. The filtered list has bounded cardinality since the scale doubles in a bounded number of padding lengths. For a canonical input file one candidate is its true padding. Use a fixed generator per candidate ordinal, or allow a generator to try all candidates and validate each. On these files generating each occurrence assignment and checking it after the one shared parse cost $O_\eta(g)=O_\eta(N/\log N)=o(N)$, plus the separate witness-discovery cost. If the layout or guessed parameters do not match, only the verified assignment on the real input can cause acceptance. The bounded-list construction does not require decoding a machine program hidden in decimal syntax.

Use a fixed universal word-program interpreter with constant overhead for each fixed generator here. It can use a fixed-width fraction of the host word for virtual addresses, separate tagged input and work banks, and a touched list to clear used memory. Arrays of $O(g)$ ordinary words fit, as do $O(h)$-bit machine values in a constant number of limbs. Fixed-code simulation on this witness language need not pay a multiplicative $\log N$ per operation. The single $O(N)$ front from the preceding section therefore finds every lifted witness eventually on this unpadded bitonic layout, using geometric shares and the parse shared across all trials. The same reasoning works for more general proofs when their discovery and the non-idle run take $O(2^{\alpha h})$ and $O(2^{\beta h})$ with $\max(\alpha,\beta)<\eta$; the fixed polynomial simulation overhead on those parts is absorbed by the exponent gap.

Pairing the clocks now gives the unconditional absence of fixed-width cycles for **all three clocks on one permitted kind of comment-free encoding**. Only the chosen ordering, refuter and permitted bounded-run implementation have been specified. A passing cycle on some other specific original program would still have the refutation consequence above.

## Exhaustion of growing matrix widths

For the physical pin format the time to find a width-$w$ certificate at **one** padding length can be bounded by $2^{O((w+1)^4)}\operatorname{poly}(h)$, keeping backpointers. This improves the earlier exponent six for this application. Each separate failure test is the pointwise product of at most three factors of width $O(w+1)$, and a fixed-size interval test. Absorb the interval factor into one of the three. Each factor has one initial row; it may itself be a direct sum implementing a sum of predicates. After a fixed timestamp prefix the product test has a decomposable row $x_1\otimes x_2\otimes x_3$. Images under a fixed timestamp symbol are again decomposable because the transition is a tensor product. Consequently a reachable space of dimension at most $O((w+1)^3)$ has a basis of actual such rows.

Store the **factor rows** of a basis, for $O((w+1)^4)$ bits. When consuming a matrix layer, take all 64 symbol images of this basis, expand temporarily into dense rows for elimination, and retain an independent subset of the *original* images with their factorizations. Row reduction itself need not preserve decomposability. Deterministic ordering of the candidates suffices. Distinct encodings of the same space are harmless: even counting all ordered factored bases gives at most $2^{O((w+1)^4)}$ encodings. Keep one such record per test in a fixed tuple. The $2^{O((w+1)^2)}$ possible next layer letters and the polynomial cost of elimination are absorbed in the same bound. Dynamic programming for $h$ layers, storing predecessors, gives actual layer matrices when a certificate exists. Cardinalities, masks and addresses of the large search can be handled in a fixed multiple of $\log N$ bits in the range used below. For example enumerate encodings into a direct-indexed bitmap or a binary trie and charge polynomial overhead in their bit length. This argument depends on having at most three factors. The generic gate checker for truth tables of arbitrary arity does not by itself have this exponent. The tensor-product description of a pointwise product and the forward-space method are classical. Priority for the factored-space search bound in this forecast application is unestablished. [Schützenberger on matrix representations of finite automata](https://igm.univ-mlv.fr/~berstel/Mps/Travaux/A/1961-4DefinitionFamilyAutInfCtl.pdf)

Fix the header, hence its constants and $w_0$. For a sufficiently small constant $c_0>0$, searching all $w\le c_0 h^{1/4}$ at the actual length $h$ costs $o(B_h)$, and the recovered certificate has checking time $\operatorname{poly}(h)$. Run this search from the witness generator instead of assuming a cycle. Stop once a valid certificate is found. The same ordinary replay, or the metadata-based one in the padded layout, produces an accepting assignment. It follows that on **every sufficiently large width** of the respective normalized header, every valid folded physical certificate has width $\Omega(h^{1/4})=\Omega((\log W)^{1/4})$. A width with no valid certificate satisfies the exclusion automatically. The same proof gives a true-zero example: in a separate guest use only the directly checked branch and a timeout of one fixed, globally correct SAT solver that runs the linear padded front first and uses exhaustive assignment search on abstention. Give the timeout sufficient constant to finish the front and answer NO on timeout. Every YES is sound, so the observed bit on its own prefix is always zero. Every sufficiently large such canonical width still has the stated lower bound on certificate width. A full register-history table gives a finite certificate on every zero width. This result bounds a proof format for a true assertion. It does not lower-bound the running time of all SAT solvers.

## A limit on an effective successor rule

A normalization can use the entire available exponent. For $k\ge2$, instead of the $N^{3/2}$ subroutine allocate geometric shares of $O(N^k)$ total host work to validated witness generators. Each fixed generator with work $O(N^{k-\epsilon})$ eventually fits; comparing or verifying a file in linear time fits as well. For $k=1$ use the preceding shared parse with the comment-free bitonic core or with the explicit padding. The frontend and clock keep their fixed code as $h$ varies. On the resulting designated header the following two bounds cannot occur together at infinitely many canonical widths:

* A single effective procedure, given the width, finds a valid certificate in $O(2^{\alpha h})$ steps for some $0\le\alpha<1$.
* Guessing and directly checking that certificate on the native branch costs $O(2^{\beta h})$ for some $0\le\beta<1/k$.

For $k\ge2$ choose rational $\eta$ with $\max(\beta,\alpha/k)<\eta<1/k$ and take stage $B_h$ as above. A generator for the SAT file can impose the search cutoff separately on every prospective $h'$. With $B_{h'}\le N$ and only $O(\log N)$ possibilities, search and replay together cost $N^{\max(1,\alpha/\eta)+o(1)}$. This is strictly below exponent $k$. Wider words in the search may be simulated with polynomial-in-$h$ overhead when all work and storage fit $2^{O(h)}$ and virtual words have $O(h)$ bits. For $k=1$ take $\max(\alpha,\beta)<\eta<1$. On the bitonic layout a bounded list includes the true parameters, search is $o(N)$, and occurrence replay and checking cost $O(N/\log N)$. The padded layout also gives $o(N)$ work after the shared parse. In both cases an early successful return or a timely YES at this stage contradicts the certified zero. Fixed polylogarithmic factors and finite small exceptions are absorbed by the strict exponent margins.

For example, suppose a proposed induction starts from a fixed finite certificate, has an effective list of children at the next padding length, and each valid node always has at least one valid child. If producing and testing the entire list per node costs $2^{o(h)}$ and the certificates have $2^{o(h)}$ direct verification cost, taking the first valid child constructs the next proof. Iterating to length $h$ still costs $2^{o(h)}$. Such a successor rule cannot close on this normalized program. Even when some valid nodes have no valid descendants, exhaustive search has the same implication if the **entire** tree up to each successful length can be generated and tested in $2^{o(h)}$ time. These statements leave room for small width-dependent proofs that are expensive to discover. They also leave the original, unnormalized common header open. A proof by nonuniform existence needs to account for the difference.

## Direct checks

The fixed staged calibration writes ordinary proper DIMACS bytes, authenticates the proposed cycle and an accepting checker path, and changes its own latch on receiving a verified YES. Across six sizes, 31 actual queries totaling 106,698 bytes produced a quiet-prefix certificate and then a latched one. Each of six single-byte same-length UNSAT edits failed, and so did all six proposed post-reply zero observations. On the two smallest sizes a second CNF wires the byte comparison, assignment check and latch directly with no supplied reply bit. Unit propagation rules out zero for the two genuine files; the two edited files have explicit models with latch zero. This exercises a small self-consuming program. It is separate from the universal learned-clock construction. [Runnable DIMACS experiment](../audits/transparent_lift_file_audit.py)

The gate-level checker accepts a finite table for each Boolean gate, affine lags $a+b2^h$, sparse negative one-seeds, a polynomial horizon and a proposed prefix/block/suffix of binary matrices. It checks all repetition counts by exact finite reachability, and replays any reported bad width, time, gate and input assignment numerically. A sample involving a signed lag passed with 18 reachable block-boundary states. The independent small-base tests cover 584 direct semantic comparisons and 24,670 arithmetic comparisons. Run `python native_gate_lift.py --example | python native_gate_lift.py -` for the sample and `python native_gate_lift.py --self-test` for the tests. The complete learned guest's gate list and a passing certificate for it have not been produced. The asymptotic encoding, witness search and factored-basis estimates above are manuscript arguments. [General gate checker](../audits/native_gate_lift.py)

A second program exhausts layer schedules for fixed start and output masks and a supplied finite alphabet of layers. It builds the finite graph of sets of boundary states and tests for a reachable repeating block with safe observations. Its resource cap returns UNKNOWN. On two sign variants of a four-variable ordinary SAT file it exhausted the four available one-dimensional layers, found a recurrent schedule on the positive fixture, and excluded recurrence on the negative fixture. Tests for width two checked 48 schedules and 432 timestamp comparisons. These files test the synthesizer on prescribed finite controllers.
