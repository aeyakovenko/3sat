# Choosing a memory check before or after seeing a false SAT execution

The order of the quantifiers in the semantic SAT lower bound can cost exponentially many guard states. This can be seen on ordinary proper SAT inputs by a complete finite classification. In this note SAT means that **two private lists differ**. On an equal pair the true answer is UNSAT, and the checker must catch false acceptances.

Let $X$ be the set of possible lists, and first require the entire left input to precede the entire right input. A machine may use unbounded time and untrusted writable memory on either side. Assume its trusted controller transferred across the cut has at most $H$ states. There are $G$ noninterfering deterministic checkers with $K\ge2$ possible boundary states each. Each checker passes every genuine *accepting* execution on every input. If there is an external acceptance cutoff, charge the elapsed time to $H$ even if the CPU cannot read it. The left input fixes the genuine boundary state of the CPU and of every checker, independent of the right input. The definitions of proposed work replies and explicit false acceptance are the ones in the [adaptive monitoring theorem](adaptive-memory-checks-and-codes-at-a-sat-cut.md). Consider the following two requirements for a fixed $1\le d\le G$.

* On each equal file, **every false accepting trajectory** is detected by at least $d$ checkers. The detecting set may depend on the trajectory.
* On each equal file, **at least $d$ checkers each detect every false accepting trajectory**. These checkers are chosen with knowledge of the entire input, before the trajectory.

With free local encoders and fixed boundary alphabets, the exact maximum number of labels $|X|$ is, respectively,
$$
 H A_K(G,d)\qquad\text{and}\qquad
 H\max\left(K,\left\lfloor G(K-1)/d\right\rfloor\right).
$$
Here $A_K(G,d)$ is the usual maximum size of a $K$-ary code of length $G$ and minimum Hamming distance $d$. These statements concern every correct strict two-phase solver in the lower direction. For $d=1$ the capacities per controller are $K^G$ and $\max(K,G(K-1))$.

## A single splice and a singleton state

Partition left labels by their genuine CPU boundary state. In one such fiber choose $x\ne z$. On $(x,x)$ take the genuine prefix for $x$ followed by the genuine accepting suffix for $(z,x)$. Answer each work load of that suffix as in its run on $(z,x)$, even if that answer contradicts the earlier writes of $x$. Actual immutable input, CPU instructions, register transfers and program counter are all correct. The resulting trajectory is one candidate on the equal file. Every checker that has the same state after $x$ and after $z$ passes it.

For the first requirement this forces state vectors in the same CPU fiber to have distance at least $d$. For the second requirement, *each* checker protecting $x$ on its own must give $x$ a state shared with **no other label in that CPU fiber**. In a fiber containing more than $K$ labels, at most $K-1$ labels can have singleton states for a given checker. Count incidences of labels with individually protecting checkers. A fiber of size $M>K$ satisfies $dM\le G(K-1)$, proving the second bound. The number of labels individually protected by $d$ checkers in a larger universe obeys the same incidence bound, even when the other labels are allowed to have none. [Finite singleton and incidence lemmas](../lean/GuardedDiagonalCodes.lean)

To attain the first bound, transmit a controller digit and put the left codeword in untrusted memory. Accept on a controller mismatch or a mismatch between the right label and the purportedly retrieved left label. For this construction the work reply must be a *valid label*, or equivalently the checker may compute its own code coordinate from the raw sequence of retrieved left digits. If the raw purported label is invalid, make the CPU reject. On an equal file every false acceptance then substitutes a different valid label, and the corresponding $d$ coordinates catch it. On a genuine unequal file it accepts. This validity check matters: if arbitrary corrupted codewords outside the code could cause acceptance, one altered coordinate could otherwise suffice. For free local computation the label can be a single untrusted alphabet symbol or the validated sequence in a fixed alphabet; the physical polynomial construction below uses raw field digits.

To attain the second bound, if $M\le K$ let every checker remember the whole label within the CPU fiber. Otherwise assign each label $d$ distinct checkers, distributing assignments in successive cyclic order modulo $G$. Each checker has at most $\lceil Md/G\rceil\le K-1$ assigned labels. It remembers the exact identity for those labels and uses one catch-all state for the rest. Given a remembered identity it compares the subsequently reported left label against that identity. This rules out every false accept on those equal inputs. The controller digit can select a separate codebook on both sides without using a checker state.

## A near-linear native computation with an information-sized gap

Set $X=[q]^m$, with $q$ a prime of order $m$, for example a prime between $2m$ and $4m$ at each scale. The left clauses enforce $z_i=u_{x_i}$, the right clauses compute $b_i=z_i\mathbin{\mathrm{XOR}}u_{y_i}$ and require some $b_i=1$. If any two compared indices differ, choose opposite Boolean values for those two $u$ variables. If every pair agrees, no model exists. Unused indices can be declared; fixed-width fields, false padding variables and a public OR chain give independent proper input blocks of $N=\Theta(m\log m)$ bits. A fixed RAM recognizes the template, stores the genuine raw digits, compares purported digits in range with the right digits and accumulates a mismatch flag. It scans every row and decides only at the end. Along either genuine verdict this takes $O(N)$ time with ordinary parsing or $O(m)$ on the packed fixed-stride layout. Recognition uses the real input and registers, so a fabricated work reply on a template input cannot trigger the general SAT fallback. The public scale can use a prime-size name bank as a parameter; a template recognizer need not test primality to decide whether the lists differ. [Construction of the proper clauses](sparse-cut-memory-and-the-price-of-zero-reads.md)

Suppose a checker on a strict one-pass solver has $b$ advice bits and $s$ bits of transferred state. Its advice can depend on the whole unfavorable file. The second bound at $d=1$ gives
$$
 b+s+\log_2 H\ \ge\ m\log_2 q=\Theta(N)
$$
if some advice string blocks **every** false acceptance on every equal file. This holds even with unlimited prefix and suffix computation, truthful CPU arithmetic and unlimited untrusted work space. A deterministic CPU with fixed logarithmic-word registers has $\log H=O(\log N)$. The order is attained, for example, by storing the full left digit vector in checker memory. Advice and state can also be traded: use the advice to specify an initial segment of the left label's packed bits and remember the residual bits and a match flag. When the prefix matches the advice, reject corrupted copies of that label on the right. This checker remains transparent when the same advice is applied to any other input.

In contrast, one field word of state at the cut and a field element $t$ as an advice seed suffice to catch **each particular** false accepting trajectory on an equal input with probability at least $1-(m-1)/q$ over uniform $t$. In the prefix compute $P_x(t)$, where $P_x(Z)=\sum_{i=0}^{m-1}x_i Z^i$. In the suffix compute $P_v(t)$ from the *reported* digits $v$, and compare. Range validation by the CPU ensures that an accepting report belongs to $\mathbb F_q^m$. On an equal file it must differ from $x$, hence its difference polynomial has at most $m-1$ roots. The same field evaluation is a transparent check on genuine histories of unequal files. Horner evaluation in a fixed order, or a running power of $t$, uses constant word registers and time per digit on the arithmetic/division RAM.

This fingerprint family needs exactly $m$ distinct seeds to protect one fixed equal file from **all** false acceptances. For any $r<m$ chosen seeds, add the nonzero polynomial $\prod_{t\text{ chosen}}(Z-t)$ to $P_x$ modulo $q$. Its coefficients give an in-range unequal reply vector passing all those seeds. With $m$ distinct seeds the degree bound forces equality. The same lower bound applies when each next seed is selected from the previous fingerprint values and the fixed file: follow the answers for the honest vector, then use a polynomial vanishing on the resulting points. The replies to that protocol remain identical. A post-run checksum with short state and high detection probability therefore cannot be substituted for the single pre-run certificate used in the RAM hierarchy argument. Polynomial fingerprints and evaluation codes are classical. [Reed and Solomon](https://doi.org/10.1137/0108018) · [Classical offline memory checking](https://www.cs.ubc.ca/~will/papers/memcheck.pdf)

## One backward input query changes the optimum

There is an unrestricted deterministic solver on this same layout for which every accepting trajectory on an equal file is impossible, even when all work reads can be fabricated. Use the purported left digits for the scan until encountering the first purported mismatch. Reread the genuine left digit at that row from immutable input and compare with the genuine right digit held in a register. Latch the result. A failed confirmation on a fabricated trajectory can reject immediately after the remaining syntax validation. No later alleged mismatch needs consideration: on an honest run the first alleged mismatch is already genuine. A true equal run never consults the left block after its cut. Every proposed acceptance on an equal file nevertheless has to pass a comparison of genuine, equal digits. A packed layout can align one copy of each left field in one physical word. Otherwise the test uses a constant number of physical word reads or reads one decimal numeral. The address and verdict latch stay in registers, and fallback is selected only by true input syntax.

Thus even a count of zero backward probes on **all genuine negative executions** does not justify the strict-cut lower bound. A correct positive run or a fabricated accepting run can make one real backward query that invalidates the splice. The distinction matters for an unrestricted SAT time argument.
