# Two future pins force a logarithmic physical cost for a fixed DIMACS layout

Consider an offline compiler for a graph $G$ on $v$ labeled vertices. It produces a proper 3-CNF $H_G$ and designates one signed target literal $p_i$ per source vertex, with arbitrary graph-dependent choice of these literals. The compiler must preserve only the following decision tests, on distinct vertices:
$$
   H_G\land p_i\land p_j\ \text{is satisfiable}\quad\Longleftrightarrow\quad ij\notin E(G).
$$
No model correspondence is required. There is one fixed target layout per $v$: the list of unordered triples of names is prescribed, including which triples physically appear. Literal signs can depend arbitrarily on $G$, and a triple may occur many times. Relabelings of a common layout can be absorbed in the port map. For a catalog of $K$ layouts the compiler may choose one for free.

The source tests already occur in 2-SAT. Take $(\neg x_i\lor\neg x_j)$ for every edge, and query by appending two positive unit pins. Selecting exactly the two requested vertices proves the positive direction. One can make these proper DIMACS files with a few common forced false variables. An indexed adjacency lookup decides the graph question quickly. This controls for the distinction between the cost of a compiled *representation* and elapsed time to decide SAT. [Earlier graph query construction](counting-static-programs-for-graph-catalogs.md)

For one fixed layout the worst-case explicit output length is $\Theta(v\log v)$ bits on graphs of maximum degree two, and $\Theta(v\log^2 v)$ bits already on degree-three graphs. The bounds hold asymptotically, with the degree-three lower bound along $v=6r$; adding boundedly many isolated vertices covers other sizes for maximum degree three. For a source with $\Theta(v)$ edges and conventional dense labels its length is $n=\Theta(v\log v)$ bits. A compiler that physically materializes the degree-three output in a fresh, initially zero packed bank therefore needs $\Omega(n)$ executed word writes in the worst case. This holds for unrestricted computation and preprocessing. The near-linear bound here prices writing a reusable physical formula.

## Counting sparse backgrounds against every program for the signs

For $v=6r$, form three left groups and three right groups of $r$ vertices each. Choose independently a bijection between each left and right group. Its matching gives edges only between that pair. The result is simple and cubic. All nine permutations can be recovered from the two-pin verdicts, yielding $(r!)^9$ distinct tables. In base-two logarithms this is $(3/2)v\log v-O(v)$ bits of information.

Let $D$ be the largest number of distinct unordered supports in the permitted layouts. On one fixed support there are only eight signed clauses. All multiplicities together represent a subset of these eight possibilities. Hence the whole base formula has at most $2^{8D}$ semantic possibilities. This remains true with existentially free auxiliary variables. At most $3D$ names occur. Among the ports, names unmentioned by the formula have observable effects only through coincidences and opposite signs. Rename these unused names canonically into at most $v$ fresh names. Thus, even permitting signed port remapping, a catalog realizes at most
$$
                 K\,2^{8D}\,[\,2(3D+v)\,]^v
$$
different pair tables. If $D=O(v\log v)$, comparison gives
$$
         8D+\log_2 K \ \ge\ (\tfrac12-o(1))\,v\log_2 v .
$$
When $D$ is larger the desired support lower bound for a single layout already holds. A subexponential-in-$v\log v$ choice of layouts does not remove it.

Writing $D$ distinct support triples costs $\Omega(D\log(2+D))$ bits, even with unevenly used or arbitrarily large decimal identifiers. Choose a small constant $c>0$. Fewer than $D/2$ of the triples can use only names below $cD^{1/3}$. Each remaining triple requires an occurrence of an identifier with $\Omega(\log D)$ decimal digits in a different clause. In an ASCII encoding those digits are nonzero bytes, so the output occupies $\Omega(D\log D/\log n)$ nonzero input-sized words. This last argument rules out satisfying the write bound simply by designating a long zero-filled interval as the output. Being handed the whole physical skeleton as preinitialized memory is a different construction cost. Omitting unused supports from an arbitrary menu also changes the model, since the list that actually appears can itself encode $G$.

The lower bound has a finite successor step. Start from **any** older graph on $v=6r$ vertices, and append a disjoint cubic graph from the nine matchings on $v$ fresh vertices. Every older pair response survives. Restrict the tests to fresh vertices when counting extensions. Only $v$ remapped literals then need to be counted, even though the new layout serves $2v$ ports. The same information bound, up to the change of length parameter, supplies an extension that fails every layout in a prescribed small catalog. For an effective catalog with finite layouts one can find an extension by finite enumeration of signs, ports, and satisfiability of pairs. Beginning with a graph of maximum degree three preserves that degree under every subsequent doubling. A new execution lower bound for a solver reading the graph itself would require an argument beyond this persistent representation obstruction.

## Why maximum degree two fits

Every component is a path, cycle, or isolated vertex. Traverse each component and place its vertices consecutively on one fixed path of $v$ positions using the permitted port remap. Mark the first position of each component and mark the last position of each cycle. In one scan keep the preceding selected bit and the first bit of the current component. At a non-start position disallow the conjunction of the preceding and current bits. At a cycle close disallow the conjunction of the current and first bits. Copy the current bit to the first-bit register on each start. All these are fixed constant-size Boolean tests and updates per position with two control bits. Thus one fixed circuit of $O(v)$ gates accepts precisely the independent sets in the chosen layout. Pin the two control bits per position and encode every gate by a proper fixed 3-CNF with unique internal values. This has $O(v)$ distinct supports and $O(v\log v)$ physical bits. The result handles all pins, including any two future ones.

The length order is attained. Use disjoint triangles on $v$ vertices for $v$ a multiple of six. Each single pin is feasible since it has a nonneighbor with which it can be paired. Pins in the same triangle cannot be equal literals. Pins in different triangles are distinguished by pairing them with a third vertex in the first triangle. All $v$ port literals are therefore distinct. A literal on a completely unused variable can conflict with at most one such literal, its opposite. Every vertex of a triangle has two conflicting neighbors, so all ports must involve occurring variables. At least $v/2$ distinct decimal names appear. Isolated padding extends the order bound to arbitrary sufficiently large $v$.

## Matching upper bound at degree three

The fixed switch network for explicit SAT handles the $O(v)$ edge clauses and all $v$ variable ports with $O(v\log v)$ switches, conditions and data wires. Its Boolean gate layout is independent of $G$. Pin the configuration bits by signed unit clauses. For a proper ternary physical file pad each short relation with fresh false bits and force each fresh triple by the seven clauses excluding its nonzero assignments. This costs a constant per relation. A two-input straight/cross switch has constant arity, so it also costs a constant number of Boolean gates and proper clauses. Number the resulting $O(v\log v)$ names consecutively. The physical length is $O(v\log^2 v)$ bits, and two additional unit or padded-unit pins on the public ports query precisely the requisite source pair. The same upper bound works for every bounded degree and indeed for $O(v)$ arbitrary 3-clauses on $O(v)$ named variables.

The compiler can **write** the file in $O(v\log v)$ native word steps for such sources. Generate the switch controls by the even-cycle routing algorithm. Precompute packed decimal name strings for all consecutive gate indices by extending the representation of $\lfloor i/10\rfloor$ by one digit. Each string is a constant number of $\Theta(\log v)$-bit words, including the ASCII byte factor. Each clause can then be appended to the packed output with a constant number of word writes. Recursive contiguous gate numbering or a one-time sequential gate list takes linear work in the number of switches. Fresh output memory fits the ordinary polynomial address range. This matches the unavoidable write clock for the cubic family. If only the control string is serialized, the ordinary SAT formula can instead be reconstructed by eliminating every switch in the RAM.
