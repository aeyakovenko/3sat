# Verifying a RAM run with one-way guesses and positive reads of fresh marks

For a fixed deterministic word RAM with a polynomial deadline $T$, there is a verifier using $O(M)$ word steps and $O(1)$ registers, where $M=O(T+1+n/w)$ for an $n$-bit packed input and $w=\Theta(\log(n+2))$. The verifier reads the actual input **once in physical order** and a certificate **once in order**. Its only other storage is a zero-initialized array of bits at word addresses. It first makes only blind stores of one, at pairwise distinct addresses. It then makes only loads at **strictly increasing** addresses, rejecting immediately if a load returns zero. Every complete passing run reads exactly the set of cells it marked. There is exactly one passing certificate when the claimed final verdict equals the actual one and none for the other verdict. All branches obey the single-store and single-load caps per cell, even for malicious certificates. The certificate uses $O(M)$ words.

The distinction is between the real RAM's elapsed time and the cost of checking a supplied history. In particular, if SAT has a deterministic $O(n^d)$ solver at any of the three proposed deadlines, then both SAT and UNSAT have verifiers of the above form within $O(n^d)$ word steps. The forward implication uses no restriction on the original solver's space or memory traffic. The certificate generator can itself run in $O(M)$ time on an ordinary unrestricted word RAM. It uses the original computation when doing so.

## One mark per row

Start with one virtual initializing store for each packed input word. Use separate addresses for work and input banks. Check the length register and unused bits in the final input word under the source convention. Give every native clock tick a fixed constant number of ordered slots; these serialize any bounded number of memory operations in a compound instruction. Simulate the program counter and registers, taking proposed load replies from the certificate. Stores have the payload computed by their real instruction. For idle slots, unused fields and padding after halt use only one canonical representation. If the deadline is reached without a halt one may designate a separate timeout value. Padded halted computations preserve their verdict. A clock can be supplied or fixed for the particular simulated program and input length.

Let $M$ now denote the exact number of slots, including initializers. In chronological slot $i$, form one row with bank, address, unique timestamp $i$, operation and value. Put idle events in a separate bank. Pack the row into a nonnegative key whose significant fields are bank, address and timestamp in that order. Blindly mark the cell with that key. Actual input words are needed only to generate the initializers. At this point the proposed memory replies may be entirely wrong.

Guess exactly $M$ keys in strictly increasing order. Check strict increase before each physical probe. Require each probed mark to contain one. Because the first phase emitted $M$ distinct keys, the accepted enumeration is their unique increasing order. Run a register holding the previous address and its current value, initially zero at every new address. A load must claim the current value and a store changes it. Check the fixed idle and bank conventions. Every read has now been verified against its last preceding write, including the input initializers. Chronological induction shows the CPU made exactly the genuine transitions. Conversely the actual replies and sorted transcript pass. Including one canonical fixed-width representation of every guess and an end marker at the prescribed proof boundary avoids extra unused certificates. Sorted memory histories and matching them to a chronological history are classical in RAM-to-circuit reductions. Here the equality test between the two tables is implemented by sparse positive bit probes. Gurevich and Shelah discuss non-erasing random-access simulation, and Irani, Naor and Rubinfeld analyze online write-once memory. This construction uses a one-way certificate and makes only positive tests during its second phase. Priority for these combined restrictions is unestablished. ## Keeping the same native word width

The single-key version uses a host word spacious enough for a complete row. This is still logarithmic. The journal's stricter convention fixes *both* source and host at $12\lceil\log_2(n+2)\rceil$ bits. At any of the deadlines $T=O(n^d)$ for $d=1,2,3$ the following alternative fits this convention for all sufficiently large $n$.

In the first phase additionally guess a rank $r_i\in\{0,\ldots,M-1\}$ for each row. Split that row's fields into a constant number $c$ of fragments of at most $\lceil\log_2(n+2)\rceil$ bits. For fragment number $j$ with payload $z$, place a mark at the concatenation
$$
 (r_i,\ j,\ i,\ z).
$$
Put $L=\lceil\log_2(n+2)\rceil$ and $s=\lceil\log_2(M+1)\rceil$. The fixed widths of the four fields are $s,\lceil\log_2 c\rceil,s,L$. For $d\le3$ the total is at most $7L+O(1)$, since $s\le3L+O(1)$. Address and value can each be split directly into twelve digits by shifts and masks on a native word. The verifier never packs an entire logical row into one register. Reject a proposed rank outside the public range before writing. No two emitted keys coincide, regardless of the remaining guesses, since $(i,j)$ is unique. Emit all fragments using the chronologically generated field bits and canonical padding.

In phase two, for each successive physical rank $r$, guess one complete proposed row with a single claimed time $0\le i<M$. Check field ranges, then probe the corresponding tuple for every $j$ in increasing order using that same $i$. Physical addresses increase strictly across ranks and fragment numbers regardless of the row supplied. A positive probe requires the actual row at time $i$ to have posted this fragment under rank $r$. Thus even two rows posted under a dishonest common rank cannot supply fragments of a hybrid row. Each rank must contain at least one posted row to pass. With $M$ posts of whole rows at $M$ ranks this forces one row per rank. Check strict lexicographic order of the recovered triples (bank, address, time), in addition to memory consistency. This forces the initially guessed ranks to be the unique correct ones. The public partition into rank and fragment intervals has one mark per interval on a passing run. All small exceptional input lengths can be handled by fixed finite code. [Finite checks of rank guesses, forged fragments and physical addresses](../audits/marked_ram_memory_scan_audit.py)

To produce the honest proof, simulate the guest with ordinary random access, record its rows and use stable counting-sort passes on fixed-width digits. There are constantly many passes in radix of order $M$ since $M\ge \lceil n/w\rceil$ and the keys have $O(\log n)$ bits. Write each row's final rank back at its chronological index. This takes $O(M)$ native word operations and touched words. A verifier given a sequential binary proof port paying one step per **bit** instead of one packed word may spend $O(Mw)$ steps to obtain the guesses. The deterministic target measures steps of the original word RAM.

## A single read-only batch accounts for the memory-checking cost

Let $G_b(X,I,Y)$ assert $Y_j=X_{I_j}$ for every requested address, allowing repetitions. For a supplied trace of $M$ word events, its last-write consistency bit reduces to **one** exact tensor for $G_b$ on a table of $O(M)$ rows and $b=O(w+\log M)$ payload bits, with $O(Mb)$ other Boolean gates or trivalent vertices. Store the chronological data as $X$. Guess an increasing sequence of (bank,address,time) records with their operations and values, gather all chronological payloads at the claimed times, and check the sorted register scan. Require times to lie in range. A duplicated time would have the same gathered fields, contradicting strict order. Thus every time is used once and a consistent trace gives exactly one accepted witness. Inactive padding to a power of two is fixed and excluded by the range check. The same local scan can expose the prior write's time on any sorted row. To verify a supplied chronological vector of last writers, include its fields in the gathered payload.

Conversely the lookup graph is already a bit-memory consistency instance with only $2M$ events. For $M$ table entries and $M$ requests, write one to each composite address $(i,X_i)$, then claim a positive reply at each $(I_j,Y_j)$. Every write sets a fresh bit and the claims are all correct exactly for the lookup graph. The address range in this direction is $M2^b$, with only $M$ marks. Thus a general exact-network speedup for history checking must already handle a single static batch, even with single-bit cells and constant replies. If payloads and timestamps are logarithmic, both reductions cost linear size in the bit length outside their one principal tensor. This is a contraction over guessed rows. Extracting their sorted order by a deterministic Boolean circuit is a separate cost. This representation gives a concrete test for a proposed speedup. One may try to rule out the two-phase verifiers for both SAT verdicts at a native deadline, which would also rule out the original deterministic solver. Merely counting the information in the work replies loses the whole computation: on every passing certificate their string is fixed by its length. Replacing those checks with free constants admits forged histories. For actual deterministic equality-SAT runs the difference between needing a stored mark and needing an initialized zero can already change linear word time to a sharp polynomial under a sparse cut.
