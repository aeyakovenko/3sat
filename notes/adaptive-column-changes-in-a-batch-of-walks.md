# Adaptive column changes can affect every walk and still take linear total time

The proposed amplification asks a single RAM run to pay repeatedly for dispersed probes of one database. There is a counterexample even when successive queries depend on past answers, and one short operation can change all $sQ$ selected bits. Start with the packed row database and $Q$ current walks, each with an independently supplied seed for every segment. At a round allow an entire row mask to change, a walk's seed on an entire segment to change, or a global renaming of the columns. Report whether every currently selected bit is one. The next update may branch on the just-reported answer. A deterministic RAM processes the initialization and the whole transcript in time linear in their encoded bit length. It can emit every verdict in order. [Static batches and the powered-walk parameters](batched-powered-walks-on-one-sat-database.md)

There are $s$ rows, $B=\Theta(\log s/\log\log s)$ columns, and $d=\Theta(\log s)$ rows per segment. Write $w=\Theta(\log(N+2))$ for the word width at the total encoded length $N$. For definiteness take the number of events and $Q$ to be polynomial in $s$, so $w=\Theta(\log s)$. Each canonical row is a $B$-bit mask and each segment seed has $\Theta(\log s)$ bits. A powered transition uses a fixed number of elementary torus moves, so decoding all $d$ positions of a changed segment takes $O(d)$ native operations. The initial description takes $\Theta(sB+Qs)$ bits. An explicitly addressed row or segment replacement has $\Theta(\log s)$ bits in the prescribed record, including its index. A full column map lists $B$ images of $\log_2 B$ bits each. A translation may be much shorter. The algorithm below charges a translation only $O(1)$ ordinary steps. At most a fixed number of alternatives per event may be listed, with the choice using earlier answers in constant time. A more elaborate controller is charged its actual evaluation time.

## A sufficient statistic for every column mapping

Store the base masks $D_i$, the currently selected base columns of all walks, and the counts $c_{i,b}$ of walks visiting column $b$ in row $i$. For every pair of columns define
$$
 M_{b,e}=\#\{i:c_{i,b}>0\text{ and }D_i[e]=0\}.
$$
A view specified by $\pi$ reads visible column $b$ as base column $\pi(b)$. Then
$$
 \text{all current walks are good under }\pi
 \quad\Longleftrightarrow\quad
 M_{b,\pi(b)}=0\text{ for every }b.
$$
The query rule works even for non-injective maps. A persistent view allowing later row replacements in its visible coordinate system uses a permutation so that an incoming mask has a unique inverse relabeling. Expanding that mask into base coordinates takes $O(B)$ steps.

For a change of one visit in row $i$ to or from $b$, update the native multiplicity $c_{i,b}$. On a crossing of zero, add or subtract the packed bad mask $\neg D_i$ to the counter row $M_{b,*}$, with one unit for each set bit. A segment replacement requires at most $2d$ such mask updates. A row mask replacement requires at most $2B$: for each $b$ visited in that row remove old-only bad columns and add new-only bad columns. Using presence instead of total multiplicity in $M$ gives this bound even when $Q$ is arbitrarily large within the stated range. For *fixed* data and fixed walks, the Boolean row mask $[M_{b,*}>0]$ is simply the OR of the bad masks at the visits to $b$. One pass of $O(Qs+sB)$ steps then supports every explicitly supplied map in $O(B)$ steps. The changing-data case requires the following extra work.

## An amortized array of exact counters

For each $b$ initialize $B$ scalar counters and two pools of pending masks, positive and negative. Let $L=B\lceil\log_2(B+2)\rceil$. A new mask enters its pool with weight one. When three masks $a,b',c$ occupy the same weight, replace them by their XOR at the same weight and $(a\mathbin{\&}b')\mathbin{|}(a\mathbin{\&}c)\mathbin{|}(b'\mathbin{\&}c)$ at twice the weight. This preserves the exact per-bit sum. At most two masks per weight remain after carrying. This is ordinary carry-save addition on packed bit planes. [Wallace, *A Suggestion for a Fast Multiplier*](https://doi.org/10.1109/PGEC.1964.263830)

Each insertion adds one mask, each compressor reduces the number of masks by one, and a flush only discards already processed masks. There can therefore be at most as many compressors as insertions over an entire run. Summing the *weights* of the masks as objects is also preserved by compression, so a pool built from at most $L$ insertions has at most $1+\lfloor\log_2 L\rfloor$ weight levels. To read one specified scalar, extract that bit from the pending masks at each level and combine the contributions with the saved value, in $O(\log L)$ real steps. Flush after $L$ events on this row by doing this for every column and clearing both pools. Its $O(B\log L)=O(L)$ work is paid for by those events. Two pools make alternating insertions and deletions harmless. Scalar counts and intermediate signed differences fit constantly many native words.

Thus mask insertion takes $O(1)$ amortized native time. A row edit or segment edit costs $O(B+d)$ amortized time. Evaluating an arbitrary map after it is supplied costs $O(B\log L)=O(B\log B)$ actual steps. To return the current view's verdict after a replacement, perform this map query as well. All these costs fit in $O(\log s)$ steps per replacement or full global renaming. Successive full permutations may compose by ordinary $O(B)$ array indexing. Initialization allocates $O(sB+Qs+B^2)$ words and inserts a mask for each first visit to an $(i,b)$, costing $O(sB+Qs)$ in total. The amortization gives a worst-case upper bound over complete input sequences, including adaptively chosen ones.

## Constant-time tests of short global translations

A translation on the square torus has only $B$ possibilities. Keep an additional eager array $V[g]=\sum_b M_{b,b+g}$. For an update by a mask $A$ in counter row $b$, form the packed word whose bit $g$ is $A[b+g]$. This can be a single lookup in a public table over $(A,b)$ of $2^B B$ entries; building all entries costs $O(2^B B^2)=s^{o(1)}$. It also can be computed by word shifts. With side $u=\sqrt B$, a vertical shift is a cyclic rotation by a multiple of $u$ bits and a horizontal shift is a rotation within each $u$-bit subfield. Split the latter into two shifts with precomputed masks for the wrapped and unwrapped bit positions. Neither operation depends on $Q$ or the number of rows. The finite catalogue lookup equally allows any fixed catalogue of $O(B)$ arbitrary column maps.

Process all signed masks due to **one local edit** using carry-save compression in separate positive and negative pools as above. This edit produces at most $2(d+B)$ masks. At its end extract and add all $B$ signed deltas to the eager array. The total cost is $O(d+B+B\log(d+B))=O(\log s)$ native steps. Initialize the eager array by the same operation on each segment of each initially inserted walk, which costs $O(Qs)$ since $B\log d=O(d)$. Every later direct translation test uses one indexed scalar, in $O(1)$ time. Translation generators specified by even one bit can compose by adding torus offsets. More generally a short catalogue command can set the view to one of the fixed entries. For a mix with arbitrary full maps, short commands can always set an absolute catalogue view; the $O(1)$ composition guarantee applies within the translation group. This convention avoids assuming that a short translation of an arbitrary input permutation has already been cached. After each local edit the verdict in a non-catalogue current view costs $O(B\log B)$, covered by that edit's bit length.

An update can have large actual effect in the selected columns. Fill every row's good set with the first half of the torus in its vertical coordinate. Take the $Q$ walks to stay in that half using hold labels. Translating every column by half the torus height makes all $sQ$ sampled bits zero after all had been one. Conversely it is possible to reroute many distinct locations by a full permutation. The proof charges neither the number of changed logical query answers nor the number of their dispersed source positions. It maintains shared counts sufficient for the Boolean verdict.

## What the algorithm settles about SAT encodings

For one static final view $\pi$, the earlier proper DIMACS miss construction needs only a guessed data column $e$ and the test $e=\pi(b)$ for the guessed walk column $b$. Add lookup multiplexers on the $\log B$ bits of $b$ to produce the bits of $e$, then use $e$ in the existing data test. The explicit $B$-entry map table uses $O(B\log B)$ Boolean gates or constant bits even without optimizing the selector sharing. This adds $O(B\log B\log(sQ+2))$ physical DIMACS bits, smaller than the original data for all large $s$. On these canonical files the relation to a global renaming is literal. Two different global views can affect all $sQ$ witness tests in the proper formula with very little native work.

For an entire adaptive transcript the proved time bound concerns the specified row/seed/edit representation. Supplying only an existential certificate of a miss does not justify taking the no-miss branch of an encoded feedback program. An assertion that arbitrary such feedback has a proper DIMACS compiler with linear bit overhead would need a separate proof. What the algorithm rules out directly is a native lower-bound argument that sums the single-walk dispersion charge on the assumption that every successive logical check needs fresh probes. Here even a controller with every future choice hidden until the preceding answer is delivered can use the shared state, including after edits of the database itself. A lower bound on explicit SAT still needs a family ruling out this reuse.
