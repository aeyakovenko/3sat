# Checking a proposed invariant on native indirect reads and writes

A finite-lift criterion can be stated on the instructions of a program with indirect random-access memory. It does not require expanding the program into physical delay gates. This gives a second designated SAT trial with a different trace, and a way to test native invariants on actual small programs. No successful invariant for the universal SAT trial is known.

## A native chart with an explicit clock

Take an auxiliary machine with $h$-bit registers and $2^h$ initially specified memory bits. Its finite program has copies, constants, bitwise Boolean operations, increment modulo $2^h$, left shift by one, zero-test branches, indirect single-bit LOAD, and indirect STORE of an immediate bit. Larger elementary instructions can be compiled into this instruction set. Fix two absorbing return locations, and inspect whether a distinguished return-one location has been entered by time $2^h-1$. The parameter is $h$, the number of digit layers. This auxiliary machine has more address space than the standard RAM on an explicit input of $h$ bits. When it runs a candidate SAT machine on an $N$-bit query, that candidate's own words retain their specified logarithmic width in $N$.

A partial certificate supplies possible values. $C_l(t)$ permits instruction location $l$; $R_i(t,v)$ permits register $i$ to have value $v$; $D_b(t,a)$ permits bit $b$ at address $a$. Each predicate is given by a layered binary matrix representation on the aligned digits of its arguments. Each location, register and bit has a fixed index from the program. The pair $D_0,D_1$ may permit both bits. A register can permit every value. Initialize by permitting the actual program counter, register values and memory contents at time zero. Finite seed data at fixed addresses and zeros elsewhere are regular digit tests. At the last time disallow the return-one location. Intermediate obligations are required for every $t<2^h-1$.

For example, with $C_l(t)$ permitted at an indirect STORE1 through register $i$, every $v$ with $R_i(t,v)$ must have $D_1(t+1,v)$. For any $a\ne v$, every permitted $D_b(t,a)$ must still be permitted at $t+1$. At LOAD through $i$ into $j$, $C_l(t)R_i(t,v)D_b(t,v)$ requires $R_j(t+1,b)$. A two-input AND requires $R_j(t+1,u\mathbin{\&}v)$ for each permitted pair of source values, conditional on $C_l(t)$. If two operands name the same register, give them the same value. Copy every unaffected register and, on non-store instructions, the unaffected memory, using separate implications. Branches require each successor program location implied by a permitted tested value and the guard. Induction on time includes the actual location, each actual register, and every actual memory bit in their respective sets. An accepting certificate therefore proves absence of a return one by the specified observation.

For each implication check that no assignment to its digit variables violates it. Each failure is a product over $\mathbb F_2$ of at most four certificate tests or their complements, with an additional fixed-width filter for arithmetic conditions. Equality, inequality, zero, bitwise Boolean operations, increment, shift by one and the final time are all tested digit by digit with constant memory; carries and the previous low bit suffice. A projection from the combined digit symbol feeds each factor only the coordinates it needs. Checking the absence of a violating word via reachable row spaces costs $O_P(h(w+1)^{12})$ operations for a fixed program $P$ and width $w$, plus polynomial overhead for reading/writing the representation in a native implementation. This deterministic procedure directly checks a guessed certificate. The same finite-letter construction as for the physical gates shows that the lengths with a width-$w$ certificate are effectively ultimately periodic for each fixed $P,w$. When storing a basis of actual tensor-product rows, the product here uses at most four factors of dimension $O_P(w+1)$. Thus the search at one length costs $2^{O_P((w+1)^5)}\operatorname{poly}(h)$. ## Which machine would a successful certificate have to describe?

Fix $k$. Take a stored program $A$ that reads a finite self-delimiting program description $p$ at fixed initial bit addresses; initialize it externally with $p$ equal to the code of $A$. Its own copy of $p$ is ordinary read-only-by-convention data. It obtains $h$ by shifting a one left until zero and counting the shifts, with a convention for finitely small $h$. This avoids a supposed regular initial predicate comparing an address with the number of layers. Define the following procedure in $A$.

1. Select the least currently unrefuted $k$-clocked standard SAT program by simulating the fixed refuter for $h$ steps.
2. At successive width caps $w=1,2,4,\ldots$, write an ordinary explicit SAT file asking if there are width-$w$ permitted-value tables accepted by the deterministic test above for *the machine with program $p$ initialized on seed $p$*, at this $h$. For example use the usual bounded nondeterministic computation encoding of a guess followed by the polynomial verifier. Smaller matrices can be zero-padded.
3. Run the selected clocked SAT program on this explicit file. Return one at the first YES and otherwise continue. Before calling the selected program, the machine must have finished emitting the legal file. Checked address/length arithmetic and capacity tests send any overflowing or unfinished construction to an idle location. The virtual SAT program receives its own word-width semantics and timeout. At observation the returned-one location is absorbing.

This is an effective finite program construction. A simple bit-memory RAM may implement the verifier, generation and the selected native ISA by bit operations. On inputs and runs of polynomial length in $h$ a naive bit-by-bit arithmetic implementation and a linear scan of a list of virtual memory writes cost only polynomial time in $h$. Polynomially many bits and steps fit before the exponential observation for sufficiently large $h$. No constant-overhead cross-ISA simulation is needed for the following implication.

If ordinary SAT has the hypothesized $O(N^k)$ solver, the selection stabilizes. At every sufficiently large $h$, a YES from the selected program on any legal trial file implies a valid certificate, hence no actual return one by observation. Consequently the observed bit is zero. If some valid certificate has width $h^{O(1)}$ at infinitely many such $h$, all stages through its next power-of-two cap can be generated and the genuine selected program simulated in $\operatorname{poly}(h)$ time and space. On one of those stages it must return YES, a contradiction. Thus **existence of polynomial-width permitted-value charts infinitely often on this specified native trial is sufficient** to exclude the $k$ clock. This reasoning does not claim every true negative has a chart of that size. The universal learner, query emitter and self-description above have not been assembled into an enumerated numeric instruction list for the experiments.

## The startup already tests a proposed exact chart

Choose the explicit width-measuring loop above with a register initialized to one and a fixed number $c$ of instructions per round. At one designated program point the time and register value are $t_i=t_0+ci$ and $v=2^i$ for $0\le i<h$. Let $b=\lceil\log_2(t_0+ch+1)\rceil$. For large $h$, split the synchronous digit word $(t,v)$ after the low $b$ positions. For each $b\le i<h$ take the prefix for $t_i$ with all $b$ low value bits zero. For each $b\le j<h$ take a suffix with all high time bits zero and the sole value bit at position $j$. Combining them queries the actual register at $t_i$ for value $2^j$. For an exact relation the resulting $(h-b)$ by $(h-b)$ matrix is the identity. A width-$w$ layered linear representation factors this cut matrix into a prefix-row matrix and a suffix-column matrix with inner dimension $w$. Therefore already the genuine startup forces $w\ge h-O(\log h)$ for an exact register chart, regardless of what follows. For just this loop-head relation, the sum of its $h$ singleton $(t_i,2^i)$ tests has width at most $h$, so the estimate is tight to an additive $O(\log h)$ there. The permitted-value check can instead allow spurious register values when the endpoint argument tolerates them. No lower bound of this size for all partial charts follows from the identity minor.

## A native test with a real read, write and observation

The separate 17-instruction calibration reads the sign of a literal in a proper DIMACS input, saves it at an indirect work address, clears its sign register, delays by a wrapping-counter loop, then reads the work bit and returns. Its promise consists of two equal-length files: the first seven clauses force three variables to one, an eighth forces a fourth variable to one, and a sign in the ninth clause distinguishes the uniquely satisfiable file from the unsatisfiable one. The four variables occur, each clause uses three distinct variables and no clause is repeated. The two-cell permission invariant tracks the sign in input and work memory without fixing the remaining work bits. It holds for every $h\ge11$ by the explicit affine time/counter identities in the audit. Finite checks for $11\le h\le15$ exhaust all 16 candidate assignments per file, verify 126,966 time transitions via source-value and alias projections, and reject all 30 injected faults. This certifies what the given instructions return on these actual files. It is a promise computation. [Program, invariant and checks](../audits/native_pointer_permission_audit.py)
