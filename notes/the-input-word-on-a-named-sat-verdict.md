# What a short name costs on the actual SAT run

For every correct deterministic SAT solver, the [paired verdict construction](proofs-of-two-ordinary-sat-verdicts.md) gives an ordinary unsatisfiable file whose generated-name verdict has no proof within a prescribed cap $b$. Its physical length can be reduced to a constant **even when the solver takes the same constant time for every $b$**. The lower bound can reside in proving the value of one particular input bit that the solver actually reads. A separate construction below gives an exact test for transferring a proof cap to execution time using a certified partial input.

## Two proper files differing in one bit

Use ten clauses on five names. Start with the seven clauses on $(3,4,5)$ excluding all valuations except $(1,0,0)$. Add $(\neg1,4,5)$ and $(\neg2,4,5)$ to force names 1 and 2 false. End with $(d,4,5)$. In the last row choose the single ASCII digit $d$ to be either 2 or 3. The first file $F_2$ is unsatisfiable and $F_3$ has the unique assignment $(0,0,1,0,0)$. Their equal-length encodings differ only in the low bit of that digit, since the two byte values are 50 and 51. Every deterministic correct solver must read the packed word containing this bit on both files. Until that read, all observations and state transitions on the two inputs agree.

Fix a sound arithmetic checker and a correct solver $M$. As before, a single syntactic template $E(e,u,i)$ has two output tags, and $u$ contains $M$, its alleged clock and $b$. The first tag names $G$, the second $P$. Keep the five short candidate conclusions of the paired construction, and add the sixth conclusion “the named output $G$ has zero at the distinguished physical bit.” In arithmetic, the latter says there is a terminating generation of that output with the indicated bit zero.

For tag 0, enumerate all proofs of up to $b$ bits for the six syntactically specified conclusions. Emit $F_3$ on finding one and $F_2$ otherwise. For tag 1, generate tag 0, execute $M$ up to its claimed deadline on those bytes, and emit $F_3$ for a timely NO or $F_2$ otherwise. Specialize $e$ to the template's own number. Reading the template to form the six conclusions executes neither tag.

If $G=F_3$, the proof triggering that choice has a false conclusion. Indeed $G$ is satisfiable, its distinguishing bit is one, $M(G)$ returns YES, $P=F_2$, and $M(P)$ returns NO. Soundness rules this out. Hence $G$ is literally $F_2$ at every cap, and even “the named input bit is zero” has no proof of at most $b$ bits. Its arithmetic proof exists in any base such as $I\Sigma_1$ by the finite terminating computation. The actual clock time on $G$ is always $T_M(F_2)$. Whenever the proposed deadline covers this one run, $P$ is literally $F_3$ at every cap as well. There is no difficulty proving the digit of the literal displayed file $F_2$.

Even polynomial generation is consistent with this example under the proposed fast-solver hypothesis. A second template uses $M$ on an ordinary Cook file for the six short-proof questions in place of brute-force enumeration. Its verifier only inspects proof syntax and the target strings. It never executes the named generator. For correct $M$, its answer determines exactly whether to emit $F_2$ or $F_3$, so the argument applies to this new template. If $M$ takes polynomial time, this generator runs in polynomial time in $b$ for fixed $M$ and clock. Its external output still has a constant-time constant word table. Certifying that table for the generated name is a separate cost.

## An exact bound for partial-input replay

Fix an integer $q\ge1$ and a sound polynomial-time arithmetic proof checker $A$. Use a new certificate checker $V_q$ for the paired files. It accepts ordinary $A$ proofs. It also accepts the following format for an explicitly written target asserting that the specified RAM has returned the stated Boolean verdict on a **named** file.

1. The core contains the target syntax, a deterministic partial word decoder $D$, and an ordinary $A$-proof $\pi$. The required conclusion of $\pi$ says that the named generator terminates with some file $y$, $D$'s length response equals $|y|$, and every defined word response of $D$ agrees with the packed word of $y$ at that address. The predicate uses the specified RAM's word-width and boundary conventions. $D$ may return undefined or diverge elsewhere. It may perform common deterministic initialization once. Word responses must be functions of the address and the common initialized state, with scratch reset between requests. The checker parses the displayed machine, generator and decoder, builds this exact arithmetic syntax and compares it with the last line of $\pi$.
2. On a certificate of total bit length $\ell$, meter at most $\ell^q$ elementary simulation steps for the decoder initialization, length request and replay together. Give the RAM its real initial state. Execute it on $D$'s replies and accept if it returns the target verdict by the inclusive limit, with every input request answered. The proof format has a tag and self-delimiting fields followed by any number of zero padding bits. Counting this padding in $\ell$ is part of the checker definition.

One precise meter is a universal RAM interpreter storing guest words as bit strings, using schoolbook bit operations and a bit trie for sparse guest addresses. Charge the individual bit operations and trie visits, also for the decoder. The metered computation allocates only polynomially many bounded-size host cells in its work and explicit input length, and has a polynomial-time deterministic simulation. For each fixed ordinary logarithmic-word RAM $M$, its instruction overhead is $\operatorname{polylog}(N+T+2)$ on an $N$-bit file over $T$ steps. The decoder's own charged work is additional. Checking the ordinary proof and syntax is polynomial in the receipt length and happens outside the replay meter. Soundness follows from soundness of $A$ and deterministic replay on the covered addresses. It holds for arbitrary named generators and uses no axiom that a particular generator outputs a particular file.

Construct fresh paired files against this checker, using the original explicit tag-0 SAT compilation or any replacement satisfying the same bounded-certificate equivalence. On every true solver-verdict target covered by the diagonal, let $d$ be the encoded length of the unpadded core for a proposed $(D,\pi)$, and $U$ the work to obtain that verdict by the specified successful partial replay. Then

$$
                         d>b\quad\text{or}\quad U>b^q .
$$

If $d\le b$ and $U\le b^q$, append exactly $b-d$ zeros. That very check would accept at length $b$. There is no second charge for the simulation budget after paying for the core. With binary length fields the core costs $|D|+|\pi|+O_M(\log(b+|D|+|\pi|+2))$ for fixed machine, generator and clock.

For example, suppose $N=b^{\alpha+o(1)}$, the incoming solver takes $O(N^k)$ steps on this family, and the decoder uses only polylogarithmic work per answered probe with total initialization $o(b^q)$. If $\alpha k<q$, successful replay costs at most $b^q$ for all large $b$. Accordingly every such view that covers the actual probes requires $|D|+|\pi|\ge b-O_M(\log b)$, even when most other addresses are left undefined. Conversely, a family satisfying those length and view conditions with $|D|+|\pi|=o(b)$ would rule out that clock. Ordinary bounded-computation compilation permits the verifier to spend $b^q$ metered steps and gives no guarantee of a size exponent $\alpha<q/k$. The constant-output example shows why an externally correct tiny decoder does not fill the missing condition.

The [Lean file](../lean/NamedVerdictInputProbe.lean) checks the concrete clauses, both model counts, the single-bit change in the serialized files, necessary word reads and soundness of a partial replay for arbitrary finite deterministic query trees, and the exact padding inequality. Arithmetic quoting, the uniform RAM interpreter and the elapsed-time accounting are manuscript arguments.
