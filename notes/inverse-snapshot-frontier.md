# A linear SAT execution realizing the indexed snapshot tradeoff

The [verdict-specific checkpoint argument](signed-snapshot-windows.md) at linear SAT time forces hard states whenever description and lookup exponents satisfy $e+d<1$. This whole range can occur on an easy family processed in $O(N)$ native time. On the same work array the best achievable product of advice bits and lookup time is determined up to logarithms across polynomial lookup budgets. This tests what one could deduce about elapsed time from that snapshot trade alone. [Earlier sequential inverse-forecast construction](stateful-inverse-windows.md) · [Classical inversion tradeoffs and sources](https://arxiv.org/abs/1408.3193)

For $m$ a power of two, encode an arbitrary permutation $\pi$ of $[m]$ in $m$ fixed-stride tautological clauses. One literal gives the data value. Two leading units can be equal or contradictory, giving either SAT sign for every permutation. The length is $N=\Theta(m\log m)$ bits. Each input-word read can be served from at most a fixed number of forward $\pi$ queries and the known sign. Conversely a given forward value can be read in constant native time. Use an ordinary globally correct solver which first recognizes this layout and scatters $i+1$ into the array at address $\pi(i)$, testing that the previous value is zero during validation. On a match run $\lceil\log_2 m\rceil$ full scans of this inverse array, reading every word and updating a register checksum, then return the sign. On a failed check invoke any correct fallback in a separate bank. The tests can scan every fixed field before accepting the layout. On these formulas the instruction count is $\Theta(N)$, and the array is the only data-dependent work bank needed after validation. If a globally linear solver is available as fallback, the wrapper also preserves that worst-case clock. The time spent before a failed check is $O(N)$, including syntax and length validation.

At every time in the first half of the scans, every inverse word still has a genuine future consumer before any overwrite. The following calculation includes the actual time, address, formula and choice of sign in the decoder's interface. For each fixed decoder there are permutations on which, **simultaneously** at all these times and on both signs, no $s$-bit description permits reconstruction of every array word within $q$ native steps when
$$
  1\le q\le m/\log^2 m,\qquad (s+1)(q+1)\le c m
$$
for a sufficiently small absolute constant adjusted for the encoding and machine. The fraction of exceptions tends to zero. In particular the snapshot lower bound holds throughout an interval of $\Theta(N)$ consecutive solver times. The decoder can use unbounded preprocessing to choose the description for a specific time and input.

Fix a time, sign, string of length at most $s$, and clock $q$. Set $r=\lfloor m/(4(Cq+1))\rfloor$, where $C$ bounds the number of forward permutation values exposed per native input read. Query the putative decoder independently on $r$ predetermined distinct target addresses, with the same string and fresh scratch. At each answer also query the proposed preimage in $\pi$ to verify it. There are at most $r(Cq+1)\le m/4$ forward queries. For a uniform permutation even adaptive queries to distinct new locations reveal a uniform sample of images without replacement. Pad the query sequence up to its cap with distinct unseen locations as necessary. Success on all $r$ targets requires all of them to occur in that sample, with probability at most $(1/4)^r$. Sum over fewer than $2^{s+1}$ strings. With $s+1\le c m/(q+1)$ the result is $2^{-\Omega(m/(q+1))}$. There are only polynomially many choices of the integer clock, absolute time and sign, and the smallest such tail exponent has order $\log^2 m$. The decoder cannot treat the current time as free unbounded advice. The same permutation thus works for every stated choice.

There is a matching uniform decoder up to logarithmic factors. For a prescribed step parameter $1\le h\le m$, place $\lceil \ell/h\rceil$ marked vertices around every permutation cycle of length $\ell>h$, spacing them at directed distance at most $h$. Leave shorter cycles unmarked. Store the marked vertices and, for each, its preceding mark in cyclic order in a sorted directory. This takes $O((m/h)\log m+\log m)$ bits because each long cycle has more than $h$ vertices. On input $y$, walk forward until the first mark or the first return to $y$. A return without a mark gives the predecessor directly. If a mark is found, jump to its stored preceding mark, then walk forward until the next step reaches $y$. This also handles a query that starts on a mark. There are at most $2h+O(1)$ forward queries and $O((h+1)\log m)$ word time with binary searches. Other work addresses in this bank return zero outside its range, and fixed metadata or a constant number of changing controller words fit in $O(\log m)$ extra bits. This implementation is the standard cycle-landmark idea for inversion.

Thus even requiring **every** time in a long window to have difficult, subsequently used memory words leaves a linear-time example. Its solver was chosen to do these computations. An unrestricted lower bound has to force additional work for every correct solver, or exploit an additional property of the hard SAT inputs.
