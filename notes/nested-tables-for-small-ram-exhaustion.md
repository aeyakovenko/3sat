# A one-variable successor for finite RAM witness suites

The [five-instruction manuscript](five-instructions-cannot-decide-dimacs-sat.md) rules out every fixed five-slot program on proper DIMACS, including nonterminating candidates. Here the finite suite can grow with a code budget and retain a previously chosen truth table as a cofactor. The program class for this successor has **two mutable word registers**, arbitrarily many code sites and a quantified amount of additional writable state. Time is unlimited. A separate LOAD replaces one register with an unmodified memory word and resumes at its fixed successor. Immutable length and width metadata are allowed. The hard input can differ from program to program.

## What one new selector buys

A deterministic Boolean query graph has a start, two terminal verdicts, and nonterminal vertices labeled by input bits. Its two outgoing edges can point anywhere. A repeated vertex on a fixed input means divergence. Write $q(A)$ for the fewest query vertices in a graph that decides the entire Boolean table $A$. For a table $A$ on $t-1$ variables and another table $B$ on those variables, set

$$T(x,z)=(1-z)A(x)+zB(x).$$

If $B\ne A$, then $q(T)\ge q(A)+1$. Some reachable query must inspect $z$, or the answer could never depend on it. Set $z=0$ and bypass every $z$-vertex along its forced zero edge, including at the start. A cycle made solely of bypassed vertices can be sent to a divergence sink. The restricted graph decides $A$ and has at least one fewer query vertex. This applies even if the new program replaces every edge of an optimal old program.

The smallest example here starts from two-bit equality, whose minimum is three. Choosing $B=0$ gives $(\neg z)\land[x=y]$, whose minimum is exactly four. Its program first checks $z$, then runs the equality program if $z=0$. The exhaustive audit evaluated all $3^3 5^6=421{,}875$ ordered three-node graphs with a designated query start; constants and smaller programs are included by padding. They realize 126 of the 256 three-bit functions. For each of the 16 two-bit tables at least one high cofactor exceeds three nodes. For equality every high cofactor except equality itself does. Lean proves the lower and upper bounds for guarded equality with an arbitrary start and unbounded halting semantics. [Lean proof](../lean/NestedQueryTable.lean) · [Exhaustive census](../audits/nested_query_table_audit.py)

The same lift has a small native realization. Align both signs of the eight-clause equality formula so each private word is either two ASCII spaces or a space followed by a minus. The four equal-length files now have 90 bytes. For the new formulas add a fixed clause $(\neg x_4\lor x_2\lor x_3)$ and a clause $(\pm x_4\lor x_2\lor x_3)$ whose sign is negative exactly when $z=0$. The six existing common clauses force $x_2=x_3=0$. The eight resulting files have 110 bytes, and their three private words are at addresses 40, 45 and 50. On this promise the optimal worst-case number of **executed RAM instructions** increases from three to five, allowing arbitrary program size and writable memory. Two LOADs and one comparison decide the old files. For the new ones compare the two loaded equality signs, reject on mismatch, then load and test the guard sign.

For the lower bound take any accepting file. Flipping any one of its private words changes the verdict, so each must be read in its original state. A run with only the required LOADs and one more instruction must spend that instruction on a data-dependent branch. It must be after the last required read: a change to a still-unread private word would preserve the branch and the rest of the instruction sequence through the verdict. On the three-word suite, before the branch every LOAD reads a distinct private word. Neither possible raw word is a private address, so each LOAD on this run must use a literal or an initially available register as address. These reads therefore access the same three words after any single sign flip. The one branch can inspect at most two replies. Changing the third contradicts correctness. On the two-word suite two compulsory LOADs already leave no room for any branch in a two-step run. These arguments apply at each accepting file even if the solver can spend arbitrarily long elsewhere. The audit independently parses the bytes and evaluates all assignments. This gives an exact small native lift under a promise. The accepting-file lower bounds also apply to globally correct programs.

Forcing a one-node increase need not give a large increase. If $B$ differs from $A$ at just one input $u$, a graph can test $z=1$ and $x=u$, returning the hardwired $B(u)$ on that one match and running its old graph for $A$ on every mismatch. This costs at most $t$ extra queries **in stored vertices**. With one exception at every extension, the resulting tables have $O(t^2)$-vertex programs starting from a fixed seed. This limits the hardness that this particular edit rule can certify as the explicit table doubles in size.

## Extending an arbitrary old table past an exponential node budget

For all sufficiently large $t$, let $M=2^t$ and $s_t=\lfloor M/(16(t+1))\rfloor$. At most $t^{s_t}(s_t+3)^{2s_t+1}$ deterministic graph descriptions use at most $s_t$ query vertices, allowing arbitrary labels, edges, start, the two verdicts and divergence. Pad to exactly $s_t$ vertices. Each description decides at most one total table. For $t\ge6$ the binary logarithm of the bound is at most $3s_t t+t<M/2$. With the low cofactor $A$ fixed there are still $2^{M/2}$ choices of $B$. Choose any extension outside the descriptions. This can be done effectively by exhaustive simulation for at most $s_t$ queries per assignment. If dependence on $z$ is required, also discard $B=A$; for all sufficiently large $t$ the strict counting margin allows this. Thus starting with any finite seed, and beginning the counting step at sufficiently large arity, there is a single nested sequence $T_t$ with $q(T_t)>s_t$ at every subsequent stage. The choice of table precedes every choice of RAM program or word placement.

The graph count is the classical subfunction counting method. The new quantifier used here fixes an entire previous cofactor before choosing the new table. The sequence has no claimed efficient table generator. ## Counting actual original LOADs at a single file length

Use the journal's [compact proper-DIMACS table encoding](balanced-selector-probes-on-compact-sat-files.md) with its group size $b=1$. At arity $t$, $F(T,u)$ has SAT verdict $T(u)$, common length $n=\Theta(2^t t)$ bits, and a common packed-word alphabet of size $h=O(1)$ including zero outside the file. There are exactly $t$ private selector words. Put their pin clauses in one contiguous section at aligned record boundaries. Reserve an additional constant fraction of the length as whole-word whitespace and slide this section by $L=\Theta(n/w)$ possible whole-word offsets, moving the same amount of whitespace from after the section to before it. Choose the common length with this slack **before** generating the width-dependent fields. Every private word then has $L$ distinct possible addresses. The order of the remaining clauses and the SAT verdict are independent of the shift. The encoding permits unused identifiers and long decimal names. At each stage use all $2^t L$ choices of selector and offset for the *one* selected $T_t$.

Let $Q=2^w=O_D(n^D)$ for $w=16\lceil D\log_2(n+2)/16\rceil$, $1\le D<2$. Consider even a length-dependent program with arbitrary literals at this width and $k$ stored LOAD sites. In the read-only case set $R=1$. With disjoint scratch, let $R$ bound the number of possible **whole scratch configurations** just after original input LOADs over this entire suite. With writes into the input, instead retain the dictionary of all addresses written so far and their latest values, including writebacks. Call a LOAD original only if its address has never been written. $R$ now counts the possible dictionaries at original LOAD returns across the suite. Scratch or dictionaries must include all extra mutable state other than the two registers and finite program counter. The initial extra state is public. A count can include impossible configurations. Unlimited computations between original LOADs are permitted.

Immediately after an original LOAD, its site, the raw reply, the other register and the scratch configuration determine the machine through its next original LOAD request, exit or divergence. Between these requests all memory replies can be computed from the saved scratch or dictionary. A STORE updates that state without inspecting an original word. There are at most $k h Q R$ such codes. When a code leads to address $a$, the code and the next reply also determine the full post-reply state. The set of codes and their next-address map are common over all translations of the chosen table. The initial state supplies one additional first request.

Write $m(a)$ for the number of codes leading to $a$. The sum over all addresses is at most $k h Q R$. If the unshifted selector addresses are $a_1,\ldots,a_t$, summing $m(a_j+v)$ over the $L$ shifts for fixed $j$ gives at most $k h Q R$. Some common shift therefore has

$$S\le t+tkhQR/L$$

slots for all original private requests, including the first. At that shift contract public computations to get a Boolean query graph on at most $S$ vertices. At each private vertex the held code and reply determine a unique successor after the intervening public steps. Written private cells are answered by the saved dictionary. Loops or divergence on hypothetical edges cause no difficulty. A program correct on the whole suite would decide $T_t$ with this graph. Thus $S>s_t$, forcing

$$kR=\Omega_D\!\left(\frac{n^{2-D}}{(\log n)^4}\right).$$

Indeed $s_t=\Theta(n/t^2)$, $L=\Theta(n/t)$ and $t=\Theta(\log n)$. The shift exhibiting failure may depend on the program. A public $b_0$-bit scratch gives $R\le 2^{b_0}$. If writes can touch at most $j$ of $m$ public addresses with payloads from a fixed palette of $v$ values, one may use $R\le\sum_{i\le j}\binom mi v^i$. When there are no writes this is a growing lower bound on the **number of stored LOAD sites**, even if the code and its immediates vary with length. Finite length alone does not make this class empty: a sufficiently large length-specific two-register decision tree can inspect the file and carry its history in its control location. [Translation argument](private-probe-contexts-in-read-only-sat.md) · [Original-read contraction on writable input](balanced-selector-probes-on-compact-sat-files.md)

For $D=1$ a single independently writable word already permits $R=Q\ge n$, so the inequality gives no exclusion for that class. The difference between abstract and native successors matters here. Setting the newest selector to zero recovers every previous *verdict*, while the width, encoded names and addresses change at the next arity. An unrestricted program can keep a third word or change its next query using stored memory. In fact the compact files have a linear-time fast path: the program can parse the template, store its public edges and traverse the indicated path. Sliding the pin section only requires skipping whole-word whitespace at its public boundaries, with fallback to a general SAT solver on syntax outside the family. Deriving an increasing lower bound on **executed** instructions per encoded bit for arbitrary writable RAMs remains open. The RAM transfer and asymptotic counting above are manuscript arguments; Lean checks the exact small graph successor.
