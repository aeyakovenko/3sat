# How much does the true RAM history determine inside its sorting circuit?

An attempt to decide modified SAT queries by replaying the genuine native computation has an exact boundary inside the ordinary memory checker. Relax the direction checks of two existing first-layer comparators per group of four records. One named switch bit per group can then have prescribed values independently, even when the CPU trajectory and every record leaving the group are fixed to their actual values. This happens on the actual native input at each stage. The construction uses the first three layers of the usual bitonic sorter. [Deterministic RAM tableau](projected-parity-holes.md#a-parsimonious-ordinary-3-cnf-near-the-native-clock) · [Batcher, *Sorting networks and their applications*](https://doi.org/10.1145/1468075.1468121)

Use the unpinned core encoding a fixed total deterministic RAM program at stage $j$, clocked at $O(M)$ with $M=2^j$. Each comparator has one Boolean switch selecting a common permutation of the two complete records, plus a gate definition that computes the intended direction from their keys. Add the original occurrence slot as the last tie-breaker in the key, including for dummies. Correct runs then have distinct keys on every wire at each layer. Equivalently a tie can be permitted when the entire tied records are identical. With distinct payloads on tied keys, stable comparisons need the slot tie-breaker for the argument below. Use explicit adjacent-key order comparisons at the final output as well as the memory and CPU consistency checks. In a sorter implementation that omits this redundant test because all comparators were originally honest, include it before relaxing the switches. It costs one word comparison per adjacent pair and preserves the honest trajectory. In each selected disjoint quartet remove only the defining equivalences for the two first-layer switch outputs, leaving their muxes and all other gates intact. No new free variables are introduced.

In zero-based lane order the first three layers pair $(0,1),(2,3)$, then $(0,2),(1,3)$, then $(0,1),(2,3)$. The middle two comparators use the same direction within the quartet; each final comparator emits its two records in its prescribed order. Flipping **both** first switches applies $P=(0\,1)(2\,3)$ to the intermediate vector. The middle comparisons exchange roles, so their combined output also transforms by $P$. Each final comparison receives its original pair reversed and emits its original ordered pair. The quartet's entire output and every later computation thus stay fixed. Starting from any satisfying assignment, recompute all affected middle and final gate bits to get a second one. Applying the change twice recovers the original gate values. This holds whether the two first switches were honest or chosen freely. Releasing only one first switch cannot guarantee this local choice for arbitrary input. On keys $(0,3,1,2)$ with an ascending block output, exactly the two opposite switch settings yield $(0,1,2,3)$. Later layers could correct other arrangements; the example concerns this block's boundary. [Lean proof for arbitrary input records and a prescribed switch in each block](../lean/NativeSorterSwitches.lean)

Even after relaxation every comparator permutes whole records. The final checks still force chronological reads at every address to agree with the last write or initialization. Induction on deterministic CPU steps forces the original entire RAM trajectory $\tau_j$ on every satisfying assignment. Write $p$ for the number of relaxed quartets and $s\in\{0,1\}^p$ for the first switch in each. The exact projection of the model set onto $(\tau,s)$ is

$$\{\tau_j\}\times\{0,1\}^p.$$

For surjectivity, start from the honest tableau, and flip both switches precisely in the groups where the first bit differs from its prescription. Moreover the $p$ involutions commute and act freely on every orbit of models. The named vector occurs exactly once per orbit for each of its $2^p$ settings. Hence the number of complete models is divisible by $2^p$, and a uniformly sampled model gives uniform independent named bits even after fixing any orbit-invariant statistic. In particular, adding $h$ parity equations involving the two first switches per quartet to a nonempty instance leaves at least $2^{p-h}$ members of any orbit it meets when $h\le p$. On that orbit the equations are affine in the $p$ simultaneous flip choices. These claims refer to the core itself or to restrictions invariant under the specified flips.

For any added predicate $G(\tau,s)$ on the chronology and these named controls, feasibility is exactly $\exists s\,G(\tau_j,s)$. Thus on the family promise, native replay followed by 2-SAT solves every such extension whose substituted predicate is a 2-CNF, even with an unbounded number of undetermined named controls. Conversely, put an ordinary 3-CNF on just the named first switches. Every original satisfying assignment extends to the relaxed native formula, and every satisfying assignment of the latter projects to an original one. Choosing a stage with $\Theta(v+1)$ record quartets for $v$ occurring variables costs $O((v+1)\operatorname{polylog}(v+2))$ bits for the core. Copying source clauses changes name width by a constant factor on dense fixed-width inputs. This gives a quasilinear-size reduction of general 3-SAT, independent of knowing $\tau_j$. The overhead of the full sorting circuit precludes claiming a bit-linear reduction on sparse source formulas by this count.

The rigid core in the [earlier extension test](native-core-extensions.md) permitted arbitrary pins on its uniquely determined gate values. Shared whole-record permutations and final consistency still force the same *word values in RAM* here, while auxiliary constraints on the already present routing bits can carry a full SAT instance. The example identifies a failure of substituting one canonical history in those queries. It gives no faster unrestricted SAT algorithm or lower bound; priority for the switch observation has not been established.
