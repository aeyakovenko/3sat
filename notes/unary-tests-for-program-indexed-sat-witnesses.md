# What a fast generator of unlabelled hard SAT files would prove

Fix a deterministic constructor G. Its row index i is an arbitrary natural number and can encode the entire proposed RAM solver. It receives a file length n and a candidate index j. It may emit an unlabelled n-byte DIMACS file. Here n counts bytes, so the physical bit length is exactly 8n. Assume that on the candidates claimed for each fixed row i the output finishes in at most A_i(n+1) native steps, uniformly over j. A row may have holes. There is no bound on the cost or behavior of G outside the claimed candidates.

Two schedules have a particularly direct connection to unary computation.

| Schedule | Candidate indices at that length | Deadlines covered |
| --- | --- | --- |
| One file at every positive n | j = 0 | Linear, quadratic and cubic |
| Up to n files when n is a power of two | 0 ≤ j < n | Quadratic and cubic |

**Theorem.** For each schedule, G defines a particular unary language U accepted by a nondeterministic logarithmic-word RAM in linear time. For a covered exponent k, suppose U has a deterministic RAM decider running in time O(m^k) at unary input length m. Then **one globally correct deterministic SAT solver** runs in O_i(n^k) on every claimed candidate of every fixed row i. This includes its own program's row and makes no assumption about knowing the candidate index from the file.

Consequently a construction that prints such candidates and proves an unbounded time-to-n^k ratio on the designated row of **each** correct solver would establish a tally language in nondeterministic linear time outside deterministic O(m^k). No time lower bound for that language is known from the construction alone. The [edit-stream variant](streaming-witnesses-at-dyadic-lengths.md) covers the linear deadline for lists of up to n candidates produced by a linear total number of elementary edits.

## Encoding an arbitrary solver and a search budget in the length

For the first schedule put u=n. For the second put u=n+j. On dyadic n the intervals [n,2n) partition the positive integers. Thus u determines both n and j and is less than twice the file length. Use a separate unary language for each schedule. Its input alphabet is the singleton {1}. For a positive input length m write

$$ m=2^r(2u+1),\qquad i=\nu_2(r+1). $$

Here the valuation counts trailing zero bits. Each i occurs at infinitely many stages r, since r+1 can be any odd multiple of 2^i. For each fixed r the unary length is within a constant factor of n. The availability of multiple stages for the same i pays for the unknown generation constant A_i. In particular there is no assumption that the constants admit a computable bound in i.

Reject m=0 or an invalid payload. Simulate the fixed G(i,n,j) for at most m of its own steps. Accept if and only if it finishes within the budget with exactly one well-formed n-byte file and this file has a satisfying assignment. The generator uses a specified virtual word width based on n and an explicit sequential output convention. All machines use the same virtual generator, including its truncations and halt convention. Oversize output may be rejected immediately. The unary machine can obtain m by a scan if necessary and decode the small integer fields by word shifts.

The generator is deterministic. After generation, a nondeterministic verifier scans the actual DIMACS file, interning each normalized occurring decimal name in a ten-child trie. On each first occurrence it guesses one truth bit, recording it for later references. It checks every clause, the header and the token grammar. A comparison with a long declared name bound costs constant work per digit of a same-length token. Normalize the header once and compare digit lengths first. The verifier's work is O(n) in addition to the O(m) simulation. These steps give a single linear clock on *all* unary inputs, even for rows which never generate a valid file.

## A single SAT program for all rows

On an actual file x of length n, try r in increasing order through floor(log₂(n+1)). For each allowed j, form the corresponding m and run the same bounded generator. Compare a timely complete output exactly to x. At the first exact match, run the assumed decider on the unary word of length m and return its answer. Off the supported lengths or in the absence of a match use an ordinary exhaustive SAT solver. Any exact match gives the true verdict by the definition of U. The fallback gives global correctness without a promise about the input or the behavior of a candidate RAM.

For a fixed row i, choose a fixed occurrence r of that row with 2^r large enough to cover A_i. For all sufficiently large n this occurrence is visited. On its claimed files an exact match occurs by this stage, possibly earlier on another row. Up to that point, each generation and comparison costs O_i(n). There are a constant number of stages for this fixed i and at most n indices per stage. This search takes O_i(n) for a singleton and O_i(n²) for the dyadic list. The deterministic unary decision is made just once, at length O_i(n). This proves the stated times. Finitely many smaller lengths can be absorbed into the private constant.

For the native simulation on arbitrary inputs, all attempted lengths m are O((n+1)²). The fixed program can use a fixed word-width coefficient large enough for the generator and unary decider at these lengths. Simulate each virtual width explicitly, with masking and the specified treatment of shifts, and keep the input and virtual work memories in disjoint address intervals. A list of addresses written during a generator trial resets its scratch in time proportional to that trial; duplicates can be zeroed repeatedly. The log-word RAM allows the fixed constant increase in width required for the simulated addresses and bookkeeping. The unary input can be materialized in O(m) steps on the one matching trial. Its possible stricter virtual word size likewise remains part of the simulation. This charges all equality tests, workspace initialization and conversion between input lengths.

There is a simple capacity check for encodings of this kind. If K(n) **distinct indexed candidates** at each length receive different positive unary lengths at most Cn, then the sum of K(t) for t≤n is at most Cn. Conversely, given this prefix bound, assigning the jth candidate the length n + j + sum of K(t) for t<n gives an injective length between n and (C+1)n. This converse is about cardinality. To use it algorithmically, the schedule and its inverse must also have suitable clocks. The two schedules above supply those implementations explicitly. In particular, n independent labels at *each* length would not fit this injective encoding with constant stretch.

## What changes if the algebraic rewrite supplies the verdict

Suppose instead that a fixed search produces signed candidates, each with its correct SAT verdict whenever it emits a record, for every row. Consider the following weaker requirement on generation. On each candidate x in row i at length n, its record appears within B_i(n+1)^k operations **including exact comparisons to the input** and any computation of the verdict. No terminating enumeration of the rest of the suite is necessary.

A single globally correct solver meets O_i(n^k) on all these candidates unconditionally. Use the same repeated row schedule. At stage r run the fixed signed search on the input from a fresh start with budget 2^r(n+1)^k, and return only on a completed exact match. Stop after floor(log₂(n+1)) and use exhaustive fallback. For each i, a sufficiently late fixed occurrence of the row covers B_i. The sum of earlier budgets is less than twice the last budget. Soundness must cover any row from which this procedure can return. If correctness of a claimed verdict is conditional on the target code already being a correct solver, this argument requires an independent verification of the verdict.

As one application, suppose each row starts from a fixed finite base file obtainable from i. At length n+1 a deterministic rewrite of the length-n file preserves its SAT bit, or specifies a known Boolean update of that bit which is sound for that step. Recover the base bit once per trial by exhaustive search. The cost is constant for each fixed row, including when the base bit was never published. If the rewrites can be replayed with O_i(t+1) work from t bytes to t+1 bytes, the total cost through length n is O_i(n²). Only the final same-length file requires comparison to x. Such a successor cannot supply the unbounded ratios required for either the quadratic or cubic exclusion. If the lengths at least double and the last generated file is at the tested length, the linear per-file costs sum to O_i(n), so it also fails at the linear milestone. Replay here means implementation on the current machine, including the cost of simulating the appropriate earlier widths and copying any necessary state. A computationally expensive or existential choice among successors is outside these hypotheses.

The program index, the unknown clock constant, the absent verdict and the missing inverse from a file to its candidate number are separate issues. The tally argument addresses all four for its stated schedules. The claim it requires about the unary SAT bits is a concrete lower-bound question in its own right.

Chen, Flum and Müller study algorithm-specific hard sequences with time measured in the unary sequence index. Gutfreund, Shaltiel and Ta-Shma obtain algorithm-specific samplable hard instances under a worst-case hardness assumption. Hartmanis, Immerman and Sewelson relate sparse and tally hardness to exponential time classes. The statements here retain fixed exponents, cap generation by the padded physical length, and deliver one correct solver simultaneously on all rows under the unary hypothesis. An earlier journal entry obtains a tally implication for a particular sparse parity verifier. Priority for the quantitative program-indexed formulation has not been established.
