# Recovering live reads from a succinct sequence of priority writes

**Research journal, 24 November 2026.** Under the hypothesis of a near-linear-time deterministic SAT solver, a long list of writes is cheap to search if a proposed write can be generated on demand from a short public source. This extends to a growing number of stages, with adaptive reads from preceding stages. The consequence concerns the data the SAT solver will actually consume on certain rejecting runs, even if the stages describing those data are chosen separately for each start time.

## An evaluator for a growing number of stages

Put $L=\max(2,\lceil\log_2(N+2)\rceil)$. Fix a deterministic stage interpreter. Data consist of $b$ read-only advice bits and a public source $x$ of $m_0$ words. Each of $j$ stages has at most $N^D$ candidate events for a fixed $D$. Unused event numbers are inactive. Given the stage and event number, the interpreter computes an active flag, one target word address and one value in at most $u$ native steps *apart from* at most a fixed number of possibly adaptive calls for words of the preceding stage. The base table is zero or has an entry generator of cost at most $u$ from the public data. At each address the greatest-index active writer in a stage wins, with the previous value retained when none writes. A fixed number of banks and ordered write slots can be incorporated into indices and addresses. All native fields have $O(L)$ bits. A stage program can be stored in the charged advice by using a fixed interpreter for its bounded instructions. Initial query parameters of $O(1)$ words may also be public.

Suppose deterministic SAT takes $O(n\log^a n)$ time for some fixed $a$. On the specified word RAM there is a uniform algorithm for any requested final table word costing at most
$$
 (m_0+b+u+1)L^{C(j+1)}
$$
steps, for a constant $C$ independent of $j,N$ and the stage contents, in the range where this upper bound is polynomial in $N$. The loose use of bits for $b$ includes reading all its headers. The underlying computation at stage $j$ can have polynomial width and repeated, data-dependent addresses.

To see this, suppose a prior-stage word has a uniform routine with clock $T_i$. For a supplied threshold $k$, consider the predicate that an active event of index at least $k$ writes the requested address at stage $i+1$. A fixed existential RAM guesses the index and executes the event interpreter, running the previous table routine whenever needed. Its bounded time is $O(u+T_i+\operatorname{poly}(L))$, with a constant covering the bounded number of earlier word queries. Its genuine public input consists of $x$, the advice and $O(1)$ numeric parameters. Materializing the bounded-computation formula and deciding it by the hypothesized SAT solver costs at most $(m_0+b+u+T_i+1)L^{C_0}$ steps. With word fields of $O(L)$ bits, the full routing, native arithmetic checks, explicit indices and materialization contribute a fixed power of $L$, including when the represented instance is much smaller than $N$. [Charged input and bounded-run compilation](materialized-input-census.md) · [Native model and formula-access conventions](packed-band-transfer.md)

Use $O(L)$ such threshold tests to find the last writing index or certify absence. Once it is found, compute that event's value with the previous-stage routine. On absence query the previous value at this address. This gives the displayed bound by induction, increasing $C$ to absorb constants and the logarithmic search. The machine code need not be unrolled into different programs at increasing depths. A fixed evaluator receives the stage number and an explicit prior cap. The predicate compiled at the next stage invokes that evaluator only at a smaller stage number. One may use integer caps $(m_0+b+u+1)L^{C(i+1)}$ and compute them by capped word multiplications. The program for the predicate and its transition templates are fixed, including its call to the uniform evaluator. At polynomial caps, the host uses a fixed width coefficient covering these addresses and deterministic subcalls. A direct nested evaluation after selecting the winning event can use stack frames or restore touched scratch on return. A fresh address bank can be indexed by the level using $O(\log(N+2))$ bits and returned in time proportional to the work spent within it. This keeps the per-stage recurrence uniform. Source SAT calls on formulas of their own lengths use their native narrower widths via masking. Neither this proof nor the resulting evaluator requires the stages to generate their whole tables.

## A consequence on the signed formulas

Take the signed formula family for a hypothetical near-linear SAT solver, choosing all padding bits zero. Each source $x$ consists of the one fixed verifier description followed by zero padding. A row can give the finite description, source length and width convention in $O(\log N)$ bits, even when the row evaluator was fixed before the verifier was formed. A source-word query reads this prefix or returns zero under the padded layout. The uniform generator therefore supplies each requested packed word of the real formula from this tiny public input after a polylogarithmic setup. The description of a local generator is allowed to depend on the completed verifier; the fixed evaluator takes that finite data as input and need not know its own description. A forged generator has no bearing on the conclusion, which applies to representations predicting the genuine answers. Fix
$$
 0<\kappa<\gamma<1,\qquad 0\le\eta<\kappa.
$$
Consider a representation at a genuine time $t$ of the following kind. It has $b+u\le N^\eta$, the uniform event-index bound above, and is required to return the genuine word only on first incoming reads during the next $2\lceil N^\gamma\rceil$ instructions (or until halt). Its final requested address may be the native address, or it may be determined by the offset, current controller and address in $O(u)$ local operations. These constant-many query words can be added to the public input of every stage, so the table represented may even depend on them. The representation otherwise uses only the real formula or its public source, the advice and local native operations. It does not receive a separate arbitrarily long array of native history as a free public input.

Under the near-linear SAT hypothesis, there is a hard interval of $\lceil N^\gamma\rceil$ consecutive starting times on arbitrarily large unsatisfiable formulas such that **at every start, every such representation requires $\Omega(\log N/\log\log N)$ stages**. Indeed the read predictor can take as its row the advice, compressed source and clock/format headers, then run the preceding algorithm. For every $j\le c_0\log N/\log L$ with $c_0$ sufficiently small depending on $\kappa-\eta$ and $C$, both the row length and lookup time sum to $o(N^\kappa)$. The predictor is a fixed machine that supports the stage count and bounds as data, with polynomial caps and a fixed default on malformed entries. The earlier live-read theorem, applied to this evaluator, contradicts such a representation at each hard start. A per-time advice string, unlimited preprocessing and polynomially many candidate writers do not affect the quantifiers. [Persistent lower bound for actual incoming reads](live-segment-snapshot-queries.md)

This argument charges the source for each compiled existence test. Allowing arbitrary reads of a genuine length-$w$ history during event generation would add up to $O(w)$ public words per test in the bound above. As a simple example, one event per position flagging whether that position contains a nonzero word makes winner existence the OR of the whole supplied array. Exact deterministic OR on an arbitrary all-zero array must inspect every word. Existing classical CRCW PRAM time lower bounds for parity already reach $\Omega(\log n/\log\log n)$ as a function of the entire input. Here the stage programs are optional nonuniform descriptions for many different pieces of one fixed run, and the conclusion depends on the fast SAT hypothesis. [Beame and Håstad](https://doi.org/10.1145/28395.28405)

An arbitrary native solver can generate all its writes by using a separate stage for every instruction and retaining its controller. This costs as many stages as the run. The missing universal simulation would have to certify much shallower descriptions on at least one start in every long interval. The [explicit permutation counterexample](scatter-inverse-live-reads.md) shows why the length of an unbounded-time description alone cannot provide the necessary local generator.

## Quadratic and cubic references

Let $k=2$ or $3$ and instead assume a deterministic SAT solver of time $O(N^k)$. The stage evaluator still works with
$$
 T_{i+1}\le (m_0+b+u+T_i+1)^k L^{C}.
$$
Indeed the bounded-run formula is quasilinear in the preceding clock and public data, and the SAT call raises its encoded length to the $k$th power. Binary search still uses $O(L)$ tests. If $m_0+b+u=\operatorname{polylog}N$, induction gives $\log(T_j+2)\le C' k^j\log L$ throughout polynomial clocks, with $C'$ fixed by the uniform stages and the polylogarithmic exponent. The same program and integer-cap convention work at increasing $j$. Bit lengths of caps fit in the physical words in the parameter range being excluded.

On the corresponding signed family with zero padding, consider **one** polylogarithmic-bit stage description for an entire rejecting run. Supply the native time and either a work address or a controller-field index to the query. Require the true answer at every legal query from initialization through rejection. Allow a different description at each input. If the stage description has polylogarithmic event work $u$, its number of stages on these inputs satisfies
$$
 j\ge \log_k(\log N)-\log_k(\log\log N)-O(1).
$$
In fact, when $k^j\le c_1\log N/\log L$ for a sufficiently small fixed $c_1>0$, the evaluator's worst-case query latency is at most $N^{1/(2k)}$. The compressed source and the stage data form one polylogarithmic-bit summary for this fixed evaluator. They would violate $qL^3+s\min(q,L)=\Omega(N^{1/k}/L^{3/k})$ on its hard family. This use of the global query bound requires a summary valid throughout the run and charges the original formula or its virtual source consistently. It does not identify a long interval of individually hard snapshots for the polynomial-time solver. [Global query bound and self-input for $k=2,3$](polynomial-solver-state-queries.md)
