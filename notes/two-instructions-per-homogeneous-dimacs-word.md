# Nearly two executed instructions per homogeneous DIMACS word

For every sufficiently large byte-aligned encoded length $N$, there is one satisfiable ordinary proper 3-CNF file $F_N$ on which **all correct programs** in the separate-operation word RAM execute at least
$$
 \left(2-O\left(\frac1{\log w}\right)\right)\frac{N}{w}
$$
instructions. Here $w=\Theta(\log N)$ is the native width in bits, rounded to a multiple of eight. The word may be large enough for arbitrary polynomial addresses. Programs can have arbitrarily many instructions or registers, use input-dependent indirect addresses, and overwrite inputs. The same positive file works for all of them. The error is $O(1/\log\log N)$ on the coefficient per word.

This gives an asymptotically sharp coefficient in the pointwise program quantifier. For each fixed file there is a globally correct program accepting it in $2\lceil N/w\rceil+O(1)$ steps. A finite program chosen separately for each length may hardwire addresses and words. Measured in encoded bits the lower bound is $\Theta(N/\log N)$. The hard promise asks whether every designated word equals the base word. [Separate-operation RAM and the previous $5/3$ homogeneous-word bound](executed-operands-on-homogeneous-sat-words.md)

## Choosing two complete clause records

Fix a sufficiently large byte width $W=w/8$. Choose $d=\lfloor W/2\rfloor$ and a $d$-digit canonical positive decimal name $u$. Make one $W$-byte word from the clause line `u 1 2 0\n` by appending spaces. Each name gives a distinct word and there are $9\cdot10^{d-1}=2^{\Omega(w)}$ choices. The high or low endianness of the native interpretation can be fixed arbitrarily.

Let $J$ be the constant number of binary numerical opcodes. A unary expression here is a rooted ordered binary formula with leaves all equal to one indeterminate and no literal constants. Let $\mathcal E_s$ contain the expressions with at most $s$ numerical gates. Its size $D_s$ obeys
$$
 D_s=\sum_{i=0}^{s}\operatorname{Cat}_i J^i
 \le 2(4J)^s\qquad (J\ge1).
$$
For each candidate physical word $A$, evaluate all these expressions on $A$ at width $w$. Give each expression two integer ranks among the $D_s$ values, in native signed and unsigned order respectively, assigning equal ranks to equal values. The vector of ranks determines every native equality, signed comparison and unsigned comparison between two expression values. It takes at most $D_s^{2D_s}$ different values.

Take $s=\lfloor\log(w)/(3\log(4J+1))\rfloor$. Then $D_s=O(w^{1/3})$ and $\log(D_s^{2D_s})=o(w)$. Two distinct clause records $A,B$ have the same vector. In particular all these comparisons have the same outcome on all-$A$ and all-$B$ sources. The numerical results themselves are allowed to differ. The pair depends only on the width, opcode semantics, and a deterministic collision rule. A uniform generator can test the first $D_s^{2D_s}+1=2^{o(w)}$ candidate names, evaluate each expression and sort the rank vectors. Even allowing polynomial overhead in $w$, the work to choose the pair is $N^{o(1)}$ when $w=\Theta(\log N)$. The mathematical construction uses exact ranks.

Let $a,b$ be the distinct variable names in $A,B$. Public proper clauses force $x_1=x_2=0$, $x_a=1$, $x_b=0$. To force a literal $L$, put in all four clauses $L\lor(\pm x_3)\lor(\pm x_4)$; take the four independent sign choices and reuse coordinates 3 and 4 across the pins. Choose $d$ large enough that $a,b>4$. Declare $\max(a,b)$ variables in the DIMACS header. The header and 16 public clauses occupy $O(w)$ bits because $\log N=O(w)$. Pad to a native boundary, then place $m$ copies of record $A$ at distinct nonzero addresses. Any nonempty subset of replacements by $B$ makes the ordinary file unsatisfiable. Each such edit keeps the same valid header, byte length, and clause count.

More precisely take $m=\lfloor N/w\rfloor-C$ with a sufficiently large fixed $C$ for the chosen word-width convention. Form the header with $m+16$ clauses, fill the public prefix, align the start of the records using ASCII spaces, and put the remaining whitespace at the end. This realizes every sufficiently large byte-aligned $N$. A large declared variable universe with unused variables is valid DIMACS. If names bounded by the file length are desired, cap $d$ also by $\lfloor (\log_{10}N)/2\rfloor$. There are still $2^{\Omega(w)}$ candidate records.

## What one fixed native execution must pay

Choose any correct decider and its actual accepting run on this file. For each of the $m$ designated addresses choose its first original-word load. Such a load must occur before any overwrite, since changing that single word reverses SAT. Erase memory by following the concrete addresses and most recent writes of this one run. Each initial designated cell is a separate source. Its repeatedly read versions are aliases of that source. A binary numerical instruction contributes its two operands and result to a factor. A comparison contributes its two operands and observed outcome. A genuinely unary operation may be padded with an unused literal port, which anchors it and has no effect on replay. A register move can be treated as an alias. Literals anchor their components. Treat an address condition on a nonselected access as an anchored comparison paid for by the access. Keep the exact addresses of the $m$ selected loads as additional unary pins, free in the count. Every perturbation satisfying these constraints reproduces the entire accepting control path, including its stores and later loads. [Full trace transfer and incidence count](charging-native-addresses-in-a-fixed-ram-trace.md)

Let $u$ be the number of unanchored tree components containing selected sources, before adding the extra unary pins. If $Q$ instructions other than the selected loads have been executed, the incidence count gives $Q\ge m-u$. In detail, with $a$ binary value-producing instructions, $b$ binary tests including the charged address tests, $m$ sources and $\ell$ distinct literal nodes in the reduced source-containing graph, there are $3a+2b$ incidence edges and $m+\ell+2a+b$ vertices. Extra individual operations can be dropped from the count. A tree contributes one to vertices minus edges, a component containing a cycle contributes at most zero, and the number of literal-containing trees is at most $\ell$. Hence $m-a-b\le u$ and $Q\ge a+b$. Reusing an operand at two ports produces parallel edges, which form a cycle.

Consider one unanchored tree with $r$ sources. It has exactly $r-1$ factors by the same identity. The entire producer cone of any word in the component is a formula with at most $r-1$ numerical gates and the original sources as leaves. The trace has no directed time cycle. A repeated operand or two reconvergent paths inside one producer cone would give an undirected incidence cycle. Outgoing fanout to other tests or to other subtrees is allowed.

If $r\le s$, each producer formula gives an expression of $\mathcal E_s$ after replacing its leaves by the same symbol. Flip all $r$ designated words in this component from $A$ to $B$. Every comparison inside the component keeps its outcome because its two operands have rank-matched unary expressions. Other components retain their original values. If no selected-load address pin is incident, the perturbed run therefore still accepts. This contradicts the actual negative verdict on the edited valid DIMACS file.

A small tree must consequently touch at least one of the selected-load address pins. On the original run the value at this pin belongs to $\{e(A):e\in\mathcal E_s\}$, a set of size at most $D_s$. The selected loads have distinct concrete addresses, so each number can account for at most one such pin. A pin attaches to a single SSA value and hence to a single component. At most $D_s$ small trees occur even if arbitrarily many registers hold an identical numerical value. The other tree components each use at least $s+1$ of the $m$ sources. Thus
$$
 u\le D_s+\frac{m}{s+1},\qquad
 T\ge 2m-D_s-\frac{m}{s+1}.
$$
This counts actual instructions and allows arbitrary workspace. Substituting $m=N/w-O(1)$ gives the stated bound. In particular the address count did not assume a left-to-right scan.

## Matching it on the same physical input

A program specialized to $F_N$ first checks the encoded input length, then loads each native input word from its hardwired literal address and compares it with its hardwired expected value. It accepts on total agreement and calls a complete SAT decider on every failed check. A final partial word costs $O(1)$ instructions under the usual padding or mask convention. If input length is unavailable, two literal comparisons test the target width $w_0$ using $2^{w_0-1}\ne0$ and $2^{w_0}=0$ modulo the execution width. At that width, any valid DIMACS input agreeing on the checked words has the target header and all its declared clauses. A possible continuation contributes only whitespace on the comment-free domain. Missing original clause bytes would have been replaced by zero padding and would have failed the comparison. This is globally correct on valid DIMACS files and takes $2\lceil N/w\rceil+O(1)$ instructions on $F_N$. For the two-record promise alone, two instructions per designated cell suffice by the same construction. Distinct finite programs may attain that bound at different lengths.

It tests same-color word pairs at concrete widths, compares all finite unary expression orders independently, parses ordinary files byte for byte, and checks the verdict on every selected subset of edits. The Lean component checks transfer of every guard across a homogeneous source substitution and its composition over a forest of guards.
