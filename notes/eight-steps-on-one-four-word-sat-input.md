# Eight executed instructions on one four-word SAT input

The subsequent full census establishes a global optimum of nine in this finite model with arbitrary addressing. [Complete theorem and replay](exact-nine-step-clock-for-four-sat-words.md)

In the four-bit native RAM and the dense sign-plane SAT catalog, the satisfiable input **5488** requires at least **eight executed instructions** in every globally correct program. Its own optimal accepting path has exactly eight steps, since its four words can each be loaded and compared to a literal. In contrast the exact pointwise optimum on **4488** is seven. These two physical input memories differ by one bit and have the same SAT verdict. The finite lower bound places the unrestricted-code **global** worst-case optimum at this one length between eight and nine. The encoded length is sixteen data bits in this catalog. ## When an indirect read saves a step

Denote the four consecutive words by $P,Q,M,N$. Acceptance means $P\mathbin{\&}M=Q\mathbin{\&}N=0$ and $(M,N)\ne(15,15)$. At a satisfiable input with $P=p$ nonzero and even, and $M=m$, take the following path:

1. Load $Q,M,N$ in three instructions.
2. Compute $j=Q\mathbin{\&}N$ and load the word at address $j$.
3. Accept on this path precisely when $M=m$ and the loaded word equals $p$. Use a general fallback after either comparison fails.

Since $p\mathbin{\&}m=0$ and $p>0$, one has $p\ne m$ and $m\ne15$. If $j=1$, the indirect read returns $Q$, whose low bit is set. If $j=2$ it returns $m$. If $j=3$ it returns $N$, whose low bit is set. Larger addresses hold zero. None returns the required even nonzero $p$. Thus the comparisons force $j=0$, so the read returned $P=p$. Every accepting file along this path is satisfiable. It takes seven steps and covers every satisfiable file with this particular $p,m$.

A positive file is sensitive at each of its four words if and only if all four are nonzero. Nonzero words make adjustment of the mate in either pair yield a conflict. A zero negative-unit mask makes its corresponding positive mask dispensable. If $P=0$ and $M$ is pivotal, then $N=15$, hence $Q=0$ and $M\ne15$, which makes $N$ dispensable. Interchanging the two pairs gives the other case. There are 50 ordered nonzero disjoint nibble pairs, and hence 2,500 four-word-sensitive positive files. Of them 1,550 have $P$ even. All negative files have a four-step certificate by pinning a conflicting pair, or by pinning both negative-unit masks to 15. Each positive file with any dispensable word has a six-step certificate by pinning the other three words. The previously proved six-step exclusion gives exact pointwise optimum seven at 4488. The low bit of $P$ in 5488 prevents that particular indirect certificate.

## Reducing the seven-step search to three finite checks

Keep one path followed by the positive base and run its fixed instruction sequence on the comparison inputs. A globally correct program must see a different comparison vector on every negative file. A comparison reads registers or literals, changes no data, and can use a saved copy of any earlier register. Thus comparisons may all be moved to the end of this *single path*, preserving their values in the original order. This does not claim one can reorder the comparisons in a whole adaptive program. Four input words are individually pivotal at 5488, so each must be loaded before a first overwrite, and before the final comparison. Call these four base reads fresh. After padding with harmless comparisons if necessary, at most two further instructions are available in addition to the four fresh loads and a final comparison. Moves and fixed jumps can be replaced by renaming or omitted.

Call a register *simple on a set of files* if throughout that set it equals one fixed raw input column or literal. A high file has all four raw words at least four. On a high file a raw column, used directly as an address, points to scratch. Initially every scratch word is zero. The three exact finite checks below use the high positive base 5488.

- **Three raw guards.** On a 21-file high suite, every conjunction of up to three comparisons between raw columns and literals that accepts the base also accepts a negative. Equality and both orders, signed or unsigned, give 82 distinct negative agreement masks. Intersecting any three leaves at least one negative.
- **One ALU and two guards.** On the same suite, four fresh loads, one ALU and two comparisons cannot separate the base. This includes an indirect fresh load through the ALU result and unrestricted comparisons with literals.
- **Two ALUs and one guard.** On a separate 24-file suite, four fresh loads, two ALUs and one comparison cannot separate the base. Either ALU result may supply an address. Values read through the first result may feed the second ALU. Some negatives in this second check have low original words.

The following case analysis treats extra loads and stores; it is required because scratch is writable.

**One ALU.** With four loads and two comparisons the second check applies directly. Consider four loads, one store, one ALU and one comparison, or five loads, one ALU and one comparison. On the high suite, before the ALU all its operands are simple. With no store, any number of loads using simple addresses yields simple values: a literal selects a fixed original or zero and a high raw address selects zero. With a store and only four base loads, every such load is fresh on the base. Its address must be a literal on the high suite, since a high raw value would select scratch on the base. An earlier store to a literal cannot hit that future fresh address; a store to a raw address hits only scratch. Consequently all those fresh reads still return the same raw columns across the suite.

Now restrict the high suite by the extra comparison that this single ALU result equals its base value. Its operands before restriction are simple, so it is one ALU on original columns or literals. On the restricted slice replace the ALU value by the constant. With no store, all later values stay simple. With a store and four necessarily fresh loads, the same induction as before keeps the loaded columns simple. The final comparison is therefore between two simple words on that slice. A successful path would yield an accepting test using one ALU, the added equality and this last comparison, with all four raw words loaded directly. The second finite check excludes it.

**No ALU.** With no store even extra loads on the high suite always produce simple words. With four base loads all reads are fresh and remain simple, even with two stores, by the preceding induction: previously stored raw addresses are high and previously stored literal addresses cannot be future fresh addresses. These paths yield at most three raw comparisons. The remaining case has one store, five loads and one comparison. Before a first possibly nonsimple load, all addresses and values are simple on the high suite. A load observing the earlier store selects between a simple initial-memory word and a simple stored word according to equality of their address operands. When that equality is nonconstant and the stored value could matter, this load cannot be a fresh original read on the base. Indeed a fresh read must be at a low address and the addressing operand here would be a fixed literal. The earlier store to a raw address misses such a literal on the entire high suite, whereas a store to the same literal would already have overwritten the alleged fresh word on the base. Thus this is the only surplus base load. Restrict to the base outcome of the raw address equality. The surplus load becomes simple. Every later base load is fresh; any address supplied by a simple word must then be a low literal, and the earlier store cannot alter that read on this slice. A path would therefore be certified by the address equality or its complement together with the last raw comparison. The first finite check excludes it, including the case when no restriction was necessary.

**Two ALUs.** All four loads must be fresh and the only comparison comes last. This is precisely the third check. These cases and the raw checks include paths of fewer than seven steps by padding. Taken together they prove the lower bound.

## The finite data in the ALU checks

With four fresh loads and no stores, an indirect read on the high base must use a previously computed ALU result. Every raw word previously read on the base is high. The same computed address cannot supply two distinct fresh reads. Move the direct loads to the start of the path, keep the ALUs in their original dependency order, and move any load through an ALU result immediately after its defining operation. No store obstructs these moves. The observed words on *all* comparison inputs are preserved, including those with low data. Enumerate the subset of original columns read directly and the subset of ALU results used for indirect reads. At each such indirect read require the actual base address to be below four and fresh. On every negative lane evaluate the true addressed word, with zero for scratch.

Registers range over full four-bit words on every example file. For each ALU enumerate its 20 permitted operations on ordered operands drawn from all 16 literals and earlier available words. Equal full tables on a fixed suite may share a representative: an ensuing arithmetic instruction, lookup or comparison cannot distinguish them on any file of that suite. The one-ALU census retained 1,170 distinct base-compatible first-stage tables across the layouts on the high suite. The two-ALU census retained 4,855 first-stage and 1,914,264 second-stage tables. Across the two-stage census the comparison loop checked 118,516,365 unordered operand pairs, testing equality and both directions of both signed and unsigned order. For two guards, an agreement mask containing another mask is redundant, since either guard can be chosen at the same point. The external Python audit also checks the scalar truth table of every C++ ALU and exhausts the 65,536 physical files for the seven-step upper construction.

Run `OPENBLAS_NUM_THREADS=1 python seven_step_native_witness_audit.py` with a C++20 compiler. The two literal suites are embedded in the audit. The algorithm is exhaustive for its specified native operations; the reduction from arbitrary program paths above is a manuscript argument. Every four-word input has an eight-step certificate by direct literal pinning. Any improvement from eight to nine for the global deterministic clock must therefore couple different paths.
