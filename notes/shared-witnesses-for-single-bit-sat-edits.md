# Five SAT edits that cannot be covered by two witnesses

A *bank* of full assignments covers a list of satisfiable files on the same variables when each file accepts at least one assignment in the bank. Suppose every two files in a list share a full witness. Any four of them can be covered by two witnesses, simply by forming two pairs. Five files already can require three. They can all differ from one proper 3-CNF by one physical ASCII bit. The minimum bank size grows under a constant-clause extension even though one deterministic SAT solver decides the entire resulting family in packed scan time. This tests a possible inference from a growing finite obstruction to a running-time lower bound.

## What the edits encode

Take a 3-uniform hypergraph on vertices $0,\ldots,b-1$. Include the negative clause $(\neg X_i\lor\neg X_j\lor\neg X_h)$ for each triple. Calibrate three distinct false names $F_1,F_2,F_3$ by the seven proper clauses excluding every assignment except $000$. Force each $T_i$ true by $(T_i\lor F_1\lor F_2)$. Add another row of the same form at the edit position for $i$. An edit changes that row's first name to $X_i$. Use the decimal identifiers $10(i+1)+3$ for $T_i$ and $10(i+1)+2$ for $X_i$, so the change flips precisely one bit at an unchanged byte offset. The names 1, 2 and 3 can serve as the false names. Duplicating a clause in the restored file is permitted in ordinary DIMACS.

For any subset $S$ of edits, a fixed witness with support $A=\{i:X_i=1\}$ works exactly when $A$ is independent, $S\subseteq A$, and the constants have their prescribed values. In particular the edited file is SAT exactly when $S$ contains no hyperedge. A single assignment covers exactly the single-edit files indexed by its support. Consequently **the minimum bank size over all single-edit files equals the hypergraph chromatic number**. Independent color classes give a bank, and assigning each vertex to the first witness covering it gives a proper coloring. This applies to arbitrary hyperedge sizes at the level of the witness relation. The physical encoding just described uses only proper triples. [Lean covering equivalence](../lean/EditWitnessBanks.lean)

Every pair is compatible. On five vertices take all ten triples, so each witness covers at most two vertices. If any triple is absent, its three vertices form an independent set and the complementary two form another. Thus this is the unique obstruction on five labeled vertices in this encoding. More generally deciding whether two witnesses suffice is NP-complete here, even when every vertex occurs in exactly four negative triples and distinct triples meet in at most one vertex. This follows from monotone not-all-equal 3-SAT on linear 3-uniform instances, or from the stronger partitioned restriction of Darmann, Döcker and Dorn. The decision version for banks is in NP by checking two assignments against all the marked rows. On these very same templates the verdict for **any** subset of edits can be found in one scan by marking its vertices and checking the negative triples. The source of hardness is choosing witnesses that cover the full list. [Darmann, Döcker and Dorn](https://arxiv.org/abs/2412.03395)

If any two triples meet in at most one vertex, the first obstruction is at seven vertices. For six vertices, each triple spoils one of the ten unordered partitions into two triples. Linearity permits at most five triples because each uses three distinct pairs. Thus some partition works, and isolated vertices give the smaller cases. At seven vertices each triple spoils five of the 35 partitions into three and four. Linearity permits at most seven triples. A non-two-colorable system must attain seven, covering every pair exactly once. Conversely in such a system every vertex lies on three triples and each triple meets all six others. The five partitions spoiled per triple are disjoint, so no balanced partition works. An independent set of five is also impossible: its ten pairs would need ten distinct triples extending outside it. Thus there is no unbalanced two-coloring either. One example is the Fano plane. Exhaustion gives 5,596 labeled linear systems at seven vertices, with 30 obstructions, each having seven triples. These cardinalities concern the proposed witness test. They do not count RAM programs. [Exhaustion and emitted-file checks](../audits/edit_witness_bank_audit.py)

## Appending one editable site

Fix $k\ge1$. Replace the negative triples by a proper CNF for $\sum_i X_i\le k$, keeping all mark rows. Add one site at a time. At prefix $i$ use bits $R_{i,j}$ for thresholds $1\le j\le k+1$, with column zero permanently true. For each new $X_i$ require the following implications, using the fixed false names to pad unary or binary clauses.

* $R_{i,j}\Rightarrow R_{i+1,j}$ for $1\le j\le k+1$.
* $X_i\land R_{i,j}\Rightarrow R_{i+1,j+1}$ for $0\le j\le k$.
* $R_{i+1,k+1}=0$. Also forbid overflow at prefix zero.

If at least $j$ sites have been selected by a prefix, the implications force its threshold bit for $j\le k+1$. Conversely the actual prefix counts satisfy every clause whenever at most $k$ sites are selected. This is a sequential cardinality constraint. Every new stage appends $O(k+1)$ proper clauses and retains every previous body row and name. Only the DIMACS header counts need updating. For an eligible set choose the full assignment setting precisely those $X_i$ true and using their actual prefix counts. Every $k$ singleton files share a witness and every witness covers at most $k$ of them. The optimal bank size is exactly $\lceil b/k\rceil$, attained by partitioning the indices into blocks of size at most $k$. This is the largest possible minimum for *any* list with a witness jointly available for each subset of size at most $k$. In particular, appending one site to $b=mk$ sites forces an entire extra assignment. [Sinz on sequential cardinality encodings](https://doi.org/10.1007/11564751_73) · [Lean proof of the counter for arbitrary sizes](../lean/EditWitnessBanks.lean)

For fixed $k$ the encoded length is $N=\Theta_k(b\log(b+2))$. At every input with exactly $k$ edits, any deterministic correct SAT decider must inspect the word containing each further possible edit. Otherwise performing that additional edit gives the same observations and the opposite verdict. In the last half of the file the editable sites are separated by $\Omega(\log b)$ bits, so one word can inspect only $O_k(1)$ of them. Thus every such accepted run needs $\Omega_k(b)$ steps. Switching an inactive site that is first inspected last among those sites gives a rejected run sharing $\Omega_k(b)$ steps up to the distinguishing read. This holds separately at all large sizes.

There is a matching $O_k(b)$-step algorithm on the canonical packed layout. Compare the file to its expected clauses while allowing either value at each marked digit, and count edits up to $k+1$. Each row spans $O_k(1)$ machine words. Decimal spellings up to the maximum identifier $O_k(b)$ can be generated once in $O_k(b)$ word operations. Generate children $10j+d$ of each identifier by shifting its packed spelling one byte and appending digit $d$. Each spelling occupies a bounded number of words. A global solver can use the encoded header and physical length to reject implausible template sizes before allocating this table, verify all bytes, and use an ordinary complete solver on any mismatch. Equivalently this gives a direct $O(N)$ byte algorithm without packing. Thus the optimum witness bank increases indefinitely, while a single correct RAM program takes $\Theta(N/\log N)$ worst-case steps on this family.

The audit solves 922 distinct parameter-and-edit settings with CaDiCaL, checks their exact physical bit distances, tests the five-vertex and Fano witness supports, and verifies that each counter extension preserves the old clause list. The unbounded bank/coloring equivalence and the counter semantics are Lean theorems. The file layout and time bounds are manuscript arguments. [Audit](../audits/edit_witness_bank_audit.py)
