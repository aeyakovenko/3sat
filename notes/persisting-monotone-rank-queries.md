# Increasing query times in a bit-write-once replay

The sparse event certificate in the [SAT solver normalization](normalizing-stores-in-a-sat-solver.md) answers a load of one regular arena slot by counting its earlier increments. Suppose the entire increment sequence **and its exact future event times** are given to a deterministic replayer in advance. Can it serve arbitrary online choices of the slot in constant amortized time using bit-write-once memory? For a polynomial-size slot alphabet the answer is no. Some externally scheduled workload of $P=H(\log H)^{O(1)}$ guest steps costs $\Omega(P\log\log H)$, where $H$ is the number of challenge increments. The bound allows a trusted read-only advice table of $H(\log H)^{O(1)}$ bits for each event calendar, arbitrarily expensive computation to prepare it, ordinary CPU registers, and caching that depends on past queries.

## The online interface

Fix $H\ge2$, a word width $w=\Theta(\log H)$ sufficient to address the prescribed data, and a sequence $C[1..H]$ over $[S]$, with $S=\lfloor H^\delta\rfloor$ for fixed $0<\delta\le1$. After the $j$th event, an externally supplied slot $s$ asks for

$$
                \operatorname{rank}_s(C,j)=|\{u\le j:C[u]=s\}|.
$$

Several queries at the same event prefix occupy distinct, increasing guest times. Every answer must be returned before the next slot is supplied. Use $L\ge1$ with $L=(\log H)^{O(1)}$ and budget $B=\lceil HL\rceil$. Event generation, any fixed initial batch and ordinary background guest work cost $O(B)$ in total. Reserve between $B$ and $2B$ online queries per run. Every run can use the same public polynomial horizon $P=\Theta(B)$, padding the tail with idle guest instructions. The offline table may depend on $C$, the number and exact dates of events, the chosen query positions and the padding. It must serve every sequence of slot choices consistent with that calendar. Its contents and the source sequence count toward the static encoding below.

The fixed deterministic machine has a constant number of ordinary words, including its CPU registers. Other writable words are initially zero and bits can only change from zero to one. Charge all processing after delivery of the offline information, including initialization, between-query work, event handling and replies. Let $F=F(H)\ge1$ bound the worst total work divided by $B$ over such runs. Constant factors from the guest encoding can be absorbed in $F$. It suffices to consider $F\le(\log H)^{O(1)}$ because larger slowdowns already exceed the claimed bound. All positions and simulated microstep times below take $O(w)$ bits, so increasing the static cell width by a fixed constant factor suffices.

## Converting amortized work into simultaneous static queries

To encode the string $C$ for arbitrary static rank queries, use at most $1+\lceil\log_2 H\rceil$ separate runs. The static encoder may do unbounded computation. Start with the unresolved prefix set $J=\{1,\ldots,H\}$. In a round with $J\ne\varnothing$, put exactly $q=\lceil B/|J|\rceil$ query positions after each event in $J$ and none after other events. This preschedules between $B$ and $B+H$ queries. Choose the table and initialize the replayer **after fixing this calendar and before choosing any queried slot**. In particular a construction that inspects the absolute dates of all future increments is covered. Different rounds are free to use different calendars, tables and fresh initial memory.

Fix $K=\lceil 4F\rceil$. Just before delivering a slot at a marked prefix, inspect counterfactually how many steps the next reply would take on each possible slot. If all would take at most $K$, record this state as a representative of that prefix. Fill its remaining positions by legal arbitrary slots. Otherwise supply a slot requiring more than $K$ and let the machine answer it. Testing the possibilities takes time only in the offline *static encoder*. The chosen trajectory is an ordinary online run, so its total work satisfies the promised bound.

If a marked prefix never produced a representative, its $q$ answered queries alone cost more than $qK$. Thus the number of unresolved prefixes left after this round is at most $FB/(qK)\le |J|/4$. Repeat on this smaller set, each time fixing the entire new calendar before its run. This removes the circular dependence between future event dates and the adversary's selected queries. Schedules picked in earlier rounds depend only on $C$ and the fixed replayer. An external static query has not yet been specified.

## Reading an old machine state in constant probes per word

Store the offline tables and encode the selected trajectory of every round. A bit-write-once word changes value at most $w$ times. For each word that changes, keep its timestamps of changes and resulting word values. To recover a word just before any recorded microstep, find its last change at or before the relevant boundary, returning zero if there is none. A static word-predecessor structure on at most $w$ keys takes $O(1)$ probes by the fusion-tree bound $O(1+\log_w(w+1))$. The timestamps and the stored word occupy $O(1)$ static cells each. A static perfect hash dictionary locates the short history of a sparse address, including the zero default on a miss. These structures exist with polynomial-in-$w$ overhead per recorded change, more than sufficient here. Their static preprocessing is unrestricted. [Fredman and Willard on fusion trees](https://www.sciencedirect.com/science/article/pii/0022000093900404) · [Fredman, Komlós and Szemerédi on static hashing](https://doi.org/10.1145/828.1884)

Store a direct representative for each $j$, including its round, time, program counter, ordinary CPU words, interface cursors, and any clock visible to the replayer. If access to previously delivered slots is part of the interface, store the canonical transcript for each round and its visible length. The total number of executed steps is $O(FB\log(H+2))$. The full representation, including all tables, historical indexes and representatives, occupies $H\,w^{O(1)}$ **bits**. An address of width $O(w)$ in the dynamic machine requires storage only if it was used for a change. An initialized read-only table occupies its declared space, including its indexing information.

On an arbitrary static query $(s,j)$, retrieve the representative, present $s$ as its next slot, and run the deterministic reply. Each historical load uses $O(1)$ probes. Keep all writes made during this counterfactual reply in a temporary overlay and consult it first on subsequent loads. The static **cell-probe** model grants unlimited local computation on the query and cells already read, so this overlay needs no further static probes. The saved earlier stream, the current external input, and the known calendar implement any permitted interface accesses. The response arrives within $K$ steps by the representative's defining property. It is the correct rank even if this trial makes different writes or control choices from the canonical run.

This gives worst-case $O(1+F)$ cell probes for statically querying an arbitrary $C$. Belazzougui and Navarro's **Theorem 2** lower-bounds rank in $H\,w^{O(1)}$-bit space by

$$
             \Omega\!\left(\log\frac{\log S}{\log w}\right)
$$

for $S\le H\,w^{O(1)}$. Their Theorem 1 reduces colored predecessor to rank with $O(1)$ extra probes. Thus for polynomial $S$ and logarithmic words $F=\Omega(\log\log H)$. This lower bound applies to indexes larger than a succinct encoding, including all the different calendar-specific advice tables above. [Theorems 1 and 2, §2](https://users.dcc.uchile.cl/~gnavarro/ps/talg14.pdf) · [Pătraşcu and Thorup on static predecessor](https://arxiv.org/abs/cs/0603043)

With unlimited preprocessing of the trusted table, $O(\log\log H)$ query time is attainable within this interface. Pack the event pairs $(C[u],u)$ in slot-major order with the slot count as satellite data. Query their static predecessor at $(s,j)$ and return zero if the predecessor has another slot. One may store every binary key prefix in a static dictionary, binary-search the longest present prefix and use the adjacent sorted leaf to obtain the predecessor. This takes $O(\log w)$ probes and $O(Hw)$ dictionary entries. The encoder can also supply the ordinary chronological event array so that a register tracks $j$. This is an offline index, with no requirement to generate its entries inside the bit-write-once budget.

## One-bit answers with two varying literal identifiers

The same lower bound holds when the only answer requested is the **parity** of the rank. Here is a direct reduction from the colored predecessor problem used in Belazzougui and Navarro's Theorem 1. Arrange its $H$ keys in a universe of $S-1$ rows of $H$ columns each, in row-major numerical order. Each key has a payload bit, and a query requests the payload of the last key at or before its position, using zero before the first key. For each row store the last payload strictly before that row. At each present key compute the XOR of its payload with that of its strict predecessor. Now list the keys in order of **column**, breaking ties by row. Emit the key's row symbol when the payload changes and a common dummy symbol when it stays the same. This gives one length-$H$ string over $S$ symbols. Store $j(c)$, the number of keys from columns at most $c$, for every column. These two extra tables cost $O(H+S)$ words.

For a query at row $r$, column $c$, take the earlier-row baseline and XOR it with $\operatorname{rank}_r(C,j(c))\bmod 2$. The row's consecutive changes telescope up to column $c$. The formula also handles empty rows and prefixes with no keys. Thus a static parity-rank query plus $O(1)$ probes recovers colored predecessor and inherits its lower bound at the stated space. The historical conversion uses only the cost and correctness of one reply, so it applies unchanged to these Boolean answers. The case $j(c)=0$ can be answered directly.

There are ordinary SAT queries with this exact interface. For a fixed event array, make one variable $Y_s$ per slot, impose at most one true flag with a fixed linear-size prefix circuit, and include a positive unit with identifier $Y_s$ to select the queried slot. Put a zero unit on $Z_0$ and four ordinary clauses at each $u$ fixing $Z_u=Z_{u-1}\mathbin{\oplus}Y_{C[u]}$. A final positive unit with identifier $Z_j$ asks for the prefix parity. With distinct flag, prefix and accumulator namespaces, the verdict is precisely $\operatorname{rank}_s(C,j)\bmod2$. The fixed-width 3-CNF has $O((H+S)\log H)$ encoded bits. Units may repeat their one literal in three positions. Across queries only the identifier in each of two designated units varies. The shared template and all of its fixed formula words are eligible for the offline preprocessing. The explicit ternary version formalized here has $4(S+H)+4$ clauses. [Lean proof of satisfiability and the exact clause count](../lean/PrefixRankParity.lean) · [Calendar and memory-history lemmas](../lean/PersistedRankQueries.lean) · [Colored-predecessor audit](../audits/rank_replay_audit.py)

Consequently even returning one SAT verdict for each of these successive inputs needs the stated worst-case aggregate work in the online bit-write-once model. The future $j$ values and their positions may be announced in advance. The new slot field $s$ is supplied at its query, after all preceding answers. Arbitrary queries to already delivered formulas can be implemented from the shared template and the saved slot transcript. This proves a lower bound for online reuse of that template. The bound per query is much smaller than the length of an ordinary instance, and the reduction does not grant access to formulas that have yet to be delivered.

## Which part occurs in normalized RAM runs?

Use the normalization variant with one ordinary binary high word per promoted address. Each guest store advances a logical version. Every $L$ stores to an address generate one high increment. First allocate each of the $S$ slot counters in fixed order by $L$ guest stores of zero to its own address. For event $u$, read the guest count at $C[u]$, add one, and store the result exactly $L$ times at that address. After event $j$ the guest data themselves hold the desired ranks. A query is a read at a requested slot. The preliminary high increments are fixed, and subtracting the known one per slot gives the challenge rank. These groups use $O((H+S)L)=O(B)$ guest operations. Event and query blocks can have fixed lengths, with padding if needed. All addresses, counts, cursor values and the padded clock have logarithmic word width. This realizes the cost separation on an interactive RAM workload, with a public high-event history and future query colors supplied online.

The [version with a fully readable future array](visible-future-rank-queries.md) charges early field accesses, and the [reset and hint bounds](bit-resets-and-advice-in-online-rank.md) quantify two further ways to service these replies. For a SAT input, the read-only formula and the fixed solver determine the future query colors. A compiler can exploit that dependence, specialize to one solver, or compute information about those future queries from the original input. The lower bound therefore defeats the proposed general replay based on chronological order, the increment table and past queries alone. It provides neither a SAT time lower bound nor a lower bound on a compiler allowed query-color-dependent advice. A static rank lower bound by itself would not handle the stateful amortized interface. The calendar selection and historical-word simulation are the extra steps. There is prior work on partially persistent rank indexes with updates known offline. Those queries can address any historical version directly. Here the dynamic program only has to answer at the current prefix and may cache previous requests. The static verifier builds coverage across several legal dynamic histories. Priority for this combination is unverified. [Compressed persistent rank and select indexes](https://cskeith.github.io/research/wads13.pdf)
