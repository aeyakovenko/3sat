# The physical size of a parity face in ordinary SAT

On a full coordinate face of binary strings, exactly $k$ distinct physical bits are free, each once, and all their $2^k$ settings are allowed. If every single-bit change reverses the verdict at every point, the verdict on this face is parity or its complement. For canonical proper ASCII DIMACS 3-CNF of length $N$ bits the **largest possible $k$ has order $N/\log N$ as a capacity bound**, with matching families at unbounded lengths. This measures independent pivotal bits. It gives a constraint on a proposed induction that increases the number of independent inputs at every step.

Here canonical means one header of the form `p cnf V C`, followed by LF, and exactly $C$ clause lines; one ASCII space separates each field, a clause has three literals and a final zero, and each line ends in LF. Positive decimal identifiers have no leading zeroes; a negative literal has a leading minus. Unused declared identifiers are allowed. Each clause uses three distinct variables. The upper bound extends to noncanonical whitespace and comments if their placement and the token layout are fixed and only name digits vary. The circuit-face construction with one independent name bit per input already attains $N=\Theta(k\log(k+1))$ on parity, with every declared identifier occurring. ## What a model of one positive file forces

More generally, fix any CNF layout and all the signs. A variable token at a particular literal occurrence may depend on its own nonempty block of $b_i$ independent bits. Its $2^{b_i}$ settings choose distinct variable names. Different tokens have disjoint bit blocks. All other tokens are fixed. Let $D_i$ be the set of names in active token $i$, let $h$ be the number of active tokens, and put $V_* = \sum_i 2^{b_i}$. All formula comparisons below concern actual satisfiability, allowing unrestricted auxiliary variables.

If $h\ge3$ and the restricted verdict is parity, **every active token has its own disjoint set of names, and every one of the $V_*$ names must also appear at a fixed occurrence**. At most one literal occurrence in a clause is active. The printed digits in the fixed occurrences alone consequently number at least
$$
                        \sum_{j=1}^{V_*}(1+\lfloor\log_{10}j\rfloor).
$$
The same claims hold for complemented parity.

To prove the first constraint, take any positive file and one of its models, considered as a total assignment to all potential names. Flipping one bit of active occurrence $i$ must produce an unsatisfiable file. Only its clause changed. Under the same assignment every other literal of that clause must therefore have been false and the original selected literal true. This applies simultaneously to every active occurrence and every model of this positive file. It excludes two active occurrences in the same clause.

Suppose distinct active tokens $i,j$ both admit a name $v$. If their signs are opposite, set both tokens to $v$. Use one bit in a third token to complete to a positive file. Its model would have to satisfy both signs on $v$. If their signs agree, set $i$ to $v$, and $j$ to a one-bit neighbor of its setting for $v$. Again complete to a positive file. Flip that bit of $j$ to select $v$. The original assignment already satisfies the newly selected literal at $j$ because it satisfied the occurrence at $i$. All other clauses retain their values, contradicting the required negative verdict. This proves disjointness.

For $v\in D_i$, choose a negative file at which $i$ selects $v$, using any outside bit to adjust parity. Flipping an $i$-bit gives a positive neighbor. Dropping the changed clause therefore leaves a satisfiable common formula. If $v$ had no fixed occurrence, disjointness and injectivity would make $v$ fresh in that common formula. Give $v$ the value satisfying the one deleted literal. This extends a model to the negative file, a contradiction. Finally $V_*$ distinct positive decimal integers cost at least the displayed number of digits even when each is printed just once.

The third token matters. Two oppositely signed unit clauses that independently select between the same two names are satisfiable exactly when the choices differ. The two false padding constants in the construction below make both units proper without any extra occurrence of either name.

With only one or two active tokens, fix all tokens except one of largest block size $b$. Half the $2^b$ names at this token give a negative file. Each such name must appear elsewhere in the fixed configuration. Otherwise the same deletion and fresh-variable argument works. Thus these other printed positions contain at least $2^{b-1}\ge V_*/4$ distinct names. This also gives $N=\Omega(V_*\log(V_*+1))$ in the small-$h$ cases. Since $2^{b_i}\ge2b_i$ for $b_i\ge1$, the physical bound follows for $k=\sum b_i$.

Parity is only one way to guarantee the pair comparisons. The disjointness and fixed-occurrence proofs for $h\ge3$ also work if every positive setting becomes negative under every single-bit flip and every setting of any two whole blocks extends to some positive setting. To obtain a negative file at $v$ with a positive neighbor, extend an $i$-setting adjacent to $v$ to a positive setting and then make the flip. Thus sparse sets of positive settings with these projection properties obey the same bound.

## Canonical syntax and a matching construction for arbitrary blocks

In a canonical body a single change between legal files must preserve the number of LF bytes, because the header specifies that number, and must preserve the number of spaces, because each of those lines contains exactly three. A minus is not a one-bit neighbor of any decimal digit. A space or LF thus cannot change to another character, and a sign cannot turn into a digit. The terminal zero is fixed. A lone change to a header with the body held fixed cannot change the SAT verdict of two valid files. Consequently a full parity face of these files has all its free bits in decimal variable names, in fixed token positions. Canonical decimal strings are injective as identifiers. In a fixed layout with separate polarity-bit positions one can also bound the number of free signs. Freeze all names. If three or more signs vary, no two such occurrences can share a variable: choose opposing polarities at the two positions and restore a positive setting at a third. Each varying literal would have to be true in the same model. Thus the signs alone also require $\Omega(k_s\log(k_s+1))$ bits at $k_s$ free signs. Freezing all signs gives the name bound, and the larger of these two counts is at least half of the total.

The same order bound holds for a proper three-literal **numeric body with arbitrary whitespace** when the body and clause count are fixed and there are no embedded comments. This allows a physical change to move a token boundary. At each byte position record whether the byte is nonwhite. The number of runs of ones is the constant number of literal and terminator tokens. Status choices at different byte positions are independent. At a byte whose status can toggle, changing $0$ to $1$ changes the run count by $1-L-R$, where $L,R$ are the two neighboring statuses, with zero sentinels. Thus the two neighbors are fixed with opposite statuses, for every choice. Each optional byte attaches to exactly one adjacent permanent nonwhite run. Runs of permanent nonwhite bytes give persistent token cores, each with at most two optional boundary bytes. The ordinal positions of the zero terminators and of the three literals per clause are fixed. A bit exclusively in always-whitespace, or in a terminator without changing the decoded tokens, cannot be pivotal.

Consequently each active signed literal depends on its own block of physical bits. Each possible *unsigned* name has at most a fixed constant of physical spellings on one block: fix the presence of the two endpoints, their values when absent, and one of the allowed signs. At the resulting token length the decimal digits of the value, including any leading zeros, are unique. Thus a block of $b$ bits has at least $2^b/O(1)$ possible names. The overlap proof permits variable signs too. For settings that name the same $v$ with opposite signs, use them directly. For matching signs, complete a neighbor of the second setting and then flip back; the witness satisfying $v$ at the first occurrence still works at the changed second occurrence. The freshness proof is identical. When there are at most two blocks, the half of settings giving rejection at a largest block still correspond to $2^b/O(1)$ distinct names. This proves the same asymptotic lower bound with fully independent physical bits anywhere in the indicated numeric body. It does not require sign bytes to be constant. A permissive reader can, for example, treat carriage return as whitespace one bit away from a minus sign.

## Variable-width clauses and changing token boundaries

The $\Omega(k\log(k+1))$ lower bound survives for **ordinary numeric CNF bodies of arbitrary clause width, with a fixed header, no embedded comments, and every corner valid**. Whitespace can change, and decimal spellings may have leading zeros and an optional sign. Interpret zero tokens as terminators. The bound here is on $k$, without a prescribed block decomposition.

First locate one permanent nonwhite byte in each of the $M$ zero terminators. Put every byte that can be whitespace in a whitespace state. In this corner the zero tokens consist of permanent nonwhite bytes. Mark one position in each. Keeping whitespace fixed, setting the permanent bytes to their values in any target corner preserves which tokens are zero. Changing one byte can affect only its token and the number of zeros must stay $M$. Now insert the optional nonwhite bytes of the target one at a time. An insertion creates a token, extends one or joins two. A token already containing a nonzero digit cannot turn into a zero. Losing a zero token, creating a zero token or joining two zero tokens would change the required count. Thus the marked bytes always belong to distinct zero tokens and meet every terminator. Between successive marks the nonzero literals belong to a persistent clause, even if the terminators extend into those regions. A free bit confined to a terminator or to terminal whitespace could not be pivotal. This fixes a partition of the free bits among clause regions; each clause depends only on its region.

Let $g$ be the number of regions with free bits. If $g\ge k/32$, retain just one free bit per region and fix the others. All names that can occur on this subface occur in two files: set all retained bits to zero, then all to one. Write $v$ for the size of their name union. A fixed total assignment to these $v$ names accepts a Cartesian product of subsets of the two choices in each region, since satisfaction is conjunction over clauses. Any such product contained in one parity class has size at most one. Covering all $2^{g-1}$ positive files therefore requires $2^v\ge 2^{g-1}$. The two files together print at least $g-1$ distinct names, proving the length lower bound.

Suppose $g<k/32$. In each active clause mark the first and last byte positions that contain a free bit. In any satisfying corner choose a model and a true literal occurrence in that clause. Changing any one bit of the region must destroy that occurrence as a true literal in that clause; otherwise the assignment still satisfies the entire file. A change outside its token and its two immediately neighboring bytes leaves this occurrence intact. Hence every byte **strictly between** the two extreme positions is nonwhite at that corner. This holds at every possible setting of an interior byte: while fixing that byte, use a distinct free bit at an extreme position to complete to a positive corner. Freeze the at most two extreme bytes in each region. At most $16g$ bits are lost. All remaining free bytes have permanently nonwhite status; all other bytes have fixed status. Thus the residual parity face has fixed token boundaries and at least $k/2$ free bits. At a fixed decimal token length an unsigned name has only constantly many signed spellings. The signed-token argument above now gives the claimed bound. The case $k$ bounded changes only the absolute constant. This argument itself requires a fixed numeric body. The following reduction handles a specified comment and header grammar.

## Free bits in the header or comments

Consider the following token-delimited ASCII dialect. LF is the only line terminator. Spaces, tabs, CR, vertical tab and form feed are horizontal whitespace. Blank lines and lines whose first nonwhitespace character is lowercase `c` are ignored. A single header line must contain precisely `p cnf V C` with nonnegative decimal counts and optional leading and trailing horizontal whitespace. All remaining noncomment data are signed or unsigned decimal literal tokens and zero terminators; exactly $C$ zero terminators are required. The body can span any number of lines. Require every file on the face to be legal. Here the same $k=O(N/\log(N+2))$ conclusion allows independent physical bits **anywhere in the file**. These explicit syntax choices use the DIMACS problem line and clause termination conventions. [DIMACS suggested format, Section 2.1](https://www.cs.ubc.ca/~babic/doc/dimacs_cnf.pdf)

On a one-bit edge between valid files the physical position of the header's `p` stays fixed. If the LF positions are unchanged, only one line can change. Both files must still have exactly one header; changing its leading position while leaving the line valid cannot happen in one edit since a header contains precisely one `p`. If an LF is added or removed, either the header is elsewhere or the joined valid header line contains exactly one `p`, necessarily the one used by the corresponding split header. An LF is not a one-bit neighbor of `p`. Changing the LF at the end of the header would require both the shorter and the longer header to be valid. The alternative byte can only be horizontal whitespace at that position, since LF has no one-bit neighbor among the header's structural characters or digits. Only trailing whitespace can have been moved from the header into the body. There is no verdict change. The same reasoning at EOF permits an empty zero-clause body. With the header endpoint fixed, earlier edits cannot affect the verdict on a face of entirely legal files. All pivotal bits therefore lie after this endpoint.

Consider a body bit for which one local byte setting supplies LF. If the scanner is outside a comment before that byte, a one-bit alternative to LF can only be horizontal whitespace on a valid numeric line. The two choices leave the same tokens. A following `c` must begin a legal comment in both choices if it is encountered outside a comment. If the scanner is inside a comment, setting LF exposes only the suffix through the next LF or EOF. That suffix is empty, a comment, or numeric tokens. The two surrounding lines delimit tokens, and no zero can be added since the clause count is unchanged. The possible edit only inserts disjuncts into one clause. Its satisfiability is monotone in the direction of supplying LF, including the case of a neutral edit.

On a parity face of dimension at least two this byte cannot have precisely one free bit, because along that coordinate both directions of verdict change occur. If the byte has more than one free bit, fix the surrounding prefix of a corner where toggling to LF is pivotal. The scanner must already be inside a comment. Two adjacent *non-LF* settings of this same byte then both leave its content ignored, giving a neutral edge. This also contradicts parity. Hence all LF positions are fixed. With fixed lines, a comment cannot become a numeric line in a single valid edit: lowercase `c` has no one-bit neighbor that is a digit, sign or horizontal whitespace. Introducing a new first character in earlier whitespace leaves the old `c` unparseable on a numeric line. Any edit that merely changes comment text has no effect on the verdict. Strip the fixed ignored lines, keeping line boundaries as whitespace. We are back in the numeric-body case at a length no greater than $N$. The one-dimensional case is already bounded by a constant. The argument covers strict or permissive spellings of zero whenever validity enforces the declared number of zero tokens.

## Encoding prescribed block sizes

For a prescribed list $b_1,\ldots,b_h$ one can meet $N=O(V_*\log(V_*+1))$. For each $i$ reserve $2^{b_i}$ different names $v_{i,u}$, using a fixed decimal prefix identifying $i$ and $b_i$ terminal digits independently chosen from ASCII 2 and 3. For instance use equal-width decimal prefixes beginning with 1. In one positive unit put the selected name $v_{i,x_i}$. These $\sum_i b_i$ bit positions are the whole physical face. Use fixed clauses implementing $v_{i,u}\leftrightarrow z_i$ for odd-parity $u$ and $v_{i,u}\leftrightarrow\neg z_i$ for even-parity $u$. Therefore $z_i$ equals the parity of the selected block. A bounded-fan-in XOR chain with a pinned output enforces the target total parity. Each gate uses constantly many clauses. Force two disjoint constants $F_1,F_2$ false using four fixed proper clauses per constant, with two other dummy names and all their sign patterns. Emit each changing unit just once as $(v_{i,x_i}\lor F_1\lor F_2)$. Pad the fixed binary and unit clauses using the same false constants. This keeps every varying physical bit at a single occurrence. Use disjoint decimal prefixes for auxiliary variables. The identifiers have $O(\log(h+1)+\max_i b_i)=O(\log(V_*+1))$ digits and there are $O(V_*)$ literal occurrences. The same size bound includes the header. Gaps in the resulting numerical range are harmless under the stated DIMACS convention. PicoSAT checks every verdict on four small block-size lists, and the byte audit checks that arbitrary simultaneous flips alter exactly the chosen physical positions. [Multibit construction audit](../audits/ordinary_circuit_face_audit.py)

In particular there cannot be an infinite sequence of such files that gains one independent fully pivotal bit at each increase of one physical byte. An arbitrarily long *finite* interval of consecutive byte lengths can carry those increments if the first file in the interval is large enough. The bound also permits one-bit modifications that expose an arbitrary residual SAT instance. An unrestricted RAM lower bound would need to force computation beyond observing the inputs. Conventional CNF encodings put parity's inputs in the assignment; in this result the bits choose the names printed in the file.
