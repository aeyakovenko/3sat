# Can repeated transitions shorten a unary hierarchy witness?

**Research journal, 2026-11-24.** Fix a unary language H in nondeterministic multitape time O(n¹²) outside nondeterministic multitape time O(n^(23/2)), supplied by the unary time hierarchy. Fix a verifier for H and put it in block-respecting form at block length b=n. It has a fixed number of tapes and O(n¹²) time. During each b-step epoch each head stays within one block until the possible move into a neighboring block at the end. Use absorbing halting states and cap the padded run at B=O(n¹¹) whole epochs, with a fixed constant chosen for this machine. A visible transition records its input and output block contents on each tape, head offsets, finite control, and which heads cross a boundary and in which direction. It has O(b) bits. It excludes the b internal nondeterministic choices and absolute block addresses. At tape boundaries include the appropriate end-marker convention among the local data. [Williams, Theorems 2.1–2.2](https://www.cs.cmu.edu/~ryanw/improved-algs-lbs2.pdf) · [Strassle and Subercaseaux, Lemma 3.1 and §§2–3](https://arxiv.org/html/2611.11832v1)

## A limit on explicitly listing distinct transitions

If an accepting run uses V different visible transitions, a nondeterministic machine can certify acceptance in Õ(B+Vb+n) bit time. First guess the dictionary of at most V full transitions. For each entry guess internal choices and independently simulate that b-step segment on the fixed number of local tapes. Reject illegal crossings and incorrect results. The checks cost Õ(Vb) and do not use a SAT solver. The dictionary entry supplies a genuine segment usable at every occurrence, because the machine has no hidden state beyond those verified fields and the untouched tape blocks.

The remaining certificate names the entry for each epoch using O(log(B+1)) bits. To avoid comparing b-bit blocks on every occurrence, sort the O(V) dictionary block strings once and assign equal strings equal short identifiers. Include the initial block patterns in this pass. At b=n, a unary input gives only constantly many kinds of initial blocks, including end markers. Replace the transition dictionary's content fields by these identifiers and join its compact records to the occurrences by sorting on entry number. Replay the directions chronologically, checking the finite control and the offsets and assigning absolute block numbers on each tape. Sort visits by (tape, block, time). Check that the first input identifier is correct for that initial block and that each following input identifier equals the preceding output. Check the initial and accepting controls. These are exact comparisons. The sorted occurrence records have O(log(n+2)) bits for this clock. Multitape merge sorting and these final passes fit the bound. Conversely the verified local branches concatenate to a legal global computation, since every read of an old block receives the checked prior contents.

For any fixed 0<ε<1/2, **infinitely many accepted unary lengths of this actual H require more than n^(10.5−ε) distinct transitions on every accepting run** of the fixed block-respecting verifier. Otherwise cap V there. The resulting time Õ(n¹¹+n^(11.5−ε)) fits the excluded O(n^(23/2)) bound. Finitely many exceptional inputs can be hardwired; nonunary strings can be rejected at the outset. This argument permits completely different internal witnesses for different dictionary entries. It rules out plain transition deduplication without imposing any hypothesis on SAT.

## Certifying an entire family of transitions at once

A more permissive certificate assigns O(log n)-bit names to block contents. Guess two Boolean circuits. W(name,j) supplies the symbol at offset j of a named block. R takes the names of all input and output blocks of an epoch, its control states, offsets, and boundary flags, and decides whether that record is allowed. Use a fixed constant in the name-length bound, sufficiently large to index O(B) names. Check the distinguished names for the constantly many initial block patterns directly using W. If supplied as guesses, these initial names must pass the same comparison. No injectivity is required of W.

Require that **for every record z with R(z)=1, there exists a genuine b-step computation realizing its decoded endpoints**. Invalid flags, offsets or decoded symbols cannot certify an eligible record. This is one global test: for a particular z, guess b choices and verify a local segment, decoding O(b) symbols from W. On a logarithmic-word RAM this calculation takes Õ(b(1+|W|)+|R|+1), counting the circuit descriptions and all gates accessed. Under a deterministic cubic SAT algorithm on encoded input bits, the quasilinear reduction to explicit SAT decides the local existential in Õ(U³), where U=b(1+|W|)+|R|+1. An outer existential guesses a bad eligible record and runs that deterministic decision procedure to completion, complementing its answer. Compiling this outer computation to one more explicit SAT instance and running the solver costs Õ(U⁹). The same SAT program is used at both levels. No local witness-selection circuit is assumed. [Quasilinear SAT completeness](https://people.csail.mit.edu/rrw/automated-lbs.pdf)

Now guess B successive named records explicitly. Evaluate R on each in Õ(1+|R|) time. Check head motion, chronology and successive visits as above, using the guessed names for content equality. Requiring matching names even when W has aliases is sound. Completeness calls for a *coherent choice of names* on the intended accepting run. Each eligible occurrence has an actual local witness by the global test, and the equality checks guarantee that separately chosen witnesses can be concatenated. The chronological sequence of records may have no short generating circuit.

For example, with both circuit description lengths bounded by n^(1/5), the global test costs Õ(n^10.8) and the occurrence checks cost Õ(n^11.2). The whole nondeterministic RAM recognition fits n^(23/2) even after quasilinear RAM-to-tape verification overhead. Hence if every sufficiently large accepted input of H had one such pair W,R and coherent accepting schedule, cubic SAT would be impossible. The unconditional diversity bound above forces such a presentation to cover very many different actual transitions; it permits a circuit to define them parametrically. A short name can identify a string of n bits, but listing one name per block does not construct W, and computing the exact eligible relation separately at every epoch by SAT would spend much more than the occurrence clock. No construction meeting these bounds for H was found. Lean verifies that consistent named visits give consistent decoded block contents throughout the trace, even with aliases and separately witnessed local semantics. The sorting and time estimates are manuscript arguments. [Lean check](../lean/EpochDictionary.lean)

## A name can denote a whole region

Replace W by a circuit Q(name,u) accepting a set of b-cell block words. The sets can overlap and some can be empty. An initial block's true content must pass Q at its distinguished name. Require that for every eligible record z and **every** tuple of concrete input block words in its named regions, there exists a b-step branch with the prescribed offsets, control and crossings whose resulting words lie in the named output regions. The outer search for a violation guesses both z and the concrete input tuple. Its inner existential guesses local choices, simulates the epoch, and runs Q on the resulting words. Thus the two nested SAT calls now cost Õ((b+|Q|+|R|+1)⁹), with the fixed tape and alphabet counts absorbed. R still acts only on the short names and metadata in the chronology.

Starting at the true initial tape contents, apply the local condition inductively to the block tuple actually present at each visit. Untouched blocks retain their region memberships; the chosen outputs acquire the required memberships for later visits. Different branches can choose different representatives of the same name. No uniform member-selection circuit for Q is needed. Quantifying only over *some* input representative per record would permit a false run: a first epoch writes zero and gives it the name {0,1}, while the next epoch requires a one and uses a different representative. Singleton regions checking every bit of W recover the previous certificate.

For H one may therefore allow |Q| up to n^1.2 while retaining |R|≤n^0.2. Local certification still costs Õ(n^10.8) and the ledger Õ(n^11.2). This also permits forgetting arbitrarily many physical bits whose possible values have no effect on a valid next step. The open point is simultaneous coverage of an actual accepting chronology and local liftability for all inputs that the proposed regions admit. Lean verifies the forward lifting without imposing disjointness or a choice of canonical representatives. [Region lifting](../lean/EpochDictionary.lean)

## Testing concrete partial records without an eligibility circuit

There is a version with no guessed circuits at all. Let an ordinary name be a literal pattern specifying at most ⌈log₂(n+2)⌉ cell offsets and their symbols. The remaining cells are free. Include special names for the known initial block kinds. Word membership in a named region is now explicit. An entire epoch record has ℓ=O(log²(n+2)) bits. Guess the ledger, check names and chronological links as above, then sort it to obtain its V distinct records. Test local liftability only for these records. One cannot infer their universal input condition by checking a single representative.

Paying for a separate nested SAT calculation for every record would be unnecessary. Group the distinct records into batches of g=max(1,⌊n³/ℓ⌋). For a batch, the outer nondeterministic search guesses a record and concrete inputs in its regions, checks by a scan that this record occurs in the batch, and runs the inner SAT procedure for existence of a legal local execution ending in the requested regions. All full words, pointers, internal choices and exact special-name tests for *one* local execution cost Õ(n) nondeterministic RAM time; hence ruling out its existence takes Õ(n³) deterministic time under the hypothesis. Batch membership costs O(gℓ) before logarithmic overhead. One outer SAT query therefore costs Õ(n⁹), including its full batch input. There are at most 1+V/g batches. This gives a total verifier clock

    Õ(n¹¹ + n⁹ + V n⁶).

For example, suppose every sufficiently large accepted length of H has an accepting chronology of the stated partial records with V≤n^5.4, each distinct record liftable for all compatible concrete input tuples. The claimed cubic SAT algorithm would give a nondeterministic recognizer in Õ(n^11.4), contradicting the defining lower bound for H. No circuit for block contents, local witnesses, the eligibility relation, or the sequence of visits appears in this premise. Many different actual n-cell transition tuples would have to share a single liftable partial record at the difficult lengths. The unconditional raw diversity bound does not establish or disprove that sharing.

The block decomposition and hierarchy are imported theorems. Priority of the dictionary arguments has not been established.

## Linear SAT permits one check of an arbitrary partial chronology

Now assume only a deterministic O(m) SAT algorithm on m encoded bits. The two nested checks from the preceding section cost **Õ(L+n)**, where L is the encoded length of the entire guessed chronology, including any explicit dictionary it references. Sort the records to check their chronological and same-block links. To test local validity everywhere, make one outer search: choose an observed record and a tuple of concrete inputs from its named regions, then test whether an honest local branch into its output regions exists. A local test on one explicit record reads O(n) symbols and costs Õ(n) after compilation and the inner linear SAT call. Identifying an observed record and resolving its names can be done by scanning the ledger, costing Õ(L+n). The outer quasilinear 3-CNF compilation followed by linear SAT still costs Õ(L+n). Fixed powers of log n include the two compilation overheads and nondeterministic RAM-to-tape verification. Ledger lengths here are polynomial in n. No bound on the number of distinct records is used.

Allow each ordinary region name to pin any chosen set of at most n^α cells to their symbols, with the remaining cells free. For fixed 0≤α<1/2 the full chronology has L=Õ(n^(11+α)) bits, since there are O(n¹¹) epochs, a fixed tape count, and each offset uses O(log n) bits. Thus if every sufficiently large accepted length of the actual H has one coherent accepting chronology of these records, all liftable for every compatible concrete input tuple, linear SAT would put H in NTIME(n^(23/2)), a contradiction. This would exclude the linear-time SAT algorithm alone. The positive margin 1/2−α absorbs the polylogarithms. Equivalently, under linear SAT, every fixed such verifier and α have infinitely many accepted lengths at which **no** such chronology works.

Individual records need not satisfy the same pin bound. Permit either a sparse literal pattern or a full raw singleton word, chosen separately at each occurrence, and allow exact dictionary references. Any actual accepting schedule with total encoded size L≤n^(11.5−ε), for fixed ε>0, passes the same clock test. A sufficient structural condition comes from an actual accepting run: at each boundary mark the positions in the block that will be read before they are next overwritten, and pin their real symbols. Reusing the actual local choices reproduces the epoch's reads and control for every compatible tuple. Any pinned output was either written during the epoch or persisted from an input already pinned for a future read. This is a sufficient way to obtain liftability, and its pin cost depends on the particular run.

**Does choosing between sparse and full records always work?** Consider an equivalent block-ledger presentation of this same H. Before the original computation, run a deterministic auxiliary schedule over two disjoint n-cell blocks. On one sweep compare all their data bits and reject permanently on a mismatch. On a return sweep increment their equally initialized counters and repeat. A synchronized marker track can delimit a field of h=11⌊log₂ n⌋ counter bits, leaving the other data positions fixed by the increments; the comparison still tests all of them. Stop the auxiliary schedule on wraparound. Equivalently its public header specifies 2ʰ comparison/increment pairs. Each local update costs O(n), the whole prefix O(n¹²), and no original data is changed. This is a uniform padding of the block-verification instance of H by two auxiliary tapes with a fixed comparison and increment rule. It preserves the hard language exactly.

For each of the Θ(n¹¹) distinct equality checks, examine the two nonempty input regions in any ledger lifting this padded execution. Holding the auxiliary controls and other blocks at their actual values, every pair of representatives must pass equality to reach the prescribed nonrejecting control. If nonempty sets A,B satisfy A×B⊆{(z,z)}, both are the same singleton. A literal pattern defining a singleton binary word must fix every data bit: flipping any unpinned bit gives another member. Apart from constantly many special initial words, the mixed literal/full format must therefore pay Ω(n) bits for each of Θ(n¹¹) distinct singleton values, even if each distinct raw word or pattern is stored only once. Explicit local replays of these comparisons one by one also cost Ω(n¹²) in total. Thus the choice between *these two record formats* is insufficient on all presentations even of a genuine hierarchy language.

The counter values in this padding have cheap arithmetic descriptions. A shared parametric decoder, a relational name that asserts equality across the two tapes, or preprocessing that removes the auxiliary computation can bypass the example. The obstruction concerns the independent-region rules and raw encodings tested here. Whether the original H admits another verifier or schedule meeting the linear-SAT criterion remains open.
