# Linear-time space lower bound for unary-clock RAM acceptance

Let $U_{\rm RAM}$ ask whether the supplied nondeterministic RAM program accepts its binary input within the supplied unary clock. For the encoding and word model below, any correct deterministic $O(N)$-time solver $A$ has a constant $\epsilon_A>0$ such that, **at every sufficiently large encoded bit length $N$**, an accepting instance and a rejecting instance each make $A$ hold at least $\epsilon_A N$ bits in nonzero auxiliary words at one instant. The charge at a step is the number of nonzero auxiliary words multiplied by the word width. A word contributes its full width even when only one of its bits is set. The usual charge for distinct touched auxiliary words is at least as large. A linear clock permits $O(N\log N)$ auxiliary bits. The proof leaves a factor of order $\log N$ between the lower bound and this automatic upper bound.

The sublinear-space exclusion has a classical antecedent. Fortnow, Lipton, van Melkebeek and Viglas present Kannan’s $\mathrm{NTIME}[n]\not\subseteq\mathrm{DTISP}[n,o(n)]$ in their random-access bit-machine model. The proof here specifies the corresponding word-machine problem and obtains the all-lengths, both-verdicts formulation from adjustable unary padding. It makes no priority claim for the strengthening. Ajtai’s element-distinctness theorem uses a different normalization, with $n$ input registers each containing order $\log n$ bits and a time cap linear in the **register count**. [FLMV, §§2 and 5.1](https://lance.fortnow.com/papers/files/tst.pdf) · [Ajtai](https://www.sciencedirect.com/science/article/pii/S0022000002918210)

## Machine and complete language

For definiteness fix $w(m)=12\lceil\log_2(m+2)\rceil$ for machines on $m$ input bits. Use a fixed register file, a read-only packed input with known bit length, zero-initialized addressable work words, and the same finite instruction basis for programs and solvers. The basis includes loads, stores, Boolean operations, shifts, addition, subtraction, multiplication, unsigned division with fixed zero-divisor semantics, and conditional control flow. A nondeterministic instruction may guess a word. Registers suffice for the interpreter’s finite control and working scalars after fixed-register spilling. These choices also work for the usual smaller register-only instruction basis when it supports the constant-cost address arithmetic used below.

Use two self-delimiting length fields for the program and the payload, followed by the program, the payload $x$, and the entire remaining suffix $1^h$. Invalid encodings reject. The guest operates at width $w(|x|)$, even when $h$ greatly exceeds $|x|$. Operand indices range over a fixed register file. Use fixed-size instruction records with register-indirect jumps and constants zero and one. Fixed programs can synthesize their fixed jump targets. Equivalently one can use variable-length instructions with a single linear pass that builds a table of constant-size decoded records, bounds-checks jump targets and immediates, and supports subsequent constant-time fetches. A direct interpreter checks the code and unary suffix and runs at most $h$ steps, so $U_{\rm RAM}\in\mathrm{NTIME}_{\rm RAM}[N]$. On an arbitrary input it must validate the claimed unary suffix. A packed scan costs $O(1+h/w(N))$ word reads. When the suffix is supplied by a reduction, its value at any requested position comes from its range endpoints in $O(1)$ time, including at packed-word boundaries. An implementation that reads one bit per instruction pays $O(h)$ for physical validation. Giving the guest a binary time bound while charging the ordinary length of that binary integer defines a different language.

For a fixed $M$ running in $c(|x|+1)$ steps, $x\mapsto(M,x,1^{\lceil c(|x|+1)\rceil})$ is a deterministic linear-time many-one reduction with output length $O(|x|+1)$. It also supports constant-time local packed reads after polylogarithmic setup, without storing the output. Conversely, the interpreter above handles *variable* program texts in linear total time. An interpreter which rescans an arbitrary description at every instruction would only justify the fixed-program direction. Thus
$$
 U_{\rm RAM}\in\mathrm{DTIME}_{\rm RAM}[N]
 \quad\Longleftrightarrow\quad
 \mathrm{NTIME}_{\rm RAM}[n]=\mathrm{DTIME}_{\rm RAM}[n]
$$
for these bit lengths, word widths, and nondeterministic choices. For the small change of width at a linear-length reduction use the sparse simulation below. A single fixed program $M$ in place of the supplied program may have a trivial acceptance problem. One can recover completeness using a deliberately universal fixed program that decodes the varying code from its payload, with an explicit bound on its overhead.

## Determining a truncated deterministic computation

Fix a linear-time decider $A$ of $U_{\rm RAM}$ and an integer $k$ bounding its time by $kN$ at all sufficiently large lengths. We will use $A$ on several distinct programs. The outer input has length $N$, with a fixed program, a short payload of $m=\Theta(\sqrt N)$ bits, and a virtual unary suffix. The following test is uniform in a numeric parameter $2\le p\le N^{1/4}$. Its constants may depend on $A$ and $k$ and are independent of $p$.

Put $q=\lfloor N/(p^2w(N))\rfloor$. Stop the outer run at its first write that would leave more than $q$ nonzero auxiliary memory words. Call this outcome overflow. A counter updated from old and new word values enforces the cap. Otherwise the outcome is the ordinary answer. Pad all halts to a common clock, using the outer solver’s own instruction count. Correct runs on these inputs halt by $kN$. A checkpoint of the capped computation consists of the controls, registers, and a sorted list with at most $q$ address/value pairs, padded to a fixed length. It has $O((q+1)w(N))$ bits. A segment checker can validate two endpoints, initialize from the first list, replay up to $\lceil kN/p\rceil$ instructions, and compare all entries and the final nonzero count to the claimed second list. An out-of-domain write, unexpected halt tag, malformed list, or bad endpoint does not certify a segment. Overflow has an explicit stuttering terminal state. All virtual input reads of the outer solver, including its own scans of the unary suffix, take constant time per read. The time per segment is $O(m+q+N/p)$ including setup.

To test a proposed outcome $v$, an outer nondeterministic machine guesses $p+1$ padded checkpoints with the correct initial state and a final state tagged $v$. An inner nondeterministic machine accepts when it finds a malformed endpoint or a defective segment. It guesses an index and checks only the selected records. Its public payload, including the **bits** of all checkpoints, has length
$$
 O(m+p(q+1)w(N))=O(m+N/p).
$$
Its unary time bound is also $O(m+N/p)$. Calling $A$ on this inner native query and inverting the answer checks that the entire list is valid. A fully valid list exists exactly for the true outcome by determinism of the capped run. Guessing or writing the list, supplying the inner query, and running $A$ all take $O(m+N/p)$ time. The outer nondeterministic test is therefore itself one bounded native query of that size. A **second call to $A$** makes the outcome test deterministic. Two such tests distinguish acceptance, rejection and overflow. The short inner queries can even be physically written within their allotted time. Only the original length-$N$ instance needs local input access for segment replay. The resulting tester takes $O(m+N/p)=O(N/p)$ instructions on the short source input, with a uniform constant. No bound on its own workspace is required.

Here are details about simulating those instructions across word widths. All query lengths are polynomial in $m$ and the nontrivial ones have at least $m$ bits. Their words require only a fixed number of host words, uniformly for the indicated $p$. Tags for a constant number of arrays and potentially wider sparse addresses can be represented by a fixed-depth radix trie. Use digits of $\max(1,\lfloor(\log_2 m)/4\rfloor)$ bits. A row keyed by a trie-node number and a digit has an address that fits a host word, since at most $O(N)$ nodes, up to a fixed factor, can be created over the simulation. The polynomial fan-out of a node costs no initialization scan. Allocate a fresh row number and rely on initially zero, untouched memory. Allocate children only on writes and return zero on missing paths. A constant number of runs can use fresh root/row numbers or a touched list for cleanup. This also lets the variable-code interpreter simulate a guest’s bank independently of its own storage, with at most $O(N)$ nodes when invoked directly on a physical $N$-bit string (use digits based on $N$ then). On a shorter source host, elementary word arithmetic, multiplication, and normalized schoolbook division on a fixed number of limbs all use constantly many operations. For division normalization, a table of highest-set-bit positions for digit-sized values can be filled in $O(m^{1/4}+1)$ time. Two digits fit in one host word. The usual normalized trial quotient needs only constantly many corrections per digit. Fixed-depth invocations can build tables based on their own length when needed, at most $O(N^{1/4}+1)$ setup per invocation, absorbed by $N/p$. This gives a concrete width simulation even when $A$ uses sparse addresses near the end of its address space. [Brent and Zimmermann, §1.4](https://members.loria.fr/PZimmermann/mca/mca-cup-0.5.5.pdf)

## A hard input of each sign at every large length

Let $J$ be a fixed deterministic interpreter on a short input $x$ of $m$ bits. Its prefix is a self-delimiting opponent program and the rest is padding or metadata; the opponent receives the entire $x$. $J$ runs the opponent for at most $m^2$ **simulated opponent steps**, accepting if it observes rejection before timeout and rejecting otherwise. The fixed-size instruction encoding, checked indexing, and separate guest-memory simulation take $O(m+m^2)$ genuine word instructions, with an absolute constant for $J$. For the sparse simulation inside $J$ use digits based on $m$ and at most $O(m^2)$ allocated nodes. Choose a fixed integer $K$ large enough to allow that clock inside every outer query used below.

Build a deterministic opponent $D_b$, for $b\in\{0,1\}$. It extracts $N,p$ from the metadata in $x$, checks the ranges and the short-length relation $m=\lfloor\sqrt{N/K}\rfloor$, and uses the tester above on
$$
 y=(J,x,1^h),\qquad h=N-|\operatorname{prefix}(J,x)|.
$$
Here the prefix includes both length fields, the program, and $x$. Thus $|y|=N$ exactly, for every large $N$, and $h$ exceeds $J$’s full time bound by the choice of $K$. Return the ordinary capped answer when available and the fixed bit $b$ on overflow. This defines fixed code because $p$ comes from the input. With valid metadata its time is at most $C N/p$ for a constant $C$ independent of $p$. Parsing and length arithmetic fit this bound (checking $Km^2\le N<K(m+1)^2$ suffices).

Now choose a fixed integer $p$ large enough that $CN/p<m^2$ throughout these lengths for all large $N$. For every such $N$, choose $x$ with the code of $D_b$, metadata for $N,p$, and enough padding to attain exactly the stated $m$. All fields fit. $D_b$ finishes in time for $J$ to invert its bit, so $U_{\rm RAM}(y)=1-D_b(x)$. If the capped outer run returned a normal answer, $D_b(x)$ would equal $A(y)=U_{\rm RAM}(y)$, a contradiction. Hence $D_b(x)=b$, the true answer is $1-b$, and on this input the uncapped solver holds more than $q$ nonzero words at some step. Their bit charge exceeds $N/p^2$ up to rounding. Using the smaller of the two resulting constants proves the theorem for both signs. No construction of the solver’s worst-case space function is used. The hard input at a given length depends on the solver.

## Where a further speedup would have to enter

A Kannan-style split with $p$ blocks and a full snapshot of $s$ bits incurs $O(N/p+ps+m)$ for the next native decision. When $s=o(N)$ a growing $p$ can make both terms $o(N)$ if an appropriate schedule is available. The hard-input proof instead lets one fixed parameter overcome all implementation constants. At $s=\Theta(N)$, no growing $p$ gives a saving from this expression. At $s=\Theta(N\log N)$ even writing a single raw word-array checkpoint as a bit payload costs that many bits. A genuine uniform checking procedure for arbitrary $O(H)$-step deterministic runs, with short original input, would suffice if its first quantified message has $o(H)$ **bits** and its remaining opposite-sign native computation has $o(H)$ **steps**, with uniform constructible bounds or another validated way to clock it. Under a linear-time solver assumption the native calls remove the two guesses within $o(H)$, contradicting the diagonal. An unbounded factor tending to infinity is enough under these public-input and uniformity conditions. Merely replaying a selected segment faster leaves the public checkpoint cost in place. For example, $p=\log\log N$ saves an unbounded factor on the replay term, while $p$ snapshots of $\Theta(N)$ bits already exceed the original clock as a bit input.

If inputs instead consist of $N$ **word tokens** with a full clock token charged per simulated step, a list of $p$ snapshots with $s$ words each costs $O(ps)$ tokens at the next call. The corresponding comparison is $o(N)$ words against $O(N)$ words, in that different normalization. For the binary encoding in this note, the $ps$-word list has $\Theta(ps\log N)$ bits. Removing the SAT compiler changes these resource bounds for the native language. A lower bound on the explicit SAT encoding still needs a resource-preserving reduction in the requisite direction.
