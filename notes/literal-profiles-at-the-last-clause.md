# What must a SAT solver compute to finish in constant time after the last clause?

For a proper explicit 3-CNF $F$, define $E_r(F)$ to be its table of extendible literal tuples. A table entry is one iff the specified signed literals are jointly true in some model of $F$. Use tuples of zero through $r$ literals on the occurring variables, indexed by dense renamed variables with a name map. Empty, repeated and inconsistent tuples have their usual meaning. The empty entry gives satisfiability. The order-one table also determines every backbone literal of a satisfiable formula. [Janota, Lynce and Marques-Silva, *Algorithms for computing backbones of propositional formulae*](https://sat.inesc-id.pt/~mikolas/bb-aicom-preprint.pdf)

**Clock equivalence.** Fix $r\ge1$ and an integer $k\ge r$. The following conditions are equivalent on logarithmic-word RAMs allowing a sufficiently large fixed width coefficient.

1. On every $n$-bit proper DIMACS input, a deterministic algorithm outputs the entire $E_r(F)$ table in $O(n^k)$ instructions.
2. There is a deterministic SAT solver correct on every valid proper DIMACS input with an $O(N^k)$ total clock on the aligned files described below. On those files where it reads all packet positions, it takes $O_r(1)$ instructions after the load discovering the last original packet. The solver may select its own access order and use unrestricted workspace.

The constants may depend on the fixed algorithms, $r$ and $k$. On other valid inputs condition 2 only requires correct termination. In the forward construction one can also retain a global $O(N^k)$ clock by using the empty entry of algorithm 1 on the fallback. We use single aligned native-word loads, a fixed number of registers, and polynomially addressable memory at each word-width coefficient. The proof works with immutable input or a writable initial input bank. A larger fixed host width is allowed for simulating a particular program. The theorem concerns a family containing arbitrary source clauses.

## The files and their bit length

Declare a dense public alphabet of size $v$ and three distinct additional anchors. A fixed public region contains the header and seven proper ternary clauses forcing the three anchors false. Every one of $p+1$ interchangeable packet addresses contains exactly $r$ complete proper ternary records on that alphabet and anchors. Any such packet is allowed, including repeated clauses. A true padding record can use three negative anchors. A pin on a source literal is a record containing it and two positive anchors. No interpretation of a packet as data or query appears in the grammar.

One explicit layout uses an overall bit length $N$ that is a power of two, a byte-aligned native width $w=16\lceil D\log_2(N+2)/16\rceil$, and $1+\lceil\log_{10}(N+2)\rceil$ digits per identifier field. Right-align each field (including sign) with spaces to keep decimal spellings canonical. Use fixed punctuation, reserve a whole word per packet, begin on a word boundary, and fill remaining bytes with accepted whitespace. Put $v+3$ and $7+r(p+1)$ in the header. To recover the layout, parse these counts and the public region first. A fixed layout rule aligns the first packet after the public region and pads the file after the last packet. Choose $D$ sufficiently large depending on $r$; this leaves room for all $r$ records in a single word. Repeated or absent declared variables are allowed. A larger choice of $D$ changes only the layout constant. The same choice is used throughout each forward or reverse simulation.

Given an arbitrary valid source of length $n$, sort, deduplicate, and densely rename its clauses. Write $c$ for its number of distinct proper clauses and $v$ for the number of distinct occurring variables. We have $v\le3c$ and $c=O(1+n/\log(n+2))$: there are only exponentially many distinct clause strings up to a specified byte length, so $c$ different representatives use $\Omega(c\log(c+1))$ bytes in total. Normalization, recording the name map and emitting the new representation take $O(n)$ word steps. This also handles names longer than a machine word. Choose $p=c$ and $N$ the next power of two above $K_r(n+2)$ for a sufficiently large fixed layout constant (which may depend on $D$). All public words and packets fit in $N=\Theta(n+1)$ bits. Place one source clause and $r-1$ true records in each of the $p$ data packets. Each remaining query packet will consist of the specified literal pins and enough true records to fill it. The order of packets has no effect on the verdict. [Normalization, including long decimal identifiers](dense-sorted-cores-for-ram-exhaustion.md)

## From a short finish to all projections

Fix the solver in condition 2. On a new source, keep a fixed list of its $p$ data packets. Simulate the solver. On its first request for an unopened packet, install and return the next data packet, through the first $p$ requests. Public words and repeated packet reads have their ordinary values. Freeze just before the next such reply. Every arrangement made so far extends to an actual legal file, and the frozen state is independent of the query. After the freeze, each reply giving a different query continues an actual cold execution on a complete file. [Earlier use of last-discovery placement](work-after-the-last-unseen-sat-word.md)

Two exceptional cases matter on arbitrary formulas. If the solver halts without requesting all packets, every completion with any admissible query in a remaining position has the same verdict. All profile entries equal the observed output. If a blind store destroys an unopened packet, place the query there and complete all other positions with the remaining data. Continue on any one such file to termination. All query choices give identical executions, because the original contents were never observed. This proves the same constant-table conclusion. Treat a primitive that observes the old contents before replacing them as a read. Repeated operations on overwritten cells subsequently use their stored values. During the common prefix any finite completed file consistent with the observations obeys the promised clock, so the simulation cannot wait indefinitely for another discovery.

In the remaining case there is a genuine last original packet load. Run its continuation from the frozen state once per table entry. Log every suffix store with its previous value and undo stores in reverse after each answer, reset the fixed registers, and replace the last packet with the next query. There is no copy of prefix workspace per entry. A wider logarithmic host can allocate disjoint address ranges for guest memory, input metadata, and an undo stack, with constant-time masking of guest word operations. For the stated polynomial clocks a fixed larger coefficient suffices for all addresses and step counts. One table entry is one output word. If the prefix took $a$ instructions and the suffix for tuple $u$ took $b_u$, the complete computation costs
$$
                       O_r\left(n+a+\sum_u(1+b_u)\right).
$$
There are $O_r((v+1)^r)$ entries. Condition 2 gives $a=O(n^k)$ and $b_u=O_r(1)$ and hence condition 1. The argument also gives the displayed sum with unequal individual tails.

## From projections to a short finish

A new solver first reads the public information and every packet except a fixed final one. It validates the inspected parts of the layout, decodes the remaining formula $G$ and computes $E_r(G)$. This takes $O(N^k)$ instructions. Fill a direct-index name map on this template’s alphabet. On a valid layout the header’s declared size may be enormous unless bounded explicitly: take $v+3\le N$ as part of the layout and test that condition first. The forward encoding above has this property. Newly occurring names in the last packet have no constraints in $G$.

Load the final word. For each of the at most $3^r$ choices of one literal from each of its clauses, reject the choice if it contains a complementary pair. Drop literals on names absent from $G$. Read the joint extension entry for the resulting tuple. Accept iff at least one choice passes. In one direction a satisfying model supplies the choices. In the other, extend a witnessing model of $G$ arbitrarily on its new names according to the consistent choice. This even handles an unsatisfiable $G$ and an empty remaining tuple.

Fixed-width decimal parsing and validation of this last word take constant RAM time after preprocessing. Divide it into a constant number of pieces of at most $(\log_2 N)/4$ bits each, with byte and field boundaries respected. Before its load tabulate each piece’s decimal contribution at its fixed place value, whitespace/sign/leading-digit status and overflow. A fixed number of table reads and word operations then validates punctuation, adds their place-weighted contributions, checks name ranges and obtains the dense indices. Use power-of-two strides for the profile table so that shifts and additions suffice for indexing. All tables take $o(N)$ preprocessing time. Punctuation, properness, and fixed formatting conditions are checked before any fast return. Inputs failing layout validation can go to a complete general solver on the original file. The algorithm can preserve the input throughout, and outside-template fallbacks do not compromise the claimed behavior on the template.

## Computing a binary matrix product from actual SAT continuations

There is a smaller list of projections for which *the better of two actual clocks* suffices. Given binary $d$-square matrices $A,B$, use the [compact DIMACS entry-selection circuit](compact-bit-projection-of-matrix-mismatch.md) with free row and column selectors. Retain the full one-hot index flags $R_i,C_j$ (add their $O(d)$ gates where necessary), compute the selected dot product, and replace the final mismatch condition by a wire evaluating the selected bit. For each row and tag make a flag $R_{i,e}$ equivalent to $R_i$ AND the assertion that this wire equals $e$. The original compact construction has $O(d^2/\log(d+2))$ clauses of identifier length $O(\log(d+2))$; zero-padding to the next power of two costs a constant factor. These counts still hold with the added decoders and outputs. The two signed flags for each row can have equal-length identifiers with a common prefix and final digits 2 and 3, by using disjoint groups of ten names. No source bit depends on this choice. Repack each baseline clause with one padding record into an aligned data packet and pad the total length to $N=\Theta(d^2)$. Preparing all packets costs $O(d^2)$ native steps.

A query packet now needs only **two** clauses, pinning $R_{i,e}$ and $C_j$. For every $i,j$ the two tagged packets differ in exactly one physical ASCII bit and produce opposite SAT verdicts. Therefore the placement simulation must reach the last read, including for a writable initial input. Let $a$ be its prefix cost, and let $b_{ij,0}, b_{ij,1}$ be the two true suffix clocks. There is a deterministic RAM algorithm outputting **all** the bits of $AB$ in
$$
          O\left(d^2+a+\sum_{i,j}\big(1+\min(b_{ij,0},b_{ij,1})\big)\right)
$$
instructions. From the frozen state interleave one instruction on each of the two continuations until the first halts. Its verdict and tag determine the product entry. For each simulated continuation keep a separate array of written values and an array of touched flags, defaulting to the original frozen word on untouched addresses. Clear only the flags actually set after each race, using a store log. The computational work of each race is linear in the faster genuine suffix, even for unrestricted guest workspace. The arrays require a sufficiently large fixed host address coefficient. This statement prices real RAM work and carries no formal-arithmetic hypothesis. A polynomial gap for bit-level RAM matrix multiplication in this accounting would require an additional theorem.

The two-clause threshold for this matrix experiment is sharp in **encoded bits**, even allowing arbitrarily expensive preprocessing. One late clause would require worst-case baseline length $\Theta(d^2\log d)$. For the lower bound fix $A=I$ and let $B$ range through the $d^2$ matrices with a single one. The entry queries on the positive tag form an identity table, so at least one baseline uses $d^2-1$ distinct names by the [one-clause bound](how-many-tests-fit-in-the-last-sat-clauses.md). For an upper construction, attach $2d^2$ flags with functional equivalences $Z_{ij,e}\leftrightarrow R_{i,e}\land C_j$. This adds $O(d^2)$ proper clauses and costs $O(d^2\log d)$ bits and construction steps. Pin one flag by a single proper clause. The two signed identifiers can again differ in one ASCII low bit. With two late clauses, arbitrary $B$ and $A=I$ give $2^{d^2}$ distinct answer functions, so a worst-case length $\Omega(d^2)$ is necessary even with any fixed number of late clauses. The preceding two-clause construction attains it. Thus the two optimal orders are exact even on a RAM that may choose where to make its last packet discovery. The lower bounds charge the query representation, independently of the solver's execution time.

A 2-CNF control separates the task of outputting a profile from deciding the underlying formula. For **Boolean-semiring** matrix products use a directed three-layer graph with arcs from row $i$ to middle index $h$ for $A_{ih}=1$ and from $h$ to column $j$ for $B_{hj}=1$. Give every graph vertex a variable and impose its positive implication along every arc. For each output pair add a variable $z_{ij}$ and implications from $z_{ij}$ to the row variable and to the negation of the column variable. The formula is always satisfiable by setting all variables false. Its positive $z_{ij}$ is extendible precisely when that row cannot reach that column: if there is no path, set $z_{ij}$ and the reachable vertices true and leave every other marker false. Thus the full order-one profile recovers the Boolean-semiring product from an always-satisfiable 2-CNF of $O(d^2\log d)$ bits. The parity product in the preceding paragraphs uses the separate 3-CNF construction. [Implication reachability and forced literals in binary clauses](https://ijcai.org/proceedings/2001/72)

## An explicit consequence for the three time milestones

Write $T_{\le}(n)$ for a monotone worst-case clock of a SAT solver. For $r=1$, append one padded unit to the normalized source and run that solver for each sign and variable, as well as for the empty entry. With ordinary copying this computes the table in
$$
       O\big(n+(1+n/\log(n+2))(n+T_{\le}(O(n)))\big).
$$
Thus linear SAT would give a globally correct solver with a constant finish on these universal one-clause packets and total class time $O(N^2/\log N)$. Quadratic SAT would give $O(N^3/\log N)$, and cubic SAT would give $O(N^4/\log N)$. In the forward construction of the previous section the prefix materializes the remaining formula on $O(N)$ bits, so it preserves each of these clocks. Refuting the corresponding class clock under the constant-finish restriction would therefore refute that unrestricted SAT clock. The equivalence itself proves none of these refutations.

Static lower bounds for arbitrary late lookup packets need care here. With one final clause of width three the earlier formula stores only three alternative literal tests for that query. Encoding many independent lookups in those tests can force a polynomial increase in the physical file length. The [exact capacity and polarity bounds](how-many-tests-fit-in-the-last-sat-clauses.md) quantify this issue even with arbitrary database-dependent preprocessing.
