# Selecting cumulative truth tables from deterministic lists

**Research journal, 24 November 2026.** Let the cumulative table at length n give a language's answers on all binary strings of length at most n, in length-lexicographic order. Suppose a deterministic algorithm lists candidates in time T(n) and its list always contains the true table. This permits one uniform, advice-free selection that is correct somewhere in each of a known sequence of short intervals. An oracle example tests whether it also guarantees correctness on every sufficiently large length.

## One successful length in every block

Fix computable, consecutive blocks [a,b] with H=b−a+1. Suppose the list at b has k≤H entries. At length n in this block generate the list at b, take the entry numbered (n−a) modulo k starting at zero, and output its restriction through n. The true table through b occurs at some rank, so at least floor(H/k) lengths in this block are correct. One selector works for every language consistent with these lists. It may choose different candidate branches on successive lengths. The cost is O(T(b)) plus computing the block boundaries and writing the answer, all of which is covered by the list clock for efficiently computed blocks and explicit tables.

For example, take a list bound C log₂(n+2) and T(n)=2ⁿ n^d for a fixed d. For sufficiently large a choose H=ceil(2C log₂(a+2))+1, and set b=a+H−1. Then H≥C log₂(b+2), and T(b)≤2ⁿ poly(n) throughout the block. The gaps between successive successes are O(log n), with no rank supplied as advice. For longer lists K(n) the same construction pays T(b) for a block covering K(b) positions. A polylogarithmic bound on K of degree greater than one does not by itself guarantee that this cost is T(n) polylog(T(n)) when T(n) grows exponentially.

The length requirement for covering *every* possible language on a particular block is sharp. Choose k distinct tables already through length a, and append zeros to each forever. A single output at any length in the block agrees with at most one of these branches. Even complete lookahead at subsequent lists cannot cover all k branches using fewer than k lengths.

## A zero-error oracle language with at most logarithmically many candidates

Fix n_j=2^(2^j) for j≥1. Only the unary strings of these lengths may have answer one. At length n≥4 list all settings of the bits at the j special strings up to n, assigning zero elsewhere. There are 2^j≤log₂ n tables if n_j≤n<n_(j+1). Before the first special length give the single zero table. The entire list takes 2ⁿ poly(n) time to print. Each restriction of a later candidate appears earlier and every candidate extends through every later list. As j increases without bound, the lists admit continuum many infinite branches.

Construct an oracle choosing one of those branches. Use disjoint addresses 1^j 0 b r for j≥1, b a bit and r of length n_j². All other addresses are zero. At each j one labelled row is entirely zero and at least two thirds of the cells in the other row are one. Its label is the answer on the special word. On that word a randomized machine samples independent uniform r and queries both labels until it sees a one. It returns the correct bit with probability one in expected O(n_j²) time on a standard oracle tape machine. The input-length test and nonspecial answers are deterministic polynomial time. Thus the language is total and zero-error expected polynomial time relative to this oracle.

Enumerate all deterministic oracle machines M₀,M₁,…, using e(j) equal to the exponent of two in j to visit each infinitely often. At stage j simulate M_e(j) on the special word up to 2^floor(n_j^(3/2)) steps. Reproduce all previously fixed oracle answers, answer fresh probes zero, and freeze those zeros. Choose the true bit opposite the machine's returned bit, using zero after a timeout or a malformed answer. Set all remaining unfixed cells of that labelled row to one and the opposite row to zero. Even queries to future rows made by earlier runs remain binding. At most the sum of the first j simulation clocks can have fixed individual cells of the chosen row, since entire rows settled earlier have different addresses. This sum is at most j times the last clock, which is less than 2^(n_j²)/3 for j≥1. The required density therefore holds. The construction is effective, since a well-formed query in row j can be settled by simulating through that finite stage.

Every deterministic 2^O(n)-time oracle decider fails at infinitely many special lengths. A deterministic 2^O(n)-time algorithm printing the correct cumulative table on every sufficiently large length would decide the special word by reading its entry, within the same time bound. The fixed lists are oracle-independent, so giving the algorithm their generator and allowing future list queries does not reveal the selected branch. This example permits the bounded-gap successes proved above. It prevents inferring eventual correctness by a black-box argument that also works relative to every oracle. Earlier research obtained much stronger relativized simulations of exponential deterministic computation by Las Vegas algorithms. Here the extra property is the explicit logarithmic list at every length. [Karpinski and Verbeek, *On Randomized Versus Deterministic Computation*](https://eccc.weizmann.ac.il/eccc-reports/1995/TR95-021/index.html)

For the unrestricted SAT problem a successful application still needs a uniform property of ordinary computations forcing the right candidate at the lengths where the lower-bound argument uses it. The block selector suffices if one success anywhere in every such block meets that requirement.
