# A fast SAT solver must reuse many different writes across blocks

**Research journal, 24 November 2026.** Suppose a fixed deterministic solver decides packed binary 3-SAT on the stated logarithmic-word RAM in $O(N\log^a N)$ steps, for a fixed nonnegative integer $a$, with unrestricted work space. There is a solver-dependent family of **unsatisfiable** formulas on which its run has
$$
\Omega\!\left(N/\log^{a+5} N\right)
$$
distinct pairs consisting of a writing block and a writable address whose value is used as an incoming word by a later block. The blocks partition a fixed upper clock for this solver into $P=\lceil L^{2a+8}\rceil$ consecutive segments, where $L=\max(2,\lceil\log_2(N+2)\rceil)$. The conclusion holds at every sufficiently large original padding length of the construction. It counts the solver's actual execution on an ordinary explicit formula. The hypothesis that such a solver exists remains open. [Packed encoding and RAM model](packed-band-transfer.md) · [Unbalanced-input SAT reduction](materialized-input-census.md)

## The counted pairs

Fix a sufficiently large constant $C_0$ for the solver and use $T=\lceil C_0 N L^a\rceil$ steps, extending a halt by idle steps without memory accesses. Choose nearly equal block lengths, at most $\lceil T/P\rceil$. Number the blocks from one. Treat a fixed memory bank tag as part of an address, and order events occurring within one instruction by the actual instruction semantics. The read-only formula is a separate bank. A read of writable address $v$ is incoming if it precedes every write to $v$ in its own block $i$. If an earlier block wrote $v$, let $j<i$ be the **last such block**. Collect $(v,j)$ for all these incoming reads and let $D$ count the distinct pairs. Multiple reads in any number of later blocks can use the same pair. An incoming read with no prior writer contributes nothing; ordinary writable memory starts at zero. The finite registers, program counter and halt state are held in the boundary CPU states.

## Checking a rejection from $O(P+D)$ public words

Guess CPU states at every boundary, including the initial and final states. Guess a variable-length list of $d$ triples $(v,j,w)$ sorted by $(v,j)$, with strictly increasing keys. The honest list has one triple per counted pair, using the last value written to $v$ during block $j$. Charge $O(1)$ words per record and bound $d$ only by a fixed constant times $T$, the maximum number of native write events. No smaller uniform promise about $d$ is needed.

To replay block $i$, start from its supplied CPU state and an empty dictionary of local writes. When the solver reads $v$, use its most recent local write if there is one. Otherwise binary-search the public list for the greatest $j<i$ at address $v$. Use the listed $w$ if found and zero otherwise. In the latter case record the putative source as $j=0$. Every replay uses the same putative data and therefore defines its own transcript deterministically even before those data have been verified. The read-only formula words are always fetched from the real input interface specified below.

The certificate passes if the initial state is prescribed, the last state is a rejecting halt, all replayed blocks give their claimed ending CPU states, and the following checks succeed.

* Every record has valid address, block and word fields and its key exceeds its preceding key. For each claimed $(v,j,w)$ replay block $j$, requiring at least one actual write to $v$ in this replay and its last such write to have value $w$.
* For each block $i$, step and within-instruction slot, inspect the event there by replaying $i$. If it is an incoming read of $v$, recover the same putative source $j$ used in replay. For every $k$ with $j<k<i$, replay block $k$ and require it never writes $v$. At $j=0$ this covers **all** earlier blocks. When $j=i-1$ there is no intervening block to challenge.

One nondeterministic test finds a failure by selecting its type and the appropriate indices. It executes a constant number of local replays, including for the intervening-block challenge. The producer check and the intervening-write check are distinct tests on the same public list. No replay calls a verifier recursively. Binary searches and a fresh local sparse dictionary, for example a binary trie on the address bits, take $O(L)$ time per operation. Multiple checked blocks use separate local dictionaries. Untrusted lengths, addresses, CPU states and index bounds are checked or given fixed invalid defaults; every challenged replay has its stated time cap.

Soundness follows by induction over blocks, then steps within a block. Once earlier blocks have their real transcripts, take the first possible divergence in the current replay. A local write provides the correct value up to this point. For an incoming read with listed source $j>0$ the producer check supplies the last real value in block $j$, and every intervening-block check rules out a later write before block $i$. With $j=0$ all earlier blocks are write-free for this address and initialization supplies the correct zero. Input reads, CPU transitions and the end-state tests finish the induction. A passing certificate therefore implies an actual rejection. Conversely the genuine boundary states and the $D$ triples pass. Whenever the honest search for a producer is nonempty, it finds the genuine most recent writer, because the pair for that particular read was included. Extra records in an alleged certificate cannot undermine soundness. The finite last-write lemma for a single address is verified in Lean. ## Charging the original input once

Let $x$ have $n_0$ bits, $H=\Theta(n_0^2)$, and take the packed reduction $F_x$ of the $H$-step nondeterministic universal computation on $x$. It satisfies $F_x\in\mathrm{SAT}$ exactly when the universal computation accepts. Its encoded length $N$ is at most $O(H\log^3 H)$, with $\log N=\Theta(\log H)$. The fixed rectangular layout supplies each requested formula word from $x$ and its indices in $O(1)$ native operations after a polylogarithmic setup. This is why the certificate verifier need only have $x$, the CPU list, and the $d$ producer records as public data. Counting a materialized copy of $F_x$ among this public input would cost too much. The SAT solver's *own* writable addresses are replayed at its specified width; the local interpreter's temporary trie and formula generator do not contribute to $D$. [Local clause access and word-width normalization](packed-band-transfer.md)

The defect test runs for
$$
R=O\!\left((1+T/P)L+\operatorname{poly}(L)\right)
$$
with $m=O(n_0+P+d)$ public words. Materialize its explicit final SAT instance, decide it with the hypothesized solver, and issue a rejection certificate precisely if there is no defect. This is one deterministic decision after the certificate guess. The final reduction costs $O(RL^{a+3}+mL^{a+2}+\operatorname{poly}(L))$ with arbitrary auxiliary space. When $d=O(T)$, the leaf lengths and clocks have logarithms $O(L)$. Native host and guest word widths have a constant ratio on these polynomial clocks, and the materialized graph and local tries can use compact polynomially bounded address ranges. [Materialized leaf and repeated input queries](materialized-input-census.md)

With the displayed choice of $P$, the replay contribution is $O(N/L^4)+\operatorname{poly}(L)=o(H)$. Likewise $(n_0+P)L^{a+2}=o(H)$. The guessing cost fits the same budget. There is therefore a **single fixed** nondeterministic certificate program with this property: a certified rejection always implies that $F_x$ is unsatisfiable, and on every unsatisfiable $F_x$ an honest branch produces a certificate in time
$$
O(D L^{a+2})+o(H).
$$
Long or unsuccessful guesses on other branches do not affect the runtime of that honest branch.

## The sign of the bounded diagonal

Let the fixed universal program accept exactly if its encoded opponent on the same input has a branch issuing its distinguished rejection signal within the universal cap $H$. Take as the encoded opponent the certificate program just described, using that signal for a successfully verified rejection of $F_x$. It includes fixed codes for the solver, universal program and reduction. On every sufficiently long padded encoding $x$ of this one opponent, a signal seen within the cap would make the universal program accept, hence $F_x$ satisfiable. The signal certifies $F_x$ unsatisfiable. Therefore the universal program does not accept on this $x$, $F_x$ is unsatisfiable, and the honest rejection branch runs too long to issue the signal inside the cap.

The universal simulation cost per step on this fixed opponent is bounded by a constant. Select $c>0$ small enough *after* fixing the opponent. If $D<cH/L^{a+2}$ on one of these sufficiently large inputs, the honest branch just bounded would be observed before the cap. Consequently $D=\Omega(H/L^{a+2})=\Omega(N/L^{a+5})$ on this family. This use of the diagonal clocks each branch directly. It needs no computable rate for convergence of $D L^{a+2}/H$ and no small bound on the running time of every false-certificate branch. The formula length is the encoded length $N(n_0)$ on the chosen padded layout, so the conclusion is indexed by original lengths $n_0$. [Bounded complementary diagonal](packed-band-transfer.md)

**What the count detects.** A computation can create many such producer pairs with ordinary memory traffic. In each consecutive pair of equal-sized blocks, write distinct scratch addresses during the first block and read them in the second. Each read then has its own counted pair, even if every read has no influence on the verdict. Conversely reading one unmodified scratch word in many blocks can use a single producer pair. The lemma forces many different cross-block producers on the displayed family. Turning this into a time lower bound requires an independent way to certify the same verdicts with less information or a bound on relevant traffic for an equivalent fast solver.
