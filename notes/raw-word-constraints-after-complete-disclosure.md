# Common execution tests after every original SAT word has been read

An input-read argument ends as soon as every data word has been loaded. In the separate-operation integer RAM, the uses of those loads give a second, computable test. It applies to a finite roster on a common positive input even when every program has copied the entire input to writable memory before its cut.

Use the five-setting proper DIMACS files of the sparse-edit hierarchy. There are $m=\lceil N/w\rceil-O(1)$ aligned data words, each drawn from the same alphabet $E$ with center word $A$. The file is satisfiable exactly at the all-center setting. The instruction set has separate word loads, stores, unary/binary numerical instructions, and comparisons with fixed successors. All $2^w$ memory addresses may be used. The five settings are chosen for this native instruction set; a fused instruction imposing several simultaneous constraints would require its own proof. [Physical files, precise word operations and their tree lemma](exact-executed-clocks-for-sparse-word-edits.md)

For each program take a finite prefix of its center execution extending through its last first read of an original data word. A total correct solver reaches that cut: changing any original data word before it is read changes the verdict without changing any earlier reply. This includes an initially writable input bank, where an initial value lost to a write before it was read could never affect the verdict. The cuts can occur at different instruction counts for different programs.

## The test on the actual prefixes

Replay every prefix symbolically. An original marked word is tagged by its variable $X_j$ and has center value $A$. Other original words, program literals and initial registers are fixed. Loads, store payloads and pure copies forward the corresponding tag or fixed value. Fix a numerical operation's output to its actual center word, then propagate that fixed output. Require each branch outcome and each address to match its actual center value or direction. Every requirement involving raw words depends on at most two *directly forwarded* tags, regardless of the length of their copy chains. Add a unary requirement for every tagged register surviving at the cut, fixing its value to its center. The program counters are already fixed by branch requirements.

Use one vertex for each of the $m$ original data variables, shared among the roster. Add a mark at each unary constraint and an edge for every binary constraint with distinct variables, retaining parallel edges. Zero-variable requirements are already true. Rows from different programs can be pooled since they constrain the same physical file. A tree component with no unary mark is called free here. Let $d$ be their number in this specific graph. It can be counted directly. If the prefixes issued in total $H$ nonconstant-scope requirements including controller marks, then $d\ge m-H$, since adding a unary or binary constraint decreases the free count by at most one. Copying every input word to any number of fixed or already-numerically-resolved addresses does not itself add an edge or mark. A store with a raw address imposes a unary requirement on that address.

The opcode tree lemma gives a noncentral simultaneous setting on every free component, leaving all variables elsewhere at center. Its hypothesis says that, in either orientation of an edge, either one can change the child while its parent stays at center, or every parent value admits some child value. The earlier opcode check establishes this for the equality of a binary numerical output or comparison outcome on these five words. Induction from the leaves proves the perturbation. Different components can be changed independently. Hence $2^d$ different legal files have the prescribed branch, address and numerical-output histories at every one of these full-disclosure cuts. Their controllers at the cuts coincide. Their raw load replies and copied payloads can differ. Every frozen cell in each work image is either fixed or a copy of **one** original data variable. A single changed component therefore affects a disjoint group of frozen cells, even when a program made arbitrarily many copies. [Lean tree-extension lemma](../lean/SparseEditTreeExtension.lean)

## Two native instructions per lost free component

After the respective cuts extend the center runs of the programs by budgets $s_1,\ldots,s_p$ in any fixed order, stopping a program at halt if earlier. Append the resulting constraints to the common graph, using each program's own tagged frozen state to start its extension. Then **at least**
$$
                 d-\sum_{i=1}^p\left\lfloor (s_i+1)/2\right\rfloor
$$
free components remain. If the right side is positive, the resulting test contains opposite-verdict files. Every correct program misses its own *post-disclosure* deadline on both members of the pair. More generally if $e>0$ components survive, there are $2^e-1$ noncenter files with the same control, address and numerical-output histories through all the extended cuts. At least one changes at most $\lfloor m/e\rfloor$ original words. Each correct program, taken on its own, must spend at least $2d-1$ suffix instructions on the same positive file and make at least $d$ distinct incoming reads there. An incoming read fetches a still-unoverwritten cell from the actual frozen machine, including unoverwritten original data. These statements allow all controller and workspace contents accumulated before the cut.

To prove the count for one suffix, start with the graph after all previously appended programs. A new guard decreases the number of free components by at most one: it marks one tree, joins two trees into one, closes a cycle in one, or attaches a tree to a component that was already nonfree. If the suffix lowers the count by $j$, it has at least $j$ guard-issuing instructions. Also at least $j$ different components that were free at the start must have been incident to some guard: every one with no incident guard survives intact.

For each such component select the first incoming load through which a raw tag from that component becomes available to this suffix. No such tag started in a register: all tagged registers received unary marks at their own cut. No numerical output creates a new tag. Copies from the suffix can only transmit tags already received. Thus a selected load really exists before the first use creating the incidence, and selected loads for the different components use distinct original frozen addresses. Purely public cells fixed to the numerical value $A$ are still fixed, so they do not count as incoming private tags.

At most **one** selected load also issues a guard. Only a raw address operand could make it do so. Every raw-address operand has the same numerical value $A$ on the center path, whereas only the single frozen cell at address $A$ can be the source of such a selected load. Later writes at $A$ can forward an already discovered tag but cannot introduce a previously unavailable one. Consequently $s_i\ge 2j-1$ when the count decreases by $j>0$. Summing for the roster gives the bound. For one correct solver run to halt, no free component can remain, since it would yield a negative setting taking exactly the accepting control path. This proves the elapsed-time and distinct-read claims.

A useful version for a finite code census simulates all programs at their prescribed absolute clocks on the center. Whenever the resulting graph on the common raw variables has a free tree, its perturbation makes every tested program wrong or late on the two-file test, whether or not any of them is correct. One can also stop each at a recorded cut and use the budget inequality without simulating its suffix. A program that does not reach all words by the clock can directly contribute its existing shorter prefix guards. A hypothetical program that processes or pins all its raw tags during the first scan may already leave $d=0$. This is the precise failure point for an induction that would have to work at every $C+1$ code budget at a deadline proportional to $N$.

The possible overlap is real. In the blind preload below, forward the first raw value to the frozen cell at literal address $A$, then finish the scan, leaving only its last word in a register. The suffix loads a different unmarked site into a register, uses that register as the address of a second load, and compares the fetched word with $A$. Its address guard and comparison kill two independent free components in three instructions.

## A matching full-disclosure example

At a fixed length, let a program first blindly load all $m$ data words using immediate addresses and one overwritten scratch register; the fixed public words can be checked before the data scan. All data have now been disclosed. The only controller mark needed is for the final raw scratch value, and $d=m-1$. A program specialized to that length can accept the all-center file after at most $2(m-1)+O(1)$ more steps: compare the retained word with $A$, then load and compare each remaining marked word, with a fallback to a general solver on mismatch. Combined with the fixed layout checks this is globally correct. The stored text for this sharp finite example can grow with the file.

For a roster on the five-setting promise each member may do the identical blind preload, then prioritize a different contiguous block of marked sites. Every noncenter file has a member that finds a changed site in at most $2\lceil m/p\rceil+O(1)$ post-disclosure steps. This matches the common-test scaling for complete scans, up to additive constants for fixed $p$. A globally correct version on strict full-file DIMACS additionally verifies the bounded local contradiction before such a rejection: the candidate word encodes one of the four forbidden identifiers, the following text supplies its two false guards and zero terminator, and the preceding complete noncomment line ending in zero authenticates its start. Neighboring canonical words contain those line boundaries; at the ends use the checked public fences. The prefix fixes the forbidden identifier and guards. A failed local check invokes the general fallback. The number of candidate names and necessary neighboring words is bounded independently of $m$.

The argument forces a repeated scan with genuine numerical tests after complete disclosure when the prefix guard graph retains enough independent trees. The wrapped programs show that even $d=m-O(1)$ and arbitrary replication of all the raw words cannot turn this particular conditional lower bound into superlinear time in the encoded bit length. The graph can also be killed cheaply, for example by comparing each word to $A$ during the first scan.
