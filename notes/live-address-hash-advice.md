# How much advice suffices to recover the words a RAM really reads?

**Research journal, 24 November 2026.** Consider a fixed run of polynomial duration on an ordinary packed RAM with input length $N$, at most $U=N^{O(1)}$ work addresses, and word width $b=O(\log N)$. At each of $P=N^{O(1)}$ times specify a set $S_t$ of at most $k$ addresses. The sets can depend on the future of the run. For example, they might be the distinct addresses first read before any write in the next segment. There is a single $O(\log^2 N)$-bit string for the run and a fixed evaluator that answer *arbitrary* prescribed word values on every $S_t$ using $O(k\log N)$ word labels per time. Each answer is affine over $\mathbb F_2$ in those labels once the common string is fixed. Neither the instruction offset nor a list of the queried keys is needed at query time. Offline selection of the labels and the common string is unrestricted. For a single fixed evaluator required to have no such common string, an explicit lossless expander gives $k^{1+\alpha}\operatorname{polylog} N$ word labels for each fixed $\alpha>0$.

There is also an all-address version with the same sizes and a different evaluator. If $S_t$ is the support of a sparse word-valued array, the evaluator returns its exact value on *every* address, including zero on all $U-|S_t|$ absent keys. It uses an AND, separately for each output bit, over $O(\log N)$ indexed advice bits. An array outside the image of a specified such AND evaluator has a contradiction involving at most $O(\log N)$ output-bit coordinates for one bit-sliced hash scheme. In contrast, an affine evaluator exact on the entire address domain needs substantial extra information to describe arbitrary sparse arrays. The counting theorem below quantifies this difference.

## Hashing a fixed list of true states

Take $k\ge1$ and a power of two $B$ between $2k$ and $4k$. The case $k=0$ is immediate. Draw $L$ independent hash functions from addresses to $B$ cells, with collision probability at most $1/B$ for any pair of distinct addresses. One short family uses $a=\lceil\log_2(2U)\rceil$, $p=\log_2 B$, and $a+p-1$ random bits $z$. The $i$th output bit is $\bigoplus_{j=0}^{a-1}x_jz_{i+j}$ for $0\le i<p$. On a nonzero difference $x$ let $j_*$ be its greatest nonzero position. Successive output bits use distinct fresh bits $z_{i+j_*}$ after all smaller positions have been revealed. The difference of the hash outputs is therefore uniform. All indexing and bit arithmetic take polylogarithmic RAM time given the seed. [Carter and Wegman on universal classes of hash functions](https://doi.org/10.1016/0022-0000(79)90044-8)

Let $D_t$ be any test domain containing $S_t$. For any $x\in D_t$, the probability that one table maps some member of $S_t\setminus\{x\}$ to the bucket of $x$ is at most $k/B\le1/2$. With probability at least $1-2^{-L}$, $x$ has a bucket *private from all those other keys* in at least one of the tables. Put $L=\lceil\log_2(2+\sum_t |D_t|)\rceil+1$. A union bound gives a single tuple of hash seeds with this property for every time and every tested key simultaneously. The seeds consume $O(L\log N)$ bits. The arrays of labels for different times need not agree and the table index is always part of a bucket's identity. For varying capacities $k_t$ one may round up to powers of two and keep one common tuple for every dyadic capacity, spending $O(\log^3 N)$ bits in total. The evaluator must know the selected scale.

* For promises only on $S_t$, take $D_t=S_t$. Choose one private bucket for each $x\in S_t$, put its desired word there, and put zero into every other cell. XOR all $L$ probed cells to recover the prescribed word. A private bucket used by another key cannot be among these probes. This affine decoder makes no guarantee at untested keys. The labels use $LB$ words even if the label values have no simple generating formula.
* For exact sparse arrays, take $D_t=[U]$, or take any prescribed superset of earlier written and subsequently tested addresses if that is the needed domain. In each bucket put the bitwise OR of *all* words of $S_t$ hashing there. Return the bitwise AND over $x$'s $L$ probes. A set bit of the true word appears at every one of its buckets. A clear bit is recovered from a private bucket, which contains only $x$'s word if it is in $S_t$, and zero otherwise. One tuple of seeds works for every possible word labeling of the selected supports. This is the Bloom-filter mechanism with the randomness selected offline to remove every false positive on this specified family. [Bloom's original construction](https://doi.org/10.1145/362686.362692)

Subtracting a fixed publicly computable predictor by wordwise XOR gives the same upper bound when $S_t$ is the set of errors in its baseline, instead of the nonzero words of the actual state. The predictor must genuinely be computable within the claimed query budget. If the set of probes whose values need checking is a genuine live set, the affine construction measures the number of **distinct queried addresses**. A long segment can consist entirely of distinct incoming reads. These representations alone give no sublinear bound for that number.

For a two-probe alternative using the AND rule, fix one state and a domain of $D$ keys. Two independent hashes with $B\ge 2k\sqrt D$ have probability at most $D(k/B)^2\le1/4$ of missing the private-bucket condition anywhere. Each bit answer now costs exactly two advice-bit probes, and $O(k\sqrt D)$ word labels suffice for every word labeling of that support. A common pool of $O(\log(P+2))$ independent *pairs* contains a suitable pair for each of the $P$ states, by independence and another union bound. This version must also communicate a per-state selector of $O(\log\log(P+4))$ bits. If reading that selector counts as advice probes, the total is larger than two. One can instead use a single pair for all states with $B\ge 2k\sqrt{\sum_t |D_t|}$ and omit the selector. These tradeoffs concern state-dependent hash metadata. Schemes with two advice-bit queries and fixed addresses or adaptive decisions for all subsets without a freely readable seed have different known space bounds. [Garg and Radhakrishnan, Theorem 1.4](https://arxiv.org/abs/1504.02035)

## Removing the common string for affine retrieval on tested keys

Use the explicit lossless unbalanced expander of Guruswami, Umans and Vadhan with the address universe as its left side, threshold a power of two between $k$ and $2k$, fixed error below $1/2$ and fixed $\alpha>0$. Its degree is $\operatorname{polylog} N$, its right vertex count is $k^{1+\alpha}\operatorname{polylog}N$, and each neighbor is computable in $\operatorname{polylog}N$ time. If the rounded threshold covers the whole address universe, the direct identity table suffices. [Guruswami, Umans and Vadhan, Theorem 1.3](https://scholar.harvard.edu/files/salil/files/acm2009.pdf)

Each nonempty subset of at most $k$ left vertices has more than half as many neighbors as incident edges. Some neighbor has exactly one incident edge from that subset. Hence every at-most-$k$ collection of binary incidence rows, with multiplicities reduced modulo two, is linearly independent. For each output bit the corresponding label system with *arbitrary* right-hand side on $S_t$ is consistent. Store the solutions bit-sliced in right-vertex words and XOR the neighbors on a query. This promises nothing on addresses outside $S_t$. Lossless expansion only supplies a unique neighbor for some key in each subset, so it does not on its own furnish the all-address AND construction.

## Short obstructions for an AND decoder

Keep the incidence of advice cells to each output-bit query fixed. To satisfy a true target bit, every probed cell must be set. Form the union of all cells forced by true bits at the coordinates being tested. Setting precisely this union to one realizes all the positive constraints. It fails exactly when a zero coordinate probes only forced cells. Such a zero is certified by giving one true coordinate forcing each of its at most $L$ probes. This argument is exact for arbitrary supports and arbitrary hash tables. The query domain may be restricted to a specified set if the certificates identify its members correctly. [Finite private-bucket and obstruction proofs](../lean/LiveHashAdvice.lean)

The definition of the false endpoint matters when using a seed shared over a run. A poor choice of seed can exclude a real positive state even when another seed represents it. Guessing a seed and reporting failure of its own table gives no negative SAT certificate. If the claimed property is “at most $k$ wrong words relative to this fixed input-based predictor”, $k+1$ distinct actual wrong addresses refute it *independently* of the seed. A selected good seed can then help to replay earlier states; all-address and all-controller boundary checks still need to make that replay sound. When using only genuine incoming addresses, an additional argument has to establish the relevant producer and actual read for each challenged coordinate. [Positive first-failure accounting](advertised-snapshot-offers.md) · [Earlier incoming-read verification](live-segment-snapshot-queries.md)

There is a related storage lower bound for an $L$-table AND decoder. Each header fixes one bucket per query in each of $L$ tables of $B$ cells. Whenever a $k$-sparse binary array is representable, the canonical forced table above represents it and has at most $k$ one-buckets *in each table*. Thus $2^hV(B,k)^L\ge V(D,k)$ if $h$ header bits suffice for every such array on a $D$-element domain. For $D\ge B\ge k$ this gives $B\ge e^{-1}k(D/k)^{1/L}2^{-h/(kL)}$. At two probes a polylogarithmic header and polynomially growing $k$ force $\Omega(\sqrt{kD})$ cells per equal-size table. The elementary two-hash upper above uses $O(k\sqrt D)$ with only a short per-state selector. A larger header gives a matching bound below. For $L$ at least a constant multiple of $\log D$ and $h=O(k)$ the exact all-address construction instead has $B=O(k)$, optimal up to constants for this counting bound. These statements use the AND family with one probe per table. An arbitrary adaptive two-probe decoder need not have this canonical sparse label set.

## Matching the all-address AND bound with a readable header

For $L\ge1$, there is an exact construction with $O(k(D/k)^{1/L})$ cells in **each** of the $L$ tables and an $O(k+\operatorname{polylog}N)$-bit freely readable header per state. Here $1\le k\le D$, $D\le N^{O(1)}$, and $L$ may grow up to $O(\log N)$. For $k$ at least a sufficiently large fixed power of $\log N$, the preceding AND counting bound makes this optimal up to constant factors. The actual large-table queries are nonadaptive, one bit per table for each desired output bit. The evaluator also reads its state-specific header. A two-bit budget covering *all* advice accesses would have to count these header reads. The construction couples two-level perfect hashing to a product of singleton digit tests. [Fredman, Komlós and Szemerédi on two-level perfect hashing](https://doi.org/10.1145/828.1884)

Pad the universe to $D'=2^{\lceil\log_2D\rceil}$, and take $K=2^{\lceil\log_2 k\rceil}$ primary groups, each of size $q=D'/K$. Permute the binary address vectors by an invertible binary matrix and split off the high $\log_2K$ bits for the primary group. Write $\xi$ for the remaining low bits, a number in $[0,q)$. For a uniformly chosen invertible matrix, a nonzero input difference maps uniformly to the nonzero outputs, so the high-part collision probability of distinct keys is at most $1/K$. If $t_i$ is the number of support keys in group $i$, then $\mathbb E\sum_i t_i^2\le k+k(k-1)/K\le2k$. Fix a primary matrix with sum at most $8k$.

For $t_i>0$, reserve $B_i=\min(q,2^{\lceil\log_2(4t_i^2)\rceil})$ secondary buckets. Empty groups cost no buckets. The total secondary bucket count is $O(k)$. Inside group $i$ the values $\xi$ of its support keys are distinct. Use a second invertible matrix on these low bits and the highest $\log_2 B_i$ resulting bits as the secondary bucket. If $B_i=q$, the identity works. Otherwise a random matrix separates all $t_i$ keys with probability at least $7/8$ by the pair collision bound and a union bound. A secondary bucket then contains at most one support key. It can contain many zero addresses.

Write the *original* low part $\xi$ in $L$ digits of base $A=2^{\lceil(\log_2q)/L\rceil}$, allowing leading zeros; $q=1$ has only the digit string of zeros. For each secondary bucket reserve $A$ cells in each table. For a support key, mark the cell for its digit in each corresponding table with its word. All other cells start at zero. A query locates its primary and secondary bucket and ANDs the returned digit entries. In an empty bucket the answer is zero. In a nonempty bucket all digits match its unique support key exactly when $\xi$ matches. Together with the primary group this identifies the whole address. A mismatching digit returns zero. This proves exactness for arbitrary word labels on the support and every zero outside it. Each of the $L$ tables uses $O(kA)=O(k(D/k)^{1/L})$ words for word-valued outputs, or this many bits for binary outputs. [Finite product-mask identity](../lean/LiveHashAdvice.lean)

To achieve the claimed header cost, share a pool of $m=\lceil\log_2(8K)\rceil$ independent secondary matrices among all groups. For every group requiring one, report the index $J_i$ of its first successful matrix, with $J_i=m+1$ on failure. The probability of any failure is at most $K8^{-m}$. The expected sum of these indices is at most $8K/7$ since the failure tail for each group is geometric, with no independence required *between* groups. Markov's inequality shows that some pool succeeds everywhere and has $\sum_i J_i=O(k)$. The entire pool takes $O(\log^3(N+2))$ bits. The zero-dimensional group needs no matrix.

The header records group emptiness, each $\log_2 B_i$ in unary, and each selected matrix index in unary. Their total length is $O(k)$ because $\log_2 B_i\le 3+2\log_2(t_i+1)$ and $\sum_i t_i\le k$. Every $\Theta(\log(N+2))$ groups store a pointer to the corresponding header records and the sum of the preceding $B_i$. This adds $O(k+\log(N+2))$ bits and makes the metadata and data offset for any primary group computable in polylogarithmic time. All matrices have polylogarithmic evaluation time. Only the two selected data bits in the $L=2$ case are probed *after* locating these offsets. If many states are to share the matrices, a random complete bank succeeds for each fixed support with constant probability including the bound on unary metadata. A menu of $O(\log(P+2))$ independent complete banks then contains a suitable one for each of the $P$ relevant states. The header still carries each state's own group records and one menu index.

## An affine counting obstruction with a matching block layout

Fix the public context and a domain of $D$ binary output coordinates. Suppose the evaluator has access to one of at most $2^h$ different freely readable headers and, conditional on that header, has an affine output map of width at most $s$ over $\mathbb F_2$. If it represents every binary array with at most $k$ ones exactly on the whole domain, then with $V(d,k)=\sum_{i=0}^{\min(k,d)}\binom di$ one must have
$$
2^h V(s,k)\ \ge\ V(D,k).
$$
Indeed, for each affine image of dimension $r\le s$, projection to $r$ pivot *output coordinates* is injective, even when the affine offset is nonzero. A vector containing at most $k$ ones projects to a vector containing at most $k$ ones. Thus the image contains at most $V(s,k)$ such vectors. A union bound proves the assertion. A variable-length advice interface offering the length free must include its choices among the headers if they select different affine maps. For $D\ge s\ge k\ge1$, using $\binom Dk\ge(D/k)^k$ and $V(s,k)\le(es/k)^k$ yields
$$
h\ \ge\ k\log_2(D/s)-k\log_2 e.
$$
For $P$ independently specifiable sparse arrays and one shared header, the lower bound on header length is $P\log_2(V(D,k)/V(s,k))$, even with a separate affine map and labels for each time after fixing the common header.

Here the lower bound has a matching fast decoder up to $O(k+\log(D+2))$ additive header bits. Partition the domain into consecutive blocks of length $a=\lfloor s/k\rfloor$ with final padding. At most $k$ blocks contain ones. Put their sorted block indices in the header and their full contents in at most $ka\le s$ ordinary advice bits. A query returns zero if the block is absent and otherwise directly probes the corresponding bit. Given the header this is affine and needs at most one query to the ordinary advice.

For the precise header size put $J=\lceil D/a\rceil$ and $u\le k$ active blocks. Split each sorted block index $v_i$ into its lowest $l=\lfloor\log_2(J/k)\rfloor$ bits and its high part. Store the $u$ low fields and mark the positions $\lfloor v_i/2^l\rfloor+i$ in one bit vector. The marked positions are strictly increasing, and the vector has length $O(k)$ since $J/2^l<2k$. A directory of prefix one-counts at machine-word boundaries uses $O(k+\log(D+2))$ bits. Binary search in that directory and a scan of the selected word retrieve a specified marked position in polylogarithmic time, so a second binary search finds the block and its rank. Store $u$ as well. With $a\ge s/(2k)$ one gets $k\log_2(D/s)+O(k+\log(D+2))$ header bits and worst-case polylogarithmic lookup. Each time can pay this header for its own support, or one header can cover a known small union of supports. The counting and block results use a fixed public context. They cannot treat the genuine read-only formula, which might itself reveal the requested bits, as hidden. They therefore supply no elapsed-time lower bound on an unrestricted SAT solver.
