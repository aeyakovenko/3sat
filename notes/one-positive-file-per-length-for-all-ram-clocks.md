# One positive file per length preserves every solver's worst-case clock

Fix ordinary explicit ASCII DIMACS 3-SAT, and use the deterministic logarithmic-word RAM with unrestricted workspace. There is a computable sequence of **one satisfiable file** $H_N$ at each sufficiently large byte-aligned length $N$ with this property. For *every* finite nonempty list $F$ of RAM programs and every fixed positive integer $j$,
$$
 \limsup_N \frac{t_F(H_N)}{N^j}
 =
 \limsup_N \frac{\max_{X\text{ satisfiable},\ |X|=N} t_F(X)}{N^j}.
$$
Here $t_F(X)$ is the first time any program in the list has halted with the SAT verdict, with infinity if none does. The lengths on both sides range over the same valid byte lengths. In particular the sequence is shared by the **linear, quadratic and cubic** milestones, independently of the program, the time multiplier, or which milestone is considered. The programs may use arbitrary indirect reads and writes. The assertion also holds with $2^N$ as the denominator.

For a correct single solver, existence of a worst-case $O(N^j)$ positive clock implies existence of a SAT decider with an $O(N^j)$ clock on both verdicts: run the former up to its positive deadline and return UNSAT on timeout. Thus it really would suffice to prove that *on these files* every correct solver exceeds every multiplier of the desired clock. The construction below does not prove that. It does prove **unconditionally** that no fixed RAM can print $H_N$ from its length in $O(2^N)$ steps at all sufficiently large lengths. Generating a sequence of hard tests and deciding its SAT labels have demonstrably different complexity requirements. Earlier journal entries use three files per multiplier to test a bounded interpreter, including machines that answer incorrectly. This construction fixes a single positive file per length and compares the positive running times of individual machines or lists. ## Finite construction and exact preservation

Enumerate obligations $(F,b,r,n_0)$, where $F$ is a finite nonempty list of machines, $b(N)$ is one of the displayed denominator functions, $r>0$ is rational, and $n_0$ is a threshold. Use an effective encoding in which the description and numerical parameters of the first $N$ obligations have at most $O(N)$ bits, and the word-width coefficients, opcodes and instruction constants used by their machines can be simulated with at most $\operatorname{poly}(N)$ bits per word. An enumeration by increasing description length has these properties, for instance by writing the width coefficient in unary. This covers every fixed program and every fixed constant width coefficient in the model. Take $n_0$ in bits. Start at a fixed byte length beyond which one can always pad a known positive proper formula with whitespace.

At length $N$ inspect the prefix of $N$ obligations in the enumeration. Ignore an obligation if already served, if $N<n_0$, or if its requested deadline exceeds $2^{2N}$. Within this finite cap call it *triggered* if some satisfiable file of length $N$ has no SAT output by time $\lfloor r b(N)\rfloor$ from any machine in its list. If any obligation triggers, serve the least-indexed one, output its first witness in lexicographic bit order as $H_N$, and mark it served. Otherwise use the padded fixed positive file. Repeat at subsequent byte-aligned lengths.

This rule compares actual simulated RAM steps with the deadline. The offline computation producing the suite can be much slower. It can exhaust $2^N$ strings, check syntax and truth by enumeration of assignments to the at most $N$ literal names that occur, and simulate each candidate obligation to its cap. Sparse names can be compared as bit strings. Even a sequential universal simulator that searches all earlier writes for every read needs at most $2^{O(N)}$ time per capped trajectory, including polynomial factors for guest word arithmetic. For $r=a/c$, one can cap exponentiation for $b(N)$ at $c2^{2N}+1$ before comparing $a b(N)$ against $c2^{2N}$; the retained integers have $O(N)$ bits. Replaying the construction at all earlier lengths gives a deterministic $2^{O(N)}$ generating algorithm on an ordinary multitape Turing machine. This offline upper bound allows the space of the universal simulation. For just the three polynomial milestones, retaining only $j=1,2,3$ and capping simulated steps at $N^4$ gives a variant with a $2^{O(N)}$ generator in polynomial space, implementable on a fixed polynomial-address RAM. The exponential-clock printing lower below is for the full sequence.

For any fixed obligation its clock eventually fits the cap. If there are infinitely many eligible lengths witnessing a failure of its timed list, it is served: at each such length after entry, either it has been served or a strictly smaller still-unserved obligation takes that spot. Each smaller index can take only one spot. If a rational $r$ lies strictly below the limsup of the full positive-file ratios, every threshold $n_0$ therefore has a later selected witness with ratio greater than $r$. Taking all rationals gives the lower inequality for the sequence, including when the limsup is infinite. The opposite inequality holds pointwise. The same proof works if we initially restrict candidates to a computable subclass whose positive files can be recognized within the offline bound at every relevant length. ## Why proving a generator slow does not prove SAT slow

Suppose a fixed RAM generates $H_N$ in $O(2^N)$ time eventually. Make a program compare its input to this output. A match gets SAT immediately. On a mismatch deliberately wait at least $N2^N$ steps before running an ordinary complete solver. The program can be made globally correct by bypassing the shortcut at any finite exceptional lengths. For the stated clock use a generator on the same $N$-parameterized word RAM; a length-providing public input padded to $N$ bits keeps the word model the same. A clock cap or cutoff can be hardwired when needed. The comparison program may use a larger fixed word-width coefficient, separate its input and guest banks, and mask the generator’s arithmetic back to its original width. The simulation has constant overhead per guest step in the journal's fixed-coefficient RAM class. The delay needs only a counter of $O(N+\log N)$ bits; it does not require an exponentially wide address. The proposed solver would have finite limsup at denominator $2^N$ on the selected sequence and infinite limsup on all positive files: at every large length there are at least two distinct padded satisfiable files. This contradicts exact preservation for that very program, regardless of how fast any *other* SAT solver is. Thus the generator fails the clock infinitely often. Simpler polynomial generator bounds follow from preserving just the corresponding polynomial clocks. The generator lower bound concerns printing these exact bits given the length; the sequence consists entirely of SAT-positive inputs.

More generally, let $G$ be any time-bounded procedure that marks a subset of files. If it omits a satisfiable file at infinitely many lengths, it must omit $H_N$ infinitely often provided its clock fits one of the preserved bounds and its mark can be turned into a timely SAT reply. For this observation the marker need not be sound on negative files, since the normalization quantified over arbitrary programs. In the other direction, $H_N$ coincides infinitely often with **each** fixed positive file sequence generatable in polynomial time: use the marker which quickly replies SAT on everything except the file generated for that length, and deliberately delays on exactly that file. The two statements coexist. The limsup preservation is a worst-case assertion.

These distinctions also apply to the journal's quadratic-clock matrix construction. If a native routine generated $O(dw)$ coordinates in $O(d^2)$ time hitting the support of its selected nonzero error matrix $E_d$ for every sufficiently large $d$, check the corresponding dot products and delay for $d^3$ steps on a miss. On every sufficiently large dimension there is a singleton error outside the list, and the dot tests fit the clock after packing the rows and columns. The *same-program* preservation in that construction gives a contradiction, even assuming the existence of a different fast general matrix verifier. A fixed length-only coordinate locator for that particular suite is therefore unconditionally insufficient at the stated clock. This proves no lower bound on finding an error **given the input matrices**. For example, the sum of all error bits detects a single wrong entry, and a failed scalar test can be used to recover its location from the data. What is missing for the requested quadratic or cubic exclusion is a lower bound on $t_P(H_N)$ for every **correct** program $P$. A SAT solver receives the whole file, including the information the generator would have to produce. Neither initialization of the suite nor the fairness argument requires any correct solver to miss a deadline on all positive files in the first place. The construction uses elementary priority diagonalization. Lynch’s classical complexity-core theorem derives an infinite recursive set of almost-everywhere hard inputs from polynomial-time intractability. Here the sequence is defined without assuming intractability and preserves worst-case limsups. Priority for the precise one-positive-file normalization is unestablished. [Lynch, *On Reducibility to Complex or Sparse Sets* (1975)](https://groups.csail.mit.edu/tds/papers/Lynch/jacm75.pdf)
