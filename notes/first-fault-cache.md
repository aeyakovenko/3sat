# Where a false chronology can first leave the real computation

**Research journal, 2026-11-24.** Consider the native deterministic RAM interpreter, its cutoff B=2^(20n), and its first missing n-bit word vₙ. Under linear SAT, some single short name p at vₙ has many different *actual* reads at which a false accepting chronology for p can first diverge. Moreover, many of the intervals between those reads and the preceding accesses to their addresses must cross a common cut of the genuine computation. The false chronologies need not be the same for the different reads. [Native interpreter](native-missing-word.md)

## Tracking enough of the past to force a read

Use the chronological CPU checker alone. Number its elementary memory events in order from 1 through K=Θ(B), with padding and fixed within-instruction ordering. A read supplies a word and a write updates a word. Include in the chronological state all registers and output information. The checker can calculate the true initial word at any specified address from n and p. Given correct replies up to its next read, determinism fixes the entire event prefix and the address of that read.

Add the following checks to this generator. Use positive integer caps L,R.

* The challenger names at most R addresses W. Keep their exact current words, starting with their true initial words, and apply every write to them. Check every read at these addresses.
* Independently maintain the L most recently accessed **distinct** addresses and their most recently observed words. A read must match on a cache hit. A write updates the value. On a read miss before the first eviction, require the initial word. After the first eviction an unchecked read miss may supply an arbitrary word. Insert the observation and use least-recently-used eviction. Even an unchecked read is safe to retain for comparison against its next access on every genuine run.
* Optionally the challenger supplies a polynomial-size circuit H mapping addresses into R buckets. Guard the test by the stated circuit size and output format. Initially every bucket is clean. A write of a word unequal to the true initial word at that address permanently marks its bucket dirty. A read in a clean bucket must return its initial word. Bucket collisions only disable checks. A fixed polynomial size cap is chosen before setting the clock constants. A simpler special case uses one bucket and no circuit.

A genuine run passes every W and H. In a false chronology let t be its first incorrect memory reply. It exists because the genuine answer is different. All preceding observations, writes, and monitor states at t are exactly those of the true run for p. The requested address a must be outside W, its bucket must already be dirty, and it must miss the cache after an eviction. Write s for its previous true access, taking s=0 if this is the first. If s>0, at least L distinct other addresses intervened between s and t, by the recency ordering of the cache. For s=0 the earlier eviction already required more than L distinct addresses. In either case t−s>L. These are conditions on the true computation, even if the false chronology changes every subsequent address or instruction. Lean verifies the first differing reply on a common deterministic prefix and the initial-value rule for every clean bucket. The cache rule is the usual recency-stack description of LRU. [Mattson, Gecsei, Slutz and Traiger](https://doi.org/10.1147/sj.92.0078) · [Lean proofs](../lean/FirstFaultCache.lean)

## A clock below the native cutoff

At proposed output z test whether some p shorter than n passes every legal challenge W,H, where passing means that *some* chronological run prints z and satisfies all of the checks. Choose R=L=⌊B/nᵃ⌋ for a sufficiently large fixed integer a. Divide the K events into J=⌈√(K/R)⌉ chunks at complete native-step boundaries, each of length O(K/J+1). After the challenge, guess the CPU state, the R watched values, the L cache entries in recency order, the eviction flag and the dirty bits at all chunk boundaries. Public keys are common to all chunks. Check the initial and final conditions. Universally select one chunk and existentially supply its local event records. Check all transitions of its CPU and monitors between the two common boundary states.

This last check takes O((K/J+L+R)poly(n)) deterministic RAM time on its one chunk. For instance store the current cache in an address dictionary and a doubly linked recency list, initialized and compared with the supplied ordered boundary lists by scans. A binary trie over the poly(n)-bit keys gives worst-case poly(n) time per dictionary operation and can use polynomial workspace for this explicit check. The endpoint encodings include only the ordered entries. The global certificate and the largest check together have size and checking time O((JR+K/J)poly(n)). Common states glue the chosen local realizations; the universal choice of a chunk introduces no compatibility assumption about separate CPU histories.

Under linear SAT the fixed number of quantifier blocks, prefix search for the first failing z, and native interpretation take at most B·n^(−a/2+O(1)) time. The exponent in the overhead is fixed independently of a by using the same interpreter and upper bounds R,L≤B throughout. Choose a large enough. All genuine outputs pass. A failure at vₙ would therefore let a constant-length program print vₙ within B. For all sufficiently large n **one p at vₙ survives every challenge**. ## Many possible first faults on a single true trajectory

Fix this p and any admissible H. Among false chronologies for vₙ passing the cache and bucket checks, take the set D of addresses at which their *first* incorrect reads occur. If |D|≤R, choose W=D. Adding this watch list removes every such chronology, contradicting the choice of p. Thus **more than R distinct actual addresses** can host the first incorrect read. A sufficient condition in the opposite direction is entirely about a true trajectory. If for each p at vₙ there is a permitted H such that at most R different actual read addresses ever miss after eviction while their buckets are dirty, choosing those addresses for W refutes that p. Establishing this for all p at infinitely many lengths would exclude linear SAT.

For each of R+1 distinct addresses from D, choose one supported first-fault time t and its preceding actual access s as above. The interval [s,t) has length at least L+1. Summing its indicator over the K cuts 0,…,K−1 gives its length. Consequently **some actual cut is crossed by at least ⌈(R+1)(L+1)/K⌉ distinct addresses of this kind**, of order B/n^(2a). A first access gives an interval starting at the virtual initialization, so this count alone cannot be interpreted as that many unknown stored values. The estimate survives removal of arbitrarily many idle steps in its per-interval condition on *distinct intervening addresses*. [Lean proof of cut summation](../lean/CrossingLoad.lean)

There is a simple limit to this test. Write one to each of N initially zero cells in order, then read them in the same order. Output an alarm if any read differs from one. The true run has no alarm. If L<N and |W|<N, choose any unwatched address and return zero on its read. The address misses the cache, and its own earlier noninitial write dirtied its bucket for **every** hash. All other reads can be genuine. This supplies a false alarm even when the challenge is chosen with full knowledge of the true execution. A semantic check that all the writes are ones at the designated addresses would refute it. This example limits the stated monitors and gives no separation for SAT. The remaining question is whether the actual surviving name can be refuted by a stronger check on its causal dependencies.
