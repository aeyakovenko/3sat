# Two physical bit edits to uniquely satisfiable 3-SAT after preprocessing

There are proper ASCII DIMACS templates with a public, unique base model such that selecting two known bits to flip requires worst-case $\Theta(\log L/\log\log L)$ deterministic word-RAM time after $L\operatorname{polylog}L$ preprocessing. Here $L$ denotes the file length in bits and words have $\Theta(\log L)$ bits. Every edited file has zero or one model. When it has one, only $O(\log L)$ coordinates of the base model change. The center assignment is the same for every database of the given size.

The query lower bound holds with arbitrary preprocessing time whenever the retained database, including the base file, occupies at most $L\operatorname{polylog}L$ words. An ordinary RAM with unrestricted workspace can write only that many words in the stated preprocessing time. The two edit locations, before and after values, and their source and sink labels may be furnished to the query algorithm. With *one* specified physical bit flip and unlimited preprocessing time, every Boolean decision problem has an $L$-entry direct answer table and constant query time. Thus two is the minimum number of announced bit flips for an unbounded worst-case warm-query lower bound under this storage and free-preprocessing convention.

## The two changes and the unique model

Use a degree-$B=2^b$, depth-$d$ butterfly. Its labels are length-$d$ digit strings. Between levels $i$ and $i+1$ the edge replaces digit $i$ with its destination digit, taking the digits in order, starting at zero. There are $V=d B^d$ nonsinks and $E=BV$ potential edges. Fix their public order. The database is a subset of those edges. Each source/sink pair has a single possible path. Whether edge $e$ at level $i$ is on it depends on exactly two tests. The source must have the specified suffix of $d-i$ digits, and the sink must have the specified prefix of $i+1$ digits. [Pătraşcu, §2 and Reduction 5](https://arxiv.org/pdf/1010.3783)

For each source and sink create a selectable leaf variable and its Boolean complement, with both directions of complementation enforced. A positive unit selects the complement at the center. Give the complement and leaf identifiers $10j+2$ and $10j+3$, respectively, with $j$ distinct for each pair. Replacing the final ASCII digit 2 by 3 changes one physical bit and selects the leaf instead. Reserve disjoint namespaces for everything else. Two such flips select one source and one sink.

On the source leaves build a complete binary OR tree on the bit addresses in reverse *digit* order, keeping a fixed bit order within each digit. On the sink leaves use forward digit order. Nodes at depths divisible by $b$ are precisely the desired suffix and prefix flags. For every possible edge add a single clause
$$
  (\neg\mathrm{suffix}_e\ \lor\ \neg\mathrm{prefix}_e\ \lor\ c_e).
$$
Use the name of a public fixed-true variable for $c_e$ when the edge is present and a public fixed-false name of the same decimal width otherwise. Center data therefore change variable *names*, not the values in the supplied base model. After two flips the formula is satisfiable exactly when all edges of the unique query path are present.

Use equivalence CNFs for every binary OR and for every complementary pair. Pad binary and unit clauses with distinct public fixed-false names from a separate namespace. Three independent constants can be fixed by the seven proper ternary clauses that forbid every other assignment to their triple. Use disjoint groups of constants for padding and data. Give all unused declared identifiers a padded negative unit. Every clause has three distinct variables, every declared name has a determined value on a satisfying file, and all positions of mutable digits are independent of the edge database. Fixed-width padding by whitespace allows uniformly spaced records if needed. The namespace has $O(E)$ identifiers and $L=O(E\log E)$ with $L\ge E$. On an accepted query the changed variables are the four leaf/complement values and the two paths of $db$ internal OR flags. This is exactly $2db+4$ changed bits when both roots are retained.

## Native clocks

For $b=\lceil4\log_2(d+2)\rceil$, take $d$ unbounded. Then $w=\Theta(\log L)$, $B\ge w^2$ eventually, and $d=\Theta(\log L/\log\log L)$. Pătraşcu's Section 5 communication inequalities imply $\Omega(d)$ probes when $\log(Sd/V)=O(\log B)$ and $w=O(\sqrt B)$. Both hold for $S=O(L\operatorname{polylog}L)$. An algorithm for the edited formulas supplies that reachability oracle. Preprocess the graph's base formula and public assignment. On a query, simulate its two replacements by overlaying them at the given locations. Retain temporary writes in the simulator's local computation for this single query. For a preprocessing RAM using arbitrary addresses, represent the touched, nonzero address/value pairs by a linear-size static dictionary with constant-probe lookup. Retain the program counter and fixed register set as well. The cell-probe preprocessing may build this dictionary at any cost. A query executing $t$ ordinary instructions then uses $O(t+1)$ probes. This also explains why a free polynomially large zero-initialized address space does not evade the lower bound. [Pătraşcu, Theorem 2 and §5](https://arxiv.org/pdf/1010.3783) · [Hagerup, Miltersen and Pagh, deterministic dictionaries](https://www.rasmuspagh.net/papers/det-jour.pdf)

Both verdicts separately attain the worst-case lower order, possibly on different databases. If all positive queries for an algorithm at a hard size finished earlier than the lower-bound threshold, one could stop after that many native steps and reject on timeout. This would give a correct fast query algorithm on both verdicts, contradicting the cell-probe bound. Interchanging the answers proves the claim for negative queries. The cutoff may depend on the size because the cell-probe lower bound already permits nonuniform query algorithms.

A matching uniform upper bound preprocesses the fixed layout into the array of edge bits. From the supplied source and sink, replace each successive $b$-bit digit and look up its edge, in $O(d)$ shifts, index arithmetic and reads. If only the edit addresses are supplied, a preprocessing index maps these to the endpoint labels. A cold solver can check this public template in $O(L)$ time, extract the two selectors and decide it by the same walk. A deterministic program correct on arbitrary SAT files can recognize the template and use exhaustive search on other files. For a list of $q$ online queries, the same preprocessed algorithm takes $O(L+qd)$ time. A fixed-width explicit list of endpoint pairs alone has $\Theta(q\log L)$ bits. The per-query lower bound cannot be added into a superlinear encoded-length lower bound by listing these pairs.

## Any nearby satisfying witness can be searched for after preprocessing

Let a proper 3-CNF with $m$ clauses and word-sized variable names have a supplied satisfying assignment $\alpha$. Fix a radius $h$ and allow at most $r$ identified old clauses to be removed and at most $r$ new clauses on the same variables to be supplied. A deterministic index occupying $O(m+v)$ words, where $v$ is the number of variables stored, decides whether the edited formula has a model within Hamming distance $h$ of $\alpha$ in
$$
  O\bigl(2^h(3/2)^{\min(h,r)}(h+r+1)^{O(1)}\bigr)
$$
word operations. A positive answer can return the list of changed variables in that time. Preprocessing on the multiplication word RAM takes $O(L+(m+v)\log(m+v+2)+m(h+r+1)^{O(1)})$ operations. An input assignment presented as a table incurs its ordinary reading cost as well. The parameterized upper bound refers to a Hamming-ball query. It decides unrestricted satisfiability on promises where every satisfiable query has a model inside that ball. [Moser and Scheder on Promise-Ball-SAT and local search](https://arxiv.org/abs/1008.4067)

Group each baseline row $C$ by its nonempty set $T$ of variables whose original literals are true under $\alpha$. Give it a set $D_C$ containing the variables of its originally false literals and its own row ID in a disjoint namespace. Its size is at most $4-|T|\le3$. With variables $X$ flipped and old rows $J$ deleted, $C$ survives and is violated exactly if $T\subseteq X$ and $D_C$ avoids $X\cup J$. Representatives must retain row identities even if the baseline contains duplicate clauses.

For each group of sets of size at most $j\le3$, keep a subfamily preserving the existence of a set disjoint from any blocker of size $K=h+r$ or less. If an empty set occurs, keep one. Otherwise greedily take disjoint sets until there are $K+1$, or the matching is maximal. In the first case keep those $K+1$. In the second their union $Z$ meets every set and has at most $jK$ elements. Partition the family by the first member of $Z$ it contains. In each part remove its common element, recurse with $j-1$, and restore that element in the retained sets. If an original set avoids the blocker then its removed common element is unblocked, so the recursive witness in its part still avoids the blocker after restoration. This builds at most $O((K+1)^j)$ representatives per group and retains at most the original number of row records overall. Scanning $O(K+1)$ marked elements suffices for each greedy test or partition at each of the at most three levels. Store the groups in a trie of depth at most three whose outgoing word keys use deterministic static dictionaries. This gives constant worst-case lookup and $O(m\log(m+2))$ total dictionary construction time. [Hagerup, Miltersen and Pagh](https://www.rasmuspagh.net/papers/det-jour.pdf)

At a search node $X$, test the new clauses directly and look up every subset $T\subseteq X$ of size one through three. Scan its representatives against $X\cup J$. This returns a violated active row if one exists in time polynomial in $h+r+1$, independent of the file length. Branch on each of the at most three variables of this row that has not yet been flipped, adding it to $X$. For every target repair containing $X$, some still-unflipped variable of the failed row belongs to the target, so one branch preserves it. Stop at depth $h$ or when every row passes. Any row originally satisfied by $\alpha$ can now branch at most twice, since at least one of its variables already belongs to $X$. Only a new row originally false at $\alpha$ can branch three ways. Once the search branches on such a row, its chosen literal stays true under monotone extension of $X$. Thus at most $r$ ternary branches occur on any root-to-leaf path. At depth $h$ the tree has at most $2^h(3/2)^{\min(h,r)}$ leaves, by induction on the budgets for depth and ternary branches. Shorter leaves can be padded by unary chains, and the number of visited nodes is at most $h+1$ times this bound. Updates need only specify row indices and word-sized literals. For the two-digit butterfly template these are computable from the two edit addresses and the retained layout.

In particular, consider *any* representation of these butterfly queries by a supplied baseline model and $O(1)$ announced bounded-width-three clause replacements computable in constant query time, with $V\operatorname{polylog}V$ file length and stored assignment size. If every positive query had some repair of radius $h=o(\log\log L)$, the search index would answer every query in $(\log L)^{o(1)}$ time with near-linear space. The butterfly lower bound rules this out. Quantitatively its worst positive repair radius is at least $\log_2\log L-O(\log\log\log L)$ on the hard sizes, with the database and positive query chosen in the worst case. This conclusion concerns all such encodings and all choices of their supplied base model. Our explicit two-bit witness bound is $O(\log L)$.

A standalone check constructs and reparses proper DIMACS, verifies the two single-bit edits physically, propagates the uniquely fixed constants and tests the full model against graph reachability. It checks 416 queries including all degree-two depth-one subgraphs, 125 unique positive repairs, 1,329 representative-family blocker patterns and 1,600 arbitrary edited-ball comparisons.
