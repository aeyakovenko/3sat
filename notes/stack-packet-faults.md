# Nested incorrect pops in a single accepting chronology

**Research journal, 24 November 2026.** A false CPU history and a different, memory-consistent history may disagree on many events even when the CPU actually read only one wrong value. For a machine with a fixed number of stacks we can measure incorrect reads directly in a single history. Under the linear SAT hypothesis, infinitely many *rejecting* inputs of a unary hierarchy language admit a locally accepting computation with nearly linearly many nested, incorrectly answered pops. They occur between one pair of time blocks. The direction of the value errors changes nearly linearly many times there, up to fixed powers of the logarithm.

Use a fixed verifier for a unary H in NTIME(n¹²) outside NTIME(⌊n¹²/log(n+2)⌋). Each ordinary work tape can be implemented by two stacks with its scanned symbol in the finite control. Head motions transfer one symbol between the two sides; a bottom marker implements the blank tail. This costs constant overhead per tape step. Drain the stacks at acceptance, then pad the run with idle operations to K=O(T) slots for T=n¹², with K a fixed constructible bound of order T. Split simultaneous operations into a fixed number of separate slots. A *chronology* chooses a sequence of CPU transitions and proposed pop symbols. Require the control, input and transitions to be locally legal, and the untyped push/pop shape on each stack to be balanced without underflow. Then the matching push of each pop is determined by shape alone. The pop is erroneous exactly when its proposed symbol differs from that matching push. Fix distinct small integer codes for the constant alphabet. Every genuinely accepting run has zero errors, and every locally accepting chronology on a NO input has an error. ## Naming the matched strings

Partition time into J=⌈K/L⌉ consecutive blocks of at most L slots. For each block and stack, match pushes and pops using a local stack initially empty. A pop on an empty local stack is an import; pushes left over at the end are exports. Compare the symbols on every locally matched pair exactly. Record the number of imports and exports and the CPU controllers at all block boundaries. A public directory giving the endpoints of the remaining transfers follows from these counts alone.

For each stack, process blocks in order. Each block imports by consuming earlier stacks of exported symbols, newest first, and then appends its own exports. Whenever the imports consume part or all of an earlier block's exports, make one packet between the two blocks. A nonempty earlier list is exhausted at most once, and at most one partially consumed list remains at the end of the current block's imports. Thus there are at most 2J packets per stack. The directory stores endpoint blocks, offsets and lengths in O(J log T) bits for fixed stack count. It takes O(J polylog(T+2)) RAM time to build and check it. Reversing the indicated pop subsequence gives the push ordering within each packet. Every pair in one packet is open at the cut following its push block and the pairs are nested there. This use of locally matched substrings and an ordered list of remaining push blocks is related to the streaming algorithm of Magniez, Mathieu and Nayak. [Dyck streaming algorithm](https://arxiv.org/abs/0911.3291) · [Pushdown graph separators and simulation](https://www.sciencedirect.com/science/article/pii/0022000089900366)

## Screening a packet for sparse errors and sign changes

Write ℓ=⌈log₂(T+2)⌉. Fix a sufficiently large integer a and take L=⌈T/ℓᵃ⌉, R=max(1,⌊T/ℓ^{3a}⌋), and G=⌈ℓᵃ⌉. For a packet of length m, let u₀,…,uₘ₋₁ be its pushed symbols in canonical order and v₀,…,vₘ₋₁ the proposed matching symbols. Choose a prime p larger than K and all symbol codes and at most a constant times K. A guessed prime can be verified by trial division in Õ(√K) time; Bertrand's postulate supplies one. Store one common checksum for each of the exponents d=0,…,R−1:

    Σⱼ uⱼ jᵈ ≡ Σⱼ vⱼ jᵈ   (mod p).

Interpret j⁰=1 also at j=0. If there are e unequal pairs with 1≤e≤R, the first e homogeneous equations have an invertible Vandermonde matrix on their e distinct positions modulo p. Each difference at these positions is nonzero modulo p, a contradiction. Hence any corrupted packet passing the checks has more than R actual incorrect pops.

Also partition each packet into consecutive bins of at most G positions and store one common *integer* symbol sum per bin. Every bin with an error has both a positive and a negative difference. Inside a corrupted packet at least ⌈e/G⌉ bins have errors, and each contributes a sign change along its own nonzero differences. In particular the signs switch Ω(T/ℓ^{4a}) times in one such packet. All those errors compare actual matching push and pop symbols on one chronological branch. Lean proves the two-sign property with ordered indices and the mismatch bound over a list of bins. ## Checking all summaries within the hierarchy clock

Guess once the directory data, boundary controllers, prime and common summaries. The latter occupy O((JR+K/G+J)log(T+2)) bits. Universally select a block, then existentially supply its O(L) slots. Replay locally, including exact within-block symbol checks, counts and CPU boundary conditions. For a test of stack emptiness or an implicit blank tail, obtain the entering stack height from the prefix of public import and export counts and update it on each operation. After those slots are fixed, universally choose an incident packet and one exponent or one bin. Compute the selected checksum or sum on the relevant subsequence of that same block, comparing it with the stored value. Direct modular powering and indexing take L polylog(T+2) time. Structural and summary checks may be separate guarded branches of this fixed-quantifier test. A passing transcript gives one choice per block simultaneously since every summary is already fixed; the common controls concatenate them into one locally accepting chronology. Genuine histories pass by using their own sums.

Under linear SAT this gives a deterministic RAM clock at most (L+JR+K/G+J+√K)log^{c}(T+2) for a fixed c. All bounds can be implemented with c independent of the eventual choice of the fixed a: numeric indices have O(log T) bits, there are a fixed number of quantified blocks, and the only factors depending on the counts are displayed. For large fixed a the bound is small enough even after quasilinear nondeterministic conversion from RAM to multitape to fit in T/log₂(n+2). A finite list of false positives could be hardwired. The hierarchy thus forces infinitely many NO inputs with passing chronologies if SAT is linear. On each such input some packet is corrupted and every corrupted packet has the fault and sign-change bounds above. Conversely it would suffice to construct a verifier of this hierarchy language in which each locally accepting chronology on each sufficiently large NO input has either a local mismatch or a packet failing these checks, while retaining legal acceptance on YES inputs. A two-stack example shows why local legality cannot by itself supply the missing property. On a unary length parameter, guess bits and push the same bit onto two stacks each time. Pop them in parallel in the second half, accepting exactly when a difference is seen. Use identical block endpoints on both stacks (or constant-sized paired operation slots). The true language is empty. There is a packet of length m=Ω(L) since O(J) packets carry all the bits. For any allowed fixed prime, the R residues and the bin sums of a length-m binary word carry at most R log₂ p + ⌈m/G⌉ log₂(G+1)=o(m) bits as T grows with the number of slots. Some two distinct words therefore share all summaries. Use the first on both push sides and on one pop side, and the second on the corresponding packet of the other pop side. Keep all other packets identical. The CPU accepts and all the checks pass. Direct synchronization of the two stack values would settle this example. A comparable invariant for the fixed hierarchy verifier remains missing.
