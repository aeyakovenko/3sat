# How many bit resets does a fast SAT solver need?

Fix $k\in\{1,2,3\}$, an integer $h\ge1$, and a fixed rational $0<\epsilon\le1$. If ordinary explicit SAT has a deterministic $O(n^k)$ solver on the stated logarithmic-word RAM, it has an **equivalent deterministic solver of the same time order** with all of the following properties simultaneously. Here $n$ is the original encoded input length, $w=12\lceil\log_2(n+2)\rceil$, $W$ counts the stores of the original solver on this input, $r$ is a power of two with $r=\Theta(w)$ and $r\le w$, and $L=r^h$.

* Outside a designated contiguous arena, each bit of addressable writable memory can only change from zero to one. This part of memory can be large.
* At most $\lfloor W/L\rfloor$ arena words are allocated, always in the initial segment of this arena. The total number of ordinary arena increments is at most $\lfloor W/L\rfloor$. The total number of $1\to0$ bit changes in **all addressable work memory** is at most this same quantity.
* Every work word is numerically nondecreasing. Each word changes value at most $O(n^\epsilon)$ times. Each change to an ordinary arena word is an increment by exactly one.

The fixed CPU registers, including the simulated CPU state and allocation cursors, are ordinary registers. The input retains its original read-only random-access interface. The constants in the simulation depend on the fixed program, $k,h,\epsilon$. The result applies to arbitrary polynomial-clock word computations with enough address bits for the sparse implementation below. It gives equivalence for each of the three SAT time targets. In particular a lower bound for SAT with these provisions for bit-write-once storage and a small bank of regular words would reach the unrestricted RAM at that exponent. A proof that charges the number of *all* nonzero words, or needs a small image of the bit-write-once store at every cut, still has to control that store. ## Versions of a logical address

For each logical address $a$, let $c_a$ be its number of guest stores so far. An uninitialized address has version zero and value zero. To store $v$, advance the version from $c$ to $c+1$ and put $v$ at the fresh payload key $(a,c+1)$. A load retrieves the payload for the current version. Every payload word is written at most once, even for a stored zero or repeated guest value. Thus all of its bit changes are $0\to1$. By induction on guest stores, exactly one payload is current at each initialized address. The same program and input therefore have the same simulated registers, memory answers and verdicts at the corresponding guest steps.

An elementary constant-overhead version keeps a single binary counter per address. In its first $s$ increments from zero, the number of downward bit changes is $s-\operatorname{popcount}(s)$ and the number of total bit changes is $2s-\operatorname{popcount}(s)$. Each increment adds one previously unset bit. The excess of upward over downward changes after the $s$ increments equals the final Hamming weight. Summing over the addresses already bounds the downward count by $W$. Smaller bounds need a counter representation that can accommodate many stores without clearing any bit.

## A digit cell that is never reset on carry

In radix $B\ge2$, index the digit of position $j$ by all its **higher** digits, with a key containing $j$ and $q=\lfloor c/B^{j+1}\rfloor$. Each digit cell starts at zero. To read the current version, start above its highest position and descend, using the recovered higher prefix as the key for the next digit. For an increment choose the least $j$ whose digit is below $B-1$. Increase just that cell by one. The lower digits that overflowed now have higher prefixes never used for them before. Their new cells still read as zero, so no old cell is cleared. Every cell increases at most $B-1$ times. The code can first read $c$, compute $c+1$ and the position $j$, then address the one changed digit. It needs $O(d)$ work and constant working registers for $d$ digits, by repeated shifts or division with the radix powers within the stated word width.

Binary encoding of the digit yields numerically increasing cells. For $B\le w+1$ a digit $x\in[0,B-1]$ can instead use the mask $2^x-1$. The transition $x\mapsto x+1$ sets a single previously zero bit. In the implementation below use $B\le w$. Precompute the inverse on these $O(w)$ possible masks by iterating the masks from zero and writing their digit numbers at immutable lookup keys. This costs $O(w)$ work using the sparse addressing below. The decoder needs neither a unit-cost population-count instruction nor a mutable table for building these constants.

Taken by itself, the digit construction gives two reference points. A radix $B=2^{\max(1,\lfloor\epsilon\lfloor\log_2(n+2)\rfloor\rfloor)}$ needs $O_{k,\epsilon}(1)$ levels for a polynomially bounded version and ensures $O(n^\epsilon)$ changes per word at constant slowdown. A unary-mask radix $B=\Theta(w)$ gives a genuine bit-write-once work bank with $O(1+\log(T+1)/\log w)$ slowdown for known polynomial clock $T$. One may also size its level count using a bound on the largest per-address update count. This second tradeoff and the reduction from RAM simulation to maintaining counters have classical antecedents, detailed below.

## Separating a high part that rarely changes

Write each version as $pL+u$, $0\le u<L=r^h$. For each $(a,p)$ maintain the $h$ digits of $u$ by the unary-mask scheme, with a distinct key for each higher prefix. When $u<L-1$, advance it by one physical bit set. When $u=L-1$, increase $p$ and let the new $(a,p+1)$ start with implicit zeros. The low bank has no bit resets on this transition either. Put each new payload at its full version key in both cases.

The simplest high representation is one ordinary binary word per promoted address. At the first rollover initialize the next slot of a dense bank and put its slot number in a previously unused immutable directory entry for $a$. Later rollovers increment that slot. An address with $s$ stores causes exactly $\lfloor s/L\rfloor$ high increments, hence

$$ H=\sum_a\left\lfloor c_a/L\right\rfloor\le \left\lfloor W/L\right\rfloor. $$

To impose the maximum-change bound as well, use the binary-digit prefix construction for each high part $p$, with radix $B$ of order $n^\epsilon$. A high increment changes just one digit. Give a high-digit key $(a,j,q)$ its own next dense arena slot on its first change, recording the slot number in an immutable directory entry. Zero digits with no entry consume no arena slot. An address can have several high-digit slots. There is at most one new slot per high increment and the total number of high-word increments is still exactly $H$. The preceding binary count applied to each arena word bounds its downward changes by its number of increments. All non-arena work bits only set. Each high word changes at most $B-1$ times, each low word at most $r-1$, and each payload or directory pointer at most once. The fixed low depth and $O_{k,\epsilon}(1)$ high depth give $O_{k,h,\epsilon}(1)$ worst-case time per simulated guest operation after setup.

## Sparse addresses in one physical bank

The logical guest may use its whole $w$-bit address range. Each metadata key is a constant-length tuple of words, with a tag distinguishing payloads, digit masks, high-digit slots and lookup constants. Use a sparse radix trie on these fixed key fields, processing the fields separately. Take a digit of $\max(1,\lfloor\log_2(n+2)\rfloor)$ bits. The number of levels per word is bounded by a constant for $w=12\lceil\log_2(n+2)\rceil$. A missing path on a load reports zero without allocating anything. On insertion, give each newly required node a fresh contiguous row of initially zero words and set the corresponding parent pointer once. Node numbers or row offsets can be encoded with a nonzero sentinel convention. Reserving a virgin row increments a register. It performs no scan of the row. Each lookup or new tuple insertion therefore takes constant worst-case time. A lookup that needs to distinguish a stored zero can use its immutable occupancy marker, or rely directly on the version invariant for payloads.

For $O(n^k)$ time there are $O(T+w)$ inserted tuples and at most a constant number of new rows per insertion, since one original store changes just one low or high digit and writes one payload. The trie reserves $O((T+w)(n+2))$ physical addresses but writes only $O(T+w)$ words. These addresses fit below a public boundary of order $(n+2)^6$ for all sufficiently large $n$ when $k\le3$. Place the dense arena above that boundary. Its consecutive slots are independent of trie allocation and the whole construction fits in the given $w$ address bits. Sizes, radix shifts and a safe fixed upper bound on the number of high digits can use $(n+2)^{k+1}$ in place of an unknown clock constant. $B^{d}$ for the last high digit need only exceed that polynomial by one radix factor. $L=r^h$ fits for sufficiently large $n$ and fixed $h$. Finite smaller lengths can use a fixed direct program or a register-only hardwired decision tree. Polynomial-in-$\log(n+2)$ setup is absorbed by each of the three time bounds. There is no need to offset a full copy of the guest address space into a second bank, or to use an ordinary rewritable hash table to implement the sparse keys.

## Checking the regular bank from one short read-only event table

There is a sound nondeterministic replay that uses only bit-write-once addressable work memory, ordinary CPU registers, and a read-only certificate of $O(H+1)$ words for the whole regular bank. The replay takes $O(T+H)$ time including table validation, for a guest clock $T\ge n$. This verifier uses private nondeterministic choices during replay in addition to the table.

Number guest memory operations chronologically, or subdivide each guest step into a fixed number of ordered slots when an instruction may do several operations. Each high increment then has a unique time $t$ and dense arena index $s$. Give the verifier the same events in two arrays. The first is strictly ordered by time. The second is strictly ordered by $(s,t)$ and records the successive counts $1,2,\ldots$ within each run of equal $s$. Include inverse array indices. The verifier checks both orders, counts, lengths, and the two inverse identities with event equality in $O(H+1)$ probes and constant working registers. An input table can be capped at $\lfloor T/L\rfloor$ events for a one-store-per-step clock, or at the corresponding constant multiple if necessary.

To read slot $s$ immediately before time $t$, guess the cut in the second array just before $(s,t)$. Test the two neighboring keys against $(s,t)$, using sentinels at the ends. There is exactly one valid cut. If its predecessor has first key $s$, the verified count there is the slot value. Otherwise the value is zero. This uses $O(1)$ probes and one guessed index, even if the same key occurs many times. As it replays each step, the verifier compares the actual requested high increment, if any, to the next event at that time in the first array. Any discrepancy rejects. Allocate slot numbers and write immutable pointers as in the deterministic simulation, and require the time-ordered array to be exhausted at termination. A step that reads an updated slot internally can add its own unit increment in a register.

Induct on time. Once all events before $t$ agree with the true run, every certified predecessor query before the current increment gives its true value. Thus the instructions up to the event comparison at $t$ determine the true decision to increment, and its true slot. The comparison forces exactly that event into the array. Together with the valid instance furnished by an honest run, this proves completeness and soundness, including for adaptively addressed reads. A deterministic replay with the same given table can use binary search in $O(\log(H+2))$ time per high-slot lookup. The table eliminates the regular bank during verification. The replay still carries the full bit-write-once bank and still spends time to follow the guest instructions.

## A matching bound for snapshot-local queries

Fix one query key and a single deterministic decoder. Give it only the current work-memory snapshot. Other inputs, including any supplied registers, must be identical throughout the queried sequence. Allow arbitrary computation and adaptive addresses between at most $q$ word probes. Suppose that during this same chronological sequence each physical word changes value at most $b$ times. Then the decoded answer has at most $(b+1)^q$ consecutive constant runs. The first address is fixed. Its contents divide the sequence into at most $b+1$ intervals. On each interval the first answer is constant, so the same argument applies to the remaining $q-1$ probes there. A decoder halting early can be padded with irrelevant repeated probes. The base case makes no memory probes and has one constant answer.

In particular recovering the values $0,1,\dots,U$ of a growing logical counter requires $q\ge\lceil\log_{b+1}(U+1)\rceil$ for $b\ge1$. The digit-prefix tree with radix $b+1$ attains the bound in the unconstrained-address probe model by allocating a known cell per prefix and reading one per digit. Each cell changes at most $b$ times. For bit-write-once $w$-bit cells, $b=w$ works and unary digits attain the same probe count when radix $w+1$ is used. With fixed bit width the addresses of all relevant prefix cells must be representable. The one-bank sparse implementation above adds a constant factor to physical probes. A public clock specifying the counter value, changing register contents, or a freely supplied witness for each read can invalidate the lower-bound premise. The lower bound applies when the decoder must recover its answer from one snapshot at a time.

## Relation to write-once RAM and to the SAT target

Irani, Naor and Rubinfeld distinguish bit-write-once memory (individual bits may set) from word-write-once memory (one store per word), with logarithmic words and some regular memory. In their 1988 report, Theorems 3.1 and 3.2 simulate in terms of space or per-address update count. Theorem 3.3 gives a bit-write-once simulation with a $\max(1,O(\log b/\log\log n))$ time factor for a bound $b$ on updates per location. Its tree per updated variable stores versions at leaves. Internal child addresses advance by setting bits. Section 3.2 also gives the online counter-maintenance reduction. The report's matching optical-interface lower bound from Vitter applies to the register-restricted online interface in which regular registers are cleared between updates. Their general model allows a regular-memory parameter such as $n^\alpha$. Specifying this parameter is different from establishing constant slowdown for unrestricted programs with that regular bank. The numerical both-direction equivalence above uses $O(T/\log^h n)$ regular words, often much larger than $T^\delta$ for fixed $\delta<1$. The high-part construction obtains the same bound on the *total number of resets* and confines them to one predetermined arena. Historical priority for this particular combination is unverified. [Authors’ technical report, §§2–3.2](https://www2.eecs.berkeley.edu/Pubs/TechRpts/1988/6043.html) · [Journal publication](https://doi.org/10.1007/BF02835833)

For each fixed $h$, even a hypothetical linear-time SAT solver can therefore be made to use at most $O(n/\log^h n)$ ordinary arena words and $O(n/\log^h n)$ bit resets in total. The same conclusion holds with $n^2$ or $n^3$ in the numerator under the corresponding hypothesis. At linear time an explicitly transmitted list of the resets, with times and addresses of $O(\log n)$ bits each, can consequently have $O(n/\log^{h-1} n)$ bits. The list does not explain the contents of the fresh payload words, the dynamic addresses they serve, or the bit settings in the large immutable directory. The checkpoint results for a small **entire** work-memory snapshot do not directly apply to this representation.
