# A linear native clock with a multilinear oracle

There is a recursive Boolean oracle $A$ and its canonical multilinear extension $\widetilde A$ over every effectively presented finite field such that a deterministic packed RAM using only $A$ can decide in $O(n)$ steps what a nondeterministic packed RAM decides in $O(n)$ steps with Boolean and extension queries. In fact the source machine may alternate at every step. Ordinary SAT and explicitly listed mixed-oracle CircuitSAT also have deterministic $O(n)$ algorithms with the Boolean oracle alone, for $n$ encoded input bits. The target word width is logarithmic in $n$. The construction embeds a tagged copy of the previously constructed recursive clock oracle; the new mixed queries require additional Boolean oracle entries. [Original clock and ISA](relativized-clock.md)

Aaronson and Wigderson already give the polynomial-time collapse by taking a PSPACE-complete oracle and its multilinear extension. Their separation test places the extension on the left and the Boolean oracle on the right. The point here is to preserve the **linear word clock**, including on a machine that can ask about a very long zero-initialized buffer by specifying just its address and length. [Aaronson and Wigderson, Definitions 2.2–2.3 and Theorem 5.1](https://www.scottaaronson.com/papers/alg.pdf)

## Query convention

A Boolean query reads a contiguous packed bit string. An extension query specifies a valid field and a contiguous array of $j$ explicitly represented field elements, in fixed-sized slots for that field. Zero has the all-zero representation; each nonzero element occupies at least one set bit in its own slot. The machine can request a specified bit of the result, or one bounded word. Invalid descriptors, out-of-range buffers and malformed fields return zero. Addresses cannot wrap around and duplicate the same physical coordinates. For one uniformly decidable format, give a prime $p$ and a monic irreducible over $\mathbb F_p$ defining a polynomial basis, with canonical residue coefficients in each slot. Check primality, irreducibility and the coefficient ranges by terminating algorithms, defaulting to zero on invalid query encodings. This presents every finite field up to isomorphism. A query has no bulk write side effect. Native work memory starts at zero, the immutable input and fixed program are the only external bit strings, and each instruction writes at most a fixed number of $w$-bit words. Nondeterministic instructions can guess an entire word. These conventions permit sparse buffers of polynomially large addressable length and persistent query memory. They charge every coordinate if the programmer creates a dense nonzero array. A succinct circuit standing for an exponentially repeated vector is a different interface.

## Why the recursion terminates even for sparse, high-arity queries

Use the leading-zero slice of $A$ for any fixed recursive Boolean predicate, for example the old clock oracle. Only two kinds of leading-one strings can have value one: wrappers for bounded machines and wrappers for explicitly listed circuits or CNFs. Give each a self-delimiting body followed by dense padding. Require the padding to contain more than half the total string length in ones. All other strings have value zero. The empty query has a fixed answer.

A machine wrapper contains a program, its actual input $x$, a step budget $t$ and word width $w$. The program uses a fixed bounded-write ISA. Fix a computable budget $B=|x|+|M|+O((t+1)w+w)$ bounding the total set bits in every physically readable bank on **any single branch**; use the known register, descriptor and write constants of this ISA in that formula. Count scalar oracle replies in the per-step writes. For definiteness use $4(B+|\mathrm{body}|+1)$ padding ones, so the wrapper length $L$ satisfies $2B<L$. Its answer is the recursive Boolean value of the bounded computation tree (OR for existential nodes, AND for universal nodes, fixed rejection on a timeout). All finite fields and widths are interpreted effectively regardless of their sizes.

Induct on $L$. A Boolean query of length $j\ge L$ made by the bounded computation cannot be any positive wrapper: its support has size at most $B<j/2$. It may still query the old leading-zero slice, whose answer is computed directly. For an extension query at $z\in F^j$, use
$$
 \widetilde A_{j,F}(z)=\sum_{u\in\{0,1\}^j} A(u)
       \prod_{i:u_i=1} z_i\prod_{i:u_i=0}(1-z_i).
$$
If a term has nonzero weight, then $\operatorname{supp}(u)\subseteq\{i:z_i\ne0\}$. This last set has at most $B$ coordinates because the slots are disjoint. If $j\ge L$, **none of these Boolean vertices can be a positive wrapper**. Evaluate terms using only the independent old slice and zero on the wrapper slice. When $j<L$, all Boolean terms have already been defined by induction. The computation tree can therefore be evaluated to finite depth without consulting any unassigned wrapper value. There is no efficiency requirement on constructing the oracle. This defines one recursive $A$ for all source machines, input lengths and field queries. The displayed extensions have individual degree at most one and agree with $A$ on the Boolean cube.

The circuit wrapper lists every argument position of every gate explicitly. On a valid body of length $m$ every oracle arity is at most $m$, whatever values the circuit wires carry. Use more than $m$ padding bits. Bounded witness enumeration and the same length induction give its answer; an ordinary CNF mode directly accepts the original encoded formula. No arithmetization of SAT is needed inside the deterministic solver.

## The charged simulation and its scope

For any fixed source program taking at most $Kn$ steps on $n$ input bits, write its machine wrapper with $t=\lceil Kn\rceil$ and its true width $w=\Theta(\log(n+2))$. The string has $O(n\log n)$ bits and takes $O(n)$ word steps to produce, including all padding. One Boolean query returns the answer. The same construction with the circuit/CNF body takes at most linear time on the original encoding. The deterministic solver uses no extension queries. A family of circuits with enormous oracle arities specified solely by binary counts would require its own model analysis.

This gives a counterexample to a separation required to hold for **every** oracle and extension in this interface, both for the native linear-time classes and for the mixed-circuit problem. It is possible for a proposed sum-check or PCP proof to exploit the fixed syntax of ordinary SAT, a restricted family of verifiers, or a different query interface. Retiring that proof requires showing its actual steps and costs extend to the oracle setting above. The Boolean theorem for ordinary machines remains open.

## The same oracle can defeat even an unbounded-alternation time speedup

Split the independent leading-zero slice into $00B_{\rm old}$ and $01R$, with the old recursive oracle fixed once and for all. The raw predicate $R$ may be positive only on unary strings $1^k$. For each recursive choice of $R$ the wrapper construction above still works. We can choose $R$ recursively so that in this **same world**
$$
 \mathrm{DTIME}^{A}_{\rm word}[n^2]\not\subseteq
 \mathrm{ATIME}^{A,\widetilde A}_{\rm word}[o(n^2)].
$$
The alternating time bound counts worst-branch native steps; a query has the concrete contiguous-buffer semantics above.

First, the value of a recursive wrapper of length $L$ can only depend on raw unary keys of length at most $L$. For a circuit wrapper, every embedded query has arity below $L$. In a machine wrapper a Boolean question or a nonzero-weight Boolean term of an extension question has at most $B<L/2$ ones. A raw unary key in such a term therefore has at most $B$ ones. Any term that reaches a recursive wrapper of length at least $L$ gets zero, independently of $R$. For shorter wrapper terms apply the induction hypothesis. This argument includes the possibility that later query coordinates or branch choices depend on earlier answers.

If every branch of an actual outer computation has at most $b$ available set bits, the entire alternating tree depends only on $R(1^k)$ for $k\le2b+O(1)$. Indeed its directly queried raw keys have weight at most $b$. Each wrapper that can contribute to any answer has length at most $2b$, by dense padding and the multilinear support implication. The previous paragraph bounds the raw dependencies of those wrappers. Arbitrarily many alternating branches do not increase this bound on key length.

Put $K(n)=n^2\lceil\log_2(n+2)\rceil$. Consider the language that contains every string of length $n$ precisely when $R(1^{K(n)})=1$. On a suitable fixed logarithmic word width a deterministic machine writes the dense raw query and obtains this bit in $O(n^2)$ time. Enumerate all alternating machines and their word-width constants, repeating each infinitely often. For a given machine $M$ choose a small rational $c_M>0$ so that on $0^n$ through $\lfloor c_M n^2\rfloor$ steps we have $2b+O(1)<K(n)$ for all sufficiently large $n$. This follows from the fixed number of writes per step and $w_M(n)=O_M(\log n)$. At a fresh such length compute the entire bounded tree with all unsettled unary bits temporarily zero, treating timeouts as rejection. Set $R(1^{K(n)})$ opposite the resulting bit. Settle all other previously unsettled unary lengths through $K(n)$ to zero, and choose the next stage with a larger key. The dependence bound preserves the bounded computation after every later change. All stage searches and exhaustive evaluations terminate; raw lengths below an increasing cutoff are settled permanently. This gives a recursive $R$ with the desired property. Any correct alternating program has a branch exceeding its cutoff at infinitely many of its stages.

The hard clock here is the cost of creating a dense *external* query. A proof of an ordinary native RAM alternation speedup could rely on the fixed, oracle-free instruction set and avoid this obstruction. The construction gives a concrete failure for a speedup preserved under the stated algebraic oracle interface.
