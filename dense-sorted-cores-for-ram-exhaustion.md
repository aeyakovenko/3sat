# Dense, sorted formulas suffice for unrestricted RAM time exhaustion

Fix the journal's deterministic RAM with its single writable, initially zero memory bank containing the input, public input length, fixed integer width coefficient $D\ge1$ and $w_D(n)=16\lceil D\log_2(n+2)/16\rceil$. Use well-formed, comment-free ASCII DIMACS with three distinct variables per clause, allowing whitespace-separated tokens and unused declared names. Define the restricted files by four requirements: all names from 1 through the variable bound occur; the three signed literals of each clause are in a prescribed total order; the list of clauses is strictly lexicographically increasing in that order; and the decimal fields and separators have their shortest prescribed spellings. Use one separating space between tokens of a clause and a newline between clauses. If the grammar permits EOF immediately after the last zero, omit a final body newline; if it requires that newline, retain it. Choose the header's terminating newline according to the grammar. Handle a formula with no clauses directly.

**Transfer theorem.** There is a uniform compiler taking any fixed RAM program correct on all these restricted files to a program deciding all the original files. On an input of $n$ bits its time is
$$
 O(1+n/\log(n+2))+O(1)\,T_P(m)
$$
for some restricted file of length $m\le n$, except for the direct constant-verdict empty case after parsing. Here $T_P(m)$ is the worst time of the candidate on restricted files of that length. The compiler may overwrite the entire original file and use all word addresses. It works at the same width coefficient, including when the candidate uses its entire guest address range. In the separate-operation ISA with at most two numerical operands per instruction the compiled program uses at most $a s+b$ stored instructions for an $s$-slot candidate, for fixed machine constants $a,b$ (and fixed $D$). The constants in the time bound are independent of $s$ when the compiled candidate is directly inlined.

Consequently for each fixed $d\ge1$, a uniform $O(n^d)$ solver on the restricted valid files exists if and only if there is one on all valid files. In particular a lower-bound proof can exhaust **only** dense, sorted, duplicate-free proper 3-CNFs with standard spacing, simultaneously for the linear, quadratic and cubic targets. If an eventual deadline is used, the finitely many smaller restricted lengths contribute a fixed bound for a correct terminating candidate. This theorem transfers the *class* of worst-case clocks. It does not turn an instance defeating $s$ instructions into one defeating $s+1$. It does not identify formulas up to arbitrary permutations of their variable names.

## A restricted file no longer than its input

Use the [packed distinct-clause scan](packed-normalization-of-dimacs-clauses.md) to group equal original variable names and retain distinct clauses in $O(1+n/\log(n+2))$ steps and words. The scan can retain one representative occurrence and the number of normalized digits of each name. Make one additional radix sort of the distinct names by that digit length. Number their groups consecutively starting at 1 in this order, with a deterministic tie break. For a variable originally having $e$ normalized digits, there are at most $10^e-1$ positive integers with at most $e$ digits. Thus its new index has at most $e$ digits. This ensures the length bound for *every occurrence*, including frequently repeated names. The largest new name, the number of occurring variables, is at most the original header bound. The new clause count is at most the original count. Original numeric fields with leading zeros can only shrink. Lengths used as radix keys are at most $n$, and two digits of radix $B=\Theta(1+n/\log(n+2))$ suffice asymptotically. Rename each retained literal and sort the resulting triples again.

The minimum separators for one header and for this many clauses cost no more bytes than the original valid token stream. Signs are preserved, sorting does not change the required separator count, and each retained clause has at least one distinct original representative. The header uses only its two minimal counters and required fixed text. Therefore the canonical output has $m\le n$ bits. This matters near jumps in the word-width function. For example, a bound $m\le2n$ alone would allow a larger guest address space than the exact host can supply.

To emit compact ASCII in the claimed word time, precompute packed decimal spellings for the integers from 1 through the larger of the two output header counts. There are $O(B)$ such values. Use $b=\max(1,\lfloor\log_2(n+2)/32\rfloor)$ decimal digits per limb. Tabulate padded $b$-digit strings and leading-zero-free spellings of every integer below $10^b$ by a direct digit computation in $o(B)$ total time for large $n$. Each limb's ASCII fits in a word. Enumerate the header-count range sequentially with an odometer in base $10^b$. It has a bounded number of limbs, so the complete spelling of each new integer needs $O(1)$ operations and $O(1)$ words. Append a token to the packed stream with a bounded number of shifts and boundary-word writes. This also emits the header, signs, terminators and newlines in $O(B)$ time. The sorted triples and spelling tables occupy $O(B)$ words.

## Running the proposed solver at its own input length

Initially use consecutive scratch arrays above the original packed file. Copy the packed restricted file down to address zero, fill unused bits of its final word with zero and clear the touched region beyond its end. When $w_D(m)$ differs from $w_D(n)$, the guest expects **one zero-extended guest word per host address**, rather than host-width chunks of its concatenated bytes. Split and expand the packed stream into that format in scratch before copying it down. At most two host loads recover a guest word because $w_D(m)\le w_D(n)$. There are $O(1+m/\log(m+2))=O(B)$ guest words and the whole normalization uses $O(B)$ host addresses. This fits even when $D=1$ at all sufficiently large $n$. After zeroing, every remaining host cell of the guest address space has its required initial contents. The metadata and any unused registers are initialized for the guest. The original input is no longer needed.

Inline each guest instruction into a bounded block of host instructions. Keep register and memory values zero-extended at the guest width $v=w_D(m)$. Truncate literals, arithmetic outputs and addresses with the guest mask. Unsigned comparisons then agree; for signed comparisons, bias both sign bits first. Host modular multiplication followed by truncation gives the guest modular product. Use two shifts and masks for rotation, with separate cases for zero count and saturating shifts. If the ISA reduces a count modulo $v$, compute that remainder by a precomputed reciprocal of $v$ using a bounded number of half-word limbs. For instance take $K=2^{w_D(n)}$, $u=\lfloor K/v\rfloor$, and a count $0\le x<K$. The quotient estimate $\lfloor xu/K\rfloor$ is at most one below $\lfloor x/v\rfloor$; one corrected subtraction suffices. Compute $u$ and width metadata once by bit division on a fixed number of host words in $\operatorname{polylog} n$ steps. The mask for a full-width guest can be constructed as the all-ones word without shifting by the width. Direct labels remain fixed labels. Thus each guest operation has a fixed native expansion with no per-access memory dictionary and no reserved part of the guest's address range. Other models with immutable input banks or code stored as data would require their own storage simulation.

A globally fixed linear-time solver could therefore exploit arbitrary syntax normalization before addressing the SAT decisions on these dense sorted cores. Conversely, once these files themselves defeat every program at the proposed time bound, arbitrary whitespace, sparse decimal identifiers, clause permutations and duplicate clauses need no additional case split. The [finite audit](dense_sorted_core_length_audit.py) checks the length and satisfiability inequalities and guest-word initialization on small and heavily padded formulas. The costed compiler and the transfer of asymptotic classes are manuscript arguments.

## Relation to binary encodings

For the usual binary listing, store each literal in a sign bit and a fixed-width index of $h=\lceil\log_2(v+1)\rceil$ bits, with an explicit header and $v$ the declared bound. Converting one of the sorted ASCII cores with $c$ clauses to this binary format costs $O(n)$ bits and time. Indeed $v\le3c$ and the sum of byte lengths of $c$ distinct clause records is $\Omega(c\log(c+1))$ for unbounded $c$. At most $\sum_{j<\ell}256^j$ different records can be shorter than $\ell$ bytes; take $\ell=\lfloor(\log_{256}c)/2\rfloor$. Thus serializing $O(c\log(v+1))$ binary bits fits in the claimed size, even if many occurrences have short original names.

In the other direction, on a binary proper three-literal list of length $n'$ bits, equal fixed-width indices can be interned by the same chunk-tree ranking in $O(n')$ time, including indices longer than a native word. There are at most $v$ distinct occurring indices and at most three per clause. Replace them by dense positive names. Each occurrence then requires $O(1+h)$ ASCII bits, with the fixed factor accounting for bits per decimal byte. Sorting and removing duplicate dense triples takes $O(n')$ time by integer radix sorting. The minimal header is also within $O(n')$ bits for the ordinary explicit counting header. This direction suffices at each proposed clock exponent $d\ge1$. The two conversions preserve polynomial clocks of a *fixed exponent* on the usual class allowing a sufficiently large fixed logarithmic width coefficient for each program. A constant expansion of the bit length in a cross-format conversion can require increasing that coefficient to host the entire guest memory. The same-coefficient, non-expanding conclusion above concerns the ASCII-to-ASCII compiler.

## An exact executed-step seed inside the restricted files

Take the standard width coefficient $D=1$ and order literals by unsigned identifier, with positive before negative on ties. The [exact sparse-edit clock](exact-executed-clocks-for-sparse-word-edits.md) survives these normalization requirements on infinitely many lengths. On the promise below its exact value is
$$
 2m-\lfloor m/(k+1)\rfloor,\qquad 1\le k\le m,\qquad m=\Theta(n/\log n).
$$
The optimal program may depend on the chosen finite promise. The lower bound holds on the same satisfiable core for every program correct on the promise, with arbitrary stored instructions and unrestricted writable memory.

For an increasing integer $q$ let $M=10^q-1$, let $A$ have $q$ decimal digits all equal to 5, let $y=M-1,z=M$, and put $m=\lfloor M/4\rfloor$. Pin every variable $i\le M-2$ false except $A$, pinned true. A pin uses the four clauses on its chosen literal and all signs of $y,z$. Add the $m$ clauses $(i\lor (i+1)\lor A)$ for $1\le i\le m$, where positive integers here denote positive literals. Sort everything and use the minimal spelling. The file has distinct proper clauses, all $M$ identifiers occur, and $n=\Theta(Mq)$. Each added clause is a separate record with an ordered first pair unaffected by edits of its third literal.

Write $W=w/8$ for bytes per word. Because $D=1$ and $n=\Theta(10^q q)$, we have $W/q\to(\log_2 10)/8<1/2$. In the third name of each added record choose a whole aligned word strictly past its first digit. Such a word exists for large $q$ at every byte alignment. Every one of these words consists entirely of ASCII 5s. Apply the repunit construction of the sparse-edit proof: if $o$ is the odd part of $w$, choose $1\le\ell\le o\le W/2$ with $o\mid(1+256+\cdots+256^{\ell-1})$. Replace the last $\ell$ bytes of the selected word by copies of one digit from 3 through 7. All altered identifiers still begin with 5. Every noncenter name is different from $A$, exceeds $i+1$, and is below $y$, so it already occurs in the pins and is forced false. The modified clause is false. Thus the verdict is SAT exactly when every marked word has its center value. No edit changes a line's position, the dense name set, any separator, a clause count, or the file length.

The five numerical word values differ by multiples of $\Delta=256^{W-\ell}(1+\cdots+256^{\ell-1})$, with $w\mid\Delta$ and $\Delta^2=0\bmod 2^w$. Digit 4 gives a bitwise submask of digit 5 and digit 7 a supermask. All marked addresses are below the numerical value of the center word. These are precisely the hypotheses on the private words in the existing instruction-replay and forest argument; the other physical words may be arbitrary fixed words, including further unmarked words equal to center. Its lower bound applies, and the unrolled equality-block program attains it. At $k=m$ the base requires at least $2m$ executed instructions of every correct full solver. This remains proportional to packed words, a factor of order $\log n$ below a bound proportional to encoded bits. The [layout audit](sorted_dense_sparse_edit_audit.py) checks actual small files and computes offsets and word edits on large orders by summing exact byte counts across decimal-length intervals.
